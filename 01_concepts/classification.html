Classical ML

Classification algorithms explained

Classification predicts a discrete label: spam or not, disease or healthy, which product category. Interviews test whether you understand how each algorithm decides, what it assumes, when it wins, and when it breaks.

Core idea

Given features X, assign a class label y Learn a decision boundary that separates classes well

Binary vs multiclass

Binary classification has two classes. Multiclass has three or more. Some algorithms handle both natively; others need wrappers such as one-vs-rest or one-vs-one.

Probability vs hard assignment

Some classifiers output a probability of belonging to each class (logistic regression, random forest). Others output a hard assignment directly (basic SVM). Probability outputs are usually more useful in practice.

Algorithm 1

Logistic regression

How it works

Despite the name, logistic regression is a classifier. It uses a linear combination of features passed through a sigmoid function to output a probability between 0 and 1.

P(y=1|X) = sigmoid(w*X + b) = 1 / (1 + e^(-(w*X + b)))

Key properties

  • Simple, fast, interpretable.
  • Outputs calibrated probabilities.
  • Works well when the relationship is roughly linear in the log-odds space.
  • Struggles with complex nonlinear decision boundaries.

Algorithm 2

Decision trees

How it works

A decision tree splits data recursively on the feature and threshold that best separates classes. Common splitting criteria are Gini impurity and information gain (entropy).

Key properties

  • Highly interpretable. You can visualize the full tree.
  • No feature scaling needed.
  • Handles nonlinear boundaries naturally.
  • Prone to overfitting if not pruned or depth-limited.
Splitting criterion What it measures
Gini impurity Probability of misclassifying a randomly chosen element. Lower is purer.
Information gain (entropy) Reduction in uncertainty after the split. Higher gain means a more useful split.

Algorithm 3

Random forest

How it works

Train many decision trees on random subsets of data and features. Each tree votes, and the final prediction is the majority class. This is called bagging with random feature subsets.

Why it helps

  • Reduces variance compared to a single tree.
  • Handles high-dimensional data well.
  • Robust to overfitting relative to individual trees.
  • Gives feature importance rankings.

Algorithm 4

Support vector machines

How it works

SVM finds the hyperplane that maximizes the margin between classes. Points closest to the boundary are the support vectors. For nonlinear problems, the kernel trick maps data into a higher-dimensional space.

Key properties

  • Effective in high-dimensional spaces.
  • The kernel trick (RBF, polynomial) handles nonlinear boundaries.
  • Less interpretable than trees or logistic regression.
  • Does not scale well to very large datasets.

Algorithm 5

K-nearest neighbors

How it works

KNN makes no assumptions about the data distribution. At prediction time, it finds the K closest training points and assigns the majority class label.

Key properties

  • Simple and intuitive.
  • No training phase, all computation at prediction time.
  • Very sensitive to feature scaling and irrelevant features.
  • Slow at prediction for large datasets. The curse of dimensionality hurts.

Algorithm 6

Naive Bayes

How it works

Applies Bayes' theorem with the naive assumption that all features are conditionally independent given the class label.

P(class|features) proportional to P(class) * product of P(feature_i|class)

Key properties

  • Extremely fast and efficient for text classification.
  • Works surprisingly well even though the independence assumption is rarely true.
  • Not great for complex feature interactions.

Algorithm 7

Gradient boosting and XGBoost

How it works

Gradient boosting builds trees sequentially. Each new tree tries to correct the errors of the previous ensemble. XGBoost, LightGBM, and CatBoost are popular optimized implementations.

Why it often wins

  • Often the best performer on tabular data.
  • Handles missing values, mixed feature types, and nonlinear relationships.
  • Feature importance and SHAP values help interpretability.
  • Requires careful tuning of learning rate, tree depth, and number of rounds.

1. Start with a weak base prediction

The ensemble begins with a simple prediction for every row. In classification this often corresponds to the overall class prior rather than a powerful tree immediately.

2. Compute what the current model is getting wrong

The next tree is trained on the residual structure of the ensemble. More formally, boosting fits the next tree to the negative gradient of the loss function with respect to the current predictions.

3. Fit a small corrective tree

The new tree focuses on cases the current ensemble still handles badly. It learns how to push predictions in the right direction for those examples.

4. Add the correction slowly

The new tree is multiplied by a learning rate before being added to the ensemble. This is why boosting often works best with many shallow trees and small controlled updates.

Core boosting update rule

Initialize model: F_0(x)

For m = 1 to M:
  Compute pseudo-residuals:
    r_im = -[∂L(y_i, F(x_i)) / ∂F(x_i)] evaluated at F = F_(m-1)

  Fit a small tree h_m(x) to residuals r_im

  Update the ensemble:
    F_m(x) = F_(m-1)(x) + η * h_m(x)

Where:
  L = loss function
  η = learning rate
  h_m = the m-th tree

What makes XGBoost different from plain boosting

  • Uses first-order gradients and second-order derivatives for smarter split scoring.
  • Adds explicit regularization on tree complexity.
  • Supports row subsampling and column subsampling.
  • Handles missing values efficiently.
  • Is engineered for speed, memory efficiency, and scalable training.

Why the second-order idea matters

XGBoost uses not only the gradient, which tells the direction of improvement, but also the Hessian, which gives curvature information. That usually leads to better split choices and a more stable optimization path than naive residual fitting alone.

XGBoost objective at a high level

Objective = Training Loss + Regularization

Objective = Σ L(y_i, ŷ_i) + Σ Ω(tree_k)

Regularization penalizes:
  - too many leaves
  - overly large leaf weights
  - unnecessarily complex trees

This is a major reason XGBoost generalizes well on tabular data.

When random forest is a better first choice

  • You need a strong baseline quickly.
  • You want less tuning pain.
  • You value robustness and simpler training behavior.
  • You do not need to squeeze the last few accuracy points.

When XGBoost is often a better first choice

  • You are working on structured tabular data.
  • You care a lot about predictive performance.
  • You can afford cross-validation and hyperparameter tuning.
  • You need a model that captures subtle nonlinear feature interactions.

Interview tip: if someone asks what algorithm you would try first for structured tabular data, gradient-boosted trees is usually a strong default answer. For unstructured data like text and images, deep learning methods are usually preferred.

Interview readiness

Questionnaire and scenarios

Question

Why is logistic regression called regression if it does classification?

Strong answer

Because internally it regresses the log-odds of the positive class as a linear function of features. The sigmoid converts the continuous output into a probability, which is then thresholded for classification.

Question

What is the difference between bagging and boosting?

Strong answer

Bagging trains independent models on random subsets in parallel and averages them to reduce variance. Boosting trains models sequentially where each new model focuses on correcting errors from the previous ones, reducing bias.

Question

Why does XGBoost often outperform random forest on tabular classification?

Strong answer

Because XGBoost builds trees sequentially to correct prior mistakes and optimizes a regularized objective using gradients and second-order information. Random forest mainly reduces variance, while XGBoost often pushes accuracy further by reducing bias too.

Scenario

Your dataset has 50 features but only 200 rows. Which classifier would you try first?

Expected reasoning

Logistic regression with regularization or SVM with a kernel. High-dimensional small-sample settings need models that handle sparsity and avoid overfitting. I would also consider feature selection.

Scenario

You already have a random forest baseline, but the leaderboard still has room to improve. What would you try next?

Expected reasoning

I would try XGBoost or LightGBM next, because boosting often pushes tabular accuracy beyond bagging-based methods. I would tune learning rate, max depth, subsampling, and number of boosting rounds using cross-validation.

Scenario

You need to explain to a business stakeholder why a customer was classified as high churn risk. Which model gives you the easiest path?

Expected reasoning

A shallow decision tree or logistic regression with clear coefficient interpretation. For more complex models, I would use SHAP or permutation importance to explain individual predictions.

Classification interviews test algorithm intuition, tradeoffs, and the ability to match the right tool to the business problem.
