Task 6

Loops & Iterative Refinement

Keep improving until it's good enough — the agent feedback loop

🧩 What This Task Teaches

This is where LangGraph truly becomes an agent framework. A loop means the workflow can go back to a previous step and try again. This enables iterative refinement — search, evaluate, and if not good enough, search again with better parameters.

Core Concept: A conditional edge that routes BACK to a previous node creates a loop. Combined with a quality check and max iteration limit, this gives you self-improving workflows that refine their output until it meets a threshold.

🔄 The Loop Pattern

🔍 Search
→
📊 Evaluate
→
🚦 Router
→
✨ Summarize
↩ If quality < 0.8 AND iterations < max → LOOP BACK to Search

📈 Execution Trace — Watching the Loop

Query: "What is LangGraph?"

1
Search → "Basic results for: What is LangGraph?"
Evaluate → Quality: 0.3 (Needs improvement)
Router → Quality insufficient → LOOP BACK
2
Search → "Detailed results with more context"
Evaluate → Quality: 0.6 (Good)
Router → Quality insufficient → LOOP BACK
3
Search → "Comprehensive results with citations and examples"
Evaluate → Quality: 0.9 (Excellent!)
Router → Quality sufficient → EXIT to Summarize ✓

💻 The Loop Code

# The router function — THIS creates the loop def should_continue(state) -> Literal["search", "summarize"]: # Safety: prevent infinite loops if state["iteration"] >= state["max_iterations"]: return "summarize" # EXIT the loop # Quality check: exit early if good enough if state["quality_score"] >= 0.8: return "summarize" # EXIT the loop return "search" # LOOP BACK to search node # Wire the conditional edge (creates the loop) workflow.add_conditional_edges( "evaluate", should_continue, { "search": "search", # ← BACK to search (LOOP) "summarize": "summarize" # ← FORWARD to summarize (EXIT) } )

🛡️ Safety Mechanisms

⚠️ Always Prevent Infinite Loops!

Every loop MUST have at least one exit condition. The two standard safeguards are:
1. max_iterations — hard limit on how many times you loop
2. quality_threshold — exit early when results are good enough

🔀 How Task 6 Differs from Task 5

Task 5 → Task 6 Evolution

Task 5 introduced conditional routing — different paths FORWARD based on state.
Task 6 uses the same mechanism but routes BACKWARD — creating a loop. This is the difference between a decision tree and a feedback system. Loops enable self-correction, iterative improvement, and quality control.

Aspect Task 5 Task 6
Routing direction Forward only (branching) Forward AND backward (looping)
Execution count Each node runs exactly once Nodes may run multiple times
Purpose Choose the right handler Improve until good enough
AI analogy Classification (pick a label) Training (iterate until convergence)

✅ Advantages of This Task

  • Self-improving workflows — output quality improves with each iteration
  • Quality control built-in — never deliver subpar results
  • Bounded execution — max_iterations prevents runaway costs
  • Early exit optimization — if first try is great, don't waste iterations
  • Foundation for agents — real agents loop: think → act → observe → think again
  • Uses LLM for summarization — first task combining loops WITH LLM intelligence

💡 Key Insight

Loops are what make the "agentic" pattern possible. The classic agent loop is: Think → Act → Observe → (repeat until done). Task 6 gives you this pattern. Task 7 adds real-world tools to the "Act" step, making the agent actually useful.
