Kubectl Commands Cheat Sheet

kubectl is the command-line tool for interacting with Kubernetes clusters. This cheat sheet covers the essential commands for deploying, managing, debugging, and scaling containerized applications in production.

Kubernetes core objects

  • Pod: Smallest deployable unit (1+ containers)
  • Deployment: Manages replica sets and rollouts
  • Service: Stable network endpoint for pods
  • ConfigMap/Secret: External configuration
  • Ingress: HTTP routing to services

Core concepts quick reference

Object Purpose Key command
Pod Run containers kubectl get pods
Deployment Manage replicas and updates kubectl get deployments
Service Network exposure kubectl get svc
Namespace Logical isolation kubectl get ns
ConfigMap Configuration data kubectl get configmaps
Secret Sensitive data kubectl get secrets
Ingress HTTP routing rules kubectl get ingress
PVC Persistent storage kubectl get pvc
HPA Auto-scaling kubectl get hpa
Job/CronJob Batch/scheduled tasks kubectl get jobs

Cluster and context management

Context and cluster commands

# View current context
kubectl config current-context

# List all contexts
kubectl config get-contexts

# Switch context
kubectl config use-context <context-name>

# Set default namespace for context
kubectl config set-context --current --namespace=my-namespace

# View cluster info
kubectl cluster-info

# View all nodes
kubectl get nodes

# View node details
kubectl describe node <node-name>

# Check component status
kubectl get componentstatuses

# View API resources available
kubectl api-resources

# View API versions
kubectl api-versions

Pods

Pod operations

# List pods in current namespace
kubectl get pods

# List pods in all namespaces
kubectl get pods -A
kubectl get pods --all-namespaces

# List pods with more info (IP, node)
kubectl get pods -o wide

# Watch pods in real-time
kubectl get pods -w

# Filter pods by label
kubectl get pods -l app=myapp
kubectl get pods -l "app=myapp,env=prod"

# Get pod YAML definition
kubectl get pod <pod-name> -o yaml

# Describe pod (events, conditions, containers)
kubectl describe pod <pod-name>

# Run a temporary pod (for debugging)
kubectl run debug --image=busybox -it --rm -- /bin/sh
kubectl run curl-test --image=curlimages/curl -it --rm -- sh

# Delete a pod
kubectl delete pod <pod-name>

# Delete pods by label
kubectl delete pods -l app=myapp

# Force delete stuck pod
kubectl delete pod <pod-name> --grace-period=0 --force

Deployments

Deployment commands

# Create deployment
kubectl create deployment myapp --image=myapp:v1

# Apply from YAML file
kubectl apply -f deployment.yaml

# List deployments
kubectl get deployments
kubectl get deploy

# Describe deployment
kubectl describe deployment myapp

# Update image (triggers rolling update)
kubectl set image deployment/myapp app=myapp:v2

# Check rollout status
kubectl rollout status deployment/myapp

# View rollout history
kubectl rollout history deployment/myapp

# Rollback to previous version
kubectl rollout undo deployment/myapp

# Rollback to specific revision
kubectl rollout undo deployment/myapp --to-revision=3

# Pause/resume rollout
kubectl rollout pause deployment/myapp
kubectl rollout resume deployment/myapp

# Restart deployment (recreate all pods)
kubectl rollout restart deployment/myapp

# Scale deployment
kubectl scale deployment myapp --replicas=5

# Delete deployment
kubectl delete deployment myapp

Services

Service commands

# Expose deployment as a service
kubectl expose deployment myapp --port=80 --target-port=8000 --type=ClusterIP
kubectl expose deployment myapp --port=80 --target-port=8000 --type=NodePort
kubectl expose deployment myapp --port=80 --target-port=8000 --type=LoadBalancer

# List services
kubectl get services
kubectl get svc

# Describe service (see endpoints)
kubectl describe svc myapp

# Get service endpoints
kubectl get endpoints myapp

# Port forward (local dev access to cluster service)
kubectl port-forward svc/myapp 8080:80
kubectl port-forward pod/myapp-abc123 8080:8000

# Delete service
kubectl delete svc myapp

# Service types explained:
# ClusterIP  → internal only (default)
# NodePort   → expose on each node's IP:port (30000-32767)
# LoadBalancer → cloud provider load balancer (external IP)
# ExternalName → DNS CNAME alias

ConfigMaps and Secrets

ConfigMap commands

# Create from literal values
kubectl create configmap myconfig \
  --from-literal=DB_HOST=postgres \
  --from-literal=DB_PORT=5432

# Create from file
kubectl create configmap myconfig \
  --from-file=config.yaml

# Create from env file
kubectl create configmap myconfig \
  --from-env-file=.env

# View configmap
kubectl get configmap myconfig -o yaml

# Edit configmap
kubectl edit configmap myconfig

# Delete configmap
kubectl delete configmap myconfig

Secret commands

# Create generic secret
kubectl create secret generic mysecret \
  --from-literal=password=s3cr3t \
  --from-literal=api-key=abc123

# Create from file
kubectl create secret generic tls-cert \
  --from-file=cert.pem \
  --from-file=key.pem

# Create docker registry secret
kubectl create secret docker-registry \
  regcred \
  --docker-server=registry.io \
  --docker-username=user \
  --docker-password=pass

# View secret (base64 encoded)
kubectl get secret mysecret -o yaml

# Decode secret value
kubectl get secret mysecret \
  -o jsonpath='{.data.password}' \
  | base64 -d

# Delete secret
kubectl delete secret mysecret

Debugging and troubleshooting

Essential debugging commands

# View pod logs
kubectl logs <pod-name>
kubectl logs <pod-name> -f              # follow/stream
kubectl logs <pod-name> --tail=100      # last 100 lines
kubectl logs <pod-name> --since=1h      # last hour
kubectl logs <pod-name> -c <container>  # specific container in multi-container pod
kubectl logs <pod-name> --previous      # previous crashed instance

# Execute command in running pod
kubectl exec -it <pod-name> -- /bin/bash
kubectl exec -it <pod-name> -- /bin/sh
kubectl exec <pod-name> -- env          # view env vars
kubectl exec <pod-name> -- cat /etc/hosts

# Get events (cluster-wide troubleshooting)
kubectl get events --sort-by=.metadata.creationTimestamp
kubectl get events -n <namespace>

# Top (resource usage) — requires metrics-server
kubectl top nodes
kubectl top pods
kubectl top pods --sort-by=memory

# Debug with ephemeral container (K8s 1.23+)
kubectl debug -it <pod-name> --image=busybox --target=<container>

# Copy files to/from pod
kubectl cp <pod-name>:/path/to/file ./local-file
kubectl cp ./local-file <pod-name>:/path/to/file

# Check pod readiness/liveness
kubectl describe pod <pod-name> | grep -A 5 "Conditions"

# Common pod issues:
# CrashLoopBackOff → check logs, app keeps crashing
# ImagePullBackOff → wrong image name/tag or registry auth
# Pending → insufficient resources or no matching node
# OOMKilled → container exceeded memory limit

Scaling and rolling updates

Manual scaling

# Scale to specific replicas
kubectl scale deploy myapp --replicas=5

# Scale to zero (stop all pods)
kubectl scale deploy myapp --replicas=0

# Scale multiple deployments
kubectl scale deploy myapp myworker \
  --replicas=3

Horizontal Pod Autoscaler

# Create HPA (CPU-based)
kubectl autoscale deployment myapp \
  --min=2 --max=10 --cpu-percent=70

# View HPA status
kubectl get hpa

# Describe HPA (see scaling decisions)
kubectl describe hpa myapp

# Delete HPA
kubectl delete hpa myapp

Rolling update strategy

# Update image (triggers rolling update)
kubectl set image deployment/myapp app=myapp:v2

# Watch the rollout progress
kubectl rollout status deployment/myapp

# The rolling update strategy in YAML:
# spec:
#   strategy:
#     type: RollingUpdate
#     rollingUpdate:
#       maxSurge: 25%        ← extra pods during update
#       maxUnavailable: 25%  ← pods that can be down

# If something goes wrong:
kubectl rollout undo deployment/myapp

# Blue-green: deploy v2 separately, switch service selector
# Canary: run v2 with fewer replicas alongside v1

Namespaces

Namespace commands

# List namespaces
kubectl get namespaces
kubectl get ns

# Create namespace
kubectl create namespace staging

# Set default namespace
kubectl config set-context --current --namespace=staging

# Run commands in specific namespace
kubectl get pods -n staging
kubectl get all -n staging

# Get resources across ALL namespaces
kubectl get pods -A
kubectl get svc --all-namespaces

# Delete namespace (deletes EVERYTHING in it!)
kubectl delete namespace staging

# Apply resources to specific namespace
kubectl apply -f deployment.yaml -n staging

YAML manifest examples

Deployment manifest

apiVersion: apps/v1
kind: Deployment
metadata:
  name: ml-api
  labels:
    app: ml-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: ml-api
  template:
    metadata:
      labels:
        app: ml-api
    spec:
      containers:
      - name: api
        image: myregistry/ml-api:v1
        ports:
        - containerPort: 8000
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
        env:
        - name: MODEL_PATH
          value: "/models/v1"
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: db-secret
              key: password
        readinessProbe:
          httpGet:
            path: /health
            port: 8000
          initialDelaySeconds: 10
          periodSeconds: 5
        livenessProbe:
          httpGet:
            path: /health
            port: 8000
          initialDelaySeconds: 30
          periodSeconds: 10

Service + Ingress

# Service
apiVersion: v1
kind: Service
metadata:
  name: ml-api-svc
spec:
  selector:
    app: ml-api
  ports:
  - port: 80
    targetPort: 8000
  type: ClusterIP
---
# Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ml-api-ingress
  annotations:
    nginx.ingress.kubernetes.io/
      rewrite-target: /
spec:
  rules:
  - host: api.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: ml-api-svc
            port:
              number: 80
---
# HPA
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: ml-api-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: ml-api
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70

Production patterns for ML

ML model deployment checklist

  • Resource limits: Set CPU/memory requests and limits
  • Health checks: Readiness probe (model loaded?) + liveness probe
  • Horizontal scaling: HPA on CPU/memory or custom metrics
  • Rolling updates: Zero-downtime deployments
  • Secrets: API keys and credentials in Kubernetes Secrets
  • Monitoring: Prometheus metrics exposed at /metrics
  • Logging: Structured JSON logs to stdout
  • GPU scheduling: nvidia.com/gpu resource requests

Common kubectl shortcuts

  • po = pods
  • deploy = deployments
  • svc = services
  • ns = namespaces
  • cm = configmaps
  • pvc = persistentvolumeclaims
  • rs = replicasets
  • ing = ingresses
  • -o wide = extra info columns
  • -o yaml = full YAML output
  • -o json = JSON output
  • --dry-run=client -o yaml = generate YAML without applying

GPU workload manifest (ML inference)

apiVersion: apps/v1
kind: Deployment
metadata:
  name: gpu-inference
spec:
  replicas: 2
  selector:
    matchLabels:
      app: gpu-inference
  template:
    metadata:
      labels:
        app: gpu-inference
    spec:
      containers:
      - name: inference
        image: myregistry/gpu-model:v1
        ports:
        - containerPort: 8000
        resources:
          limits:
            nvidia.com/gpu: 1      # Request 1 GPU
            memory: "8Gi"
          requests:
            nvidia.com/gpu: 1
            memory: "4Gi"
            cpu: "2"
        volumeMounts:
        - name: model-store
          mountPath: /models
      volumes:
      - name: model-store
        persistentVolumeClaim:
          claimName: model-pvc
      tolerations:
      - key: nvidia.com/gpu
        operator: Exists
        effect: NoSchedule
      nodeSelector:
        accelerator: nvidia-tesla-t4
