Task 5

Edges & Conditional Routing

Your workflow becomes INTELLIGENT — it decides its own path

🧩 What This Task Teaches

Until now, all workflows were linear: A → B → C → END. Task 5 introduces branching — the workflow examines the current state and chooses which path to take. This is what separates a dumb pipeline from an intelligent agent.

Core Concept: Conditional edges use a ROUTER FUNCTION that inspects state and returns a string indicating which path to take. The graph then follows that path. This is dynamic, data-driven control flow.

📧 The Email Routing Example

📧 Analyze Email
↓ router decides ↓
spam_score > 0.6
🚫 Spam Folder
contains "urgent"
⭐ Important
otherwise
✅ Normal Inbox

🔌 Two Types of Edges

Normal Edge

Always goes the same way. Fixed, predictable flow.

workflow.add_edge("analyze", "output")
→ ALWAYS goes analyze → output

Conditional Edge

A function DECIDES which path. Different data = different paths.

workflow.add_conditional_edges(
  "analyze", router_fn, {...})
→ Could go to spam, important, OR normal

💻 The Router Function

def email_router(state) -> Literal["spam", "important", "normal"]: """Examines state, returns a PATH NAME""" if state["spam_score"] > 0.6: return "spam" # → goes to process_spam node elif "urgent" in state["email_text"].lower(): return "important" # → goes to process_important node else: return "normal" # → goes to process_normal node # Wire it up: workflow.add_conditional_edges( "analyze", # Source node email_router, # Router function { # Mapping: return value → target node "spam": "spam", "important": "important", "normal": "normal" } )

🧪 Test Cases — Same System, Different Paths

"Meeting tomorrow at 3pm" → Normal Inbox

"URGENT: Server down, need immediate help" → Important
"Check out these cat photos" → Normal Inbox

🔀 How Task 5 Differs from Task 4

Task 4 → Task 5 Evolution

Task 4 had fixed flow: every input goes through ALL nodes in the same order.
Task 5 adds INTELLIGENCE to the flow itself — different inputs take different paths. The graph is no longer a straight line; it's a decision tree. This is the fundamental building block of agent-like behavior: deciding what to do based on what you know.

Aspect Task 4 Task 5
Flow pattern Linear: A → B → C → D Branching: A → (B | C | D)
Path decision Fixed at build time Dynamic at runtime
New concept Node types Router functions + conditional edges
Behavior Same path for all inputs Different path per input

✅ Advantages of This Task

  • Dynamic decision-making — workflows become intelligent, not just mechanical
  • Router functions — clean, testable decision logic separated from processing
  • Multiple paths converge — all branches can lead back to END (or to a shared node)
  • Type-safe routing — Literal type hints make valid paths explicit
  • Foundation for loops — if you can route forward, you can also route BACKWARD (Task 6)

💡 Key Insight

Conditional edges are what make LangGraph an "agent framework" rather than just a pipeline. An agent DECIDES what to do next. A router function IS that decision. Task 6 takes this further: what if one of the routing options goes BACK to a previous node? That's a loop.
