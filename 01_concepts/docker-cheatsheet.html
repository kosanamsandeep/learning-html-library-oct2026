Docker Commands Cheat Sheet

Essential Docker commands for building, running, debugging, and deploying containerized applications. Organized by workflow: from basic container operations to production-ready multi-stage builds and Docker Compose orchestration.

Core concepts

  • Image: Read-only template (blueprint)
  • Container: Running instance of an image
  • Dockerfile: Script to build an image
  • Volume: Persistent storage outside container
  • Network: Communication between containers

Container basics

Lifecycle commands

# Run a container (pull image if not local)
docker run <image>

# Run interactively with terminal
docker run -it <image> /bin/bash

# Run in background (detached)
docker run -d <image>

# Run with a name
docker run --name my-app -d <image>

# Stop a running container
docker stop <container_id|name>

# Start a stopped container
docker start <container_id|name>

# Restart a container
docker restart <container_id|name>

# Remove a stopped container
docker rm <container_id|name>

# Force remove a running container
docker rm -f <container_id|name>

# List running containers
docker ps

# List ALL containers (including stopped)
docker ps -a

# Show container resource usage
docker stats

Image management

Build, tag, push, pull

# Build image from Dockerfile in current directory
docker build -t myapp:v1 .

# Build with specific Dockerfile
docker build -f Dockerfile.prod -t myapp:prod .

# Build with build arguments
docker build --build-arg ENV=production -t myapp:prod .

# Build without cache (fresh build)
docker build --no-cache -t myapp:v1 .

# Tag an image
docker tag myapp:v1 registry.example.com/myapp:v1

# Push to registry
docker push registry.example.com/myapp:v1

# Pull from registry
docker pull registry.example.com/myapp:v1

# List local images
docker images

# Remove an image
docker rmi <image_id|name:tag>

# Show image history (layers)
docker history <image>

# Inspect image metadata
docker inspect <image>

# Save image to tar file
docker save -o myapp.tar myapp:v1

# Load image from tar file
docker load -i myapp.tar

Running containers — common patterns

Port mapping

# Map host:container port
docker run -p 8080:80 nginx

# Map multiple ports
docker run -p 8080:80 -p 443:443 nginx

# Map to specific host interface
docker run -p 127.0.0.1:8080:80 nginx

# Random host port
docker run -P nginx

Environment variables

# Single env var
docker run -e DB_HOST=localhost myapp

# Multiple env vars
docker run -e DB_HOST=db -e DB_PORT=5432 myapp

# From env file
docker run --env-file .env myapp

# Override entrypoint
docker run --entrypoint /bin/sh myapp

Resource limits and restart policies

# Limit memory
docker run -m 512m myapp

# Limit CPU
docker run --cpus="1.5" myapp

# Memory + CPU limits
docker run -m 1g --cpus="2" myapp

# GPU access (NVIDIA)
docker run --gpus all nvidia/cuda:12.0-base nvidia-smi
docker run --gpus '"device=0,1"' myapp

# Restart policies
docker run --restart=no myapp          # Never restart (default)
docker run --restart=always myapp      # Always restart
docker run --restart=unless-stopped myapp  # Restart unless manually stopped
docker run --restart=on-failure:5 myapp    # Restart on failure, max 5 attempts

Networking

Network commands

# List networks
docker network ls

# Create a network
docker network create my-network

# Run container on specific network
docker run --network my-network --name api myapp

# Connect running container to network
docker network connect my-network <container>

# Disconnect from network
docker network disconnect my-network <container>

# Inspect network (see connected containers)
docker network inspect my-network

# Container DNS: containers on same network can reach
# each other by container name
docker run --network my-network --name db postgres
docker run --network my-network --name api -e DB_HOST=db myapp
# api can reach db at hostname "db"

Volumes and storage

Volume commands

# Named volume (Docker manages location)
docker volume create my-data
docker run -v my-data:/app/data myapp

# Bind mount (host directory → container)
docker run -v /host/path:/container/path myapp
docker run -v $(pwd)/src:/app/src myapp

# Read-only mount
docker run -v $(pwd)/config:/app/config:ro myapp

# Tmpfs mount (in-memory, not persisted)
docker run --tmpfs /app/tmp myapp

# List volumes
docker volume ls

# Inspect volume
docker volume inspect my-data

# Remove volume
docker volume rm my-data

# Remove unused volumes
docker volume prune

# Copy files to/from container
docker cp myfile.txt container:/app/
docker cp container:/app/logs ./local-logs/

Docker Compose

Compose commands

# Start all services
docker compose up

# Start in background
docker compose up -d

# Start specific service
docker compose up -d api

# Stop all services
docker compose down

# Stop and remove volumes
docker compose down -v

# Rebuild images
docker compose build

# Rebuild and start
docker compose up --build

# View logs
docker compose logs
docker compose logs -f api

# Scale a service
docker compose up -d --scale worker=3

# Execute command in running service
docker compose exec api bash

# List running services
docker compose ps

docker-compose.yml example

services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://
          user:pass@db:5432/mydb
    depends_on:
      db:
        condition: service_healthy
    volumes:
      - ./src:/app/src
    restart: unless-stopped

  db:
    image: postgres:16
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD", "pg_isready"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:

Dockerfile best practices

Multi-stage build (production pattern)

# Stage 1: Build dependencies
FROM python:3.12-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# Stage 2: Production image (smaller)
FROM python:3.12-slim AS production
WORKDIR /app

# Copy only installed packages from builder
COPY --from=builder /install /usr/local

# Copy application code
COPY ./src ./src

# Non-root user for security
RUN useradd -m appuser
USER appuser

# Health check
HEALTHCHECK --interval=30s --timeout=5s \
  CMD curl -f http://localhost:8000/health || exit 1

EXPOSE 8000
CMD ["uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]

Layer caching tips

  • Put rarely-changing instructions first (base image, system deps)
  • COPY requirements.txt before COPY . (dependencies cached separately)
  • Use .dockerignore to exclude unnecessary files
  • Combine RUN commands to reduce layers
  • Use --no-cache-dir for pip to reduce image size

Security best practices

  • Use specific image tags (python:3.12-slim, not python:latest)
  • Run as non-root user (USER directive)
  • Don't store secrets in image (use env vars or secrets)
  • Use multi-stage builds (no build tools in production)
  • Scan images: docker scout cves <image>
  • Use slim/alpine base images when possible

Debugging containers

Essential debugging commands

# Execute shell in running container
docker exec -it <container> /bin/bash
docker exec -it <container> /bin/sh  # alpine images

# View container logs
docker logs <container>
docker logs -f <container>          # follow (stream)
docker logs --tail 100 <container>   # last 100 lines
docker logs --since 1h <container>   # last hour

# Inspect container details (env, network, mounts)
docker inspect <container>

# View container processes
docker top <container>

# View filesystem changes
docker diff <container>

# Export container filesystem for inspection
docker export <container> -o container-fs.tar

# View real-time events
docker events

# Check why container exited
docker inspect <container> --format='{{.State.ExitCode}}'
docker inspect <container> --format='{{.State.Error}}'

Cleanup commands

Reclaim disk space

# Remove all stopped containers
docker container prune

# Remove unused images
docker image prune

# Remove ALL unused images (not just dangling)
docker image prune -a

# Remove unused volumes
docker volume prune

# Remove unused networks
docker network prune

# Nuclear option: remove everything unused
docker system prune -a --volumes

# Check disk usage
docker system df

# Remove specific containers by filter
docker rm $(docker ps -aq --filter "status=exited")

Production patterns for ML

ML model serving container

FROM python:3.12-slim

WORKDIR /app

# System deps for ML libraries
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
    libgomp1 && \
    rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir \
    -r requirements.txt

COPY ./models ./models
COPY ./src ./src

RUN useradd -m appuser
USER appuser

EXPOSE 8000
CMD ["uvicorn", "src.main:app", \
     "--host", "0.0.0.0", \
     "--port", "8000", \
     "--workers", "4"]

GPU-enabled container

FROM nvidia/cuda:12.1.0-runtime-ubuntu22.04

# Install Python
RUN apt-get update && \
    apt-get install -y python3.11 \
    python3-pip && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY requirements-gpu.txt .
RUN pip install --no-cache-dir \
    -r requirements-gpu.txt

COPY . .

# Run with: docker run --gpus all
CMD ["python3", "serve.py"]
