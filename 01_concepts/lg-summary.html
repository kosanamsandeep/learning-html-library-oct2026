🔗 What Makes Each Task Different From the Previous

Task 2 → Task 3

From "remembering" to "growing"

State isn't just preserved — it accumulates. Lists grow, counters increment. Each step ADDS to what exists.

Task 3 → Task 4

From "same work" to "specialized roles"

Nodes stop being generic accumulators and become specialists — validators, analyzers, classifiers, formatters.

Task 4 → Task 5

From "linear" to "branching"

Flow is no longer fixed. A router FUNCTION examines state and picks the path. Different inputs = different executions.

Task 5 → Task 6

From "branching forward" to "looping back"

The conditional edge goes BACKWARD, creating a loop. Nodes execute multiple times, each time improving results.

Task 6 → Task 7

From "closed system" to "connected"

The workflow reaches beyond itself — calling DuckDuckGo for real web data. No more simulated results.

Task 7 → Task 8

From "single-pass" to "deep enrichment"

Instead of one search + one summary, the workflow layers knowledge: generate → search → extract → synthesize.

Task 8 → Task 9

From "demo" to "production"

All concepts combined into a working research agent with loops, tools, memory, and a Streamlit UI.

🧠 The Core Pattern of LangGraph

Every LangGraph application follows this formula:

State + Nodes + Edges = Workflow

Where edges can be conditional (routing), backward (loops), or simple (linear).
Where nodes can be pure logic, LLM-powered, or tool-connected.
Where state can be simple values, accumulating lists, or full knowledge bases.
