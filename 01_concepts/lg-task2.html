Task 2

Sequential vs Stateful Processing

The fundamental "why" behind LangGraph

🧩 What This Task Teaches

This is the motivation task. It shows you the exact problem that LangGraph was created to solve: traditional LangChain chains have no memory between steps. Each step is independently executed, like separate conversations with an amnesiac.

Core Problem: In a sequential chain, Step 3 cannot remember what happened in Step 1. In a stateful graph, ALL steps can access and build upon shared information.

⚔️ The Comparison

Sequential Chain (LangChain Traditional)

Step 1: Greet Alice
→
Step 2: Say Goodbye
→
Step 3: Who was it?
Each step is INDEPENDENT — Step 3 doesn't know the name was "Alice" ❌

Stateful Graph (LangGraph)

Greet (saves name)
→
Farewell (reads name)
→
Memory Test (reads name)
All nodes share state — every step can access "Alice" ✅

📊 Side-by-Side Comparison

Feature Sequential Chain Stateful Graph
Memory Between Steps ❌ None — each step starts fresh ✅ Full state preserved
Data Sharing Manual — must pass explicitly Automatic — shared state object
Flow Control Linear only (A → B → C) Any pattern (loops, branches)
Error Recovery Restart from beginning Resume from last state
Good For Simple, one-shot tasks Complex, multi-step workflows

💻 How The Code Works

Sequential (No Memory)

# Each chain is independent — like talking to a new person each time prompt1 = "Say hello to {name}" prompt2 = "Say goodbye" # ← Can't access 'name' — it's gone! prompt3 = "What was their name?" # ← Has NO idea!

Stateful Graph (Full Memory)

# State is shared — like passing a notebook between team members class ConversationState(TypedDict): name: str # ← Available to ALL nodes greeting: str farewell: str def greet_person(state): # Reads state['name'] → "Alice" return {"greeting": f"Hello {state['name']}!"} def say_farewell(state): # ALSO reads state['name'] → still "Alice"! return {"farewell": f"Bye {state['name']}!"}

✅ Advantages of This Task

  • Motivates LangGraph's existence — you see exactly WHY stateful processing matters
  • Shows the limitation of basic chains — chains are fast but dumb (no memory)
  • Introduces TypedDict state — the structured way to define what your graph remembers
  • First StateGraph construction — add_node, set_entry_point, add_edge, compile

💡 Key Insight

LangGraph's superpower starts here: shared state. Every node reads from and writes to the same state object. This is the foundation that makes everything else (routing, loops, tools, memory) possible.

🔗 What This Enables Next

Now that you understand state, Task 3 shows how state doesn't just persist — it accumulates. Nodes don't just read state; they add to it, building up information over time.
