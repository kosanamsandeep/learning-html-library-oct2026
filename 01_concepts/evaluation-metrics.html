Model evaluation

Evaluation metrics: Type 1 and Type 2 errors, F1 score, and everything around them

Metrics are how you know if your model is actually useful. Interviews consistently test whether you understand what each metric captures, when accuracy is misleading, and how Type 1 versus Type 2 errors map to real business costs.

This page covers classification and regression metrics end to end, including the confusion matrix, precision, recall, F1, AUC-ROC, MSE, R-squared, and cross-validation.

Core rule

A model is only as good as the metric you evaluate it on. Pick the wrong metric and you optimize for the wrong thing.

Why this matters for interviews

Nearly every ML interview includes a question about metrics. Interviewers use it to test whether you can connect a model to a business problem, not just minimize a loss function.

The mindset

Always start from: what is the cost of being wrong? A false positive in spam filtering is different from a false positive in cancer screening. The right metric depends on the problem.

The foundation

Confusion matrix

Predicted Positive Predicted Negative
Actually Positive True Positive (TP) False Negative (FN) — missed a real positive
Actually Negative False Positive (FP) — false alarm True Negative (TN)

Everything else is derived from this. Precision, recall, F1, specificity, and accuracy are all computed from these four values. If you understand the confusion matrix, you can derive any metric on paper.

Critical concepts

Type 1 and Type 2 errors

Type 1 error (false positive)

You reject the null hypothesis when it is actually true. In ML terms: the model predicts positive when the true label is negative.

  • Example: telling a healthy patient they have a disease.
  • Example: marking a legitimate email as spam.
  • Also called: false alarm, alpha error.

Type 2 error (false negative)

You fail to reject the null hypothesis when it is actually false. In ML terms: the model predicts negative when the true label is positive.

  • Example: missing a patient who actually has a disease.
  • Example: failing to detect a fraudulent transaction.
  • Also called: miss, beta error.

The business question

Which error is more expensive? If missing a disease is worse than a false alarm, minimize Type 2 errors (maximize recall). If a false alarm is expensive, minimize Type 1 errors (maximize precision). This tradeoff drives your metric choice.

Core metrics

Precision, recall, and F1 score

Metric Formula What it answers When to prioritize
Precision TP / (TP + FP) Of all positive predictions, how many were correct? When false positives are costly: spam, content moderation, ad targeting.
Recall (Sensitivity) TP / (TP + FN) Of all actual positives, how many did we catch? When false negatives are costly: disease detection, fraud, safety.
Specificity TN / (TN + FP) Of all actual negatives, how many did we correctly identify? When you care about correctly identifying the negative class.
Accuracy (TP + TN) / total What fraction of all predictions were correct? Only when classes are balanced and both errors are equally costly.

Deep dive

F1 score explained

What F1 is

The harmonic mean of precision and recall. It balances both concerns into a single number.

F1 = 2 * (precision * recall) / (precision + recall)

Why harmonic mean and not arithmetic

The harmonic mean penalizes extreme imbalances. If precision is 1.0 but recall is 0.01, the arithmetic mean would be 0.505 which looks okay. The harmonic mean gives 0.02, which correctly signals a problem.

F-beta score

A generalization that lets you weight precision vs recall differently.

F_beta = (1 + beta^2) * (precision * recall) / (beta^2 * precision + recall)

F2 weights recall higher. F0.5 weights precision higher.

When to use F1

  • When you care about both precision and recall roughly equally.
  • On imbalanced datasets where accuracy would be misleading.
  • When there is no clear reason to prioritize one error type.

Threshold-independent

AUC-ROC and AUC-PR

ROC curve

Plots True Positive Rate (recall) against False Positive Rate (1 - specificity) at every possible classification threshold.

  • AUC-ROC = 1.0 means perfect separation.
  • AUC-ROC = 0.5 means random guessing.
  • Measures overall ability to rank positives higher than negatives.

Precision-Recall curve

Plots precision against recall at every threshold. AUC-PR is the area under this curve.

  • More informative than ROC on highly imbalanced datasets.
  • Focuses on the positive class performance.
  • Use AUC-PR when the minority class is what you care about.

Interview tip: when the dataset is highly imbalanced, say you prefer AUC-PR over AUC-ROC and explain why. The ROC curve can look deceptively good on imbalanced data because the false positive rate denominator is large.

Common pitfall

The accuracy trap on imbalanced datasets

The problem

If 95% of data is class 0, a model that always predicts 0 gets 95% accuracy. That model is useless for the minority class but accuracy says it is excellent.

The fix

Use precision, recall, F1, or AUC-PR. These metrics evaluate how well the model handles the class you actually care about, not just the dominant one.

Beyond binary

Multiclass metrics

Averaging method How it works When to use
Macro average Compute the metric for each class, then take the unweighted mean. When all classes are equally important regardless of frequency.
Weighted average Compute per-class metric, then average weighted by class support. When larger classes should contribute more to the overall score.
Micro average Aggregate TP, FP, FN globally across all classes, then compute metric. When you want a single aggregate performance number.

Log loss (cross-entropy): measures the quality of predicted probabilities, not just the hard class decision. Lower is better. Commonly used as the training objective and also as an evaluation metric.

Continuous outputs

Regression evaluation metrics

Metric Formula intuition What it tells you Watch out
MSE Average of squared errors. Penalizes large errors heavily due to squaring. Not in original units. Sensitive to outliers.
RMSE Square root of MSE. Same as MSE but in original units. Still sensitive to outliers.
MAE Average of absolute errors. More robust to outliers than MSE. Does not penalize large errors as heavily.
R-squared 1 - (SS_res / SS_total) Proportion of variance explained by the model. Can be artificially inflated by adding variables. Use adjusted R-squared.
Adjusted R-squared R-squared adjusted for number of predictors. Penalizes model complexity. More honest with many features. Only decreases when a new feature does not contribute enough.
MAPE Average of percentage errors. Intuitive percentage-based interpretation. Undefined or misleading when actuals are near zero.

Decision guide

Choosing the right metric

Situation Primary metric Why
Balanced binary classification Accuracy or F1 Both errors are roughly equally costly.
Imbalanced, missing positives is expensive Recall, F2, or AUC-PR You need to catch as many positives as possible.
Imbalanced, false alarms are expensive Precision or F0.5 You need high confidence when you predict positive.
Ranking quality matters AUC-ROC or AUC-PR You want to evaluate across all thresholds, not just one.
Regression with outliers MAE Less sensitive to large errors than MSE.
Regression, large errors are very bad RMSE Squaring penalizes large deviations more heavily.
Need to explain model quality simply Adjusted R-squared or MAPE Percentage-based metrics are easier for stakeholders.

Robust estimation

Cross-validation

What it is

Split data into K folds. Train on K-1 folds and evaluate on the held-out fold. Repeat K times so every fold serves as the test set once. Report the average metric across folds.

Why it matters

  • Gives a more reliable estimate of model performance than a single train-test split.
  • Helps detect overfitting: if training scores are high but CV scores are low, you are overfitting.
  • Standard choice is 5-fold or 10-fold. Stratified folds for imbalanced data.

Nested cross-validation: use an outer loop for performance estimation and an inner loop for hyperparameter tuning. This avoids leaking tuning information into the test evaluation.

Interview readiness

Questionnaire and scenarios

Question

What is the difference between Type 1 and Type 2 errors?

Strong answer

Type 1 is a false positive: rejecting the null when it is true. Type 2 is a false negative: failing to reject the null when it is false. In applied ML, Type 1 is a false alarm and Type 2 is a miss.

Question

Why is F1 better than accuracy on imbalanced data?

Strong answer

Because accuracy can be inflated by the dominant class. F1 balances precision and recall for the positive class, so a model that ignores the minority class scores poorly on F1 even if accuracy is high.

Question

When would you use AUC-PR instead of AUC-ROC?

Strong answer

On highly imbalanced datasets. AUC-ROC can be misleading because the false positive rate denominator is very large, making it look good. AUC-PR focuses directly on the positive class performance.

Question

What is the difference between MSE and MAE?

Strong answer

MSE squares errors so it penalizes large errors heavily. MAE takes absolute errors so it is more robust to outliers. If a few large errors are very costly, use MSE or RMSE. If you want median-like robustness, use MAE.

Scenario

You are building a fraud detection model. Only 0.5% of transactions are fraudulent. Which metric do you report and why?

Expected reasoning

Not accuracy. I would report recall (to ensure most fraud is caught), precision (to control false alarms), F1, and AUC-PR. The exact priority depends on how expensive each error type is to the business.

Scenario

Your model has perfect recall but terrible precision. What is going on?

Expected reasoning

The model is predicting positive for almost everything, so it catches all true positives but also generates many false positives. I need to raise the classification threshold or improve the model's discrimination ability.
