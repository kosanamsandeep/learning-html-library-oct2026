Sequence modeling foundations

How RNNs work

A recurrent neural network processes a sequence one step at a time while carrying forward a hidden state that acts like memory. Each new token or timestep updates that state, and the updated state influences future outputs.

RNNs were an early standard for text, speech, and time-series modeling before attention and transformers largely replaced them in many tasks.

One-line flow

x_t + h_(t-1) -> new h_t -> output y_t

Main idea

The same recurrent cell is applied at every timestep. That means the model shares parameters across time rather than learning a separate set of weights for each word position.

Why that helped historically

It gave sequence models an explicit notion of temporal order. Unlike bag-of-words methods, RNNs naturally cared about the order in which tokens arrived.

Hidden state

The hidden state is the running summary of what the RNN has seen so far. At timestep t, the network combines the current input and the previous hidden state to compute the new hidden state.

Why the state matters

If the state represents useful prior context, the model can use past information when predicting the current output. That is how sequence memory is approximated.

Simple recurrence

h_t = activation(W_x * x_t + W_h * h_(t-1) + b)
y_t = W_y * h_t

Unrolling through time

To understand an RNN, people often draw it unrolled across timesteps. The same cell appears repeatedly for t = 1, 2, 3, and so on. This makes it easier to see that the model is a deep computation graph across time.

Important detail: the weights are shared across all timesteps. That is why the unrolled picture shows repeated copies of the same cell, not different cells with different parameters.

How training works

Training still uses backpropagation, but now the graph extends across time. This is called backpropagation through time, or BPTT.

What BPTT means

The loss at later timesteps sends gradients backward not just through layers, but through earlier timesteps as well. That is how early states and weights get credit or blame.

RNN limitation Why it happens Why transformers helped
Difficulty with long-range dependencies Information must pass through many timesteps, making gradients unstable or weak. Attention creates shorter paths between tokens.
Sequential computation Each timestep depends on the previous hidden state, so parallelization is limited. Transformers process many positions in parallel during training.
Vanishing or exploding gradients BPTT repeatedly multiplies derivatives across time. Transformer optimization usually scales better for long contexts.

Most direct comparison

RNNs remember by carrying state forward step by step. Transformers relate tokens directly with attention. That is the practical reason transformers largely displaced vanilla RNNs for many NLP tasks.

Interview readiness

Questionnaire and scenarios

Question

What is the hidden state in an RNN?

Strong answer

It is the running summary of past sequence information that gets updated at each timestep and passed to the next timestep.

Question

Why do vanilla RNNs struggle with long-term dependencies?

Strong answer

Because gradients must travel through many recurrent steps during training, which often causes vanishing or exploding gradients and makes long-range information harder to preserve.

Scenario

You need a model for a long document with dependencies across far-apart tokens. Would vanilla RNN be your first choice?

Expected reasoning

No. I would usually prefer a transformer because attention handles long-range relationships more directly and parallelizes much better.

Scenario

How is BPTT different from ordinary backpropagation?

Expected reasoning

It is the same basic gradient idea, but the computation graph is unrolled over time, so gradients propagate backward across timesteps as well as across layers.

RNN questions in interviews usually test your understanding of hidden state, sequential dependence, and why transformers replaced many recurrent architectures.
