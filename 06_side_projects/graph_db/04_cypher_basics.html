Chapter 04 · Cypher

Cypher basics — draw your query

Cypher is "ASCII art for graphs". You sketch nodes as () and relationships as -->, and the database finds matching shapes. Master six verbs here: MATCH, RETURN, WHERE, CREATE, MERGE, SET/DELETE.

The pattern syntax (read this first)

graph LR
    A["(p:Person)"] -->|"[:BOUGHT]"| B["(pr:Product)"]
    classDef person fill:#dbeafe,stroke:#2563eb,color:#1e3a8a;
    classDef product fill:#d4f3e9,stroke:#0f9d77,color:#14241f;
    class A person;
    class B product;

In Cypher this exact picture is written (p:Person)-[:BOUGHT]->(pr:Product).

Node → (variable:Label {prop: value})
e.g. (p:Person {name:'Alice'})
Relationship → -[r:TYPE {prop: v}]->
e.g. -[:BOUGHT {on:'2023-01-10'}]->

Variables (p, r) are just handles so you can refer back to a node/relationship later in the query. Labels and types are the categories.

1 · MATCH + RETURN — find things

The bread and butter. Find a shape, return parts of it.

// All people
MATCH (p:Person)
RETURN p.name, p.city;

// Who bought what
MATCH (p:Person)-[:BOUGHT]->(pr:Product)
RETURN p.name AS buyer, pr.name AS product;
Mnemonic: MATCH the picture, RETURN the pieces. If you can draw it on a whiteboard, you can MATCH it.

2 · WHERE — filter

// People over 30 in London
MATCH (p:Person)
WHERE p.age > 30 AND p.city = 'London'
RETURN p.name, p.age;

// Tech products under £100
MATCH (pr:Product)
WHERE pr.category = 'Tech' AND pr.price < 100
RETURN pr.name, pr.price
ORDER BY pr.price DESC;

Inline shorthand: (p:Person {city:'London'}) equals WHERE p.city = 'London'. Use inline for equality, WHERE for ranges and logic.

3 · CREATE — add new data

// A new person and a new purchase in one go
MATCH (book:Product {name:'Graph Book'})
CREATE (gina:Person {name:'Gina', age:27, city:'Rome'})
CREATE (gina)-[:BOUGHT {on:'2023-05-01'}]->(book)
RETURN gina;
CREATE always inserts. Run it twice and you get two Ginas. To avoid duplicates, use MERGE ↓.

4 · MERGE — create only if missing (upsert)

MERGE = "find this pattern, or create it if it doesn't exist." Idempotent — safe to re-run.

// Won't duplicate Gina if she already exists
MERGE (gina:Person {name:'Gina'})
ON CREATE SET gina.age = 27, gina.city = 'Rome'
ON MATCH SET  gina.lastSeen = date()
RETURN gina;
MERGE on a unique key (e.g. {name:'Gina'} or an id) — otherwise MERGE may match more than you intend.
ON CREATE / ON MATCH let you set different properties depending on whether it was new or already there.

5 · SET & DELETE — update and remove

// Update a property
MATCH (p:Person {name:'Bob'})
SET p.age = 36, p.vip = true;

// Add a label
MATCH (p:Person {name:'Alice'})
SET p:Premium;

// Delete a relationship only
MATCH (:Person {name:'Gina'})-[r:BOUGHT]->(:Product)
DELETE r;

// Delete a node AND its relationships
MATCH (p:Person {name:'Gina'})
DETACH DELETE p;
You can't DELETE a node that still has relationships. Use DETACH DELETE to remove the node and its relationships in one move.

The six verbs at a glance

Verb Does Think
MATCH Find an existing pattern SQL SELECT ... FROM
WHERE Filter matches SQL WHERE
RETURN Output columns SQL SELECT list
CREATE Insert (always) SQL INSERT
MERGE Upsert (find or create) SQL INSERT ... ON CONFLICT
SET / DELETE Update / remove SQL UPDATE / DELETE

Try it yourself

easy Return the names of everyone living in Paris. 
MATCH (p:Person {city:'Paris'})
RETURN p.name;
Carol and Erin.
easy List each product and how many people bought it. 
MATCH (:Person)-[:BOUGHT]->(pr:Product)
RETURN pr.name, count(*) AS buyers
ORDER BY buyers DESC;
count(*) after a MATCH counts matching rows per group.
medium Safely add a "Tablet" product without duplicating it if re-run. 
MERGE (t:Product {name:'Tablet'})
ON CREATE SET t.price = 600, t.category = 'Tech'
RETURN t;
MERGE on the unique name makes it idempotent.
