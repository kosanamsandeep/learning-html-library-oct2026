Chapter 05 · Cypher

Intermediate Cypher — the real power

This is where graph databases leave SQL behind: multi-hop traversals, variable-length paths, aggregation, and WITH pipelines. You'll write your first recommendation engine in a handful of lines.

1 · Multi-hop traversal — "friends of friends"

Just chain more pattern. Each -[]-> is one hop.

// Alice's friends-of-friends (2 hops), excluding herself & direct friends
MATCH (alice:Person {name:'Alice'})-[:FRIENDS_WITH]->(friend)-[:FRIENDS_WITH]->(fof)
WHERE fof <> alice
  AND NOT (alice)-[:FRIENDS_WITH]->(fof)
RETURN DISTINCT fof.name AS suggestion;
graph LR
    Alice(["Alice"]) -->|FRIENDS_WITH| Bob(["Bob"])
    Alice -->|FRIENDS_WITH| Carol(["Carol"])
    Bob -->|FRIENDS_WITH| Dave(["Dave (FoF)"])
    Carol -->|FRIENDS_WITH| Erin(["Erin (FoF)"])
    classDef person fill:#dbeafe,stroke:#2563eb,color:#1e3a8a;
    classDef fof fill:#ede9fe,stroke:#7c3aed,color:#4c1d95;
    class Alice,Bob,Carol person;
    class Dave,Erin fof;

In SQL this is a self-join per hop. In Cypher it's one more arrow.

2 · Variable-length paths — "how connected?"

*1..3 means "follow this relationship 1 to 3 hops." This is graph-only magic.

// Everyone reachable from Alice within 3 friendship hops
MATCH path = (alice:Person {name:'Alice'})-[:FRIENDS_WITH*1..3]->(other)
RETURN other.name, length(path) AS hops
ORDER BY hops;
Pattern Meaning
-[:R]-> exactly 1 hop
-[:R*1..3]-> between 1 and 3 hops
-[:R*]-> any number of hops (careful!)
-[:R*2]-> exactly 2 hops
Always bound your *. Unbounded * on a dense graph can explore millions of paths. Use *1..3 style limits.

3 · Aggregation — count, collect, avg

// Average rating per product
MATCH (:Person)-[r:REVIEWED]->(pr:Product)
RETURN pr.name, avg(r.rating) AS avgRating, count(r) AS reviews
ORDER BY avgRating DESC;

// Collect each person's purchases into a list
MATCH (p:Person)-[:BOUGHT]->(pr:Product)
RETURN p.name, collect(pr.name) AS basket;

Implicit grouping: Cypher groups by the non-aggregated keys in RETURN automatically — no GROUP BY needed. Here it groups by pr.name / p.name.

4 · WITH — pipelines between stages

WITH is like a pipe: it passes results from one part of the query to the next, letting you filter on aggregates or chain logic.

// Products with average rating >= 4 only
MATCH (:Person)-[r:REVIEWED]->(pr:Product)
WITH pr, avg(r.rating) AS avgRating
WHERE avgRating >= 4
RETURN pr.name, avgRating
ORDER BY avgRating DESC;
WITH = SQL's HAVING + subqueries combined. Anything not carried through WITH is dropped from the pipeline.

5 · A real recommendation query

"People who bought what you bought, also bought…" — collaborative filtering in 5 lines.

MATCH (me:Person {name:'Alice'})-[:BOUGHT]->(p:Product)
      <-[:BOUGHT]-(other:Person)-[:BOUGHT]->(rec:Product)
WHERE NOT (me)-[:BOUGHT]->(rec)
RETURN rec.name AS recommendation, count(*) AS strength
ORDER BY strength DESC;
graph LR
    Me(["Alice (me)"]) -->|BOUGHT| Shared{{"Laptop"}}
    Other(["Bob"]) -->|BOUGHT| Shared
    Other -->|BOUGHT| Rec{{"Mouse (recommend!)"}}
    classDef person fill:#dbeafe,stroke:#2563eb,color:#1e3a8a;
    classDef product fill:#d4f3e9,stroke:#0f9d77,color:#14241f;
    classDef rec fill:#fde68a,stroke:#d97706,color:#78350f;
    class Me,Other person;
    class Shared product;
    class Rec rec;

Alice and Bob both bought the Laptop; Bob also bought a Mouse → recommend the Mouse to Alice. Notice the <-[:BOUGHT]- arrow pointing back.

6 · OPTIONAL MATCH — left join

Keep rows even when the pattern doesn't match (returns null).

// Every person, plus their reviews if any
MATCH (p:Person)
OPTIONAL MATCH (p)-[r:REVIEWED]->(pr:Product)
RETURN p.name, pr.name AS reviewed, r.rating;

People who never reviewed still appear, with null for the review — exactly like a SQL LEFT JOIN.

Try it yourself

medium Find products bought by Alice's friends that Alice hasn't bought. 
MATCH (a:Person {name:'Alice'})-[:FRIENDS_WITH]->(f)-[:BOUGHT]->(pr:Product)
WHERE NOT (a)-[:BOUGHT]->(pr)
RETURN DISTINCT pr.name;
medium Who has the most friends? 
MATCH (p:Person)-[:FRIENDS_WITH]-(f)
RETURN p.name, count(DISTINCT f) AS friends
ORDER BY friends DESC LIMIT 1;
The undirected -[:FRIENDS_WITH]- (no arrow) counts friendships both ways.
hard Spending per city, only cities spending over £1000. 
MATCH (p:Person)-[:BOUGHT]->(pr:Product)
WITH p.city AS city, sum(pr.price) AS spend
WHERE spend > 1000
RETURN city, spend ORDER BY spend DESC;
WITH aggregates first, then WHERE filters the aggregate.
