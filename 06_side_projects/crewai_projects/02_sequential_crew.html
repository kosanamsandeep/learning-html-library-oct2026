Build 02 · Beginner+

A crew that hands work down a line

A researcher gathers facts, then a writer turns them into an article. The writer's task pulls the researcher's output via context, and the crew runs as Process.sequential.

What this build does

Two agents, two tasks, executed in order. The magic is context=[research_task] — that wires the first task's output into the second task's input.

Beginner+ Process.sequential context multi-agent

The pipeline

flowchart LR
    R["researcher"] --> RT["research_task
→ findings"]
    RT -->|context| WT["write_task"]
    W["writer"] --> WT
    WT --> OUT["final article"]

Tasks run top-to-bottom; context passes one task's result into the next.

The code

from crewai import Agent, Task, Crew, Process

researcher = Agent(
    role="Senior Researcher",
    goal="Uncover key facts about {topic}",
    backstory="A rigorous analyst who cites concrete details.",
    llm="gpt-4o",
)
writer = Agent(
    role="Tech Content Writer",
    goal="Write an engaging article from research",
    backstory="You turn dense findings into clear, lively prose.",
    llm="gpt-4o",
)

research_task = Task(
    description="Research the current state of {topic}. List the top findings.",
    expected_output="5 bullet findings with specifics.",
    agent=researcher,
)
write_task = Task(
    description="Write a 4-paragraph article on {topic} using the research.",
    expected_output="A polished 4-paragraph article in markdown.",
    agent=writer,
    context=[research_task],          # ← receives research_task's output
    output_file="article.md",        # optionally write result to disk
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential,       # run tasks in listed order
    verbose=True,
)

result = crew.kickoff(inputs={"topic": "vector databases"})
print(result)

Sequential vs Hierarchical

Process.sequential

Tasks run in the order you list them. Output flows down via context. Predictable and easy to debug — start here.

Process.hierarchical

A manager agent (you supply manager_llm) plans, delegates tasks to workers, and validates results. Better for complex, branching work.

# Hierarchical: a manager LLM coordinates the workers
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.hierarchical,
    manager_llm="gpt-4o",        # the coordinator
)
In hierarchical mode you don't pre-assign every task to an agent — the manager decides who does what. Use sequential until you actually need delegation.

Best practices

  • Order tasks deliberately in sequential mode — the list is the pipeline.
  • Use context=[...] instead of stuffing prior output into descriptions manually.
  • Write results with output_file for artifacts you need later.
  • Reach for hierarchical only when needed — the manager adds LLM calls and nondeterminism.
