Flows, memory & production polish

Crews are autonomous; Flows give you precise, event-driven orchestration that can wrap crews. Plus built-in memory, planning, and observability.

What this build covers

Advanced Flow @start / @listen memory=True planning=True AgentOps

Crews vs Flows — when to use which

Crew

Autonomous, role-playing agents that figure out how. Great when you want emergent collaboration and minimal wiring.

Flow

Event-driven, deterministic orchestration. You control the path with @start/@listen, conditionals, and shared state — and can call crews from inside steps.

A CrewAI Flow

flowchart LR
    S["@start
generate_topic"] --> L1["@listen
run_research_crew"]
    L1 --> L2["@listen
write_report"]
    L2 --> END["state.report"]

Each method emits an event; @listen wires the next step. State is shared and type-safe.

from crewai.flow.flow import Flow, listen, start
from pydantic import BaseModel

class ReportState(BaseModel):
    topic: str = ""
    report: str = ""

class ReportFlow(Flow[ReportState]):

    @start()
    def pick_topic(self):
        self.state.topic = "agentic AI in 2025"

    @listen(pick_topic)
    def research(self):
        # call a Crew here and store its output in state
        result = research_crew.kickoff(inputs={"topic": self.state.topic})
        self.state.report = str(result)

    @listen(research)
    def finish(self):
        print("DONE:", self.state.report[:200])

ReportFlow().kickoff()
Flows also support @router for conditional branching and or_/and_ to listen on multiple events — this is CrewAI's answer to graph-style control flow.

Memory — agents that remember

Turn on memory and the crew gains short-term, long-term, and entity memory automatically (backed by a local vector store).

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential,
    memory=True,        # short-term + long-term + entity memory
    verbose=True,
)
Memory type Holds
Short-term Context within the current run (RAG over recent steps).
Long-term Insights persisted across runs (improves over time).
Entity Facts about people/places/things the crew encounters.

Planning — a plan before execution

crew = Crew(
    agents=[...], tasks=[...],
    planning=True,            # an LLM drafts a step-by-step plan first
    planning_llm="gpt-4o",
)

With planning=True, CrewAI generates an explicit plan before the crew runs, which improves coordination on multi-step tasks.

Observability & guardrails

  • AgentOps — one-line integration for dashboards, traces, and cost/latency tracking of every agent step.
  • OpenTelemetry / Langtrace / OpenLIT — CrewAI emits telemetry these tools can ingest.
  • Task guardrails — pass a guardrail function to a Task to validate/repair output before it passes downstream. 
import agentops
agentops.init()      # now every kickoff is traced in the AgentOps dashboard
crew.kickoff(inputs={"topic": "RAG patterns"})

Production checklist

  • Use Flows for anything with branching or external triggers; keep Crews for the autonomous sub-tasks.
  • Enable memory=True for assistants that should learn across runs.
  • Add task guardrails to enforce output shape.
  • Instrument with AgentOps before shipping — multi-agent cost adds up fast.
  • Scaffold with crewai create crew and keep agents/tasks in YAML for maintainability.

Where CrewAI stands first

CrewAI stands first for getting a believable role-based team running fastest — the role/goal/backstory model is the most intuitive on-ramp to multi-agent AI, and Flows add deterministic orchestration when you need it.
