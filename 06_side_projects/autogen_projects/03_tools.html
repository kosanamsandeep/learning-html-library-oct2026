Give your agent tools

An agent that can only talk is limited. Pass plain Python functions as tools and the LLM decides when to call them — fetching weather, querying a DB, hitting an API — then reflects on the result.

What this build does

We define ordinary async Python functions, hand them to the agent as tools, and turn on reflect_on_tool_use so the agent turns raw tool output into a natural-language answer.

Intermediate tools=[...] reflect_on_tool_use FunctionTool

The tool-calling loop

flowchart TD
    U["User: 'Weather in Paris?'"] --> A["AssistantAgent"]
    A -->|LLM decides| D{"Need a tool?"}
    D -->|yes| T["call get_weather('Paris')"]
    T --> R["tool result: '18°C, sunny'"]
    R --> A
    A -->|reflect_on_tool_use| F["'It's 18°C and sunny in Paris.'"]
    D -->|no| F

The LLM picks the tool and arguments; AutoGen executes it and feeds the result back for a final, reflected answer.

The code

import asyncio
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.ui import Console
from autogen_ext.models.openai import OpenAIChatCompletionClient

# A tool is just a typed function. The docstring + type hints become
# the schema the LLM sees, so write them clearly.
async def get_weather(city: str) -> str:
    """Return the current weather for a given city."""
    # In real life: call a weather API here.
    return f"It's 18°C and sunny in {city}."

async def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b

async def main():
    client = OpenAIChatCompletionClient(model="gpt-4o")

    agent = AssistantAgent(
        "assistant",
        model_client=client,
        tools=[get_weather, add],          # pass functions directly
        reflect_on_tool_use=True,         # summarise tool output in natural language
        system_message="Use tools when helpful. Be concise.",
    )

    await Console(agent.run_stream(task="What's the weather in Paris, and what is 21 + 21?"))
    await client.close()

asyncio.run(main())

reflect_on_tool_use — on vs off

False (default) True
Agent returns… The raw tool result as the final message. An LLM-written summary of the tool result.
Best for… Structured output you parse yourself. Chat / conversational answers.
Extra cost None. One more LLM call to reflect.

Wrapping a tool explicitly with FunctionTool

Passing a bare function is the shortcut. Wrap it in FunctionTool when you want a custom name or description shown to the LLM.

from autogen_core.tools import FunctionTool

weather_tool = FunctionTool(
    get_weather,
    description="Get the current weather for a city by name.",
)
agent = AssistantAgent("assistant", model_client=client, tools=[weather_tool])
MCP & built-in tools: AutoGen also ships adapters so agents can use Model Context Protocol servers and prebuilt tools (code execution, web browsing) from autogen-ext — same tools=[...] slot.

Best practices

  • Type hints + docstrings are the API. The LLM only knows what the signature and docstring tell it. Be explicit.
  • Keep tools small and single-purpose. One function = one capability is easier for the model to choose correctly.
  • Validate inputs inside the tool. The LLM can pass odd arguments; never trust them blindly (especially for DB or shell access).
  • Return strings or JSON-serialisable values so the result is easy to feed back into the conversation.
