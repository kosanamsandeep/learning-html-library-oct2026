Dynamic teams, humans & observability

Everything you need for a real multi-agent system: an LLM that picks the next speaker (SelectorGroupChat), human-in-the-loop, saving/loading team state, and OpenTelemetry tracing.

SelectorGroupChat — the LLM routes the conversation

flowchart TD
    M{{"Selector (LLM)
reads history, picks next speaker"}}
    M --> P["planner"]
    M --> R["researcher"]
    M --> C["coder"]
    P --> M
    R --> M
    C --> M
    M -->|termination| END["Done"]

Unlike round-robin's fixed order, the selector chooses the most relevant agent each turn — ideal for teams with specialised roles.

from autogen_agentchat.teams import SelectorGroupChat
from autogen_agentchat.conditions import TextMentionTermination, MaxMessageTermination

planner    = AssistantAgent("planner",    model_client=client, system_message="Break the goal into steps.")
researcher = AssistantAgent("researcher", model_client=client, tools=[web_search], system_message="Gather facts.")
coder      = AssistantAgent("coder",      model_client=client, system_message="Write code. Say TERMINATE when complete.")

team = SelectorGroupChat(
    [planner, researcher, coder],
    model_client=client,                       # the LLM used to PICK the next speaker
    termination_condition=TextMentionTermination("TERMINATE") | MaxMessageTermination(20),
)

await Console(team.run_stream(task="Research and prototype a URL shortener."))

Human-in-the-loop with UserProxyAgent

Add a real person as an agent. When it's their turn, AutoGen pauses and waits for input — perfect for approvals.

from autogen_agentchat.agents import UserProxyAgent

human = UserProxyAgent("human", input_func=input)   # prompts at the console

team = RoundRobinGroupChat([assistant, human],
                           termination_condition=TextMentionTermination("DONE"))
await Console(team.run_stream(task="Plan a release; ask me to approve each step."))
For web apps, pass an async input_func that resolves when your UI submits — and pair it with HandoffTermination so an agent can explicitly hand control to the human.

Persisting team state

Save the full conversation/team state to resume later — the basis for durable, long-running sessions.

# Save after a run
state = await team.save_state()
json.dump(state, open("team_state.json", "w"))

# ...later, rebuild the team and restore
await team.load_state(json.load(open("team_state.json")))
await Console(team.run_stream(task="Continue where we left off."))

Observability — OpenTelemetry tracing

AutoGen emits OTEL traces, so every agent message, tool call, and model request shows up in Jaeger, Grafana, or any OTLP backend.

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(provider)
# AutoGen runtimes auto-instrument: traces now flow to your collector.
AgentOps & AutoGen Studio are higher-level options: AgentOps gives dashboards/cost tracking with one line; AutoGen Studio is a low-code UI to prototype teams visually.

Choosing a team type

Team Next speaker chosen by… Use when
RoundRobinGroupChat Fixed rotation Pipelines, reviewer loops.
SelectorGroupChat An LLM each turn Dynamic, specialised teams.
Swarm Explicit handoffs Agents decide who to delegate to.
MagenticOneGroupChat An orchestrator Complex open-ended web/file tasks.

Production checklist

  • Always cap with MaxMessageTermination alongside any text/handoff condition.
  • Trace everything. Multi-agent bugs are invisible without OTEL or AgentOps.
  • Persist state for long sessions and crash recovery.
  • Set token budgets (TokenUsageTermination) to control cost.
  • Isolate code execution in a container/Docker code executor — never run LLM-written code on the host.

Where AutoGen stands first
