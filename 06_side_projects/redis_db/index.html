What is Redis in one picture?

Redis (REmote DIctionary Server) is an in-memory data store: it keeps your data in RAM, so reads and writes happen in microseconds. At its core it's a giant, server-side dictionary — every value is stored under a key — but the values can be rich data structures, not just strings.

When should you reach for Redis?

✅ Great fit

  • Caching — sit in front of a slow DB/API and serve hot data instantly.
  • Sessions & tokens — fast, expiring per-user state.
  • Rate limiting & counters — atomic INCR per second/user.
  • Leaderboards & ranking — sorted sets do this natively.
  • Queues & streams — background jobs, event pipelines, pub/sub.
  • Real-time — presence, live counts, geospatial, feature flags.

⚠️ Probably not

  • System of record for data you can't afford to lose without care (it's RAM-first).
  • Complex multi-table queries, JOINs, ad-hoc analytics (use SQL).
  • Datasets far larger than your RAM budget (RAM is the cost).
  • Deep relationship traversal (use a graph DB).
Rule of thumb: if a query is asked constantly and must return in milliseconds — or you need counters, queues, expiring keys, or rankings — Redis is usually the simplest, fastest answer. It often sits alongside your main database, not instead of it.
