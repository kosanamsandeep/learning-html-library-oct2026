Chapter 03 · Data

The data types — and a dataset to practice on

Redis's superpower is its values. Each key holds a purpose-built data structure. Learn the five core types, then paste in a small online-store dataset that every later chapter queries.

The five core types (memorize these)

Type Holds Use it for Star commands
String Text, number, or binary (≤512MB) Cache values, counters, flags, JSON blobs SET GET INCR
List Ordered sequence (linked list) Queues, stacks, recent items, timelines LPUSH RPOP LRANGE
Hash Field → value map (an object) Store an object: user, product, session HSET HGET HGETALL
Set Unordered unique members Tags, unique visitors, membership tests SADD SISMEMBER SINTER
Sorted set Unique members each with a score Leaderboards, ranking, priority queues ZADD ZRANGE ZREVRANK

Bonus types you'll meet later: Streams (append-only logs / event pipelines), Bitmaps & HyperLogLog (space-efficient counting), and Geospatial (radius queries).

1 · Strings — the workhorse

SET product:1:name "Laptop"
GET product:1:name            # → "Laptop"

# Strings double as atomic counters
SET product:1:stock 10
DECR product:1:stock          # → (integer) 9
INCRBY product:1:stock 5      # → (integer) 14

# Set with an expiry (seconds) — great for caches
SET cache:home "<html>…" EX 60
TTL cache:home                # → seconds left

2 · Lists — ordered, push/pop from both ends

# A simple job queue (push left, pop right = FIFO)
LPUSH queue:emails "welcome:42" "reset:7"
RPOP queue:emails            # → "welcome:42" (oldest first)
LLEN queue:emails            # → items remaining

# Recent activity feed, keep only newest 5
LPUSH user:42:recent "viewed:laptop"
LTRIM user:42:recent 0 4
LRANGE user:42:recent 0 -1   # → all items
graph LR
    L["LPUSH ►"] --> A["item3"] --> B["item2"] --> C["item1"] --> R["► RPOP"]
    classDef n fill:#dbeafe,stroke:#2563eb,color:#1e3a8a;
    class A,B,C n;

Push on the left, pop on the right → a FIFO queue. Push and pop on the same end → a stack. BRPOP blocks until an item arrives (a worker waiting for jobs).

3 · Hashes — store an object under one key

HSET user:42 name "Alice" email "a@x.io" age 30
HGET user:42 email        # → "a@x.io"
HGETALL user:42            # → all fields & values
HINCRBY user:42 age 1      # → 31 (atomic field increment)

A hash is more memory-efficient and tidier than many separate user:42:name, user:42:email string keys when fields belong together.

4 · Sets — unique, unordered, fast membership

SADD product:1:tags "tech" "portable" "tech"
SMEMBERS product:1:tags     # → {"tech","portable"} (deduped)
SISMEMBER product:1:tags "tech"  # → 1 (true)

# Set algebra: who follows BOTH Alice and Bob?
SADD followers:alice "u1" "u2" "u3"
SADD followers:bob "u2" "u3" "u4"
SINTER followers:alice followers:bob  # → {"u2","u3"}

SINTER/SUNION/SDIFF do intersection, union and difference server-side — perfect for tags, common friends, and audience targeting.

5 · Sorted sets — ranking built in

# A leaderboard: member + score
ZADD leaderboard 100 "alice" 85 "bob" 120 "carol"
ZREVRANGE leaderboard 0 2 WITHSCORES
# → carol 120, alice 100, bob 85 (top 3)
ZINCRBY leaderboard 10 "bob"     # bob → 95
ZREVRANK leaderboard "alice"     # → her 0-based rank
Why this is special: the set stays sorted by score automatically, so "top 10", "my rank", and "players scoring 50–100" are all O(log n) — no re-sorting, no extra index.

Paste-in dataset · a tiny online store

This is our main practice dataset. Paste the whole block into redis-cli (each line is one command). Later chapters query it. 

# --- wipe current DB first (optional) ---
FLUSHDB

# --- Products as hashes ---
HSET product:1 name "Laptop" price 1200 stock 5 category "tech"
HSET product:2 name "Phone" price 800 stock 9 category "tech"
HSET product:3 name "Coffee Mug" price 15 stock 50 category "home"
HSET product:4 name "Graph Book" price 40 stock 20 category "books"

# --- Product tags as sets ---
SADD tag:tech 1 2
SADD tag:bestseller 1 4
SADD tag:gift 3 4

# --- Users as hashes ---
HSET user:1 name "Alice" city "London"
HSET user:2 name "Bob" city "Paris"

# --- Each user's cart as a list of product ids ---
RPUSH cart:1 1 4
RPUSH cart:2 2 3 3

# --- Sales counters as strings ---
SET sales:product:1 37
SET sales:product:2 52
SET sales:product:4 61

# --- A best-sellers leaderboard as a sorted set ---
ZADD bestsellers 37 "product:1" 52 "product:2" 61 "product:4"
Verify it loaded: 
DBSIZE                       # total keys
HGETALL product:1            # the Laptop hash
ZREVRANGE bestsellers 0 -1 WITHSCORES   # ranked sellers

Choosing the right type (decision cheatsheet)

Need one value / counter / flag? → String
Need order, a queue or stack? → List
Need an object with fields? → Hash
Need uniqueness or set math? → Set
Need ranking / scores? → Sorted set
Need an event log / stream? → Stream (ch. 06)
