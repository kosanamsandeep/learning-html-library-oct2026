Python 3.10+ · the practical reference

Every type annotation you'll meet — with an example you can copy

Type hints are just labels. They don't change runtime behavior, but they let your editor, mypy/pyright, FastAPI, Pydantic, and your teammates understand your code. This page lists every common annotation, why it exists, and how to remember it.

Mental model Primitives Containers Optional / Union Callable, Iterable, Iterator Generics + TypeVar Literal, Final, ClassVar TypedDict, NamedTuple, dataclass, Protocol Annotated, NewType, Self, override Async types Memory tricks Practice quiz

1. The mental model — three buckets

Every annotation in Python is one of these three things. Once you see it that way, the long typing import list stops being scary.

🟢 "What kind of thing?"

Built-in primitives: int, str, bool, float, bytes, None.

🔵 "A container of what?"

list[str], dict[str, int], tuple[int, str], set[float].

🟣 "A description, not a type"

Optional, Union, Literal, Callable, Annotated, TypeVar, Protocol — these qualify other types.

Python 3.10+ rule: you almost never need to import from typing for the basics anymore. Use the built-ins.
Old (Python 3.8) Modern (3.10+)
List[int] list[int]
Dict[str, int] dict[str, int]
Tuple[int, str] tuple[int, str]
Set[str] set[str]
Optional[int] int | None
Union[int, str] int | str

2. Primitives — no imports needed

name: str = "Aria"
age: int = 30
height: float = 1.72
is_active: bool = True
raw: bytes = b"\x00\x01"
nothing: None = None        # rarely written; usually appears as `-> None`

def greet(name: str) -> None:
    print(f"Hello {name}")

A function with no return value is annotated -> None.

3. Containers — "a box of what?"

Annotation Means Example value
list[int] A list whose items are ints [1, 2, 3]
dict[str, int] Dict with str keys, int values {"a": 1}
set[str] A set of strings {"a", "b"}
tuple[int, str] Exactly two items: int, then str (fixed length, mixed types) (42, "ok")
tuple[int, ...] Any number of ints (variable length, same type) (1, 2, 3, 4)
frozenset[str] Immutable set frozenset({"a"})

Real examples

def average(numbers: list[float]) -> float:
    return sum(numbers) / len(numbers)

def word_counts(words: list[str]) -> dict[str, int]:
    counts: dict[str, int] = {}
    for w in words:
        counts[w] = counts.get(w, 0) + 1
    return counts

def split_name(full: str) -> tuple[str, str]:
    first, _, last = full.partition(" ")
    return first, last

def unique_tags(posts: list[dict[str, str]]) -> set[str]:
    return {tag for p in posts for tag in p["tags"].split(",")}

4. Optional and Union — "maybe" and "either"

Optional = "this or None"

from typing import Optional

def find_user(uid: int) -> Optional[dict]:
    ...

# Modern equivalent (3.10+):
def find_user(uid: int) -> dict | None:
    ...

Union = "any of these"

from typing import Union

def parse(x: Union[int, str]) -> int:
    ...

# Modern equivalent:
def parse(x: int | str) -> int:
    ...
Mnemonic: Optional[X] = X | None. Nothing more. Don't use Optional to mean "the parameter is optional" — use a default value for that. 
# Wrong meaning:
def page(size: Optional[int]):   # implies "int OR None"
    ...

# Right meaning of "optional parameter":
def page(size: int = 10):        # has a default, so caller can skip
    ...

5. Callable, Iterable, Iterator, Sequence, Mapping

Use the most general type your function actually needs. list is too narrow when any iterable will do.

Annotation Meaning Use when…
Iterable[X] Anything you can for over once You only loop.
Iterator[X] Iterable that also supports next() You hand-roll iteration / generators.
Sequence[X] Indexable + length (list, tuple, str) You need obj[0] and len(obj) but don't mutate.
Mapping[K, V] Read-only dict-like You only look things up.
MutableMapping[K, V] Dict-like and writable You insert/delete keys.
Callable[[A, B], R] Function taking A, B, returning R You accept a function/callback. 
from typing import Iterable, Callable, Mapping, Iterator

def first_match(items: Iterable[int], pred: Callable[[int], bool]) -> int | None:
    for x in items:
        if pred(x):
            return x
    return None

def count_keys(data: Mapping[str, object]) -> int:
    return len(data)

def evens_up_to(n: int) -> Iterator[int]:
    for i in range(n):
        if i % 2 == 0:
            yield i
Library-design tip: in function inputs, prefer abstract types (Iterable, Mapping). In outputs, return concrete types (list, dict). Callers should give you the least and you should give them the most.

6. Generics — TypeVar and Generic

"Generic" = a function/class that works for many types but keeps them consistent. 

from typing import TypeVar

T = TypeVar("T")

def first(items: list[T]) -> T:
    return items[0]

x: int = first([1, 2, 3])    # T inferred as int
y: str = first(["a", "b"])    # T inferred as str

Why it matters: without T, you'd write def first(items: list) -> object, and the caller would lose all type info on the return value.

Bounded TypeVar

from typing import TypeVar

Number = TypeVar("Number", int, float)   # only these two allowed

def double(x: Number) -> Number:
    return x * 2

double(3)      # int -> int
double(3.5)    # float -> float
# double("a")  # mypy error

Python 3.12+ shorter syntax

def first[T](items: list[T]) -> T:
    return items[0]

class Stack[T]:
    def push(self, x: T) -> None: ...
    def pop(self) -> T: ...

7. Literal, Final, ClassVar

Literal — "must be one of these exact values"

from typing import Literal

def set_mode(m: Literal["read", "write", "append"]) -> None:
    ...

set_mode("read")    # ok
set_mode("execute") # mypy error

Final — "never reassign me"

from typing import Final

API_URL: Final = "https://api.com"
# API_URL = "..."  # mypy error

ClassVar — class attribute, not instance

from typing import ClassVar

class Counter:
    instances: ClassVar[int] = 0   # shared across all Counter()s
    value: int                     # per-instance

8. Shaping data — TypedDict, NamedTuple, dataclass, Protocol

TypedDict — a dict with known keys

from typing import TypedDict

class User(TypedDict):
    id: int
    name: str
    email: str

def send_welcome(u: User) -> None:
    print(u["name"], u["email"])

send_welcome({"id": 1, "name": "Aria", "email": "a@b.com"})  # ok
# Missing/extra/wrong-typed keys -> mypy error

NamedTuple — fast, immutable, indexable

from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float

p = Point(1.0, 2.0)
p.x, p[0]   # both work

@dataclass — the modern default for "a record"

from dataclasses import dataclass

@dataclass(frozen=True)
class Money:
    amount: float
    currency: str = "USD"

m = Money(9.99)
# m.amount = 1  # error, frozen

Protocol — structural typing ("duck typing with hints")

from typing import Protocol

class HasArea(Protocol):
    def area(self) -> float: ...

def describe(shape: HasArea) -> str:
    return f"area is {shape.area()}"

class Square:                # no inheritance from HasArea!
    def __init__(self, side: float):
        self.side = side
    def area(self) -> float:
        return self.side ** 2

describe(Square(3))   # ok — Square structurally matches HasArea
You want… Use
Dict-shaped data from JSON TypedDict
Lightweight immutable record, tuple-friendly NamedTuple
Object with methods, defaults, validation @dataclass or Pydantic
"Anything that has these methods" Protocol

9. Advanced but useful

Annotated — attach metadata for libraries (FastAPI/Pydantic love this)

from typing import Annotated
from fastapi import Query

def search(
    q: Annotated[str, Query(min_length=3, max_length=50)],
) -> list[str]:
    ...

The type checker sees str. The library reads the metadata for validation/docs.

NewType — distinct type for ID-style values

from typing import NewType

UserId = NewType("UserId", int)
ProductId = NewType("ProductId", int)

def get_user(uid: UserId) -> dict: ...

uid = UserId(42)
get_user(uid)              # ok
# get_user(42)             # mypy error — plain int rejected
# get_user(ProductId(1))   # mypy error — wrong kind of id

Self — "instance of my own class" (Python 3.11+)

from typing import Self

class Builder:
    def with_name(self, n: str) -> Self:
        self.name = n
        return self
    def with_age(self, a: int) -> Self:
        self.age = a
        return self

Any — escape hatch, use sparingly

from typing import Any

def parse_json(s: str) -> Any:
    import json
    return json.loads(s)   # could be anything
Every Any turns off type checking for that value. It's contagious — try object or a TypedDict first.

cast — "trust me, mypy"

from typing import cast

raw: object = get_thing()
n = cast(int, raw)   # no runtime check, just a hint to the checker

@override (Python 3.12+) — catch typos in subclasses

from typing import override

class Base:
    def run(self) -> None: ...

class Child(Base):
    @override
    def run(self) -> None: ...   # error if Base.run is renamed/removed

10. Async types

from typing import Awaitable, AsyncIterable, AsyncIterator, Coroutine

async def fetch(url: str) -> str:           # returns a Coroutine[Any, Any, str]
    ...

def schedule(task: Awaitable[int]) -> None: # accept any awaitable
    ...

async def stream() -> AsyncIterator[bytes]:
    for chunk in [b"a", b"b"]:
        yield chunk

For most code you just write async def foo() -> X. The fancy types matter when you accept user-provided awaitables.

11. Memory tricks

If you want to say… Reach for…
"a list of X" list[X]
"a dict from K to V" dict[K, V]
"X or nothing" X | None (or Optional[X])
"X or Y" X | Y (or Union[X, Y])
"a function taking A,B returning R" Callable[[A, B], R]
"any iterable" Iterable[X]
"a dict with known keys" TypedDict
"just one of these literal strings" Literal["a", "b"]
"a generic container" TypeVar + Generic
"any object with method .foo()" Protocol
"this constant never changes" Final
"this is a class attribute" ClassVar
"a return that's the same type as self" Self
The 3-question rule:
  1. Is it a primitive? → use int/str/bool/...
  2. Is it a container of one type? → use list[X] / dict[K,V] / set[X]
  3. Is it "X or something else"? → use X | Y or X | None
That covers 80% of real-world code.

12. Look-at-it practice — annotate these in your head

For each unannotated function, write the type hint in your head, then check the answer.

  1. def square(n):
    return n * n
    Answer 
    def square(n: int) -> int:
    return n * n
  2. def make_user(name, age=None):
    return {"name": name, "age": age}
    Answer 
    def make_user(name: str, age: int | None = None) -> dict[str, str | int | None]:
    return {"name": name, "age": age}
  3. def get_or_default(d, key, default):
    return d[key] if key in d else default
    Answer 
    from typing import TypeVar, Mapping
K = TypeVar("K")
V = TypeVar("V")

def get_or_default(d: Mapping[K, V], key: K, default: V) -> V:
    return d[key] if key in d else default
  4. def first_even(items):
    for x in items:
        if x % 2 == 0:
            return x
    return None
    Answer 
    from typing import Iterable

def first_even(items: Iterable[int]) -> int | None:
    for x in items:
        if x % 2 == 0:
            return x
    return None
  5. def apply(fn, value):
    return fn(value)
    Answer 
    from typing import Callable, TypeVar
T = TypeVar("T")
R = TypeVar("R")

def apply(fn: Callable[[T], R], value: T) -> R:
    return fn(value)
  6. def send_email(to, subject, body, cc=None, bcc=None):
    ...
    Answer 
    def send_email(
    to: str,
    subject: str,
    body: str,
    cc: list[str] | None = None,
    bcc: list[str] | None = None,
) -> None:
    ...
  7. def log_level(name):
    # name must be one of these
    return {"info": 20, "warn": 30, "error": 40}[name]
    Answer 
    from typing import Literal

def log_level(name: Literal["info", "warn", "error"]) -> int:
    return {"info": 20, "warn": 30, "error": 40}[name]
  8. class Box:
    def __init__(self, value):
        self.value = value
    def replace(self, new):
        self.value = new
        return self
    Answer 
    from typing import Generic, TypeVar, Self
T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, value: T) -> None:
        self.value = value
    def replace(self, new: T) -> Self:
        self.value = new
        return self

13. The one import line you'll actually use

from typing import (
    Optional, Union, Any,
    Iterable, Iterator, Callable, Sequence, Mapping,
    TypeVar, Generic, Protocol,
    Literal, Final, ClassVar,
    TypedDict, NamedTuple, NewType, Annotated, Self, cast,
)

You don't need all of them at once — but having this list in front of you while annotating a tricky function is the fastest way to learn.

14. Running the type checker

# pick one and stick with it per project
pip install mypy        # the original
pip install pyright     # what Pylance uses, faster

mypy your_module.py
pyright your_module.py

Type hints with no checker is just documentation. Hook the checker into pre-commit or CI to make them real.
