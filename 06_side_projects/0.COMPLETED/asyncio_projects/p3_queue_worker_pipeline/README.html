Queue worker pipeline — producers, consumers, and backpressure

Many async systems are not just "call 10 APIs." They are pipelines: one part creates jobs, another part processes jobs, and the queue between them protects the system from overload.

The story

An order service receives work faster than it can process. If every order immediately creates a task, memory can explode. A queue gives you control: producers wait when the queue is full, workers pull jobs at a sustainable pace, and the coordinator knows when all work is finished.

Files

File Purpose
main.py Async producer, worker pool, bounded queue, queue drain, and cancellation-based shutdown.
requirements.txt No external dependencies.

Mental model

Producer creates jobs
->
Bounded queue buffers jobs
->
Workers process jobs
->
Coordinator waits for drain

The queue is the handoff point. Its maxsize is backpressure: if workers fall behind, producers must wait.

Core code

queue = asyncio.Queue(maxsize=4)
workers = [asyncio.create_task(worker(f"worker-{i}", queue)) for i in range(3)]

await producer(queue, total_jobs=10)
await queue.join()

for task in workers:
    task.cancel()
await asyncio.gather(*workers, return_exceptions=True)

Important queue methods

Method Meaning
await queue.put(job) Add a job; wait if the queue is full.
await queue.get() Take a job; wait if the queue is empty.
queue.task_done() Tell the queue this job has finished processing.
await queue.join() Wait until every queued job has been marked done.

How to run

cd 06_side_projects/asyncio_projects/p3_queue_worker_pipeline
python main.py

What to remember

  • Queues decouple producers from consumers.
  • A bounded queue prevents unlimited memory growth.
  • queue.join waits for all jobs to finish.
  • Workers often run forever and are stopped by cancellation.
Interview answer: I use asyncio.Queue when async tasks need a safe handoff point. Producers put work into the queue, workers consume it, and a bounded queue creates backpressure so the system cannot accept infinite work.
