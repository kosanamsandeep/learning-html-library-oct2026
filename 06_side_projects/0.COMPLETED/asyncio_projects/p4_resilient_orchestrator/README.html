Project 4 · Advanced

Resilient orchestrator — concurrency limits, retries, timeouts, cancellation

Production async code is not just "run everything at once." It must protect downstream systems, retry temporary failures, stop slow work, and cancel work that no longer matters.

The story

A dashboard endpoint needs profile, orders, payments, recommendations, and inventory. Calling all five at once is faster, but blindly flooding services is dangerous. This project adds the controls that separate toy async code from production async code.

Production controls

Control Problem it solves
Semaphore Limits concurrency so you do not overwhelm downstream services.
Timeout Prevents one slow call from holding the whole request forever.
Retry Handles temporary failures without immediately failing the user request.
TaskGroup Gives structured concurrency: related tasks are created and awaited as a group.
Cancellation Stops work that is no longer needed, such as a user disconnecting.

The semaphore says "only two service calls may run at once." The TaskGroup says "these tasks belong to one orchestration scope."

Cancellation

Cancellation is cooperative. Calling task.cancel() does not kill code in the middle of a CPU instruction. It injects CancelledError at the next await point. That gives your coroutine a chance to clean up.

try:
    while True:
        await asyncio.sleep(0.4)
except asyncio.CancelledError:
    print("cleanup before stopping")
    raise

What to remember

  • Unbounded concurrency is a production risk.
  • Semaphores create bulkheads around scarce resources.
  • Timeouts and retries should be close to the network call.
  • Cancellation should be handled, cleaned up, and re-raised.
  • TaskGroup makes related tasks easier to reason about than loose background tasks.
Interview answer: In production asyncio code, I combine concurrency with control: semaphore for limits, timeout for deadlines, retry for transient failures, and cancellation handling for graceful shutdown or user disconnects.
