Concurrent API fetcher — call many slow services at once

The most common real use for asyncio is fan-out I/O: call users, orders, payments, inventory, and pricing services without waiting for each one sequentially.

The story

Your dashboard needs data from four services. If each service takes around one second and you call them one by one, your page is slow. If you call them concurrently, the page waits roughly for the slowest service, not the sum of all services.

Files

File Purpose
main.py Simulates remote API calls, sequential fetch, concurrent fetch, completion-order processing, and timeouts.

Patterns taught

Pattern When to use it
gather You want all results and usually want them in input order.
as_completed You want to process the fastest responses first.
wait_for You want to stop waiting after a deadline.
create_task You want to schedule work now and manage it later.

Core code

async def fetch_concurrent(endpoints):
    calls = [fake_api_call(name, latency) for name, latency in endpoints]
    return await asyncio.gather(*calls)

async def fetch_with_timeout(name, latency, timeout):
    try:
        await asyncio.wait_for(fake_api_call(name, latency), timeout=timeout)
        return f"{name}: success"
    except asyncio.TimeoutError:
        return f"{name}: timed out"

Completion order vs input order

asyncio.gather returns results in the same order you passed calls. asyncio.as_completed yields tasks as they finish. In a UI, completion order can let you show partial results sooner.

How to run

cd 06_side_projects/asyncio_projects/p2_concurrent_api_fetcher
python main.py

What to remember

  • Use concurrent calls when requests are independent.
  • Add timeouts so one slow service does not freeze the whole workflow.
  • Use as_completed when early partial results matter.
  • Async code still needs error handling; concurrency makes failures arrive from many places.
Interview answer: asyncio helps API fan-out because independent I/O calls can wait at the same time. The event loop switches between tasks at await points, so total latency approaches the slowest call instead of the sum of all calls.
