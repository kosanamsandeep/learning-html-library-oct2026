Project 1 · Beginner

Asyncio basics — event loop, coroutine, task, await, gather

This project makes the first mental model concrete: async code is not magic speed. It lets your program use waiting time instead of wasting it.

The story

You run a small coffee counter. Making one drink includes waiting: the machine heats, milk steams, coffee drips. If you stand still for every wait, three orders take the sum of all waits. If you start all waits and come back as each one finishes, customers get served faster. That is asyncio.

Mental model

Coroutine starts
->
Hits await
->
Event loop runs another task
->
Coroutine resumes

A coroutine is an async function that can pause. A task is a coroutine scheduled on the event loop. await is the pause point where the task gives control back.

Core code

async def make_coffee(name: str, seconds: float) -> str:
    print(f"start {name}")
    await asyncio.sleep(seconds)
    return f"{name} ready"

async def concurrent_demo():
    return await asyncio.gather(
        make_coffee("espresso", 1.0),
        make_coffee("latte", 1.5),
        make_coffee("mocha", 0.8),
    )

asyncio.sleep is not real work. It is a safe teaching stand-in for network waiting, database waiting, file waiting, or timer waiting.

Sequential vs concurrent

Style What happens Time intuition
Sequential Start espresso, wait, start latte, wait, start mocha, wait. 1.0 + 1.5 + 0.8 ≈ 3.3s
Concurrent Start all three, wait for all to finish. max(1.0, 1.5, 0.8) ≈ 1.5s

How to run

cd 06_side_projects/asyncio_projects/p1_async_basics

What to remember

  • async def creates a coroutine function.
  • await pauses until an awaitable is done.
  • asyncio.run(main()) starts the event loop.
  • asyncio.gather runs multiple awaitables concurrently.
  • asyncio.create_task schedules work now and lets you await it later.
Interview answer: asyncio is best for I/O-bound concurrency. It lets many tasks share one thread by yielding control at await points.
