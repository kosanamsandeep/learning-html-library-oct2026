Task 4

Nodes — Your Workflow Workers

Modular, single-responsibility processing units

🧩 What This Task Teaches

Nodes are the individual workers in your graph. Each node does ONE specific job and passes results forward. This task shows you the different TYPES of nodes you can build and how they form a processing pipeline.

Core Concept: A node is a Python function that receives state, does ONE thing well, and returns state updates. Think of each node as a specialist on a team — one validates, one analyzes, one decides, one formats.

🔨 The Four Node Types Demonstrated

📥

Input Node

Validates and cleans incoming data. The "gatekeeper" that ensures quality input.

🔍

Analyze Node

Processes data — counts words, extracts features, transforms content.

😊

Decision Node

Makes judgments based on state — determines sentiment, classifies content.

📤

Output Node

Formats and presents results. The "reporter" that delivers the final answer.

🔄 The Processing Pipeline

For input: "This is a great example of how nodes work together!"

1
Input Node — Validates and trims the text
IN: raw text → OUT: {text: "This is a great example..."}
2
Analyze Node — Counts words
IN: state.text → OUT: {word_count: 9}
3
Sentiment Node — Classifies mood based on keywords
IN: state.text, state.word_count → OUT: {sentiment: "positive 😊"}
4
Output Node — Formats everything into a report
IN: all state → OUT: {output: formatted_report}

💻 Node Pattern

# Every node follows the SAME pattern: def my_node(state: WorkflowState): # 1. READ what you need from state text = state["text"] # 2. DO your specific job word_count = len(text.split()) # 3. RETURN only what you changed return {"word_count": word_count} # Wire them up: workflow.add_node("input", input_node) workflow.add_node("analyze", analyze_node) workflow.add_edge("input", "analyze") # Connect in order

🔀 How Task 4 Differs from Task 3

Task 3 → Task 4 Evolution

Task 3 showed state accumulation with simple add-to-cart logic.
Task 4 introduces the concept of specialized nodes — each node has a different PURPOSE and RESPONSIBILITY. This is the Single Responsibility Principle applied to graph workflows. Instead of "add item" nodes, you now have validate/analyze/decide/format nodes — a real processing pipeline.

Aspect Task 3 Task 4
Node variety All nodes do similar work (add items) Each node has a unique role
State complexity Simple (list + number) Rich (text + count + sentiment + output)
Design pattern Accumulate data Transform & enrich data
Real-world analogy Filling a shopping cart Assembly line with specialists

✅ Advantages of This Task

  • Modularity — each node can be tested, replaced, or reused independently
  • Separation of concerns — validation is separate from analysis is separate from output
  • Debugging ease — when something breaks, you know exactly which node to examine
  • Scalability — add new nodes without changing existing ones
  • No LLM dependency — demonstrates that nodes can be pure logic (cheaper, faster, deterministic)

💡 Key Insight

Nodes are like LEGO blocks. Once you learn to build good nodes — single-purpose, state-aware, clean return values — you can snap them together in any order. Task 5 will show you how to make the ORDER itself dynamic (routing).
