Project 5 · Advanced

RAG that grades itself and self-corrects

Plain RAG retrieves once and hopes for the best. Agentic RAG turns retrieval into a graph: decide whether to retrieve, grade the documents, rewrite the question if they're weak, and only then answer. This is the CRAG / Self-RAG pattern.

What this project does

The agent decides if it even needs the knowledge base. If it retrieves, a grader node judges whether the documents are relevant. Irrelevant? It rewrites the question and tries again. Relevant? It generates an answer grounded in those documents. The loop guards against the two classic RAG failures: bad retrieval and hallucinated answers.

Two conditional edges: "retrieve or answer?" and "are these docs good enough?". The rewrite→retrieve loop is the self-correction.

State for a RAG graph

from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph.message import add_messages

class RAGState(TypedDict):
    messages: Annotated[list, add_messages]
    question: str
    documents: list[str]
    retries: int

The grader — a structured-output LLM as judge

The key idea: use the LLM to score retrieval, with a constrained schema so the output is machine-readable.

from pydantic import BaseModel, Field

class Grade(BaseModel):
    relevant: bool = Field(description="Do the docs answer the question?")

grader = llm.with_structured_output(Grade)

def grade_documents(state: RAGState) -> str:
    docs = "\n\n".join(state["documents"])
    verdict = grader.invoke(
        f"Question: {state['question']}\n\nDocs:\n{docs}"
    )
    if verdict.relevant:
        return "generate"
    if state["retries"] >= 2:        # don't loop forever
        return "generate"            # answer with what we have
    return "rewrite"

The nodes

def retrieve(state: RAGState) -> dict:
    docs = retriever.invoke(state["question"])     # vector store
    return {"documents": [d.page_content for d in docs]}

def rewrite_question(state: RAGState) -> dict:
    better = llm.invoke(
        f"Rewrite this to retrieve better results: {state['question']}"
    )
    return {"question": better.content, "retries": state["retries"] + 1}

def generate(state: RAGState) -> dict:
    context = "\n\n".join(state["documents"])
    answer = llm.invoke(
        f"Answer using ONLY this context.\n\n{context}\n\nQ: {state['question']}"
    )
    return {"messages": [answer]}

Wiring the conditional loop

builder = StateGraph(RAGState)
builder.add_node("retrieve", retrieve)
builder.add_node("rewrite", rewrite_question)
builder.add_node("generate", generate)

builder.add_edge(START, "retrieve")
# grade_documents returns "generate" or "rewrite"
builder.add_conditional_edges("retrieve", grade_documents,
    {"generate": "generate", "rewrite": "rewrite"})
builder.add_edge("rewrite", "retrieve")   # the self-correction loop
builder.add_edge("generate", END)

graph = builder.compile()
This is "agentic": the workflow makes decisions about its own process — whether to retrieve, whether the context is good, whether to try again — instead of blindly running a fixed pipeline.

Plain RAG vs Agentic RAG

Aspect Plain RAG Agentic RAG
Retrieval Always, once Only when needed, can repeat
Bad documents Answers anyway → hallucination Detected by grader → rewrite
Vague questions Poor results Rewritten for better recall
Shape Linear chain Graph with loops + branches
Cost Lower per call Higher, but far fewer wrong answers

Best practices

  • Always bound the loop. A retries counter (or recursion_limit) prevents infinite rewrite cycles.
  • Grade with structured output. with_structured_output gives you a real boolean/enum to branch on, not free text you have to parse.
  • Add a hallucination check. A second grader can verify the final answer is actually supported by the documents before returning it (full Self-RAG).
  • Stream the steps. Users tolerate latency better when they see "Searching… → Checking sources… → Writing answer".
  • Cache retrieval. Identical rewritten queries shouldn't hit the vector store twice.
