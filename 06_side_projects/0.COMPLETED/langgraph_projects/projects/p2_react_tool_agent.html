Project 2 · Beginner+

Give the model hands: the ReAct loop

An agent is just an LLM that can call tools and loop until it's done. You'll build the canonical reason → act → observe cycle with bind_tools, ToolNode, and a conditional edge.

What this project does

The model receives a question. If it needs external data (math, search, a database), it emits a tool call instead of a final answer. A ToolNode runs the tool, appends the result to state, and routes back to the model. The model reads the result and either calls another tool or returns the final answer.

The single conditional edge after agent is the entire "agent loop". It keeps cycling until the model stops asking for tools.

The ReAct cycle in words

1
Reason. The LLM looks at the conversation and decides: answer now, or call a tool?
2
Act. If a tool is needed it emits a structured tool_call (name + arguments).
3
Observe. The ToolNode executes it and adds a ToolMessage with the result back into state.
4
Repeat. Control returns to the model, now richer by one observation. Loop until it answers.

The code, annotated

from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from langchain.chat_models import init_chat_model
from langchain_core.tools import tool

# 1) TOOLS — any typed Python function becomes a tool with @tool.
@tool
def multiply(a: int, b: int) -> int:
    """Multiply two integers."""
    return a * b

@tool
def get_weather(city: str) -> str:
    """Return the current weather for a city."""
    return f"It's 27°C and sunny in {city}."

tools = [multiply, get_weather]

# 2) BIND the tool schemas to the model so it knows it can call them.
llm = init_chat_model("openai:gpt-4o-mini")
llm_with_tools = llm.bind_tools(tools)

# 3) THE AGENT NODE — just an LLM call; the model decides to call tools or not.
def agent(state: MessagesState) -> dict:
    return {"messages": [llm_with_tools.invoke(state["messages"])]}

# 4) BUILD: ToolNode runs whatever tools the model asked for.
builder = StateGraph(MessagesState)
builder.add_node("agent", agent)
builder.add_node("tools", ToolNode(tools))

builder.add_edge(START, "agent")
# tools_condition: if last msg has tool_calls -> "tools", else -> END
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")   # observe -> reason again

graph = builder.compile()

graph.invoke({"messages": [{"role": "user",
    "content": "What's 23 * 17, and the weather in Pune?"}]})
Two prebuilts do the heavy lifting. ToolNode reads the model's tool_calls, runs the matching Python functions (in parallel if there are several), and writes the results back. tools_condition is the ready-made router that checks "did the model ask for a tool?".

The shortcut — create_react_agent

Everything above is so common that LangGraph ships it as one function. Use the manual graph to understand; use the prebuilt in real code. 

from langgraph.prebuilt import create_react_agent

agent = create_react_agent(
    model="openai:gpt-4o-mini",
    tools=[multiply, get_weather],
    prompt="You are a concise, helpful assistant.",
)
agent.invoke({"messages": [{"role": "user", "content": "Weather in Pune?"}]})

What the message list looks like mid-loop

# Message type Content
0 HumanMessage "What's 23 * 17, and weather in Pune?"
1 AIMessage tool_calls: multiply(23,17), get_weather("Pune")
2 ToolMessage 391
3 ToolMessage "It's 27°C and sunny in Pune."
4 AIMessage "23 × 17 = 391, and it's 27°C and sunny in Pune."

The add_messages reducer from P1 is what lets every step append cleanly to this list.

Best practices

  • Write great docstrings + type hints. They become the tool schema the model reads. Vague docstrings = wrong tool calls.
  • Make tools defensive. Validate inputs and return a clear error string rather than raising — the model can recover from an error message.
  • Cap the loop. Set a recursion_limit so a confused model can't loop forever: graph.invoke(..., {"recursion_limit": 25}).
  • Keep tools small and single-purpose. Ten focused tools beat one do-everything tool.
Diagnostics tip: stream with stream_mode="updates" to watch each reason/act step, or turn on LangSmith (P4) to see every tool call, its arguments, latency, and token cost.
