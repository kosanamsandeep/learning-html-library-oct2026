🧠 Understand LangGraph from the core

Six projects modeled on the best-in-class patterns from the official langchain-ai/langgraph examples. Each one adds one real superpower: state, tools, memory, human control, self-correction, and multi-agent orchestration.

How to read this series

Every project page follows the same shape so you can move fast: what it does → the graph (Mermaid diagram) → annotated code → key concepts → memory / diagnostics / best practices. Do them in order — each builds on the last.

Why LangGraph and not plain chains? A chain is a straight line that forgets everything between runs. LangGraph models your app as a graph of nodes over shared state, with persistence, loops, branching, and human checkpoints built in. That is what turns "an LLM call" into "an agent".

What you'll be able to explain afterwards

🔁 The core loop

How state flows through nodes, how reducers merge updates, and why edges (not call stacks) control the flow.

🧩 Memory done right

Short-term (thread checkpoints) vs long-term (Store), trimming/summarizing message history, and why thread_id is the unit of a conversation.

🔬 Diagnostics

Streaming modes, LangSmith traces, time-travel debugging, and durable execution so a crash resumes instead of restarting.

🏛️ Architecture

When to use a single ReAct agent vs a supervised multi-agent system, and how subgraphs keep large graphs maintainable.
