Project 1 · Beginner

The smallest graph that already remembers

Build a chatbot as a StateGraph. You'll meet the four ideas every LangGraph app is made of: state, nodes, edges, and reducers.

What this project does

A user sends a message. One node calls the LLM. The reply is appended to a running list of messages held in the graph's state. Because the state persists between turns, the bot "remembers" the conversation without you wiring any memory yourself.

One node. The power isn't the shape — it's that messages is shared, typed state that the reducer keeps appending to.

The four core ideas

1. State

A typed dict that flows through the graph. Here it holds the message list. Every node receives it and returns a partial update.

2. Node

A plain Python function (state) -> partial_state. The chatbot node calls the model and returns new messages.

3. Edge

A wire that says "after this node, go there". START → chatbot → END.

4. Reducer

add_messages decides how a node's update merges into state: append instead of overwrite. This is why history grows.

The code, annotated

from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain.chat_models import init_chat_model

# 1) STATE — a TypedDict. The Annotated[...] attaches a REDUCER to the field.
class State(TypedDict):
    messages: Annotated[list, add_messages]   # append, don't overwrite

llm = init_chat_model("openai:gpt-4o-mini")

# 2) NODE — receives state, returns a PARTIAL update {"messages": [...]}.
def chatbot(state: State) -> dict:
    reply = llm.invoke(state["messages"])
    return {"messages": [reply]}

# 3) BUILD the graph: add node, wire edges.
builder = StateGraph(State)
builder.add_node("chatbot", chatbot)
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

graph = builder.compile()

# 4) RUN it.
result = graph.invoke({"messages": [{"role": "user", "content": "Hi, who are you?"}]})
print(result["messages"][-1].content)
The whole trick: Annotated[list, add_messages]. Without the reducer, returning {"messages": [reply]} would replace the list and the bot would forget. With it, LangGraph appends.

How one turn flows through state

sequenceDiagram
    participant U as You
    participant G as Graph
    participant N as chatbot node
    participant R as add_messages reducer
    U->>G: invoke({messages: [HumanMessage("Hi")]})
    G->>N: state = {messages: [Human("Hi")]}
    N->>N: llm.invoke(messages) -> AIMessage("Hello!")
    N-->>G: return {messages: [AIMessage("Hello!")]}
    G->>R: merge update into state
    R-->>G: messages = [Human("Hi"), AIMessage("Hello!")]
    G-->>U: final state

Streaming — see tokens as they arrive

Real apps stream. LangGraph exposes .stream() with several modes. Use "messages" for token-by-token, "updates" to see each node's output, "values" for the full state after every step. 

for chunk in graph.stream(
    {"messages": [{"role": "user", "content": "Explain LangGraph in one line"}]},
    stream_mode="updates",            # what each node produced
):
    print(chunk)

Best practices from day one

  • Use MessagesState when you can. LangGraph ships a built-in state class that already has messages: Annotated[list, add_messages] — you can subclass it instead of redefining.
  • Nodes return partial updates, never the whole state. Return only the keys you changed; reducers handle the merge.
  • Keep nodes pure and small. One responsibility each — it makes testing and diagnostics trivial later.
  • Compile once, invoke many. builder.compile() returns a reusable runnable.
Mental upgrade: a "chain" hides state in function arguments. A StateGraph makes state a first-class, inspectable object. Everything later in this series — tools, memory, human checkpoints — is just more nodes reading and writing that same state.
