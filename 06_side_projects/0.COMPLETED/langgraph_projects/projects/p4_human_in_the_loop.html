Project 4 · Intermediate

Pause for a human · time-travel · real diagnostics

Agents that take actions (send email, spend money, delete data) need a human gate. You'll use interrupt() to pause mid-graph, resume with Command, rewind with time-travel, and wire LangSmith for production-grade observability.

What this project does

Build an agent that drafts an action, then pauses and waits for a human to approve, edit, or reject before continuing. Because P3 gave us a checkpointer, the graph can stop, persist, and resume hours later from the exact same spot.

Intermediate interrupt() Command(resume=) time travel LangSmith
Prerequisite: human-in-the-loop requires a checkpointer (P3). The pause works by saving a checkpoint and exiting; the resume reloads it.

The code — pause with interrupt()

from langgraph.types import interrupt, Command
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver

def draft_action(state):
    proposal = llm.invoke(state["messages"])
    return {"proposal": proposal.content}

def human_review(state):
    # interrupt() SAVES state and surfaces this payload to the caller, then STOPS.
    decision = interrupt({
        "question": "Approve this action?",
        "proposal": state["proposal"],
    })
    # Execution RESUMES here when you send Command(resume=...).
    return {"decision": decision}

def execute_action(state):
    # ... actually perform the side effect, now that a human approved ...
    return {"status": "done"}

builder = StateGraph(State)
builder.add_node("draft_action", draft_action)
builder.add_node("human_review", human_review)
builder.add_node("execute_action", execute_action)
builder.add_edge(START, "draft_action")
builder.add_edge("draft_action", "human_review")
builder.add_edge("human_review", "execute_action")
builder.add_edge("execute_action", END)

graph = builder.compile(checkpointer=InMemorySaver())

Run → pause → resume

config = {"configurable": {"thread_id": "approval-1"}}

# 1) Start. The graph runs until interrupt(), then RETURNS control.
result = graph.invoke({"messages": [...]}, config)
print(result["__interrupt__"])     # {"question": "Approve...", "proposal": "..."}

# 2) Show it to a human. They approve.
# 3) Resume EXACTLY where it paused by sending the human's answer.
final = graph.invoke(Command(resume="approved"), config)
print(final["status"])           # "done"
Why this is powerful: the pause is durable. The process can exit, the user can approve from a web UI three hours later, and a fresh call with the same thread_id continues from the saved checkpoint — no re-running earlier nodes.

The four human-in-the-loop patterns

Pattern What the human does How
Approve / reject Gate an action interrupt() → resume with yes/no
Edit state Fix the proposal before it runs resume with the edited value
Review tool call Inspect/modify args before a tool fires interrupt before the ToolNode
Provide input Answer a clarifying question interrupt returns the human's text

Time travel — debug by rewinding

Because every step is checkpointed, you can list the history, pick an earlier checkpoint, and re-run from there — optionally after editing the state. This is the single best debugging tool in LangGraph.

# list every checkpoint for this thread
history = list(graph.get_state_history(config))

# pick a point in the past
past = history[3]

# optionally edit state at that point, then fork a new run from it
graph.update_state(past.config, {"proposal": "a corrected draft"})
graph.invoke(None, past.config)   # resume from the edited past checkpoint

Diagnostics & observability — the best-practice layer

🔭 LangSmith tracing

Set two env vars and every node, LLM call, tool call, token count, and latency is recorded in a visual trace.

export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY=ls-...

📡 Streaming modes

updates (per-node output), values (full state), messages (tokens), debug (everything). Mix them: stream_mode=["updates","messages"].

♻️ Durable execution

With a checkpointer, a crashed run resumes from the last completed node instead of restarting — no duplicated side effects.

🚦 Guardrails

Set recursion_limit, wrap tools in try/except, and gate risky actions behind interrupt().

Production mindset: tracing answers "what did the agent actually do and why?", checkpoints answer "can it recover and be inspected?", and interrupts answer "can a human stop it before harm?". Together they make an agent trustworthy.
