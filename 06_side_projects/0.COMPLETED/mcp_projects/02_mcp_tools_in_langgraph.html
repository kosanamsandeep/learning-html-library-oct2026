Build 02 · Beginner+

Plug MCP tools into a LangGraph agent

Use langchain-mcp-adapters to load the tools from build 01's server and hand them to a prebuilt LangGraph ReAct agent — the model now calls your MCP tools autonomously.

What this build does

The adapter library connects to one or more MCP servers, fetches their tools, and converts each into a LangChain BaseTool. LangGraph's create_react_agent then runs the classic reason → act → observe loop over those tools.

The end-to-end flow

    S-->>C: 8
    C-->>A: 8
    A->>LLM: observation = 8
    LLM-->>A: call multiply(8, 12)
    A->>C: invoke "multiply"
    C->>S: MCP call multiply(8,12)
    S-->>A: 96
    A->>LLM: observation = 96
    LLM-->>A: "The answer is 96."
    A-->>U: "The answer is 96."

The agent reasons, calls MCP tools through the client, feeds results back, and repeats until it can answer.

The code — agent over a local stdio server

import asyncio
from langchain_mcp_adapters.client import MultiServerMCPClient
from langgraph.prebuilt import create_react_agent

async def main():
    # 1) Describe the server(s) to connect to. stdio = launch as subprocess.
    client = MultiServerMCPClient({
        "math": {
            "command": "python",
            "args": ["math_server.py"],   # path to build 01's server
            "transport": "stdio",
        },
    })

    # 2) Fetch MCP tools -> LangChain tools.
    tools = await client.get_tools()

    # 3) Build a ReAct agent with those tools.
    agent = create_react_agent("openai:gpt-4o", tools)

    # 4) Run it. The agent decides which MCP tools to call.
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "What is (3 + 5) x 12?"}]}
    )
    print(result["messages"][-1].content)

asyncio.run(main())
That's the whole integration. Nothing in the agent code is math-specific — swap the server and the same agent gains entirely different tools. That is the MCP payoff.

What get_tools() actually returns

Each MCP tool becomes a LangChain StructuredTool whose name, description, and args schema come straight from the server. You can inspect them:

tools = await client.get_tools()
for t in tools:
    print(t.name, "—", t.description)
# add — Add two integers and return the sum.
# multiply — Multiply two integers and return the product.

Because they're ordinary LangChain tools, they work anywhere tools do: bind_tools, custom StateGraph nodes, or ToolNode — not just the prebuilt agent.

Using the tools in a custom StateGraph

If you've done the LangGraph projects, you can drop MCP tools into a hand-built graph instead of the prebuilt agent:

from langgraph.graph import StateGraph, MessagesState, START
from langgraph.prebuilt import ToolNode, tools_condition
from langchain.chat_models import init_chat_model

tools = await client.get_tools()
llm = init_chat_model("openai:gpt-4o").bind_tools(tools)

def call_model(state: MessagesState):
    return {"messages": [llm.invoke(state["messages"])]}

g = StateGraph(MessagesState)
g.add_node("model", call_model)
g.add_node("tools", ToolNode(tools))     # executes MCP tool calls
g.add_edge(START, "model")
g.add_conditional_edges("model", tools_condition)
g.add_edge("tools", "model")
graph = g.compile()

Best practices

  • Fetch tools once, reuse the agent. Call get_tools() at startup, not on every request.
  • Name servers meaningfully in the client dict ("math", "github") — it aids debugging and tracing.
  • Keep the LLM tool-capable. Use a model that supports function/tool calling (gpt-4o, Claude, etc.).
  • Watch the loop with LangSmith to see exactly which MCP tool was chosen and with what arguments.
