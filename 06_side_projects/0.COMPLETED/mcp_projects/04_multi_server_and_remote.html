Many servers, remote transport & public tools

Real agents combine several MCP servers — some you wrote, many you didn't. Connect multiple servers at once, switch to streamable-HTTP, and pull in ready-made public MCP servers (filesystem, GitHub, web search) instead of building everything yourself.

The client merges tools from every server into one flat tool list the agent can pick from.

Switching your server to HTTP transport

stdio is local-only. To share a server (or run it remotely), serve it over streamable HTTP — one line changes.

# math_server.py — now reachable over the network
if __name__ == "__main__":
    mcp.run(transport="http", host="127.0.0.1", port=8000)
    # endpoint: http://127.0.0.1:8000/mcp

Connecting multiple servers (mixed transports)

from langchain_mcp_adapters.client import MultiServerMCPClient
from langgraph.prebuilt import create_react_agent

client = MultiServerMCPClient({
    # a local server you launch as a subprocess
    "math": {
        "command": "python", "args": ["math_server.py"],
        "transport": "stdio",
    },
    # a remote/hosted server reached over HTTP
    "github": {
        "url": "https://api.githubcopilot.com/mcp/",
        "transport": "streamable_http",
        "headers": {"Authorization": f"Bearer {GITHUB_TOKEN}"},
    },
})

tools = await client.get_tools()      # tools from BOTH servers, merged
agent = create_react_agent("openai:gpt-4o", tools)

await agent.ainvoke({"messages": [{"role": "user",
    "content": "Add 2+2, then list my open GitHub issues."}]})
Naming matters at scale. If two servers expose a tool with the same name, the server key ("math", "github") keeps them distinct and makes traces readable.

Using ready-made public MCP servers

You rarely build everything. The ecosystem ships hundreds of servers. Common ones run via npx (Node) or uvx (Python) with zero install: 

client = MultiServerMCPClient({
    # Official filesystem server (Node) — sandboxed to a directory
    "fs": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"],
        "transport": "stdio",
    },
    # A Python server run with uvx (no manual install)
    "fetch": {
        "command": "uvx",
        "args": ["mcp-server-fetch"],
        "transport": "stdio",
    },
})
Where to find servers What it is
Official servers repo modelcontextprotocol/servers — reference + community servers (filesystem, fetch, git, memory, time…).
MCP Registry The official registry/catalog of published servers.
Smithery A popular marketplace to discover and one-click install MCP servers.
FastMCP / vendor docs Many SaaS products (GitHub, Stripe, Notion…) now ship official hosted MCP endpoints.
Trust before you connect. A third-party MCP server can run code and read data. Only connect to servers you trust, prefer official ones, scope filesystem servers to a single directory, and review the tools it exposes in the Inspector first.

Best practices

  • Mix transports freely — stdio for local, streamable-HTTP for remote, in one client.
  • Prefer official/registry servers and pin versions for reproducibility.
  • Limit the blast radius: sandbox filesystem servers, use read-only tokens, and only enable the servers a given agent actually needs.
  • Cap the tool count. Dozens of tools hurt accuracy — connect only relevant servers per agent.
