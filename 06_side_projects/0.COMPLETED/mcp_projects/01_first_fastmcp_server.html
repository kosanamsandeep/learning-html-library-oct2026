Your first MCP server with FastMCP

Expose two Python functions as MCP tools, run the server over stdio, and inspect it. This server is what every later build connects to.

What this build does

FastMCP turns a decorated Python function into an MCP tool — it auto-generates the JSON schema from your type hints and docstring, so an LLM client knows exactly how to call it.

Beginner FastMCP @mcp.tool stdio transport

Anatomy of an MCP server

flowchart TD

Decorate → schema is generated → server runs → any client can discover and call the tool.

The code — math_server.py

from fastmcp import FastMCP

# 1) Create the server. The name shows up in clients.
mcp = FastMCP("Math Server")

# 2) A tool = a decorated function. Type hints + docstring become the schema.
@mcp.tool
def add(a: int, b: int) -> int:
    """Add two integers and return the sum."""
    return a + b

@mcp.tool
def multiply(a: int, b: int) -> int:
    """Multiply two integers and return the product."""
    return a * b

# 3) Run it. Default transport is stdio (great for local dev).
if __name__ == "__main__":
    mcp.run()

Run it:

python math_server.py
The docstring is the contract. The model only sees the tool's name, type signature, and docstring. Write them as if documenting an API — clear names and a one-line description dramatically improve tool selection.

Inspect it before wiring an agent

The MCP Inspector is a browser UI to list a server's tools and call them by hand — your first debugging step.

# Launch the Inspector against your server
npx @modelcontextprotocol/inspector python math_server.py

# or with the FastMCP CLI
fastmcp dev math_server.py

You'll see add and multiply with their schemas, and can invoke them with test arguments.

Transports — stdio vs HTTP

Transport How Use when
stdio mcp.run() (default) Local: the client launches the server as a subprocess. Simplest.
streamable-http mcp.run(transport="http", port=8000) Remote/shared: the server runs as a web service. (Build 04.)

Quick test from a Python client

FastMCP also ships a client, so you can call the server programmatically without an LLM:

import asyncio
from fastmcp import Client

async def main():
    async with Client("math_server.py") as client:
        tools = await client.list_tools()
        print([t.name for t in tools])          # ['add', 'multiply']
        result = await client.call_tool("add", {"a": 2, "b": 3})
        print(result.data)                       # 5

asyncio.run(main())

Best practices

  • One capability per tool. Small, focused tools are easier for the model to pick correctly.
  • Always type-hint and docstring. They are the schema.
  • Return JSON-serialisable values (numbers, strings, dicts) so any client can consume them.
  • Start on stdio for local development; switch to HTTP only when you need a shared/remote server.
