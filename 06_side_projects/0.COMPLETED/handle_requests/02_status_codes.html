Chapter 02 · Reference

HTTP status codes 1xx → 5xx (with a memory trick)

There are ~60 official codes. You'll really only see ~15. Learn the family rule first, then the famous codes.

👉 Want runnable code? See Implement 1xx → 5xx in FastAPI for copy-pasteable handlers.

The memory trick — "HSRCS" or just the moods

Family Mnemonic word "Mood" of the server One-line meaning
1xx Hold on 🙂 "still thinking" Informational, the real response is coming.
2xx Success 😀 "did it!" Everything worked.
3xx Redirect 👉 "look over there" You need to go somewhere else to get it.
4xx Client error 😤 "you messed up" Your request is wrong (bad input, no auth, wrong URL).
5xx Server error 🔥 "I messed up" The server crashed or can't fulfill a valid request.
Single sentence: "1 hold, 2 success, 3 redirect, 4 your fault, 5 my fault."

1xx · Informational (you'll almost never see these)

Code Name What it really means
100 Continue "I got your headers, send me the body."
101 Switching Protocols "OK, upgrading to WebSocket / HTTP/2."
103 Early Hints "Here are some links you can preload while I finish."

2xx · Success (the happy ones)

Code Name Use when…
200 OK Generic success with a body.
201 Created POST that created a new resource. Return its URL in Location.
202 Accepted "I got it, I'll process later." (async jobs)
204 No Content Success but nothing to return (e.g., DELETE).
206 Partial Content Range request — video seek, resumable downloads.

3xx · Redirect (look elsewhere)

Code Name What it really means
301 Moved Permanently Update your bookmarks. SEO-relevant.
302 Found Temporarily over there. Most common redirect.
304 Not Modified Cache is still fresh — don't re-download.
307 Temporary Redirect Like 302 but the verb (POST) is preserved.
308 Permanent Redirect Like 301 but the verb is preserved.
301 vs 308: 301 may silently change POST → GET (legacy browsers). 308 keeps the method. For APIs, use 308.

4xx · Client error ("you")

Code Name When you'll see it
400 Bad Request Malformed JSON, missing fields, garbage input.
401 Unauthorized "I don't know who you are." → log in / send a token.
403 Forbidden "I know who you are, but you're not allowed."
404 Not Found The URL/resource doesn't exist.
405 Method Not Allowed Right URL, wrong verb (POSTed to a GET-only route).
408 Request Timeout You took too long to send the request.
409 Conflict Version conflict, duplicate insert, race condition.
410 Gone Was here, now permanently removed.
413 Payload Too Large Your upload exceeds the server's limit.
415 Unsupported Media Type Wrong Content-Type.
418 I'm a teapot The famous joke RFC. Real APIs sometimes use it for abuse.
422 Unprocessable Entity JSON parsed fine, but values are semantically wrong. (FastAPI default for validation errors.)
429 Too Many Requests Rate limited. Honor Retry-After header.
401 vs 403 trick: 401 = "auth missing/invalid". 403 = "auth fine, permission denied".

5xx · Server error ("me")

Code Name When you'll see it
500 Internal Server Error Uncaught exception. The catch-all "something broke".
501 Not Implemented Method/feature isn't built yet.
502 Bad Gateway Upstream server (behind the load balancer) returned junk.
503 Service Unavailable Server overloaded or in maintenance.
504 Gateway Timeout Upstream took too long. Often a DB or 3rd-party API.
507 Insufficient Storage WebDAV / S3-style "out of space".
5xx debugging order: 500 → check app logs. 502/504 → check the upstream service. 503 → check load and the maintenance flag. 4xx never wakes you up at 3am, 5xx does.

Decision flow when you see a non-2xx

flowchart TD
    A[Got a status code] --> B{1xx?}
    B -- yes --> B1[Ignore — wait for the real response]
    B -- no --> C{2xx?}
    C -- yes --> C1[✅ Parse body and continue]
    C -- no --> D{3xx?}
    D -- yes --> D1[Follow Location header
requests does this for you]
    D -- no --> E{4xx?}
    E -- yes --> E1[Fix YOUR request
auth, validation, URL]
    E -- no --> F{5xx?}
    F -- yes --> F1[Retry with backoff
then page on-call]

How to handle them in requests

r = requests.get(url, timeout=5)

if r.status_code == 429:
    wait = int(r.headers.get("Retry-After", "5"))
    time.sleep(wait)
    return retry()

# Easiest pattern: raise on 4xx/5xx
try:
    r.raise_for_status()      # raises HTTPError
except requests.HTTPError as e:
    log.error("upstream failed %s %s", r.status_code, r.text)
    raise
