Parallel essentials you must learn when sending requests

Knowing GET/POST is 20% of the job. The other 80% lives in headers, timeouts, retries, TLS, content negotiation, and observability. This page is the things you'll wish you knew before your first outage.

Every box is a place a request can fail, timeout, get rate-limited, or be rewritten. Every concept below is "how to behave well at one of those boxes".

1. Headers you'll keep meeting

Header Direction What it does
Content-Type both "How to parse the body" (e.g. application/json).
Accept request "What I want back" (e.g. application/json).
Authorization request Credentials (Bearer, Basic, etc.). See ch. 06.
User-Agent request Who's calling (some servers block defaults).
Accept-Encoding request Compression you accept (gzip, br).
Content-Encoding response Compression actually used.
Cache-Control both How / how long this can be cached.
ETag / If-None-Match both Conditional GET — server replies 304 if unchanged.
Retry-After response How long to wait (used with 429 / 503).
X-Request-Id / traceparent both Correlation IDs for tracing across services.
Location response Where to go on a 3xx redirect or after a 201 Created.

2. Timeouts — the single most ignored production rule

Dangerous default

requests.get(url)
# No timeout. If the server hangs,
# your worker hangs forever.

Safe

requests.get(url, timeout=(3, 10))
# (connect=3s, read=10s)
# Raises requests.Timeout on breach.

Timeout budget tip: per-call timeout < per-request budget < user-visible deadline. A request that takes 5 services × 30s timeout = a hung user.

3. Retries and backoff — and the idempotency rule

Only retry idempotent verbs by default (GET, PUT, DELETE, HEAD, OPTIONS). Retrying a POST without a unique key risks creating duplicates. 
from requests.adapters import HTTPAdapter, Retry

retry = Retry(
    total=3,
    backoff_factor=0.5,                # 0.5, 1, 2 seconds
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["GET", "PUT", "DELETE"],  # NOT POST
    respect_retry_after_header=True,
)

s = requests.Session()
s.mount("https://", HTTPAdapter(max_retries=retry))
s.get("https://api.com/users/42", timeout=5)

For non-idempotent POSTs, send an Idempotency-Key header — server uses it to deduplicate retried calls.

4. Connection pools (Sessions, keep-alive)

HTTP/1.1 supports keep-alive — reuse the same TCP+TLS connection for many requests. A requests.Session() uses a pool of up to 10 connections per host by default. Without it, you pay the handshake cost on every call.

5. TLS — what https:// actually buys you

  • Encryption: ISPs can't read your traffic.
  • Server authentication: you're really talking to api.com (cert chain verified against the CA store).
  • Integrity: the bytes weren't tampered with in transit.

verify=False disables the cert check. Never use in production — it silently makes you vulnerable to man-in-the-middle.

6. Redirects, content negotiation, compression

  • Redirects: requests follows 3xx automatically. Inspect r.history to see the chain. Set allow_redirects=False if you don't want it (e.g., to test that login returns a 302).
  • Content negotiation: client sends Accept: application/json; server picks the best representation. The same URL can return JSON, XML, or HTML.
  • Compression: servers gzip the body. requests auto-decompresses when you read r.text or r.json().

7. Streaming large responses

Eats RAM

r = requests.get(big_url)
open("f.bin","wb").write(r.content)
# Whole file in memory.

Streaming

with requests.get(big_url, stream=True, timeout=30) as r:
    with open("f.bin","wb") as f:
        for chunk in r.iter_content(1024 * 64):
            f.write(chunk)

8. Rate limiting + the Retry-After header

Servers signal "you are too fast" with 429 Too Many Requests and a Retry-After header (seconds, or HTTP date). Always honor it; otherwise you trigger temp bans.

9. CORS — only matters from browsers

Browsers refuse cross-origin requests unless the server returns Access-Control-Allow-Origin. CORS is a browser security feature, not a server one. curl and requests ignore it entirely — that's why "it works in curl but not in JS".

10. Observability — the three things to log on every call

  1. Correlation ID (X-Request-Id or traceparent) — propagate it across every hop.
  2. Latency (r.elapsed) — alert when p95 spikes.
  3. Status code + URL (template, not the full path with IDs).
log.info("upstream call",
         method="GET", url="/users/:id",
         status=r.status_code,
         ms=r.elapsed.total_seconds() * 1000,
         request_id=r.headers.get("X-Request-Id"))

The production-ready snippet

from requests import Session
from requests.adapters import HTTPAdapter, Retry

def make_session() -> Session:
    s = Session()
    s.headers.update({
        "User-Agent": "myservice/1.4 (+ops@my.co)",
        "Accept": "application/json",
    })
    retry = Retry(
        total=3,
        backoff_factor=0.5,
        status_forcelist=[429, 500, 502, 503, 504],
        allowed_methods=["GET", "PUT", "DELETE"],
        respect_retry_after_header=True,
    )
    s.mount("https://", HTTPAdapter(max_retries=retry, pool_connections=20, pool_maxsize=20))
    return s

session = make_session()

def fetch_user(uid: int) -> dict:
    r = session.get(f"https://api.com/users/{uid}", timeout=(3, 10))
    r.raise_for_status()
    return r.json()
