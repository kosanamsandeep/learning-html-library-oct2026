Chapter 03 · 3xx Redirects

3xx — "go look over there instead"

The subtle part of redirects is whether the method and body are preserved. 301/302 historically let clients switch POST→GET; 307/308 guarantee they don't. Pick deliberately.

The redirect cheat-sheet

Code Permanent? Method preserved? Use for
301 Moved Permanently Yes Often changed to GET URL changed forever (SEO)
302 Found No Often changed to GET Temporary move
303 See Other No Forces GET Post/Redirect/Get after a form POST
304 Not Modified — — Cache validation (ETag / If-None-Match)
307 Temporary Redirect No Yes (POST stays POST) Temp move, keep method+body
308 Permanent Redirect Yes Yes Permanent move, keep method+body
Gotcha: RedirectResponse defaults to 307 in Starlette/FastAPI — method-preserving. If you want a browser POST to become a GET (the usual form pattern), explicitly use 303.

Basic redirect — RedirectResponse

from fastapi import FastAPI, status
from fastapi.responses import RedirectResponse

app = FastAPI()

# 308 — permanent, method-preserving (old API path -> new one)
@app.get("/v1/users")
def moved():
    return RedirectResponse("/v2/users", status_code=status.HTTP_308_PERMANENT_REDIRECT)

# 302 — temporary
@app.get("/lucky")
def lucky():
    return RedirectResponse("https://example.com", status_code=status.HTTP_302_FOUND)

303 See Other — the Post/Redirect/Get pattern

After a successful form POST, redirect to a GET page so a browser refresh doesn't resubmit the form. 303 guarantees the follow-up is a GET.

from fastapi import FastAPI, Form, status
from fastapi.responses import RedirectResponse

app = FastAPI()

@app.post("/submit")
def submit(name: str = Form(...)):
    # ...save the form...
    # Redirect to a GET result page; refresh won't re-POST.
    return RedirectResponse(f"/thanks?name={name}",
                            status_code=status.HTTP_303_SEE_OTHER)

@app.get("/thanks")
def thanks(name: str):
    return {"message": f"Thanks, {name}!"}

307 vs 308 — when the body must survive

If you redirect a POST /pay and you need it to stay a POST with its JSON body, use 307 (temporary) or 308 (permanent). 301/302 may silently turn it into a GET and drop the body.

from fastapi import FastAPI, Request, status
from fastapi.responses import RedirectResponse

app = FastAPI()

@app.post("/pay")
async def pay_old(request: Request):
    # Forward to the new endpoint, preserving POST + body.
    return RedirectResponse("/v2/pay", status_code=status.HTTP_307_TEMPORARY_REDIRECT)

@app.post("/v2/pay")
async def pay_new(request: Request):
    body = await request.json()
    return {"charged": body}

304 Not Modified — conditional GET with ETag

304 saves bandwidth: if the client's cached copy still matches your ETag, return 304 with no body and the client reuses its cache.

from fastapi import FastAPI, Request, Response, status
import hashlib

app = FastAPI()

def current_data() -> dict:
    return {"id": 1, "name": "widget", "version": 7}

@app.get("/items/1")
def get_item(request: Request):
    data = current_data()
    etag = hashlib.md5(str(data).encode()).hexdigest()

    # If the client already has this version, tell it to use its cache.
    if request.headers.get("if-none-match") == etag:
        return Response(status_code=status.HTTP_304_NOT_MODIFIED,
                        headers={"ETag": etag})

    return Response(
        content=str(data),
        media_type="application/json",
        headers={"ETag": etag, "Cache-Control": "no-cache"},
    )
# First call returns 200 + ETag; second call sends it back and gets 304:
curl -i http://127.0.0.1:8000/items/1
curl -i -H 'If-None-Match: <etag-from-above>' http://127.0.0.1:8000/items/1
# => HTTP/1.1 304 Not Modified
304 has no body. Like 204, it must be empty — only headers (especially the matching ETag) travel back.

Summary

  • Default RedirectResponse = 307. Be explicit.
  • Form POST → result page: 303 (forces GET).
  • Keep method + body: 307 / 308.
  • Permanent move (SEO): 301 / 308.
  • Caching: 304 with ETag / If-None-Match.
