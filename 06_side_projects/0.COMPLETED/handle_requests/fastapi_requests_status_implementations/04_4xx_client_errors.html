Chapter 04 · 4xx Client errors

4xx — "your request is the problem"

This is where raise HTTPException earns its keep. Each 4xx is a precise message to the caller about what they did wrong — wrong input, no auth, no permission, gone, conflict, too fast.

The 4xx you'll raise most

Code Meaning Trigger in your code
400 Bad Request Malformed / semantically wrong input raise HTTPException(400, ...)
401 Unauthorized Not authenticated (who are you?) + WWW-Authenticate header
403 Forbidden Authenticated but not allowed raise HTTPException(403, ...)
404 Not Found Resource doesn't exist raise HTTPException(404, ...)
405 Method Not Allowed Wrong verb for the route Mostly automatic + Allow header
409 Conflict Clashes with current state (dup, version) raise HTTPException(409, ...)
422 Unprocessable Entity Validation failed Automatic via Pydantic
429 Too Many Requests Rate limit hit + Retry-After header

400 / 404 / 409 — the everyday raises

from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    id: int
    name: str

DB: dict[int, Item] = {}

@app.post("/items")
def create(item: Item):
    if item.name.strip() == "":
        # 400 — the value passed type validation but is semantically invalid
        raise HTTPException(status.HTTP_400_BAD_REQUEST, "name cannot be blank")
    if item.id in DB:
        # 409 — conflicts with existing state
        raise HTTPException(status.HTTP_409_CONFLICT, "item id already exists")
    DB[item.id] = item
    return item

@app.get("/items/{item_id}")
def read(item_id: int):
    item = DB.get(item_id)
    if item is None:
        # 404 — not there
        raise HTTPException(status.HTTP_404_NOT_FOUND, "item not found")
    return item
400 vs 422: use 422 (automatic) when the input fails type/schema validation; raise 400 when input is well-formed but breaks a business rule.

401 Unauthorized — must include WWW-Authenticate

Per spec, a 401 should tell the client how to authenticate via the WWW-Authenticate header. FastAPI lets you pass headers on the exception. 

from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()
oauth2 = OAuth2PasswordBearer(tokenUrl="token")

def current_user(token: str = Depends(oauth2)):
    user = verify(token)          # returns None if bad/expired
    if user is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="invalid or expired token",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return user

@app.get("/me")
def me(user=Depends(current_user)):
    return user
401 vs 403: 401 = "I don't know who you are" (authenticate first). 403 = "I know who you are, and you still can't do this."

403 Forbidden — authenticated but not allowed

from fastapi import FastAPI, Depends, HTTPException, status

app = FastAPI()

@app.delete("/admin/items/{item_id}")
def admin_delete(item_id: int, user=Depends(current_user)):
    if not user.is_admin:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "admin role required")
    # ...delete...
    return {"deleted": item_id}

405 Method Not Allowed — mostly free

If a path exists but not for that verb, FastAPI returns 405 automatically with the correct Allow header. You usually don't write code for it — just define the verbs you support. 

from fastapi import FastAPI

app = FastAPI()

@app.get("/items")     # only GET is defined
def list_items():
    return []

# A POST /items now auto-returns:
#   405 Method Not Allowed
#   Allow: GET

422 Unprocessable Entity — validation, automatic

This is FastAPI's superpower: Pydantic validates the request and returns a detailed 422 before your code runs. You can also customize the error shape. 

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Signup(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    age: int = Field(ge=18)

@app.post("/signup")
def signup(body: Signup):
    return {"ok": True}

# POST {"username": "ab", "age": 10}  ->  422 with a precise error list,
# e.g. "username: string too short", "age: input should be >= 18"
# Optional: reshape the default 422 body
from fastapi import Request, status
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

@app.exception_handler(RequestValidationError)
async def validation_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
        content={"error": "validation_failed", "fields": exc.errors()},
    )

429 Too Many Requests — with Retry-After

When a caller exceeds a rate limit, return 429 and tell them when to come back via Retry-After (seconds). 

from fastapi import FastAPI, Request, HTTPException, status
import time

app = FastAPI()
HITS: dict[str, list[float]] = {}
LIMIT, WINDOW = 5, 60   # 5 requests per 60s

@app.get("/search")
def search(request: Request):
    ip = request.client.host
    now = time.time()
    hits = [t for t in HITS.get(ip, []) if now - t < WINDOW]
    if len(hits) >= LIMIT:
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="rate limit exceeded",
            headers={"Retry-After": str(WINDOW)},
        )
    hits.append(now)
    HITS[ip] = hits
    return {"results": []}
In production use a battle-tested limiter like slowapi backed by Redis so limits hold across multiple workers — the in-memory version above is for learning.

Bonus: one consistent error shape for all 4xx

Override the default HTTPException handler so every error returns the same JSON envelope — easier for clients to parse.

from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import JSONResponse

app = FastAPI()

@app.exception_handler(HTTPException)
async def http_exc_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"error": {"code": exc.status_code, "message": exc.detail}},
        headers=exc.headers,
    )
