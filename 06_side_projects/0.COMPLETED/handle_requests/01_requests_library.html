Chapter 01 · The foundation

How the requests library actually works

When you call requests.get("https://api.com/users"), a lot more happens than "fetch a URL". This page shows the full life of one request — DNS, TCP, TLS, HTTP — and then catalogs every verb, every payload type, and the things you'll keep typing for the next ten years.

Life of a request HTTP verbs Payloads Response object Sessions Cheat sheet

1. What happens when you call requests.get(url)

sequenceDiagram
    participant U as Your code
    participant R as requests (urllib3)
    participant DNS
    participant TCP as Socket
    participant TLS
    participant S as Server

    U->>R: requests.get("https://api.com/users", headers=..., timeout=5)
    R->>R: Build Request object (method, url, headers, body)
    R->>DNS: Resolve api.com -> 203.0.113.4
    DNS-->>R: IP
    R->>TCP: Open TCP connection to 203.0.113.4:443
    TCP-->>R: Connected
    R->>TLS: TLS handshake (verify cert)
    TLS-->>R: Encrypted channel
    R->>S: GET /users HTTP/1.1
Host: api.com
Headers...
    S-->>R: HTTP/1.1 200 OK
Headers + body
    R->>R: Wrap into Response object
    R-->>U: response

requests is a friendly wrapper around urllib3, which is a wrapper around Python sockets + ssl. You write one line; eight subsystems run.

Mental model: a request is just 4 things — a method, a URL, some headers, and an optional body. A response is 3 things — a status code, headers, and an optional body. Everything else is a detail.

2. The HTTP verbs (methods)

A verb tells the server what you want to do. The URL says which resource.

Verb Intent Has body? Idempotent? Safe? Cached? Typical use
GET Read a resource No (avoid) Yes Yes Yes GET /users/42
POST Create / generic action Yes No No Rarely POST /users (new user)
PUT Replace a resource entirely Yes Yes No No PUT /users/42 (full overwrite)
PATCH Modify part of a resource Yes Often No No PATCH /users/42 (change email only)
DELETE Remove a resource Optional Yes No No DELETE /users/42
HEAD Like GET, but no body No Yes Yes Yes Check if file exists / Content-Length
OPTIONS Ask what the server supports No Yes Yes No CORS preflight

Safe

"Safe" = the call does not change state on the server. GET, HEAD, OPTIONS.

Idempotent

"Idempotent" = calling it 1 time or 10 times gives the same final state. POST is the only common non-idempotent verb. That's why retries are dangerous for POST.

In requests

import requests

requests.get("https://api.com/users/42")
requests.post("https://api.com/users", json={"name": "Aria"})
requests.put("https://api.com/users/42", json={"name": "Aria", "age": 30})
requests.patch("https://api.com/users/42", json={"age": 31})
requests.delete("https://api.com/users/42")
requests.head("https://api.com/files/report.pdf")
requests.options("https://api.com/users")

# Or generic:
requests.request("POST", "https://api.com/users", json={...})

3. What is a "payload" and what types exist

The payload (a.k.a. request body) is the data you send with the request. The server has to know how to read it — that's the job of the Content-Type header.

Payload type Content-Type When to use requests argument
JSON application/json APIs, microservices, JS frontends. The default in 2026. json={"k": "v"}
URL-encoded form application/x-www-form-urlencoded Classic HTML form submission, OAuth token endpoints. data={"k": "v"}
Multipart form multipart/form-data File uploads + extra fields. files={"f": open(...)}
Raw bytes / text application/octet-stream, text/plain, etc. Uploading a single file as the whole body, streaming binary. data=b"...bytes..."
Query string n/a (lives in the URL) GET filters, pagination, search params. params={"page": 2}
XML / SOAP application/xml, text/xml Legacy enterprise / banking / SOAP APIs. data=xml_string, headers={"Content-Type": "application/xml"}
Protobuf / binary application/x-protobuf High-perf services. (gRPC handles this for you — see ch. 03.) data=msg.SerializeToString()

Side-by-side: the same "create user" three ways

JSON (modern API)

requests.post(
    "https://api.com/users",
    json={"name": "Aria", "age": 30},
    timeout=5,
)
# Sets Content-Type: application/json
# Body: {"name":"Aria","age":30}

URL-encoded form

requests.post(
    "https://api.com/users",
    data={"name": "Aria", "age": 30},
    timeout=5,
)
# Sets Content-Type: application/x-www-form-urlencoded
# Body: name=Aria&age=30

Multipart (with a file)

requests.post(
    "https://api.com/users",
    data={"name": "Aria"},
    files={"avatar": open("a.png", "rb")},
    timeout=5,
)
# Sets Content-Type: multipart/form-data; boundary=...
# Body: a multipart envelope with each field as a part

Query string (GET filter)

requests.get(
    "https://api.com/users",
    params={"role": "admin", "page": 2},
    timeout=5,
)
# Final URL:
# https://api.com/users?role=admin&page=2
Gotcha: data= with a dict means form-encoded. data= with a string means raw body. json= serializes a dict to JSON and sets the right header. Pick one — never mix data= and json= in the same call.

4. The Response object

r = requests.get("https://api.com/users/42", timeout=5)

r.status_code      # 200
r.ok               # True if 200 <= status < 400
r.headers          # CaseInsensitiveDict
r.headers["Content-Type"]

r.text             # str (decoded using r.encoding)
r.content          # raw bytes
r.json()           # parsed dict/list (raises if body is not JSON)

r.url              # final URL after redirects
r.history          # list of intermediate Response objects (redirects)
r.elapsed          # timedelta of the round-trip

r.raise_for_status()   # raises HTTPError on 4xx/5xx — use this!
Rule of thumb: always call r.raise_for_status() in production code. Otherwise a 500 silently flows through your pipeline as r.text == "Internal error".

5. Sessions — reuse connections, cookies, and defaults

Every requests.get(...) opens and tears down a fresh TCP+TLS connection. That's slow. A Session reuses the connection (HTTP keep-alive) and persists cookies + headers.

Without session — wasteful

for uid in user_ids:
    r = requests.get(f"{API}/users/{uid}",
                     headers={"Authorization": f"Bearer {tok}"})
    # New TCP + TLS handshake every iteration

With session — fast + clean

with requests.Session() as s:
    s.headers.update({"Authorization": f"Bearer {tok}"})
    for uid in user_ids:
        r = s.get(f"{API}/users/{uid}")
        # Same TCP + TLS connection reused

Bonus: a Session also stores cookies the server sets, so subsequent calls behave like a real "logged-in" browser. (See ch. 06.)

6. The 10-line cheat sheet you will copy forever

import requests

r = requests.get(
    "https://api.com/users",
    params={"page": 2},               # ?page=2
    headers={"Authorization": "Bearer ..."},
    timeout=(3, 10),                  # (connect, read) seconds — ALWAYS set
)
r.raise_for_status()
data = r.json()
Production rule #1: timeout= is not optional. The default is no timeout, meaning your worker can hang forever waiting for a dead server.
