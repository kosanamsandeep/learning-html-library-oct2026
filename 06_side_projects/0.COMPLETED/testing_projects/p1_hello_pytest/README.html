Project 1 · Beginner

Hello pytest — the smallest possible first test

Forget testing for a moment. This project teaches you the muscle memory: write a function, write a test, run pytest, read the green dot. Once that loop feels natural, everything else in this track will click.

The story

You join a team on your first day. Someone hands you a four-function calculator and says, "make sure this still works tomorrow." You could click around in a REPL forever, or you could write five tiny tests and run them every time the code changes. That is the entire idea of automated testing.

This project gives you a four-function calculator and five tests. Run them once and you will see the green output that engineers feel slightly addicted to.

Files in this project

You do not register tests anywhere. The naming convention is the contract.

Core code — the calculator

def add(a, b):       return a + b
def subtract(a, b):  return a - b
def multiply(a, b):  return a * b

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("cannot divide by zero")
    return a / b

Notice that divide explicitly raises on bad input. Raising clear errors is more testable than returning special values like None or -1.

Core code — the tests, in AAA shape

def test_add_two_positive_numbers():
    # Arrange
    a, b = 2, 3
    # Act
    result = add(a, b)
    # Assert
    assert result == 5

def test_divide_by_zero_raises():
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)

Two ideas matter here:

  • Plain assert. Pytest rewrites it under the hood so the failure message shows real values like assert 4 == 5.
  • pytest.raises. The cleanest way to assert "this should explode." If no exception is raised, the test fails.

What "green" and "red" look like

Green (all passing)

===== 5 passed in 0.04s =====

You can refactor with confidence.

Red (something broke)

FAILED test_calculator.py::test_add_two_positive_numbers
>       assert result == 5
E       assert 6 == 5

You instantly know which line and which value is wrong.

How to run it

cd 06_side_projects/testing_projects/p1_hello_pytest
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

pytest -v
# Optional:
pytest -v -k divide       # run only tests with "divide" in the name
pytest -x                 # stop at the first failure
pytest -s                 # show print() output

Try to break it (the best way to learn)

  1. Open calculator.py and change return a + b to return a + b + 1.
  2. Run pytest again. Watch the failure message point right at the lie.
  3. Fix it and watch the green output return. That feedback loop is the whole game.

What you should take away from P1

  • A test is just a function that asserts a fact about your code.
  • Pytest discovers tests by filename and function name. No registration code.
  • The AAA shape (Arrange, Act, Assert) keeps tests readable forever.
  • Errors should be raised, not hidden. They are easier to test.
Interview-ready answer: "pytest is the modern Python testing framework. It auto-discovers any test_*.py file, lets me write plain assert statements, and prints rich failure messages. I structure each test as Arrange, Act, Assert, so the intent is clear to anyone reading it."

Reading order

  1. Open calculator.py and read the four functions.
  2. Open test_calculator.py and read each test.
  3. Run pytest -v in this folder.
  4. Break a function on purpose and rerun to see the failure output.
  5. Go to P2 · Fixtures and parametrize.
