🔍 Code Review Copilot

A copilot that watches your pull requests, summarises the change, flags likely bugs and risks, and leaves inline suggestions — before a human reviewer even opens the tab.

The story — why this copilot exists

Code review is essential but slow. PRs wait hours or days for a busy senior. Reviewers burn time on the boring 80% — style, missing tests, obvious null-checks — leaving less energy for the architectural 20% that actually needs a human.

A review copilot handles the first pass automatically: it posts a clear summary and concrete suggestions seconds after a PR opens, so humans review faster and focus on what matters.

Inspired by: qodo-ai/pr-agent (formerly CodiumAI PR-Agent), sweepai/sweep, and CodeRabbit — among the most-starred automated-review tools.

The flow — from "PR opened" to inline comments

    participant GH as GitHub

    GH->>A: webhook "pull_request opened"
    A->>GH: fetch diff + changed files
    A->>A: split large diffs into chunks
    A->>LLM: diff + review rubric

    A->>GH: post PR summary comment
    A->>GH: post inline suggestions on lines
    Note over GH: Human reviews faster, focuses on design

The copilot runs as CI: triggered by the PR event, it reasons over the diff and writes structured feedback back to GitHub.

The code — fetch the diff and review it

import os, json
from github import Github
from openai import OpenAI

gh = Github(os.environ["GITHUB_TOKEN"])
client = OpenAI()

def review_pr(repo_name: str, pr_number: int):
    pr = gh.get_repo(repo_name).get_pull(pr_number)

    # Collect the patch (diff) for each changed file.
    diff = "\n".join(
        f"### {f.filename}\n{f.patch}"
        for f in pr.get_files() if f.patch
    )

    rubric = (
        "You are a senior code reviewer. Review the diff for: bugs, security "
        "issues, missing tests, and readability. Return JSON with keys "
        "'summary' (str) and 'comments' (list of {file, line, suggestion})."
    )
    resp = client.chat.completions.create(
        model="gpt-4o",
        response_format={"type": "json_object"},
        messages=[
            {"role": "system", "content": rubric},
            {"role": "user", "content": diff},
        ],
    )
    return json.loads(resp.choices[0].message.content), pr

The code — post the feedback back

def post_review(repo_name: str, pr_number: int):
    review, pr = review_pr(repo_name, pr_number)

    # 1) Overall summary as a normal PR comment.
    pr.create_issue_comment(f"## 🤖 Copilot review\n\n{review['summary']}")

    # 2) Inline suggestions on specific lines.
    commit = pr.get_commits().reversed[0]
    for c in review["comments"]:
        pr.create_review_comment(
            body=f"💡 {c['suggestion']}",
            commit=commit, path=c["file"], line=c["line"],
        )
Structured output is the trick. Forcing JSON (response_format) lets you map each suggestion onto an exact file + line, turning prose into actionable inline comments.

Ship it as a GitHub Action

# .github/workflows/ai-review.yml
name: AI Review
on:
  pull_request:
    types: [opened, synchronize]
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install pygithub openai
      - run: python review.py
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}

Now every PR gets an automatic first-pass review — zero human effort.

Advantages this copilot brings

Advantage Why it matters
Faster cycle time Feedback in seconds, not the next business day.
Consistency The same rubric is applied to every PR, every time.
Frees seniors Humans skip the boring 80% and focus on design.
Catches the obvious Null-checks, missing tests, leaked secrets, smells.
Onboarding aid Juniors learn from concrete, in-context suggestions.

Best practices & guardrails

  • Chunk large diffs and review per-file to stay within context limits.
  • The copilot suggests, humans merge. Never let it approve or auto-merge — it's a reviewer, not the gate.
  • Tune the rubric to your standards (style guide, security policy) for signal over noise.
  • Skip generated/vendored files to avoid useless comments and wasted tokens.
  • Never echo secrets found in diffs into public comments — redact.
