🤖 Multi-Agent Builder Copilot

The capstone: instead of one assistant, a team of specialised copilots — a planner, a coder, and a tester — that take a feature request, write the code, run the tests, fix failures, and open a pull request. A human approves the plan and the final merge.

The story — why this copilot exists

The earlier copilots each do one job. But real software work is multi-step: understand the request, plan, write code across files, run tests, read failures, fix, repeat. No single prompt does this reliably.

A builder copilot splits the work across specialised agents that critique each other and loop until the tests pass — the same structure behind the most ambitious autonomous-coding projects. It's where everything in this folder (RAG, tools, HITL, agents) comes together.

Inspired by: All-Hands-AI/OpenHands (OpenDevin), gpt-engineer-org/gpt-engineer, geekan/MetaGPT, and Aider-AI/aider — top-starred autonomous software engineers.

A plan-then-build-then-verify loop with two human gates: approve the plan, and own the merge.

The tools the team shares

from langchain_core.tools import tool
import subprocess, pathlib

@tool
def read_file(path: str) -> str:
    """Read a file from the repo."""
    return pathlib.Path(path).read_text()

@tool
def write_file(path: str, content: str) -> str:
    """Create or overwrite a file (runs in a sandbox/branch)."""
    pathlib.Path(path).write_text(content)
    return f"wrote {path}"

@tool
def run_tests() -> str:
    """Run the pytest suite and return the output."""
    r = subprocess.run(["pytest", "-q"], capture_output=True, text=True, timeout=300)
    return r.stdout + r.stderr

The code — three agents in a graph

from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import create_react_agent

coder  = create_react_agent("openai:gpt-4o", [read_file, write_file],
                            prompt="You implement the plan by editing files.")
tester = create_react_agent("openai:gpt-4o", [run_tests],
                            prompt="You run tests and report pass/fail with details.")

def plan_node(s):   return {"messages": planner.invoke(s)["messages"]}
def code_node(s):   return {"messages": coder.invoke(s)["messages"]}
def test_node(s):   return {"messages": tester.invoke(s)["messages"]}

def tests_passed(s):
    return END if "passed" in s["messages"][-1].content.lower() else "code"

g = StateGraph(MessagesState)
g.add_node("plan", plan_node)
g.add_node("code", code_node)
g.add_node("test", test_node)
g.add_edge(START, "plan")
g.add_edge("plan", "code")
g.add_edge("code", "test")
g.add_conditional_edges("test", tests_passed, {"code": "code", END: END})  # fix-and-retry loop
builder = g.compile()
The test loop is the secret. Letting the coder see real test failures and try again is what lifts these systems from "writes plausible code" to "writes code that works." Verification, not generation, is the hard part.

Advantages this copilot brings

Advantage Why it matters
Automates multi-step work Whole small features, not just snippets.
Self-correcting The test loop catches and fixes its own mistakes.
Separation of concerns Specialised agents outperform one do-everything prompt.
Human stays in control Approve the plan, own the merge — no surprise changes.
Composable Swap the orchestrator (LangGraph / CrewAI / AutoGen) freely.

Best practices & guardrails

  • Always sandbox — run in a container and a throwaway branch; never on main or the host.
  • Two human gates: approve the plan up front, review the PR at the end. Never auto-merge.
  • Cap the loop — a max-iterations limit so a failing test can't spin forever (and rack up cost).
  • Scope tools tightly and time-box shell calls.
  • Trace everything (LangSmith/OTEL) — multi-agent runs are impossible to debug blind.
