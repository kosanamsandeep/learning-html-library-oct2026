📚 Docs Q&A Copilot

A copilot that answers questions using your own documents — PDFs, a wiki, a handbook — and cites where each answer came from. The foundational copilot pattern: Retrieval-Augmented Generation (RAG).

The story — why this copilot exists

A raw LLM knows a lot about the world but nothing about your company's onboarding guide, your product manual, or last quarter's policy doc. Ask it and it will confidently make something up. Teams waste hours digging through wikis and Slack for answers that already exist somewhere.

A Docs Q&A copilot fixes this by grounding every answer in your real documents and showing citations, so people get trustworthy answers in seconds — and can verify them.

Inspired by: imartinez/privateGPT, Mintplex-Labs/anything-llm, and danswer-ai/danswer — all top-starred "chat with your data" projects.

How RAG works — two phases

flowchart TD
    subgraph Ingest["① Ingest (once, offline)"]
        D["Docs: PDF, MD, HTML"] --> CH["Chunk into passages"]
        CH --> EM["Embed each chunk"]
        EM --> VS[("Vector store")]
    end
    subgraph Query["② Query (per question)"]
        Q["User question"] --> QE["Embed question"]
        QE --> SR["Similarity search"]
        VS --> SR
        SR --> TOP["Top-k relevant chunks"]
        TOP --> P["Prompt: question + chunks"]
        P --> LLM["LLM"]
        LLM --> A["Answer + citations"]
    end

Ingest turns documents into searchable vectors; query retrieves the most relevant chunks and asks the LLM to answer only from them.

The code — ingest your documents

from langchain_community.document_loaders import PyPDFDirectoryLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

# 1) Load every PDF in a folder.
docs = PyPDFDirectoryLoader("./handbook").load()

# 2) Split into overlapping chunks so retrieval is precise.
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=150)
chunks = splitter.split_documents(docs)

# 3) Embed + store. This is your searchable knowledge base.
store = Chroma.from_documents(chunks, OpenAIEmbeddings(), persist_directory="./kb")

The code — answer with citations

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

retriever = store.as_retriever(search_kwargs={"k": 4})

prompt = ChatPromptTemplate.from_template(
    """Answer the question using ONLY the context below.
If the answer isn't in the context, say you don't know.

Context:
{context}

Question: {question}"""
)
llm = ChatOpenAI(model="gpt-4o", temperature=0)

def ask(question: str):
    hits = retriever.invoke(question)
    context = "\n\n".join(d.page_content for d in hits)
    answer = llm.invoke(prompt.format(context=context, question=question))
    sources = {d.metadata.get("source") for d in hits}
    return answer.content, sources

text, srcs = ask("How many vacation days do new hires get?")
print(text, "\nSources:", srcs)
The "only from context" instruction is the safety rail. It turns a creative model into a grounded one — if the docs don't contain the answer, the copilot says so instead of hallucinating.

Wrap it in a UI

import streamlit as st

st.title("📚 Handbook Copilot")
if q := st.chat_input("Ask about the handbook…"):
    answer, sources = ask(q)
    st.write(answer)
    st.caption("Sources: " + ", ".join(sources))

Advantages this copilot brings

Advantage Why it matters
Grounded answers Cuts hallucinations — replies come from your real docs.
Citations Users can verify; builds trust and meets compliance needs.
Private Your data stays in your store; works with local models too.
Always current Re-ingest to update knowledge — no model retraining.
Cheap to run One retrieval + one LLM call per question.

Level it up

  • Hybrid search (keyword + vector) for names, IDs, and acronyms.
  • Re-ranking the top-k with a cross-encoder for sharper context.
  • Per-user access control so the copilot only retrieves docs a user may see.
  • Evaluation with a golden Q&A set to catch regressions (faithfulness, answer relevance).

Best practices

  • Tune chunk size/overlap — too big dilutes relevance, too small loses context.
  • Always carry metadata (source, page) so citations are precise.
  • Set temperature=0 for factual, repeatable answers.
  • Handle "I don't know" gracefully — it's a feature, not a failure.
