SBOM Diff Checker

A tool that compares two Software Bills of Materials (before and after a PR) and flags new, removed, or changed dependencies — making dependency review a first-class part of code review.

Architecture & Data Flow

The diff checker takes two CycloneDX or SPDX documents, normalizes them to a common key space, and produces a structured diff report suitable for posting as a CI comment.

  1. Generate SBOMs — Before the merge, generate an SBOM from the target branch. The PR branch generates its own SBOM after changes.
  2. Normalize records — Convert both SBOMs into a flat map keyed by Package URL (PURL), preserving version, license, and dependency information.
  3. Compute set differences — Identify components in AFTER but not BEFORE (added), BEFORE but not AFTER (removed), and those present in both with different versions (changed).
  4. Classify change severity — Apply semantic versioning rules to determine if a version change is breaking (major), additive (minor), or safe (patch).
  5. Post results — Output a structured report or GitHub PR comment summarizing the diff with color-coded severity indicators.

Breaking vs. Non-Breaking Changes

Not all dependency changes are equal. The diff checker classifies each version change by applying semantic versioning (semver) rules to determine risk level.

Change Type Semver Rule Example Risk Action
Major version bump X.y.z → X+1.y.z 2.1.0 → 3.0.0 High Requires manual review; API-breaking changes expected
Minor version bump x.Y.z → x.Y+1.z 1.2.0 → 1.3.0 Medium New functionality, backward-compatible; review release notes
Patch version bump x.y.Z → x.y.Z+1 1.2.3 → 1.2.4 Low Bug fixes; safe to auto-approve
New dependency Not in BEFORE SBOM pkg:pypi/new-pkg@1.0.0 Medium Review why new dependency was added; vet the package
Removed dependency Not in AFTER SBOM pkg:pypi/old-pkg@1.0.0 Low Usually safe, but verify nothing depended on it transitively
Downgrade Version decreased 2.0.0 → 1.9.0 High Flag immediately; could indicate rollback or conflict
Real-world impact: In 2021, a researcher added a malicious dependency to the ua-parser-js npm package via a compromised maintainer account. The package was pulled within hours, but teams without SBOM diffing had no automated way to detect they'd acquired a new transitive dependency. An SBOM diff checker would have flagged the new package as added with a medium-severity alert immediately.

Starter Code: Python SBOM Diff Checker

#!/usr/bin/env python3
"""sbom_diff.py — Compare two CycloneDX SBOM files and report changes."""

import json
import sys
from collections import defaultdict


def load_sbom(path):
    """Load a CycloneDX JSON SBOM and return components indexed by PURL."""
    with open(path) as f:
        data = json.load(f)

    components = {}
    for comp in data.get("components", []):
        purl = comp.get("purl") or comp.get("bom-ref", comp["name"])
        components[purl] = {
            "name": comp["name"],
            "version": comp["version"],
            "purl": purl,
        }
    return components


def parse_semver(version):
    """Return (major, minor, patch) tuple, defaulting to (0,0,0) on failure."""
    parts = version.split(".")
    try:
        return (int(parts[0]), int(parts[1]) if len(parts) > 1 else 0,
                int(parts[2]) if len(parts) > 2 else 0)
    except (ValueError, IndexError):
        return (0, 0, 0)


def classify_change(old_ver, new_ver):
    """Classify a version change by semver risk level."""
    old = parse_semver(old_ver)
    new = parse_semver(new_ver)

    if new < old:
        return "downgrade", "high"
    if new[0] > old[0]:
        return "major", "high"
    if new[1] > old[1]:
        return "minor", "medium"
    if new[2] > old[2]:
        return "patch", "low"
    return "unchanged", "none"


def diff_sboms(before_path, after_path):
    """Compare two SBOMs and return categorized differences."""
    before = load_sbom(before_path)
    after = load_sbom(after_path)

    before_keys = set(before.keys())
    after_keys = set(after.keys())

    added = after_keys - before_keys
    removed = before_keys - after_keys
    common = before_keys & after_keys

    results = {
        "added": [],
        "removed": [],
        "changed": [],
        "summary": {
            "total_before": len(before),
            "total_after": len(after),
            "added_count": len(added),
            "removed_count": len(removed),
        },
    }

    for purl in sorted(added):
        comp = after[purl]
        results["added"].append({
            "name": comp["name"],
            "version": comp["version"],
            "purl": purl,
            "severity": "medium",
        })

    for purl in sorted(removed):
        comp = before[purl]
        results["removed"].append({
            "name": comp["name"],
            "version": comp["version"],
            "purl": purl,
            "severity": "low",
        })

    for purl in sorted(common):
        b = before[purl]
        a = after[purl]
        if b["version"] != a["version"]:
            change_type, severity = classify_change(b["version"], a["version"])
            results["changed"].append({
                "name": a["name"],
                "old_version": b["version"],
                "new_version": a["version"],
                "purl": purl,
                "change_type": change_type,
                "severity": severity,
            })

    return results


def print_report(diff):
    """Print a human-readable diff report."""
    def fmt_sev(s):
        icons = {"high": "🔴", "medium": "🟡", "low": "🟢", "none": "⚪"}
        return f"{icons.get(s, '⚪')} {s.upper()}"

    print(f"\n{'='*60}")
    print(f"SBOM Diff Report")
    print(f"{'='*60}")
    print(f"Before: {diff['summary']['total_before']} components")
    print(f"After:  {diff['summary']['total_after']} components")

    if diff["added"]:
        print(f"\n{'─'*60}")
        print(f"🟢 NEW DEPENDENCIES ({len(diff['added'])})")
        for d in diff["added"]:
            print(f"  + {d['name']}@{d['version']}  [{d['purl']}]")

    if diff["removed"]:
        print(f"\n{'─'*60}")
        print(f"🔴 REMOVED DEPENDENCIES ({len(diff['removed'])})")
        for d in diff["removed"]:
            print(f"  - {d['name']}@{d['version']}  [{d['purl']}]")

    if diff["changed"]:
        print(f"\n{'─'*60}")
        print(f"🟡 CHANGED VERSIONS ({len(diff['changed'])})")
        for d in diff["changed"]:
            print(f"  ~ {d['name']}: {d['old_version']} → {d['new_version']}  [{fmt_sev(d['severity'])}]")

    print(f"\n{'='*60}")


def main():
    if len(sys.argv) != 3:
        print("Usage: sbom_diff.py <sbom-before.json> <sbom-after.json>", file=sys.stderr)
        sys.exit(1)

    diff = diff_sboms(sys.argv[1], sys.argv[2])
    print_report(diff)


if __name__ == "__main__":
    main()

CI Integration & Automation

The real power of SBOM diffing emerges when it runs automatically on every pull request. Here is an example GitHub Actions workflow that generates and compares SBOMs:

# .github/workflows/sbom-diff.yml
name: SBOM Diff Check
on:
  pull_request:
    paths:
      - 'requirements.txt'
      - 'pyproject.toml'
      - 'Pipfile.lock'

jobs:
  sbom-diff:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # needed to check out base branch

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Generate base SBOM
        run: |
          git checkout ${{ github.event.pull_request.base.sha }}
          python -m venv /tmp/venv-base
          source /tmp/venv-base/bin/activate
          pip install -r requirements.txt
          python sbom_gen.py --output /tmp/sbom-before.json

      - name: Generate PR SBOM
        run: |
          git checkout ${{ github.sha }}
          python -m venv /tmp/venv-pr
          source /tmp/venv-pr/bin/activate
          pip install -r requirements.txt
          python sbom_gen.py --output /tmp/sbom-after.json

      - name: Run diff
        run: |
          python sbom_diff.py /tmp/sbom-before.json /tmp/sbom-after.json

      - name: Post PR Comment
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const report = fs.readFileSync('/tmp/diff-report.txt', 'utf8');
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `## SBOM Diff Report\n\`\`\`\n${report}\n\`\`\``
            });
Best practice: Make SBOM diffing a required status check on your base branch. This ensures no dependency change enters production without review — reducing the risk of supply chain attacks like event-stream or colors-faker incidents.

Running & Extending

Quick start:

# Generate two SBOMs to compare
pip install requests==2.28.0
python sbom_gen.py --output sbom-before.json

pip install requests==2.31.0
python sbom_gen.py --output sbom-after.json

# Run the diff
python sbom_diff.py sbom-before.json sbom-after.json

Ideas for extension:

  • GitHub PR integration: Post diff results as a PR review with inline annotations for each changed component.
  • Vulnerability cross-reference: After computing the diff, query the OSV or GitHub Advisory API for CVEs affecting changed components.
  • Policy engine: Add a rules file that defines allowed/unallowed packages or version ranges. Fail the CI check if policy is violated (e.g., "no GPL-licensed packages").
  • Web UI: Build a simple dashboard showing dependency health over time by archiving SBOMs and diffs per build.
  • Multiple formats: Support SPDX documents alongside CycloneDX for broader tool compatibility.
