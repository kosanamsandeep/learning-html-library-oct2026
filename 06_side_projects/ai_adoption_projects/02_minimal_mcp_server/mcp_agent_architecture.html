The critical difference: In the custom approach, you are responsible for every piece highlighted in yellow — the MCP Client Layer. Let's break it down step by step.

🔁 The Complete Sequence

1

Startup — Spawn Servers

Your app starts. You call stdio_client(server_params) for each MCP server, which spawns the Python script as a subprocess. This gives you a (read, write) pipe pair.

2

Startup — Initialize Sessions

Wrap each pipe pair in ClientSession(read, write) and call await session.initialize() to perform the MCP handshake.

3

Startup — Discover Tools ⭐ (Critical)

Call await session.list_tools() on each server. This returns JSON Schemas describing every tool the server exposes. You collect these schemas and hold them in memory.

4

Startup — Inject into LLM

Convert each MCP tool schema into the format your LLM expects (OpenAI function-calling format, Anthropic tool format, etc.) and pass them in every LLM call:

# MCP tool schema → OpenAI tool format
{
    "type": "function",
    "function": {
        "name": mcp_tool.name,
        "parameters": mcp_tool.inputSchema  # JSON Schema
    }
}
5

Runtime — LLM Calls a Tool

The LLM returns a tool_call with a tool name and arguments. Your router examines which tool was called and routes to the correct MCP server.

6

Runtime — Execute on Correct Server

Call await session.call_tool(tool_name, arguments) on the right server session. Get the result and feed it back to the LLM as a ToolMessage.

Server Lifecycle — Spawn Per-Request vs Keep Alive

YOUR CHOICE

🔁 Spawn Per LLM Call

Simple but slower

Start the MCP server subprocess fresh for every LLM tool call.

async def call_tool(name, args):
    # Start server fresh each time
    async with stdio_client(params) as (r, w):
        async with ClientSession(r, w) as s:
            await s.initialize()
            return await s.call_tool(name, args)
  • ✅ Simple — no state management
  • ✅ Clean isolation — no stale state
  • ❌ ~200-500ms startup latency per call
  • ❌ Wasted if 3 calls happen in a row

♻️ Keep Alive (Pooled)

Production standard

Start once at app boot, reuse across all LLM calls.

# App startup
session = await create_session(params)
tools = await session.list_tools()

# Each LLM call — reuse session
result = await session.call_tool(name, args)
  • ✅ Near-zero latency on calls (no spawn)
  • ✅ One-time startup cost
  • ⚠️ Need health checks + reconnect
  • ⚠️ Server keeps memory allocated

🏭 What production systems actually do (hybrid)

Start servers once at boot, keep them alive, but add a health-check heartbeat. If a server crashes or becomes unresponsive, restart it transparently.

class MCPConnectionPool:
    def __init__(self):
        self.servers: dict[str, MCPConnection] = {}

    async def add_server(self, name, params):
        conn = await create_connection(params)
        self.servers[name] = conn
        # Start background health check
        asyncio.create_task(health_loop(name, conn))

    async def health_loop(self, name, conn):
        while True:
            await asyncio.sleep(30)
            if not await is_alive(conn):
                log(f"Server {name} dead. Restarting...")
                self.servers[name] = await create_connection(params)

    async def call_tool(self, server, name, args):
        conn = self.servers[server]
        return await conn.session.call_tool(name, args)

How Does the LLM "Know" About the Tools?

This is the most common confusion. The LLM itself doesn't magically know about your MCP tools. Here's exactly how the chain works:

    LLM-->>Code: tool_call: search_docs({"query": "FastAPI CORS"})

    Server-->>Code: Tool result
    Code->>LLM: tool_result back as message

Key insight: The MCP server doesn't talk to the LLM directly. Your code is the middle layer:

  1. Your code asks the MCP server "what tools do you have?" (list_tools())
  2. Your code converts those schemas into the LLM's format
  3. Your code injects them into every LLM API call via the tools parameter
  4. Now the LLM "knows" about the tools because you told it via the API
  5. When the LLM wants to use one, it returns a tool_call — your code catches it and calls the MCP server

📦 The MCPManager Pattern

Most production code wraps all this into a single class:

class MCPManager:
    def __init__(self):
        self.sessions = {}
        self.tool_definitions = []  # ← This is the bridge

    async def add_server(self, name, params):
        session = await connect(params)          # spawn + handshake
        tools = await session.list_tools()            # discover
        for t in tools:
            self.tool_definitions.append({              # store + map
                "name": t.name,
                "server": name,                       # ← know which server
                "schema": t.inputSchema,
            })
        self.sessions[name] = session

    def get_llm_tools(self):                     # ← inject into LLM
        return [self.to_openai_format(t) for t in self.tool_definitions]

    async def execute(self, tool_name, args):     # ← route + execute
        server = self.find_server(tool_name)
        return await self.sessions[server].call_tool(tool_name, args)

Minimal Production Pattern — Full Code

Putting it all together: a complete MCP-backed LangGraph agent.

# pip install mcp langgraph langchain-openai

import asyncio
import json
from mcp import ClientSession
from mcp.client.stdio import stdio_client, StdioServerParameters
from langgraph.graph import StateGraph
from langchain_openai import ChatOpenAI


# ─── MCP Connection Pool ───────────────────────────────────

class MCPManager:
    """Manages MCP server lifecycle, tool discovery, and routing."""

    def __init__(self):
        self.sessions: dict[str, ClientSession] = {}
        self.tool_registry: list[dict] = []    # ← table mapping name → server
        self.llm_tools: list[dict] = []         # ← schemas ready for LLM

    async def add_server(self, name: str, params: StdioServerParameters):
        # 1. Spawn server subprocess
        read, write = await stdio_client(params).__aenter__()

        # 2. Create session and handshake
        session = await ClientSession(read, write).__aenter__()
        await session.initialize()

        # 3. ★ Discover tools from this server
        result = await session.list_tools()
        for tool in result.tools:
            self.tool_registry.append({
                "mcp_name": tool.name,
                "server": name,
                "schema": tool.inputSchema,
            })
            # 4. Convert to OpenAI/Anthropic tool format
            self.llm_tools.append({
                "type": "function",
                "function": {
                    "name": tool.name,
                    "description": tool.description or "",
                    "parameters": tool.inputSchema,
                }
            })

        self.sessions[name] = session
        print(f"✓ {name}: {len(result.tools)} tools loaded")

    async def call_tool(self, tool_name: str, args: dict):
        # 5. ★ Route to the correct server
        for entry in self.tool_registry:
            if entry["mcp_name"] == tool_name:
                session = self.sessions[entry["server"]]
                result = await session.call_tool(tool_name, args)
                return result.content
        raise ValueError(f"Tool '{tool_name}' not found")


# ─── LangGraph Agent ────────────────────────────────────────

async def build_agent(mcp: MCPManager):
    llm = ChatOpenAI(model="gpt-4o")

    # Graph state
    class AgentState(dict):
        messages: list

    async def call_llm(state: AgentState):
        # ★ Inject MCP tool schemas directly into the LLM call
        response = await llm.ainvoke(
            state["messages"],
            tools=mcp.llm_tools              # ← tools discovered from MCP
        )
        return {"messages": [response]}

    async def execute_tool(state: AgentState):
        last = state["messages"][-1]
        for tc in last.tool_calls:
            result = await mcp.call_tool(tc.name, tc.args)   # ← route + execute
            state["messages"].append({
                "role": "tool",
                "content": str(result),
                "tool_call_id": tc.id,
            })
        return state

    # Build graph
    graph = StateGraph(AgentState)
    graph.add_node("llm", call_llm)
    graph.add_node("tool", execute_tool)
    graph.add_edge("llm", "tool")
    graph.add_conditional_edges(
        "tool",
        lambda s: "llm" if s["messages"][-1].tool_calls else "__end__"
    )
    graph.set_entry_point("llm")
    return graph.compile()


# ─── Main ───────────────────────────────────────────────────

async def main():
    # Configure MCP servers
    mcp = MCPManager()
    await mcp.add_server("docs-search", StdioServerParameters(
        command="/path/to/.venv/bin/python",
        args=["/path/to/server.py"],
    ))
    await mcp.add_server("mcp-examples", StdioServerParameters(
        command="/path/to/.venv/bin/python",
        args=["/path/to/examples_server.py"],
    ))

    # Build and run agent
    agent = await build_agent(mcp)
    result = await agent.ainvoke({
        "messages": [{"role": "user", "content": "Search for FastAPI CORS info"}]
    })
    print(result["messages"][-1].content)


if __name__ == "__main__":
    asyncio.run(main())
