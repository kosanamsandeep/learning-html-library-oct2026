Project 02

Minimal MCP Server

A small Model Context Protocol server that exposes API documentation as a searchable tool. Build it once, connect it to any MCP-compatible agent — Claude Code, Copilot, Cline, or your own.

OVERVIEW

What is MCP and why does it matter?

The Model Context Protocol (MCP) is an open standard, announced by Anthropic in late 2024, that defines how AI applications connect to external tools and data sources. Think of it as "USB-C for AI" — a single protocol that any AI agent can use to discover and call tools, read resources, and follow prompts, regardless of which model or framework powers it.

Before MCP, every integration was bespoke: you wrote a LangChain tool one way, a Copilot extension another way, and a custom agent integration a third way. With MCP, you write one server and every MCP-compatible agent can use it out of the box. This project builds the smallest useful MCP server: one that searches a documentation corpus and returns relevant results to the agent.

Key insight: An MCP server is just a process that speaks JSON-RPC over stdin/stdout (stdio) or HTTP. The mcp Python SDK handles all the protocol boilerplate — you only write the tools.

Sequence diagram showing the MCP handshake and tool call flow between agent and server.

The flow has three phases:

  1. Initialization: The agent (MCP client) sends an initialize request with its protocol version and capabilities. The server responds with its supported version and lists its tools via the tools/list capability.
  2. Tool discovery: The agent calls tools/list to get the available tools, their names, descriptions, and JSON Schema input parameters.
  3. Tool invocation: The agent calls tools/call with the tool name and arguments. The server executes the logic and returns the result. The agent folds the result into its response to the user.
STARTER CODE

Python — minimal_mcp_server.py

This server exposes a single search_docs tool that searches either a local JSON index or a remote documentation API. The FastMCP class from the mcp SDK handles all the protocol details — you only decorate a Python function with @mcp.tool().

#!/usr/bin/env python3
"""minimal_mcp_server.py — One MCP tool to search documentation."""

import json
import httpx
from mcp.server import FastMCP

# --- Configuration ---
DOCS_API_URL = "https://docs.example.com/api/search"
LOCAL_INDEX   = "docs_index.json"   # fallback local corpus

# Create the MCP server — FastMCP handles init, tool listing, and transport
mcp = FastMCP(
    name="Docs Search Server",
    instructions="Search documentation and return relevant results.",
)


def _search_local(query: str, top_k: int = 5) -> list[dict]:
    """Simple keyword-search over a local JSON index."""
    try:
        with open(LOCAL_INDEX) as f:
            entries = json.load(f)
    except FileNotFoundError:
        return [{"title": "Index not found", "content": ""}]

    query_lower = query.lower()
    scored = []
    for entry in entries:
        score = entry["title"].lower().count(query_lower) * 3 \
              + entry["content"].lower().count(query_lower)
        if score > 0:
            scored.append((score, entry))
    scored.sort(key=lambda x: x[0], reverse=True)
    return [entry for _, entry in scored[:top_k]]


async def _search_remote(query: str, top_k: int = 5) -> list[dict]:
    """Query a remote documentation search API."""
    async with httpx.AsyncClient(timeout=10) as client:
        resp = await client.get(DOCS_API_URL, params={"q": query, "limit": top_k})
        resp.raise_for_status()
        return resp.json().get("results", [])


@mcp.tool(description="Search project documentation. Returns title + snippet for each match.")
async def search_docs(
    query: str,
    top_k: int = 5
) -> str:
    """Search documentation for the given query. Tries remote API first, falls back to local."""
    try:
        results = await _search_remote(query, top_k)
    except Exception:
        results = _search_local(query, top_k)

    if not results:
        return "No results found."

    lines = [f"### {r['title']}\n{r.get('content', r.get('snippet', ''))[:500]}"
             for r in results]
    return "\n\n---\n\n".join(lines)


# --- Entry point ---
if __name__ == "__main__":
    # Run with stdio transport (default)
    # Connect: claude mcp add docs-server -- python minimal_mcp_server.py
    mcp.run(transport="stdio")

How to connect it

Once the server is running, register it with any MCP-compatible client:

# Claude Code
claude mcp add docs-search -- python /path/to/minimal_mcp_server.py

# Or in .claude/settings.json
{
  "mcpServers": {
    "docs-search": {
      "command": "python",
      "args": ["/path/to/minimal_mcp_server.py"]
    }
  }
}
Zero config for any agent: The same server works with Claude Code, GitHub Copilot (via MCP support), Cline, Continue.dev, and any other MCP client. No per-agent adapters needed.
DEEP DIVE

How one server serves every agent

MCP achieves cross-agent compatibility through three design decisions:

Design element What it does Why it matters
JSON-RPC 2.0 transport All messages are JSON-RPC request/response/notification frames over stdio or SSE Any process that can read stdin and write stdout can be an MCP server — no HTTP server, no sockets, no framework lock-in
Capability negotiation On initialize, client and server exchange their supported protocol version and feature flags A server written for MCP 2024-11-05 works with clients implementing that version; negotiation prevents silent failures
Tool schema via JSON Schema Tools are described with standard inputSchema (JSON Schema), and the agent introspects them The agent knows exactly what parameters a tool expects and can generate valid calls without pre-configured knowledge

MCP vs. other integration patterns

Pattern Effort per tool Agent lock-in Discoverability
MCP Server Write once None — any MCP client works Automatic via tools/list
LangChain Tool Write once LangChain agents only Manual registration
OpenAI Function Calling Write once per schema OpenAI API only Inline in request
Custom HTTP endpoint Full API per tool Custom client needed None
STEP-BY-STEP

How to adopt this project

1
Install the MCP SDK — pip install mcp httpx. This gives you FastMCP, the high-level server class, plus httpx for async HTTP calls.
2
Define your tools — decorate async Python functions with @mcp.tool(). Use type annotations for your parameters; the SDK generates JSON Schema from them automatically.
3
Run the server — call mcp.run(transport="stdio") at the bottom. Test it by piping JSON-RPC messages or using the MCP Inspector: npx @modelcontextprotocol/inspector python server.py.
4
Register with your agent — add it to Claude Code's MCP config, Copilot's .github/copilot-instructions.md MCP section, or any MCP client's config file.
5
Iterate — add more tools, resources (files the agent can read), or prompts (reusable prompt templates). The same server grows with your needs.
