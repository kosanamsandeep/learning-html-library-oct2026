Start the MCP Server

LINES 54-59

What the code looks like:

58async with MCPClient("server/mcp_server.py") as mcp: 59 print("✅ Connected and session initialized")

What happens under the hood:

sequenceDiagram
    participant Main as main.py
    participant MCP as MCPClient
    participant OS as Operating System
    participant Server as MCP Server

    Main->>MCP: MCPClient("server/mcp_server.py")
    MCP->>OS: spawn subprocess: python server/mcp_server.py
    OS-->>Server: process started, stdio pipes connected
    MCP->>Server: initialize() handshake
    Server-->>MCP: server_info {name: "code-review-tools", version: ...}
    MCP-->>Main: ✅ Connected!

🧠 Key insight

An MCP server is just a Python script that reads from stdin and writes to stdout using JSON-RPC messages. The MCPClient class spawns it as a subprocess — two processes talking to each other through stdio pipes.

Discover MCP Tools

LINES 72-77

What the code looks like:

72tools = await mcp.list_tools() 73print(f"Found {len(tools)} tools:") 74for t in tools: 75 print(f" • {t.name}") 76 print(f" {t.description.split('.')[0]}.")

This sends a list_tools JSON-RPC request to the MCP server. The server responds with 5 tool definitions, each containing:

Tool 1

read_source_file

Read a Python source file from disk. Takes: path

Tool 2

analyze_syntax

Parse Python code with AST. Takes: code

Tool 3

check_dependencies

Scan imports, flag risky packages. Takes: code

Tool 4

check_code_style

Check line length, naming, whitespace. Takes: code

Tool 5

format_report

Format findings into markdown report. Takes: defects, warnings, ok_checks, file_name

🧠 Key insight

The agent never imports anything from the server. It just receives tool schemas dynamically. No hardcoded tool list. If you add a 6th tool to the server, it auto-appears here.

Build the LangGraph Workflow

LINE 88

What the code looks like:

88graph = create_review_graph(mcp)

This calls into agent/graph.py to build a StateGraph — a directed graph where each node calls an MCP tool.

The graph has 6 nodes connected like this:

flowchart LR

    RF -->|Send() fan-out| CD[check_deps]
    RF -->|Send() fan-out| CS[check_style]
    AS & CD & CS -->|fan-in join| GR[gather_results]
    GR --> RP[generate_report]
    RP --> END

How each node is wired:

NodeCalls MCP ToolArgumentsReturns
read_file read_source_file {"path": file_path} Raw file content
analyze_syntax analyze_syntax {"code": content} JSON with functions, classes, warnings
check_deps check_dependencies {"code": content} JSON with imports, risky findings
check_style check_code_style {"code": content} JSON with style issues
gather_results (no MCP call) Reads state from all 3 branches Categorized defects/warnings/ok
generate_report format_report {"defects": [...], "warnings": [...], ...} Markdown report string

🧠 Key insight — The mcp object is passed through

Every node function receives the mcp client because it's captured in the closure. The nodes do await mcp.call_tool(tool_name, args) — they don't know how the tool works, they just pass arguments and get results.

Run the Workflow

LINES 100-115

What the code looks like:

102result = await graph.ainvoke({ 103 "file_path": file_path 104})

This single call kicks off the entire LangGraph execution. Here's the full execution sequence:

sequenceDiagram
    participant Main as main.py
    participant LG as LangGraph
    participant MCP as MCP Client
    participant Server as MCP Server

    Main->>LG: ainvoke({"file_path": "sample_code/vulnerable_code.py"})

    Note over LG: Node: read_file
    LG->>MCP: call_tool("read_source_file", {"path": "..."})
    MCP->>Server: JSON-RPC: tools/call
    Server-->>MCP: file content (2539 chars)
    MCP-->>LG: result text
    Note over LG: 3 parallel Send() branches

    par Parallel Branch 1
        Note over LG: Node: analyze_syntax
        LG->>MCP: call_tool("analyze_syntax", {"code": content})
        MCP->>Server: JSON-RPC
        Server-->>MCP: {"valid_syntax": true, "functions": [...], "warnings": [...]}
        MCP-->>LG: result
    and Parallel Branch 2
        Note over LG: Node: check_deps
        LG->>MCP: call_tool("check_dependencies", {"code": content})
        MCP->>Server: JSON-RPC
        Server-->>MCP: {"imports": [...], "risky_findings": ["pickle..."]}
        MCP-->>LG: result
    and Parallel Branch 3
        Note over LG: Node: check_style
        LG->>MCP: call_tool("check_code_style", {"code": content})
        MCP->>Server: JSON-RPC
        Server-->>MCP: {"issues": [...], "issue_count": 5}
        MCP-->>LG: result
    end

    Note over LG: All 3 branches complete → gather_results
    Note over LG: Node: gather_results (fan-in join)
    Note over LG: Node: generate_report
    LG->>MCP: call_tool("format_report", {defects, warnings, ok_checks, file_name})
    MCP->>Server: JSON-RPC
    Server-->>MCP: markdown report
    MCP-->>LG: report string
    LG-->>Main: result = {"report": "# 📋 Code Review Report: ..."}

    Main->>Main: print(result["report"])

The parallel fan-out is powered by LangGraph's Send():

# In graph.py — route_to_analyzers(): return [ Send("analyze_syntax", state), # runs in parallel Send("check_deps", state), # runs in parallel Send("check_style", state), # runs in parallel ]

LangGraph spawns all three branches concurrently. The gather_results node won't run until all three complete — that's the fan-in / join point.

✓

Cleanup

LINE 147

When the async with MCPClient(...) block exits, Python calls __aexit__ which:

  1. Closes the MCP ClientSession
  2. Closes the stdio pipes → terminates the server subprocess

No dangling processes, no manual cleanup needed.

# ── Pick the file ── file_path = sys.argv[1] if len(sys.argv) > 1 else "sample_code/vulnerable_code.py" # ── STEP 1: Start MCP server ── async with MCPClient("server/mcp_server.py") as mcp: # ── STEP 2: Discover tools ── tools = await mcp.list_tools() # ── STEP 3: Build LangGraph ── graph = create_review_graph(mcp) # ── STEP 4: Run workflow ── result = await graph.ainvoke({ "file_path": file_path }) # ── Print report ── print(result.get("report")) # ── Cleanup: MCP server terminated ──

What's Happening

📂 File selection
Takes a command-line argument or defaults to the sample file.
🔌 Spawn server
MCPClient starts server/mcp_server.py as a subprocess and connects via MCP protocol.
🔎 Discover
Asks the server "what tools do you have?" → gets 5 tool schemas back.
🧠 Build graph
Creates a LangGraph StateGraph where each node calls an MCP tool.
▶️ Run
Passes in the file path → the graph executes: read → analyze (3× parallel) → gather → format → report.
🧹 Cleanup
async with block exits → MCP server subprocess is terminated.
