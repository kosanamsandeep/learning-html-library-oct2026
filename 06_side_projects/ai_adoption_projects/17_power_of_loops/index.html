Power of Loops

Recurring Tasks & Autonomous Iteration with Claude Code

What is a Loop?

The /loop command tells Claude Code to run a prompt or slash command on a recurring interval. Each iteration is a fresh turn — Claude sees new context (file changes, command output, time passing) and decides what to do next. Combined with ScheduleWakeup (background polling between sessions) and CronCreate (durable scheduling), loops form the backbone of autonomous agent workflows. 

flowchart TD
    Start([Start]) --> Invoke["/loop <interval> <prompt>"]
    Invoke --> Execute[Claude executes prompt
with current context]
    Execute --> Check{Continue?}
    Check -->|Yes| Wait[Wait for interval]
    Wait --> Execute
    Check -->|No / Esc| Done([Loop exits])

    subgraph Schedule["Scheduling (background)"]
        Wake[ScheduleWakeup] --> Cron[CronCreate]
        Cron --> Trigger[Wake on schedule]
        Trigger --> Execute
    end

    Execute -.->|Optional
external API| Poll[Poll CI / Deploy / APIs]
    Poll -.-> Execute

Key components

  • /loop <interval> <command> — Run a slash command or prompt every interval (e.g. 10m, 1h).
  • ScheduleWakeup — A hook that wakes Claude at a future time to re-run a loop. Lives inside the session.
  • CronCreate — Creates a durable cron schedule that survives session restarts. Used for production-grade recurring tasks.
  • Manual break — Press Esc or the prompt asks to stop; the loop exits cleanly.

Three Loop Patterns

A Fixed-Interval Polling

/loop 5m "check deploy status"

Poll an external system at a regular, predictable cadence. Best when you know the typical response time and want consistent monitoring.

flowchart LR
    subgraph Claude["Claude Code"]
        L["/loop 5m"]
        P["Check deploy status"]
    end
    subgraph External["External System"]
        CI[CI Pipeline]
        DEPLOY[Deployment]
        LOGS[Logs / Metrics]
    end
    L -->|every 5 min| P
    P -->|poll| CI
    P -->|poll| DEPLOY
    P -->|poll| LOGS
    CI -->|status| P
    DEPLOY -->|status| P
    P -->|report| L

B Dynamic Pacing

Claude decides the interval based on context — CI pipeline stage, cache freshness, backoff on errors.

Use when the optimal wait time varies. Claude inspects the current state and picks the next check-in delay.

flowchart TD
    Start([Start]) --> Run[Run check]
    Run --> Analyze{Analyze state}
    Analyze -->|"Building (early)"| Fast["Wait 2m"]
    Analyze -->|"Testing (mid)"| Mid["Wait 5m"]
    Analyze -->|"Deploying (late)"| Slow["Wait 10m"]
    Analyze -->|"Failed / Blocked"| Alert[Alert & exit]
    Fast --> Run
    Mid --> Run
    Slow --> Run

Example: "wait 2m while building, 5m while testing, 10m during deploy canary"

C Loop-Until-Dry

Keep iterating until K consecutive rounds return nothing new. Great for bug hunting, security audits, or code review sweeps.

flowchart TD
    Start([Start]) --> Hunt[Analyze code / logs]
    Hunt --> Found{Found issues?}
    Found -->|Yes| Fix[Fix / report]
    Fix --> Hunt
    Found -->|No| Inc[Dry counter += 1]
    Inc --> Dry{Dry ≥ K?}
    Dry -->|No| Hunt
    Dry -->|Yes| Done([Done — K dry rounds])

/loop 1m "find remaining bugs — stop after 3 empty rounds"

Practical Examples

Three runnable Python scripts that simulate the loop patterns in action.

01 — CI Poller examples/01_poll_ci.py

Simulates polling a CI pipeline as it transitions through states. Use the --loop flag to auto-recheck.

# Example usage
python examples/01_poll_ci.py --loop --interval 2

02 — Deploy Watcher examples/02_deploy_monitor.py

Simulates watching a multi-stage deployment (build → push → canary → production) with possible failures and rollbacks.

# Example usage
python examples/02_deploy_monitor.py --watch --interval 3

03 — Bug Hunter examples/03_loop_until_dry.py

Simulates the loop-until-dry pattern: diminishing returns bug finding that stops after N consecutive empty rounds.

# Example usage
python examples/03_loop_until_dry.py --dry-threshold 3 --total-bugs 15

Build Your Own Loop Skill

Wrap a recurring loop into a reusable slash command by creating a Skill. A skill lets you invoke your loop with /my-poller instead of typing the full prompt each time. Below is a working skill template — see skill_template/SKILL.md for the full file. 

# File: skill_template/SKILL.md
# Deploy Watcher Skill
# Place in .claude/skills/ or project skills directory

name: deploy-watcher
description: |
  Watch a deployment progress through build → push → canary → production.
  Reports each stage and exits on success, failure, or rollback.

trigger:
  type: slash_command
  command: deploy-watch

action: |
  Check the deployment status by running:
  python examples/02_deploy_monitor.py --watch --interval 3
  Report the current stage and any failures.
  Loop every 10 seconds until the deploy completes or fails.

loop:
  default_interval: 10s
  stop_conditions:
    - Deploy status is "success" or "failed"
    - Rollback detected

How to install a loop skill

  1. Create a .claude/skills/ directory in your project root.
  2. Add the SKILL.md file (like the template above).
  3. Run /deploy-watch in Claude Code — it will loop automatically.
  4. Customize the default_interval and stop_conditions to match your workflow.

For more on skills, see the Claude Code Skills documentation.
