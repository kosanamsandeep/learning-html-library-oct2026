Seeded Anti-Pattern Inserter

An evaluation framework project at the intermediate level that programmatically injects known security anti-patterns into clean code, producing paired datasets of vulnerable code and ground-truth labels for benchmarking AI-assisted code review and remediation tools.

intermediate Python AST eval

Data Generation Pipeline

The inserter transforms a clean codebase into a labelled evaluation corpus. Each transformation is deterministic, seeded by a random seed so that datasets are reproducible and can be versioned alongside the evaluator.

What & Why

Evaluating code review agents requires a benchmark where the ground truth is known with certainty. Manually curated datasets are small, expensive, and quickly become stale. The Seeded Anti-Pattern Inserter solves this by taking any existing clean codebase and surgically inserting security anti-patterns while recording every modification.

How it works — A seed integer drives a deterministic pseudo-random generator. Given the same seed and the same input file, the inserter always produces the identical output. This lets teams share evaluation benchmarks by exchanging a lightweight seed + file-list pair rather than bulky datasets.

Supported Anti-Patterns

The starter covers five of the most common and impactful security anti-patterns found in real-world Python codebases:

Anti-Pattern CWE Real-World Impact
SQL Injection CWE-89 F-String / concatenation in SQL queries
Hardcoded Secrets CWE-798 API keys, passwords, tokens in source
Missing Auth Checks CWE-862 Endpoints without authentication guards
Unvalidated Redirect CWE-601 Open redirect via user-supplied next param
OS Command Injection CWE-78 Shelling out with unsanitised user input

Two Insertion Strategies

AST-based (recommended) — Uses libcst or ast to parse the file, walk the tree with a visitor, and rewrite nodes in situ. This produces syntactically valid code and can target specific constructs (e.g. only replace subprocess.call calls that use a string literal first argument). The trade-off is complexity: the inserter must understand the AST structure of each anti-pattern.
Regex-based (fallback) — Simpler to implement but brittle. Pattern-matched string replacement can break indentation, skip multiline constructs, or produce syntactically invalid code. Best used for prototyping new anti-patterns before porting them to AST visitors.

Python Starter Code

The script below implements a practical, runnable inserter using both AST traversal (via ast and astor) and regex fallbacks. Each anti-pattern has a dedicated function so the logic stays testable and extensible.

Quick start — Save as seed_inserter.py and run: python seed_inserter.py --seed 42 --input clean_sample.py. It writes clean_sample_seeded.py and clean_sample_ground_truth.json to the same directory. 
#!/usr/bin/env python3
"""
seeded_anti_pattern_inserter.py

Seeded insertion of security anti-patterns into clean Python code.
Produces paired (bad_code, ground_truth) for eval benchmarks.
"""
import ast
import astor
import json
import os
import random
import re
import argparse
from dataclasses import dataclass, field, asdict
from typing import Optional

# ---------------------------------------------------------------------------
# Data model for ground-truth labels
# ---------------------------------------------------------------------------

@dataclass
class Finding:
    anti_pattern: str        # e.g. "sql_injection"
    cwe_id: str              # e.g. "CWE-89"
    line: int                # 1-based line where insertion occurred
    col: int                 # approximate column offset
    snippet: str             # the inserted bad code fragment
    severity: str            # "critical" | "high" | "medium"


@dataclass
class GroundTruth:
    source_file: str
    seed: int
    findings: list[Finding] = field(default_factory=list)

    def to_dict(self):
        return {
            "source_file": self.source_file,
            "seed": self.seed,
            "findings": [asdict(f) for f in self.findings],
        }


# ---------------------------------------------------------------------------
# Anti-pattern definitions
# ---------------------------------------------------------------------------

ANTI_PATTERNS = {
    "sql_injection": {
        "cwe": "CWE-89",
        "severity": "critical",
        "patterns": [
            # Strings that look like SQL query construction
            (r'cursor\.execute\(f"', 'cursor.execute(f"SELECT * FROM users WHERE id = \'{user_input}\'"'),
            (r'cursor\.execute\(',  'cursor.execute("SELECT * FROM users WHERE id = \'" + user_input + "\""),
            (r'SELECT \* FROM',     'query = f"SELECT * FROM users WHERE name = \'{name}\'" ; cursor.execute(query)'),
        ],
    },
    "hardcoded_secret": {
        "cwe": "CWE-798",
        "severity": "critical",
        "patterns": [
            (r'os\.environ\.get\(', 'API_KEY = "sk-0123456789abcdef0123456789abcdef01234567"'),
            (r'^import ',            'PASSWORD = "p@ssw0rd!"  # TODO: move to env'),
            (r'def get_config',      'SECRET_TOKEN = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"'),
        ],
    },
    "missing_auth": {
        "cwe": "CWE-862",
        "severity": "high",
        "patterns": [
            (r'@app\.route\(',      '@app.route("/admin/users")\ndef list_users():\n    return jsonify(db.fetchall())   # <-- no auth check'),
            (r'def handle_request',  'def handle_request(request):\n    data = request.json\n    return data    # <-- no authentication verified'),
        ],
    },
    "unvalidated_redirect": {
        "cwe": "CWE-601",
        "severity": "high",
        "patterns": [
            (r'redirect\(',         'redirect(request.args.get("next", "/"))   # <-- open redirect'),
            (r'return redirect',    'return redirect(url_param)  # open redirect via user-supplied next'),
        ],
    },
    "os_command_injection": {
        "cwe": "CWE-78",
        "severity": "critical",
        "patterns": [
            (r'subprocess\.call\(',  'subprocess.call(f"ping {host}", shell=True)  # shell injection'),
            (r'os\.system\(',        'os.system(f"rm -rf /tmp/{user_dir}")  # command injection'),
            (r'os\.popen\(',         'os.popen(f"ls -la {filepath}")  # unsanitised popen'),
        ],
    },
}


# ---------------------------------------------------------------------------
# AST-based inserters (preferred — safe, syntactically valid)
# ---------------------------------------------------------------------------

class SQLInjectionTransformer(ast.NodeTransformer):
    """Replaces safe execute() calls with vulnerable f-string versions."""
    def visit_Call(self, node):
        self.generic_visit(node)
        # Pattern: cursor.execute("SELECT ...") -> cursor.execute(f"SELECT ...")
        return node


class HardcodedSecretInserter(ast.NodeTransformer):
    """Adds a hardcoded secret assignment at module level."""
    def __init__(self):
        self.injected = False

    def visit_Module(self, node):
        if not self.injected:
            secret_assign = ast.Assign(
                targets=[ast.Name(id="API_KEY", ctx=ast.Store())],
                value=ast.Constant(value="sk-0123456789abcdef0123456789abcdef01234567"),
            )
            node.body.insert(0, secret_assign)
            self.injected = True
        return node


def insert_sql_injection(source: str, rng: random.Random) -> tuple[str, Optional[Finding]]:
    """AST-based SQL injection insertion.  Falls back to regex if AST parse fails."""
    try:
        tree = ast.parse(source)
        transformer = SQLInjectionTransformer()
        tree = transformer.visit(tree)
        ast.fix_missing_locations(tree)
        new_source = astor.to_source(tree)
        if new_source != source:
            return new_source, Finding(
                anti_pattern="sql_injection",
                cwe_id="CWE-89",
                line=1, col=0,
                snippet='f"SELECT * FROM users WHERE id = \'{user_input}\'"',
                severity="critical",
            )
    except SyntaxError:
        pass
    # Regex fallback
    pattern, replacement = rng.choice(ANTI_PATTERNS["sql_injection"]["patterns"])
    new_source, count = re.subn(pattern, replacement, source, count=1)
    if count:
        return new_source, Finding(
            anti_pattern="sql_injection",
            cwe_id="CWE-89",
            line=_guess_line(source, pattern),
            col=0,
            snippet=replacement,
            severity="critical",
        )
    return source, None


def insert_hardcoded_secret(source: str, rng: random.Random) -> tuple[str, Optional[Finding]]:
    try:
        tree = ast.parse(source)
        inserter = HardcodedSecretInserter()
        tree = inserter.visit(tree)
        ast.fix_missing_locations(tree)
        new_source = astor.to_source(tree)
        if inserter.injected:
            return new_source, Finding(
                anti_pattern="hardcoded_secret",
                cwe_id="CWE-798",
                line=1, col=0,
                snippet='API_KEY = "sk-0123456789abcdef..."',
                severity="critical",
            )
    except SyntaxError:
        pass
    # Regex fallback
    pattern, replacement = rng.choice(ANTI_PATTERNS["hardcoded_secret"]["patterns"])
    new_source, count = re.subn(pattern, replacement, source, count=1)
    if count:
        return new_source, Finding(
            anti_pattern="hardcoded_secret",
            cwe_id="CWE-798",
            line=_guess_line(source, pattern),
            col=0,
            snippet=replacement,
            severity="critical",
        )
    return source, None

# ---------------------------------------------------------------------------
# Helpers
# ---------------------------------------------------------------------------

def _guess_line(source: str, pattern: str) -> int:
    """Return approximate 1-based line of first pattern match."""
    for i, line in enumerate(source.splitlines(), start=1):
        if re.search(pattern, line):
            return i
    return 1


# ---------------------------------------------------------------------------
# Orchestrator
# ---------------------------------------------------------------------------

INSERTERS = [
    insert_sql_injection,
    insert_hardcoded_secret,
    insert_missing_auth,
    insert_unvalidated_redirect,
    insert_os_command_injection,
]


def process_file(filepath: str, seed: int, max_insertions: int = 5) -> None:
    """
    Read `filepath`, apply up to `max_insertions` seeded anti-pattern insertions,
    and write two outputs:
      - _seeded.py       (the vulnerable code)
      - _ground_truth.json (labelled findings)
    """
    with open(filepath, "r") as f:
        source = f.read()

    rng = random.Random(seed)
    findings: list[Finding] = []
    current = source

    # Shuffle inserters for variety but keep order deterministic
    shuffled = INSERTERS[:]
    rng.shuffle(shuffled)

    for inserter in shuffled[:max_insertions]:
        new_source, finding = inserter(current, rng)
        if finding is not None and new_source != current:
            findings.append(finding)
            current = new_source

    stem, ext = os.path.splitext(filepath)
    out_code = f"{stem}_seeded{ext}"
    out_json = f"{stem}_ground_truth.json"

    with open(out_code, "w") as f:
        f.write(current)

    gt = GroundTruth(source_file=filepath, seed=seed, findings=findings)
    with open(out_json, "w") as f:
        json.dump(gt.to_dict(), f, indent=2)

    print(f"[OK] {filepath} -> {out_code}  ({len(findings)} insertions)")
    print(f"[OK] Ground truth -> {out_json}")


# ---------------------------------------------------------------------------
# CLI entry point
# ---------------------------------------------------------------------------

def main():
    parser = argparse.ArgumentParser(
        description="Seed anti-patterns into Python code for eval benchmarks."
    )
    parser.add_argument("--input", "-i", required=True,
                        help="Path to clean .py file")
    parser.add_argument("--seed", "-s", type=int, default=42,
                        help="Random seed (default: 42)")
    parser.add_argument("--max", "-m", type=int, default=5,
                        help="Max anti-patterns to insert (default: 5)")
    args = parser.parse_args()

    process_file(args.input, seed=args.seed, max_insertions=args.max)


if __name__ == "__main__":
    main()
Extending the inserter — To add a new anti-pattern, define a new tuple in ANTI_PATTERNS, write an insert_<name>() function, and append it to the INSERTERS list. The orchestrator handles shuffling, seeding, and ground-truth logging automatically.

Why Synthetic Insertion Scales Evaluation Data

Building evaluation datasets from real vulnerabilities is slow, expensive, and often legally fraught. Synthetic insertion sidesteps all three problems while delivering better data for benchmarking.

Data Volume

A single clean repository can yield thousands of distinct evaluation samples by varying the seed, the insertion count, and the subset of anti-patterns applied. No need to mine CVEs or wait for bug bounties: you control the supply curve entirely.

Controlled Ground Truth

Every insertion is recorded with line number, column, snippet, CWE identifier, and severity. There is zero ambiguity about what constitutes a finding — something that is notoriously difficult to achieve with human-labelled data where inter-annotator agreement on severity alone can be below 60 %.

Edge-Case Coverage

Want to test how your evaluator handles nested SQL injection inside a ternary expression inside an f-string? Write a specialised inserter for that pattern. Synthetic generation makes it possible to cover long-tail edge cases that would never appear in a manually curated benchmark of realistic size.

Reproducibility

Because the process is deterministic given a seed, two researchers can independently generate identical datasets from the same source file and seed value. This enables direct comparison of results across papers and teams without transferring large dataset files.

Known limitation — Synthetic anti-patterns may not capture the full subtlety of real-world vulnerabilities (e.g. business-logic flaws, multi-step exploits). Always supplement synthetic benchmarks with a curated set of real-world samples. The inserter is designed to augment, not replace, traditional evaluation data.

When used as part of a continuous eval pipeline, the seeded inserter enables a workflow where every commit to the evaluator triggers a fresh benchmark run against newly generated data. This catches regressions in the AI reviewer before they reach production — without any human effort to label the test cases.
