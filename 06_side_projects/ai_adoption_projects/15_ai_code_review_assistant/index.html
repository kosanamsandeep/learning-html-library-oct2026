Project 15 · Cross-Cutting · Capstone

AI Code Review Assistant

An end-to-end pipeline that reviews every PR against your organisation's anti-pattern corpus, updates the SBOM when dependencies change, and cryptographically signs the review output with the CI system's identity. It weaves eval, supply chain security, and attestation into a single automated workflow.

Pipeline Architecture

Unlike isolated tools that handle one concern, this capstone project builds a multi-stage pipeline that touches every challenge area of AI adoption in a production environment: evaluation (review against known anti-patterns), supply chain (SBOM diffing and signing), and governance (verifiable attestation of automated reviews).

Starter Code — Pipeline Orchestration

import json
import hashlib
import subprocess
from pathlib import Path
from typing import Optional

# ----- Stage 1: Anti-Pattern Scan + LLM Review -----

ANTI_PATTERN_CORPUS = {
    "sql-injection": {"pattern": r"execute\(.*\+.*\)", "severity": "critical"},
    "hardcoded-secret": {"pattern": r"(password|secret|api_key)\s*=\s*['\"][^'\"]+['\"]", "severity": "high"},
    "shell-injection": {"pattern": r"os\.system\(.*\+.*\)", "severity": "critical"},
    "insecure-deserialization": {"pattern": r"pickle\.loads\(.*\)", "severity": "high"},
    "weak-crypto": {"pattern": r"md5\(|sha1\(", "severity": "medium"},
}


def stage_review(diff_text: str) -> dict:
    """Scan diff against anti-pattern corpus and run LLM review."""
    findings = []
    for name, spec in ANTI_PATTERN_CORPUS.items():
        import re
        matches = re.finditer(spec["pattern"], diff_text)
        for m in matches:
            line_num = diff_text[:m.start()].count("\n") + 1
            findings.append({
                "pattern": name,
                "severity": spec["severity"],
                "line": line_num,
            })
    # In production: call LLM for deeper review
    return {
        "anti_pattern_matches": findings,
        "llm_findings": [],
        "overall_score": max(0, 100 - len(findings) * 15),
    }


# ----- Stage 2: SBOM Generation and Diff -----

def generate_sbom(repo_path: Path) -> dict:
    """
    Wrap a tool like syft or cdxgen to produce
    an SBOM in CycloneDX JSON format.
    """
    result = subprocess.run(
        ["syft", str(repo_path), "-o", "cyclonedx-json"],
        capture_output=True, text=True, timeout=120,
    )
    if result.returncode != 0:
        raise RuntimeError(f"SBOM generation failed: {result.stderr}")
    return json.loads(result.stdout)


def diff_sbom(base_sbom: dict, head_sbom: dict) -> dict:
    """
    Compare two CycloneDX SBOMs and return added,
    removed, and vulnerable components.
    """
    def _pkg_set(sbom: dict) -> set:
        return set(
            f"{c['name']}@{c['version']}"
            for c in sbom.get("components", [])
        )

    base = _pkg_set(base_sbom)
    head = _pkg_set(head_sbom)
    return {
        "added": sorted(head - base),
        "removed": sorted(base - head),
        "vulnerable": [],  # In production: query OSV/GHSA
    }


# ----- Stage 3: Signing -----

def sign_report(report: dict, key_id: str = "ci-bot@org.com") -> dict:
    """
    Sign the report digest with the CI identity.
    Uses cosign keyless signing in production.
    """
    report_bytes = json.dumps(report, sort_keys=True).encode()
    digest = hashlib.sha256(report_bytes).hexdigest()
    # In production: subprocess.run(["cosign", "sign-blob", ...])
    report["signature"] = {
        "key_id": key_id,
        "digest": f"sha256:{digest}",
        "algorithm": "sha256",
        "signed_at": "2025-07-14T15:30:00Z",  # use datetime.utcnow()
    }
    return report


# ----- Full Pipeline -----

def run_pipeline(pr_number: int, repo_path: Path, base_sbom: Optional[dict] = None) -> dict:
    # Gather diff
    result = subprocess.run(
        ["git", "diff", "origin/main..."],
        capture_output=True, text=True, cwd=repo_path,
    )
    diff_text = result.stdout

    # Stage 1
    review_results = stage_review(diff_text)

    # Stage 2
    head_sbom = generate_sbom(repo_path)
    sbom_delta = diff_sbom(base_sbom or {}, head_sbom)

    # Build envelope
    report = {
        "pr": {
            "number": pr_number,
            "sha": subprocess.run(
                ["git", "rev-parse", "HEAD"],
                capture_output=True, text=True, cwd=repo_path,
            ).stdout.strip(),
        },
        "review_results": review_results,
        "sbom_delta": sbom_delta,
    }

    # Stage 3: sign
    report = sign_report(report)
    return report


# ----- CLI entry point -----

if __name__ == "__main__":
    report = run_pipeline(
        pr_number=1234,
        repo_path=Path("/tmp/my-repo"),
        base_sbom=None,
    )
    print(json.dumps(report, indent=2))

How the Three Challenge Areas Intersect

This project demonstrates that AI eval, supply chain security, and governance are not independent concerns—they interact in production in ways that isolated tools miss:

Eval + Supply Chain

An AI-generated code change that introduces a vulnerable dependency (e.g. a known-vulnerable version of a logging library) would be caught by the review LLM, but only the SBOM diff can confirm the version change. Together they provide defence in depth.

Eval + Signing

Without signing, there is no way to prove that the review was actually performed by the CI system and not forged. Signing links the review output to a specific pipeline run, enabling audit trails and non-repudiation.

Supply Chain + Signing

The SBOM delta is useless if it can be tampered with. Signing the combined report ensures that the dependency changes detected by the pipeline are the ones visible in the audit log, not modified after the fact.

All Three + Observability

The signed report becomes a verifiable data point for the governance dashboard (Project 16). It feeds metrics like "percentage of PRs reviewed by AI" and "mean time to address flagged dependencies."

Capstone takeaway: The most robust AI-assisted workflows embed evaluation and security checks into a pipeline that is verifiable by design. Anyone inspecting a PR should be able to trace the review back through the signed attestation to the specific pipeline run, agent configuration, and anti-pattern corpus version used.
