Benchmark Mapping Tool

For every bug in SWE-bench (or any public benchmark), tag it with language, category, difficulty, and context length required. Then overlay your own organisation's bug distribution to see where the benchmark covers your needs—and where it doesn't.

The Gap Analysis Problem

Engineering teams frequently adopt public benchmarks (SWE-bench, HumanEval, MBPP, etc.) to evaluate code-generation models. The implicit assumption: if a model scores well on the benchmark, it will perform well on our codebase. This is frequently false.

Using the Analysis to Justify a Custom Eval Framework

A mapping tool doesn't just produce pretty charts—it gives you data to make strategic decisions about your eval investment.

Scenario A: High overlap (>60%)

Your org's bug profile closely matches the benchmark. You can use the public benchmark as your primary eval, supplemented by a small set of org-specific tests. Investment: low.

Scenario B: Moderate overlap (30-60%)

The benchmark covers some of your needs but misses significant portions. Use the mapping to identify which dimensions are uncovered and build targeted custom evals for those. Investment: medium.

Scenario C: Low overlap (<30%)

Your stack differs fundamentally from the benchmark (e.g. proprietary language, embedded systems, domain-specific bugs). A public benchmark may mislead your eval strategy. Build a custom eval framework from scratch. Investment: high, but necessary.

Pro tip: Run the mapping quarterly. As your codebase evolves and new benchmarks emerge, the overlap region shifts. An annual check can save you from silently training against a stale benchmark.

Starter Code — Downloading and Analysing SWE-bench Metadata

import json
import csv
from collections import Counter, defaultdict
from typing import Optional

# ----- Step 1: Fetch SWE-bench metadata -----
# SWE-bench publishes metadata as a JSON array of instances.
# Each instance describes a GitHub PR with a bug fix.

SWE_BENCH_URL = (
    "https://raw.githubusercontent.com/princeton-nlp/SWE-bench/"
    "main/swebench/harness/metadata/swe-bench.json"
)


def fetch_swebench_metadata(url: str = SWE_BENCH_URL) -> list[dict]:
    """Download and parse SWE-bench instance metadata."""
    import urllib.request

    with urllib.request.urlopen(url) as f:
        data = json.loads(f.read().decode("utf-8"))
    return data


# ----- Step 2: Classify each instance -----

def classify_instance(instance: dict) -> dict:
    """
    Extract or deduce dimensions from a SWE-bench entry.

    Each entry looks roughly like:
    {
      "instance_id": "django__django-12345",
      "repo": "django/django",
      "base_commit": "...",
      "hints_text": "...",
      "problem_statement": "...",
      "patch": "..."
    }
    """
    repo: str = instance.get("repo", "")
    instance_id: str = instance.get("instance_id", "")
    problem: str = instance.get("problem_statement", "")
    patch: str = instance.get("patch", "")
    hints: Optional[str] = instance.get("hints_text")

    # Simple language inference from repo name
    lang_map = {
        "django": "Python",
        "sympy": "Python",
        "astropy": "Python",
        "flask": "Python",
        "pylint": "Python",
        "matplotlib": "Python",
        "requests": "Python",
        "scikit-learn": "Python",
    }
    language = "Python"  # SWE-bench is Python-dominated

    # Category heuristic based on problem text
    category = "logic error"
    if "crash" in problem.lower() or "exception" in problem.lower():
        category = "error handling"
    elif "secur" in problem.lower() or "injection" in problem.lower():
        category = "security"
    elif "performance" in problem.lower() or "slow" in problem.lower():
        category = "performance"
    elif "race" in problem.lower() or "deadlock" in problem.lower():
        category = "concurrency"

    # Rough context length (lines changed)
    changed_lines = len(patch.splitlines()) if patch else 0
    if changed_lines < 20:
        difficulty = "Easy"
    elif changed_lines < 80:
        difficulty = "Medium"
    else:
        difficulty = "Hard"

    return {
        "instance_id": instance_id,
        "repo": repo,
        "language": language,
        "category": category,
        "difficulty": difficulty,
        "context_lines": changed_lines,
        "has_hints": hints is not None,
    }


# ----- Step 3: Generate tag distribution -----

def build_tag_report(instances: list[dict]) -> dict:
    """Aggregate tag distributions across dimensions."""
    classified = [classify_instance(i) for i in instances]

    report = {
        "total": len(classified),
        "by_language": Counter(),
        "by_category": Counter(),
        "by_difficulty": Counter(),
        "languages_detail": defaultdict(lambda: Counter()),
    }

    for c in classified:
        report["by_language"][c["language"]] += 1
        report["by_category"][c["category"]] += 1
        report["by_difficulty"][c["difficulty"]] += 1
        report["languages_detail"][c["language"]][c["category"]] += 1

    return report


# ----- Step 4: Compare with your org's bugs -----
# (Assume org_bugs.csv has same schema)

def load_org_bugs(path: str = "org_bugs.csv") -> list[dict]:
    """Load your organisation's tagged bug dataset."""
    bugs = []
    with open(path, newline="") as f:
        reader = csv.DictReader(f)
        for row in reader:
            bugs.append(row)
    return bugs


def compute_overlap(
    bench_tagged: list[dict],
    org_tagged: list[dict],
) -> dict:
    """
    Returns per-dimension overlap stats.
    Overlap = proportion of org bugs that share
    at least one tag with a benchmark bug.
    """
    bench_sets = {
        dim: set(b[dim] for b in bench_tagged)
        for dim in ["language", "category", "difficulty"]
    }
    org_sets = {
        dim: set(b[dim] for b in org_tagged)
        for dim in ["language", "category", "difficulty"]
    }

    overlap = {}
    for dim in bench_sets:
        intersection = bench_sets[dim] & org_sets[dim]
        overlap[dim] = {
            "bench_unique": len(bench_sets[dim] - org_sets[dim]),
            "org_unique": len(org_sets[dim] - bench_sets[dim]),
            "shared": len(intersection),
            "shared_values": sorted(intersection),
        }
    return overlap


# ----- Step 5: Visualise (with matplotlib) -----

def plot_distributions(report: dict, org_report: dict):
    """Side-by-side bar charts of benchmark vs org distributions."""
    import matplotlib.pyplot as plt

    fig, axes = plt.subplots(1, 3, figsize=(15, 5))

    for i, dim in enumerate(["language", "category", "difficulty"]):
        bench_counts = report[f"by_{dim}"]
        org_counts = org_report.get(f"by_{dim}", {})

        labels = sorted(set(list(bench_counts.keys()) + list(org_counts.keys())))
        bench_vals = [bench_counts.get(l, 0) for l in labels]
        org_vals = [org_counts.get(l, 0) for l in labels]

        x = range(len(labels))
        axes[i].bar([v - 0.2 for v in x], bench_vals, width=0.4, label="Benchmark")
        axes[i].bar([v + 0.2 for v in x], org_vals, width=0.4, label="Org")
        axes[i].set_title(dim)
        axes[i].set_xticks(list(x))
        axes[i].set_xticklabels(labels, rotation=45)
        axes[i].legend()

    plt.tight_layout()
    plt.savefig("benchmark_mapping.png", dpi=150)
    print("Saved benchmark_mapping.png")

Extending the Tool

  • Multiple benchmarks: Add SWE-bench-lite, HumanEval, MBPP, and BigCodeBench. Compare overlap across all of them to pick the best-fit public eval.
  • Tag confidence: Instead of hard classification, use an LLM to read the problem statement and assign tags with confidence scores.
  • Trend over time: Track your organisation's bug distribution quarterly. If you're shifting toward a new language or domain, the overlap with existing benchmarks changes.
  • Custom eval ROI calculator: Estimate the cost of building custom evals for the "org only" region versus the cost of false positives from an ill-fitting benchmark.
Bottom line: A benchmark mapping tool turns the question "Is our model good?" into the more actionable "Good at what, compared to our actual bug profile?" It's the first step toward a custom eval framework that measures what actually matters to your team.
