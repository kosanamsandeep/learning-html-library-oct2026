Project 03

Agent Audit Trail Hook

A Git prepare-commit-msg hook that automatically appends an AI attribution footer to every commit message — providing traceability, compliance, and metadata standards for AI-generated or AI-assisted code.

OVERVIEW

Why trace AI contributions?

As AI-generated code becomes a larger share of production codebases, teams need answers to three questions:

  • Accountability: Which parts of this commit were written by a human, which were AI-generated, and which were AI-assisted (human-edited)?
  • Compliance: Some regulated industries require disclosure of AI-generated code. Licenses (e.g., MIT vs. GPL) may apply differently to AI outputs depending on jurisdiction.
  • Debugging: When an AI-generated pattern causes a bug, knowing the tool, model, and prompt that produced it speeds up root-cause analysis.

The Agent Audit Trail Hook solves this by intercepting every commit and appending a structured metadata footer to the commit message. The metadata is human-readable and machine-parseable, so it works in git log, code reviews, and compliance dashboards.

Principle: Make AI attribution automatic, structured, and non-optional. If the hook isn't installed, clearly distinguish AI-assisted from purely human commits via the message footer conventions.

The prepare-commit-msg hook intercepts the commit before the editor opens, giving the developer a chance to see and edit the attribution before finalizing.

Git provides several hook points for commit messages:

Hook When it fires What we do
prepare-commit-msg After the default message is created, before the editor opens Append the AI attribution footer. The developer sees it and can edit or remove it if the commit is purely human.
commit-msg After the editor closes, before the commit is finalized Validate that the footer is present (or has an explicit AI-Skip: true marker). Reject if missing.
STARTER CODE

Bash — prepare-commit-msg hook

Save this script as .git/hooks/prepare-commit-msg in your repository and make it executable (chmod +x .git/hooks/prepare-commit-msg). It reads environment variables that your AI tools set before invoking git, and appends a structured attribution footer.

#!/usr/bin/env bash
# .git/hooks/prepare-commit-msg — Append AI attribution footer to commit messages.
#
# Environment variables (set by AI coding tools before calling git commit):
#   AI_AGENT        — tool name, e.g. "claude-code", "copilot", "cursor"
#   AI_MODEL        — model identifier, e.g. "claude-sonnet-4", "gpt-4o"
#   AI_SESSION_ID   — unique session identifier for traceability
#   AI_ASSISTANCE   — "generated" | "assisted" | "reviewed" | empty

set -euo pipefail

COMMIT_MSG_FILE="$1"
COMMIT_SOURCE="${2:-}"    # e.g. "message", "template", "merge", "squash"

# If the commit already has an AI footer, skip.
if grep -q "^Co-authored-by:.*<.*@.*>" "$COMMIT_MSG_FILE" 2>/dev/null; then
    exit 0
fi

# Determine if this is an AI-assisted commit
AI_AGENT="${AI_AGENT:-}"
AI_MODEL="${AI_MODEL:-}"
AI_SESSION="${AI_SESSION_ID:-}"
AI_ASSISTANCE="${AI_ASSISTANCE:-}"

# If no AI variables are set, check if this looks like a merge/amendsquash — skip those
if [ -z "$AI_AGENT" ] && [ -z "$AI_MODEL" ]; then
    # No AI metadata — could be human-only. Leave message as-is.
    exit 0
fi

# Build the footer
FOOTER=""
FOOTER+=$'\n\n---\n'

# Co-authored-by lines (standard Git convention)
if [ -n "$AI_AGENT" ]; then
    FOOTER+="Co-authored-by: $AI_AGENT <ai+$AI_AGENT@git.local>\n"
fi

# AI metadata block (machine-parseable)
FOOTER+=$"AI-Agent: ${AI_AGENT:-unknown}\n"
FOOTER+=$"AI-Model: ${AI_MODEL:-unknown}\n"
if [ -n "$AI_SESSION" ]; then
    FOOTER+=$"AI-Session: $AI_SESSION\n"
fi
if [ -n "$AI_ASSISTANCE" ]; then
    FOOTER+=$"AI-Assistance: $AI_ASSISTANCE\n"
fi

# Append the footer to the commit message
printf "$FOOTER" >> "$COMMIT_MSG_FILE"

Accompanying validation hook — commit-msg

Save as .git/hooks/commit-msg (also executable) to require the footer on AI-assisted commits:

#!/usr/bin/env bash
# .git/hooks/commit-msg — Validate that AI attribution footer is present or explicitly skipped.

set -euo pipefail
COMMIT_MSG_FILE="$1"

# Allow explicit skip
if grep -q "^AI-Skip: true" "$COMMIT_MSG_FILE" 2>/dev/null; then
    exit 0
fi

# Enforce footer presence if AI involvement is declared
if grep -qE "^(AI-Agent|AI-Model|Co-authored-by.*ai)" "$COMMIT_MSG_FILE" 2>/dev/null; then
    # Footer present — good
    exit 0
fi

# If AI_AGENT environment variable is set but footer is missing, reject
if [ -n "${AI_AGENT:-}" ]; then
    echo "ERROR: AI agent detected ($AI_AGENT) but no attribution footer found." >&2
    echo "Add an AI-Skip: true line if this is intentionally human-only." >&2
    exit 1
fi
METADATA STANDARDS

What to track — and why

A well-designed attribution footer balances completeness with readability. Here is the recommended set of metadata fields and the rationale for each:

Field Example Purpose
Co-authored-by claude-code <ai+claude-code@git.local> Standard Git trailer — visible in git log, GitHub UI, and code review tools. Humans and AI appear the same way.
AI-Agent claude-code, copilot, cursor Identifies the tool. Useful for tracking which AI tools are being used in the codebase.
AI-Model claude-sonnet-4-20250514, gpt-4o Identifies the specific model version. Critical for debugging: if a model update changes behavior, you can see which commits used which version.
AI-Session uuid-a1b2c3d4-... Correlates all commits from a single AI session. Helps reconstruct the context in which changes were generated.
AI-Assistance generated, assisted, reviewed Degree of AI involvement. generated = fully AI-written, assisted = human edited AI output, reviewed = human wrote, AI reviewed.
AI-Skip true Explicit human-only marker. Lets the validation hook distinguish "forgotten footer" from "intentionally human commit".
Recommendation: Configure your AI coding tools to set these environment variables before invoking git. For example, Claude Code sets CLAUDE_CODE_SESSION_ID — your hook can map it to AI_SESSION_ID. Add a shell alias like alias gcam='AI_AGENT=manual git commit -a -m' for human commits.
STEP-BY-STEP

How to adopt this project

1
Create the hook files — write prepare-commit-msg and commit-msg into .git/hooks/. Make both executable (chmod +x).
2
Configure your AI tools — set up environment variables like AI_AGENT and AI_MODEL in your AI tooling's config. For Claude Code, wrap it in a script that exports these before calling git commit.
3
Test the flow — make an AI-assisted change and run git commit. Verify the footer appears in the editor. Accept and check git log.
4
Add to template — if using git init or a cookiecutter template, include these hooks in hooks/ and run git config core.hooksPath hooks so they're shared with the team.
5
Build a compliance dashboard — parse git log --format=full to extract AI metadata, count AI vs. human commits, and identify which agents and models are most used.
Team tip: Store hooks in a .githooks/ directory at the repo root and run git config core.hooksPath .githooks so every clone gets them automatically.
