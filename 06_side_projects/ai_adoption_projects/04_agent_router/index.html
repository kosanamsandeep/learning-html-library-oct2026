Project 04

Agent Router

A thin orchestrator that classifies incoming tasks by type and routes them to the most capable agent in your pool — with fallback strategies, capability registries, and graceful degradation when no agent matches perfectly.

OVERVIEW

Why route instead of hard-code?

Organizations that adopt AI coding tools rarely stop at one. A typical setup might include:

  • Claude Code for architecture design, planning, and refactoring
  • GitHub Copilot for inline autocomplete and quick function generation
  • A custom MCP-augmented agent for domain-specific tasks like security analysis or database schema design
  • A fast, cheap model (e.g., Claude Haiku) for formatting, linting, and simple Q&A

Without a router, the developer manually decides which tool to use for each task — a slow, inconsistent process. The Agent Router automates this decision: it classifies the task, consults a capability registry, and dispatches to the best matching agent.

Key principle: Routing is classification + dispatch. Switching is manual. A router makes agent selection systematic, transparent, and auditable.

The router classifies every incoming task, matches it against the agent registry, and dispatches to the highest-scoring agent — or falls back to a general-purpose agent.

The routing decision has four stages:

  1. Classification: Extract task type, domain, complexity, and required capabilities from the user input. This can be an LLM call, a few-shot classifier, or a rule-based heuristic (keyword matching).
  2. Registration: Each agent declares its capabilities in a registry — what task types it handles, what models it uses, its strengths and limitations.
  3. Scoring: Compare the task profile against each agent's capability profile. Produce a match score (0.0 - 1.0) for each agent.
  4. Dispatch: Send the task to the agent with the highest score. If all scores fall below a threshold, route to a fallback agent instead.
STARTER CODE

Python — router core logic

The following implementation shows the pure routing logic decoupled from any specific agent SDK. The agent registry is declarative, the classifier is a simple keyword-based heuristic (upgradable to an LLM classifier), and the dispatcher is a clean match → score → route pipeline.

"""agent_router.py — Classify, match, and dispatch tasks to the right agent."""

from dataclasses import dataclass, field
from typing import Callable, Literal
import re


# ---------------------------------------------------------------------------
# Data models
# ---------------------------------------------------------------------------


@dataclass
class TaskProfile:
    """What we know about an incoming task after classification."""
    raw_input: str
    task_type: str                     # "code_gen" | "review" | "architect" | "explain" | "security" | ...
    domain: str = "general"              # "python" | "fastapi" | "infra" | ...
    complexity: Literal["low", "medium", "high"] = "medium"
    language: str = "python"
    requires_context: bool = False


@dataclass
class AgentCapability:
    """What an agent can do and how good it is at it."""
    name: str
    description: str
    task_types: list[str]                  # task types it handles
    domains: list[str]                     # domain specializations
    max_complexity: Literal["low", "medium", "high"] = "high"
    supports_context: bool = True
    invoke: Callable[[str], str] = field(repr=False)  # how to call this agent


# ---------------------------------------------------------------------------
# Classifier
# ---------------------------------------------------------------------------


def classify_task(user_input: str) -> TaskProfile:
    """Heuristic classifier. Replace with an LLM call for stronger accuracy."""
    text = user_input.lower()

    # Task type heuristics
    if re.search(r"review|audit|check|security|vulnerab", text):
        task_type = "security"
    elif re.search(r"architect|design|plan|schema|system|diagram", text):
        task_type = "architect"
    elif re.search(r"explain|what is|how does|why|difference|compare", text):
        task_type = "explain"
    elif re.search(r"write|implement|create|add|refactor|update|fix", text):
        task_type = "code_gen"
    else:
        task_type = "code_gen"

    # Domain detection
    domain = "general"
    if re.search(r"fastapi|django|flask|api|endpoint|route", text):
        domain = "web"
    elif re.search(r"docker|kubernetes|k8s|deploy|ci|cd|terraform", text):
        domain = "infra"
    elif re.search(r"sql|database|query|schema|migration|orm", text):
        domain = "data"

    # Complexity estimate
    complexity = "medium"
    if re.search(r"simple|quick|trivial|easy|format|rename", text):
        complexity = "low"
    elif re.search("complex|advanced|large|multi|distributed|optimize", text):
        complexity = "high"

    return TaskProfile(
        raw_input=user_input,
        task_type=task_type,
        domain=domain,
        complexity=complexity,
        requires_context="context" in text or "existing" in text,
    )


# ---------------------------------------------------------------------------
# Matching & scoring
# ---------------------------------------------------------------------------

def score_agent(task: TaskProfile, agent: AgentCapability) -> float:
    """Score how well an agent matches a task (0.0 - 1.0)."""
    score = 0.0

    # Task type match (highest weight)
    if task.task_type in agent.task_types:
        score += 0.5

    # Domain match
    if task.domain in agent.domains:
        score += 0.2
    elif "general" in agent.domains:
        score += 0.1

    # Complexity fit
    complexity_order = {"low": 0, "medium": 1, "high": 2}
    if complexity_order[task.complexity] <= complexity_order[agent.max_complexity]:
        score += 0.2
    else:
        score += 0.05  # can still try but not ideal

    # Context support
    if task.requires_context and agent.supports_context:
        score += 0.1

    return min(score, 1.0)


def route(
    task: TaskProfile,
    agents: list[AgentCapability],
    threshold: float = 0.3,
) -> AgentCapability:
    """Route the task to the best-matching agent, falling back if needed."""
    scored = [(score_agent(task, a), a) for a in agents]
    scored.sort(key=lambda x: x[0], reverse=True)

    best_score, best_agent = scored[0]
    if best_score < threshold:
        # Below threshold — find fallback agent
        fallbacks = [a for a in agents if "fallback" in a.task_types]
        if fallbacks:
            return fallbacks[0]
        return best_agent  # best effort

    return best_agent


# ---------------------------------------------------------------------------
# Example usage
# ---------------------------------------------------------------------------

if __name__ == "__main__":
    # Define agent pool
    agents = [
        AgentCapability(
            name="claude-code",
            description="Architecture and planning agent",
            task_types=["architect", "code_gen", "explain"],
            domains=["general", "web", "infra", "data"],
            max_complexity="high",
            supports_context=True,
            invoke=lambda msg: f"[claude-code] {msg[:50]}...",
        ),
        AgentCapability(
            name="copilot",
            description="Inline code generation agent",
            task_types=["code_gen"],
            domains=["general", "web"],
            max_complexity="medium",
            supports_context=True,
            invoke=lambda msg: f"[copilot] {msg[:50]}...",
        ),
        AgentCapability(
            name="security-agent",
            description="Security review agent",
            task_types=["security", "review"],
            domains=["web", "infra"],
            max_complexity="high",
            supports_context=True,
            invoke=lambda msg: f"[security-agent] {msg[:50]}...",
        ),
        AgentCapability(
            name="quick-agent",
            description="Fast, cheap agent for simple tasks",
            task_types=["code_gen", "explain", "fallback"],
            domains=["general"],
            max_complexity="low",
            supports_context=False,
            invoke=lambda msg: f"[quick-agent] {msg[:50]}...",
        ),
    ]

    # Simulate tasks
    tasks = [
        "Design a microservices architecture for an e-commerce platform",
        "Write a FastAPI endpoint for user registration",
        "Review this code for security vulnerabilities: ...",
        "Rename the variable `x` to `user_count`",
    ]

    for t in tasks:
        profile = classify_task(t)
        agent = route(profile, agents)
        print(f"Task: {t}")
        print(f"  → Classified: type={profile.task_type}, domain={profile.domain}, complexity={profile.complexity}")
        print(f"  → Routed to: {agent.name} (score: {score_agent(profile, agent):.2f})")
        print()
DEEP DIVE

Routing vs. switching — why it matters

These terms are often used interchangeably, but they describe fundamentally different mechanisms:

Dimension Routing Switching
Decision basis Task characteristics (type, domain, complexity, required capabilities) Simple rule (e.g., "if file is .py, use Copilot") or manual choice
Granularity Per-task — each task is individually classified and routed Per-session or per-file — the same agent handles everything
Fallback Graceful degradation: score below threshold → fallback agent Hard failure: "this agent can't handle that" with no recovery
Observability Routing decisions are logged, scored, and auditable Choice is opaque — no record of why an agent was chosen
Adaptability New agents register capabilities; scoring adjusts automatically Rules must be manually updated when the agent pool changes
When to use each: Use routing when you have 3+ agents with overlapping capabilities and tasks that vary in type and complexity. Use switching (a simple if-else) when you have exactly two agents with clearly separated responsibilities — but be prepared to upgrade to routing as the system grows.
STEP-BY-STEP

How to adopt this project

1
Define your agent pool — list every coding agent your team uses. For each, document: what task types it handles, what domains it knows, its maximum complexity, and whether it can access project context.
2
Build the registry — represent each agent as a AgentCapability object (as in the starter code). Store the registry in a JSON or YAML file for easy editing.
3
Implement the classifier — start with keyword heuristics (fast, no external dependency). If accuracy is insufficient, swap to an LLM call that returns structured JSON.
4
Choose a fallback strategy — options: route to a general-purpose agent, ask the user to choose, or return an error with the available agents. The starter code uses a "quick-agent" fallback.
5
Add observability — log every routing decision: task, classification, scores, chosen agent, response time. Use this data to tune thresholds and detect when agents' capabilities drift.
