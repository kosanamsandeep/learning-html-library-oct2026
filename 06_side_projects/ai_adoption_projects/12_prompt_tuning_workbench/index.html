The fan-out / fan-in pattern: one corpus, many prompt variants, parallel evaluations, and a single dashboard for evidence-based decisions.

🤔 What & Why

Prompt tuning is the iterative process of adjusting a prompt's wording, structure, instructions, and examples to maximise consistency, accuracy, and usefulness of a language model's outputs. It is the primary lever for improving model performance without retraining.

The Case for Systematic Tuning

Problem Ad-hoc Approach Systematic Tuning
Small wording tweaks Go with intuition, no record Track every variant side-by-side
Which prompt is best? Vibe check on 2 examples Score across a representative corpus
Regression catching Discover later in production Catch early via eval harness
Knowledge transfer Prompt lives in one person's head Shared dashboard + versioning

Core Disciplines

🧪 Controlled Experimentation
Change one variable at a time. Keep the corpus, model, temperature, and evaluation rubric fixed so you can attribute any score difference to the prompt change alone.
🔬 A/B Testing for Prompts
Treat each prompt variant as a hypothesis. Run both variants against the same inputs and measure with the same rubric. Blind scoring reduces bias.
📊 Result Visualisation
A table of numbers is hard to scan. Build radar charts, bar comparisons, and per-question heatmaps to spot patterns that aggregate scores hide.

🏷 Experiment Design for Prompt Changes

Warning: Without proper experiment design, you risk overfitting to a handful of examples, chasing noise, or deploying regressions. The following framework mitigates those risks.

1. Controlling Variables

Every experiment compares a control (your current production prompt) against one or more treatments. Hold these fixed:

  • Model & version — different model families or even checkpoint versions behave differently.
  • Temperature & sampling params — if you vary temperature you confound prompt quality with randomness.
  • Evaluation rubric — the same scoring function must judge every variant.
  • Corpus — use the same test questions in the same order. Stratify by difficulty, domain, and expected output shape.

2. Statistical Significance

A 3-point accuracy difference on 10 questions is not reliable. Use these heuristics to know when a difference matters:

Corpus Size Detectable Effect Confidence
10 – 20> 15 ppLow — directional only
30 – 50> 10 ppMedium — useful signal
75 – 150> 5 ppGood — reliable ranking
200+> 3 ppStrong — statistically significant

pp = percentage points. Smaller effects require larger N. Use McNemar's test or a paired bootstrap for significance testing.

3. Iteration Strategies

🔀 Binary Search
Start with two extreme variants (verbose vs. terse). Pick the winner, then split the difference. Converges quickly on the right level of detail.
📝 Factor Isolation
Change one atomic factor per round: role assignment, delimiter style, output format, example count, instruction position. Build a table of which factors matter.
🧱 Ensemble Selection
If no single variant dominates across all metrics, combine the best elements: take Variant B's instructions + Variant D's format into a new hybrid variant and re-run.

4. Keeping an Experiment Log

Every tuning round should record:

Pro tip: Version your prompts in a Git repository alongside the evaluation corpus. Tag each tuning round so you can reproduce any past result in one command.

📑 Scoring Rubric Template

A good rubric makes evaluation objective and repeatable. Below is a four-dimension example you can adapt. Each dimension is scored 0 – 4. 

{
  "dimensions": [
    {
      "name": "Accuracy",
      "description": "Are facts and figures correct?",
      "scale": "0 = major error, 4 = flawless"
    },
    {
      "name": "Completeness",
      "description": "Does it cover all requested aspects?",
      "scale": "0 = misses most, 4 = covers all"
    },
    {
      "name": "Conciseness",
      "description": "Is it appropriately brief?",
      "scale": "0 = rambling, 4 = efficiently stated"
    },
    {
      "name": "Format Adherence",
      "description": "Does output match the requested structure?",
      "scale": "0 = wrong format, 4 = perfect match"
    }
  ],
  "aggregation": "average across dimensions per question"
}

Scores can be assigned by a human, a judge LLM, or a programmatic checker, depending on the task. Always spot-check automated judges.
