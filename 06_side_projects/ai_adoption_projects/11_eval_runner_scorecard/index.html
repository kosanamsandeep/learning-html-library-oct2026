Eval Runner & Scorecard

A modular evaluation harness that feeds a curated corpus through an LLM API, collects responses, compares them against ground-truth labels, and produces a color-coded HTML scorecard with precision, recall, and F1 metrics. Designed for intermediate+ developers who want to systematically measure classifier and extractor quality before shipping to production.

What & Why

Eval Harness Design

An evaluation harness is the scaffolding that lets you run a large number of test cases through an LLM in a repeatable, auditable way. Instead of ad-hoc prompting, you define a corpus of input / ground-truth pairs, feed each one to the model through a consistent prompt template, and collect the raw output for later comparison.

Why it matters: Without a harness, evaluations become manual, inconsistent, and impossible to reproduce. A harness gives you a single command to re-run your entire test suite after any prompt change, model swap, or system prompt update.

LLM API Integration

The harness calls the LLM via a generic call_llm() function that abstracts over provider details. This lets you swap between models (GPT, Claude, Gemini, open-source via Ollama, etc.) without touching the evaluation logic. The function accepts a system prompt, a user prompt, and optional parameters (temperature, max tokens), and returns the response text.

Classification Metrics

For classification and extraction tasks the most widely used metrics are precision, recall, and their harmonic mean F1 score. Each is computed per label and then macro- or micro-averaged across all labels.

MetricFormulaWhat it measures
Precision TP / (TP + FP) Of the items the model flagged as positive, how many were truly positive?
Penalises false alarms.
Recall TP / (TP + FN) Of all the truly positive items, how many did the model catch?
Penalises misses.
F1 Score 2 × P × R / (P + R) Balanced single-number summary. High F1 means both precision and recall are solid.

Python Eval Loop

The core of the harness is a loop that reads the corpus, calls the LLM for each item, classifies the response, and accumulates confusion-matrix counts. The starter below uses a generic call_llm() placeholder — swap it with any provider SDK (OpenAI, Anthropic, etc.) to get started. 

import json, csv, os, sys
from dataclasses import dataclass, field
from typing import Any


# ---------------------------------------------------------------------------
# Corpus item — modify fields to match your task
# ---------------------------------------------------------------------------
@dataclass
class EvalItem:
    item_id: str
    text: str
    ground_truth: str          # expected label or extracted value


# ---------------------------------------------------------------------------
# Generic LLM caller — replace the body with your provider's SDK
# ---------------------------------------------------------------------------
def call_llm(system_prompt: str, user_prompt: str, **kwargs) -> str:
    """
    Send a prompt to the LLM and return the response text.

    Example with the Anthropic SDK:
        import anthropic
        client = anthropic.Anthropic()
        msg = client.messages.create(
            model="claude-sonnet-4-20250514",
            system=system_prompt,
            messages=[{"role": "user", "content": user_prompt}],
            max_tokens=kwargs.get("max_tokens", 512),
            temperature=kwargs.get("temperature", 0.0),
        )
        return msg.content[0].text

    Example with the OpenAI SDK:
        from openai import OpenAI
        client = OpenAI()
        resp = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user",   "content": user_prompt},
            ],
            max_tokens=kwargs.get("max_tokens", 512),
            temperature=kwargs.get("temperature", 0.0),
        )
        return resp.choices[0].message.content
    """
    raise NotImplementedError("Replace this function body with your LLM SDK call.")


# ---------------------------------------------------------------------------
# Label extraction from LLM output
# ---------------------------------------------------------------------------
def parse_label(raw: str) -> str:
    """Extract a classification label from the LLM's raw text response."""
    return raw.strip().split("\n")[0].strip().lower()


# ---------------------------------------------------------------------------
# Classification metrics
# ---------------------------------------------------------------------------
@dataclass
class Metrics:
    labels: list[str] = field(default_factory=list)
    precision: dict[str, float] = field(default_factory=dict)
    recall: dict[str, float] = field(default_factory=dict)
    f1: dict[str, float] = field(default_factory=dict)
    support: dict[str, int] = field(default_factory=dict)
    accuracy: float = 0.0
    macro_precision: float = 0.0
    macro_recall: float = 0.0
    macro_f1: float = 0.0


def compute_metrics(
    ground_truths: list[str],
    predictions: list[str],
) -> Metrics:
    labels = sorted(set(ground_truths) | set(predictions))
    conf: dict[tuple[str, str], int] = {}
    for gt, pred in zip(ground_truths, predictions):
        conf[(gt, pred)] = conf.get((gt, pred), 0) + 1

    m = Metrics(labels=labels)

    for label in labels:
        tp = conf.get((label, label), 0)
        fp = sum(conf.get((other, label), 0) for other in labels if other != label)
        fn = sum(conf.get((label, other), 0) for other in labels if other != label)
        support = tp + fn

        m.precision[label] = tp / (tp + fp) if (tp + fp) else 0.0
        m.recall[label]    = tp / (tp + fn) if (tp + fn) else 0.0
        m.f1[label]        = (2 * m.precision[label] * m.recall[label] /
                              (m.precision[label] + m.recall[label])
                              ) if (m.precision[label] + m.recall[label]) else 0.0
        m.support[label]   = support

    correct = sum(1 for gt, pred in zip(ground_truths, predictions) if gt == pred)
    m.accuracy = correct / len(ground_truths) if ground_truths else 0.0

    m.macro_precision = sum(m.precision[l] for l in labels) / len(labels) if labels else 0.0
    m.macro_recall    = sum(m.recall[l]    for l in labels) / len(labels) if labels else 0.0
    m.macro_f1        = sum(m.f1[l]        for l in labels) / len(labels) if labels else 0.0

    return m


# ---------------------------------------------------------------------------
# Main eval loop
# ---------------------------------------------------------------------------
SYSTEM_PROMPT = """You are a content classifier. Given an email, classify its intent
into exactly one of: support, billing, feature_request, spam, other.
Reply with ONLY the label — no explanation, no punctuation."""

USER_TEMPLATE = "Classify this email:\n\n{text}\n\nLabel:"


def run_eval(corpus: list[EvalItem]) -> Metrics:
    ground_truths: list[str] = []
    predictions: list[str] = []

    for i, item in enumerate(corpus):
        print(f"[{i+1}/{len(corpus)}] {item.item_id} ... ", end="", flush=True)
        try:
            user_prompt = USER_TEMPLATE.format(text=item.text)
            raw = call_llm(SYSTEM_PROMPT, user_prompt, temperature=0.0, max_tokens=64)
            pred = parse_label(raw)
        except Exception as exc:
            print(f"ERROR: {exc}")
            pred = "__error__"

        ground_truths.append(item.ground_truth)
        predictions.append(pred)
        print(pred)

    return compute_metrics(ground_truths, predictions)


# ---------------------------------------------------------------------------
# Corpus loader — adapt to your data format
# ---------------------------------------------------------------------------
def load_corpus(path: str) -> list[EvalItem]:
    items: list[EvalItem] = []
    with open(path, newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            items.append(EvalItem(
                item_id=row["id"],
                text=row["text"],
                ground_truth=row["label"].strip().lower(),
            ))
    return items


# ---------------------------------------------------------------------------
# Entry point
# ---------------------------------------------------------------------------
if __name__ == "__main__":
    corpus_path = sys.argv[1] if len(sys.argv) > 1 else "corpus.csv"
    corpus = load_corpus(corpus_path)
    metrics = run_eval(corpus)

    print("\n========== RESULTS ==========")
    print(f"Accuracy : {metrics.accuracy:.3f}")
    print(f"Macro-P  : {metrics.macro_precision:.3f}")
    print(f"Macro-R  : {metrics.macro_recall:.3f}")
    print(f"Macro-F1 : {metrics.macro_f1:.3f}")
    print()
    for label in metrics.labels:
        print(f"  {label:20s}  P={metrics.precision[label]:.3f}  "
              f"R={metrics.recall[label]:.3f}  F1={metrics.f1[label]:.3f}  "
              f"(n={metrics.support[label]})")
Pro tip: Use temperature=0.0 for evaluations — you want deterministic output so you can compare runs. Set max_tokens just large enough for a label so the harness stays fast and cheap.

Precision vs. Recall vs. F1: Tradeoffs

Choosing the right metric depends entirely on the cost of a false positive versus the cost of a false negative in your specific application. There is almost always a tension: improving precision tends to hurt recall, and vice versa.

Concrete Scenarios

Spam Filtering

Optimise for precision. A false positive (marking a legitimate email as spam) is far worse than letting an occasional spam message through. Users will tolerate a few spam emails in their inbox; they will not tolerate missing an important message. Here, high precision is worth sacrificing some recall.

Cancer Screening

Optimise for recall. Missing a positive case (false negative) could cost a life. A higher false-positive rate is acceptable because follow-up tests can rule out the healthy patients. The model needs to catch as many true positives as possible, even if it means more false alarms.

Search Relevance

Balance both (F1). A search engine that returns only perfect results (high precision) but misses most of the relevant documents (low recall) frustrates users. One that returns everything (high recall) but buries the best results in noise also frustrates users. F1 measures the sweet spot between the two.

Sentiment Routing

Macro F1. When a negative review is routed to the support team while a positive one is dropped, both false positives and false negatives have moderate but asymmetric costs. Macro F1 gives equal weight to each class and reveals whether the model is performing consistently across all sentiment levels.

When to Watch Each Metric

If you care about…Focus on…Because…
Not wasting users' time Precision Precision penalises false positives — alerts that go to the wrong team, misrouted tickets, irrelevant search results shown to the user.
Not missing critical items Recall Recall penalises false negatives — a support escalation that was ignored, a compliance violation that wasn't flagged, a bug report that was classified as "other."
Overall model health F1 + Accuracy F1 balances precision and recall. Accuracy gives a quick sanity check but can be misleading on imbalanced datasets (a model that always predicts "other" on a 95%-other corpus has 95% accuracy but 0% recall for minority classes).
Rare-class performance Per-label F1 + Macro F1 Macro F1 averages per-label F1 scores, treating small classes the same as large ones. If macro F1 is much lower than weighted F1, your model is failing on under-represented categories.
Watch out for accuracy paradox: On a severely imbalanced dataset (e.g., 98% class A, 2% class B), a model that always predicts A gets 98% accuracy but is useless. Always examine per-class precision, recall, and F1 — not just the top-line number.

Putting It All Together

Building an eval runner is one of the highest-leverage investments you can make in an LLM-powered product. The pattern is always the same:

  1. Curate a corpus of realistic inputs with human-verified ground-truth labels.
  2. Run the harness to collect model predictions for every item.
  3. Compare predictions to ground truth and compute confusion-matrix metrics.
  4. Generate a scorecard that makes regressions visible at a glance.
  5. Iterate on prompts, examples, or model choice and re-run.

With the starter code above you can have a working eval loop in minutes. Swap in your own corpus, your own call_llm() implementation, and your own label-extraction logic, and you will have a repeatable, auditable evaluation pipeline that grows with your project.
