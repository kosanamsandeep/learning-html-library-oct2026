🚦 API hardening & abuse prevention

A scalable API is also an attractive target: bots scrape it, scripts hammer it, and crafted requests try to exhaust it. Hardening means controlling how much, how fast, and how big — plus failing safely when limits are hit.

Every "unbounded" path is a denial-of-service waiting to happen. Bound rate, size, and query cost.

Rate limiting & throttling

Cap requests per client (by API key, user, or IP) to stop brute force, credential stuffing, scraping, and accidental floods. Use a shared store (Redis) so limits hold across replicas.

# Example with slowapi (a Starlette/FastAPI rate-limit helper)
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address, storage_uri="redis://cache:6379")

@app.post("/login")
@limiter.limit("5/minute")            # tight limit on sensitive endpoints
async def login(request: Request, body: LoginRequest):
    ...
Layer your limits: a global limit per IP at the edge, a per-user limit in the app, and stricter limits on expensive or sensitive routes (login, search, export). Return 429 Too Many Requests with a Retry-After header.

Bound the size of everything

Unbounded inputs are a DoS vector — a 2 GB body or a deeply nested JSON can exhaust memory before your code even runs.

Limit Where Stops
Max request body size Reverse proxy (nginx client_max_body_size) Memory exhaustion
Field length / list size Pydantic max_length, max_items Algorithmic blow-up
Upload size & type Stream + validate MIME/magic bytes Malicious/huge files
Request timeout Server/gateway timeouts Slowloris / hung connections
JSON depth/keys Validate or limit parser Billion-laughs-style attacks 
from pydantic import BaseModel, Field
from typing import Annotated

class BulkRequest(BaseModel):
    # Cap list length so a client can't ask you to process a million items at once.
    ids: Annotated[list[int], Field(max_length=100)]

Mass assignment / over-posting

If you bind a request body straight onto your DB model, an attacker can set fields you never meant to expose — like is_admin or account_balance.

❌ Vulnerable — trusts the whole payload

@app.patch("/me")
async def update_me(payload: dict, user: User = Depends(current_user)):
    await users.update(user.id, **payload)   # payload={"is_admin": true} 😱

✅ Hardened — explicit input schema, allow-list fields

class ProfileUpdate(BaseModel):
    model_config = {"extra": "forbid"}     # reject unknown fields
    display_name: str | None = None
    bio: str | None = None          # no is_admin, no balance here

@app.patch("/me")
async def update_me(payload: ProfileUpdate, user: User = Depends(current_user)):
    await users.update(user.id, **payload.model_dump(exclude_unset=True))
Strategy: use separate models for input and output. Never reuse your ORM/DB model as the request schema, and never serialize your DB model directly to the client (it leaks internal/sensitive fields).

Pagination & query cost control

An endpoint that returns "all" of something is a DoS button. Always paginate, cap the page size, and prefer keyset (cursor) pagination at scale.

from fastapi import Query

@app.get("/items")
async def list_items(
    limit: int = Query(20, ge=1, le=100),    # hard upper bound
    cursor: str | None = None,
    user: User = Depends(current_user),
):
    return await items.page(owner_id=user.id, limit=limit, after=cursor)
  • Add DB indexes for every filter/sort column to keep queries cheap.
  • Set statement timeouts on the DB so a pathological query can't run forever.
  • Beware N+1 queries and unbounded joins under attacker-controlled filters.

Safe error handling & observability

How you fail matters as much as how you succeed.

from fastapi import Request
from fastapi.responses import JSONResponse
import logging, uuid

log = logging.getLogger("app")

@app.exception_handler(Exception)
async def unhandled(request: Request, exc: Exception):
    trace_id = str(uuid.uuid4())
    # Full detail to logs (server-side), correlation id to client.
    log.exception("unhandled error", extra={"trace_id": trace_id, "path": request.url.path})
    return JSONResponse(status_code=500,
        content={"error": "internal_error", "trace_id": trace_id})
  • Log security events: auth failures, authz denials, rate-limit hits, input rejections — these are your breach early-warning system (OWASP A09).
  • Monitor & alert on spikes in 4xx/5xx, 401/403, and 429.
  • Never return stack traces or internal identifiers to clients.

API hardening checklist

  • Rate limits applied globally and tighter on sensitive endpoints; 429 + Retry-After.
  • Max body size enforced at the proxy; uploads streamed & type-checked.
  • List/field lengths bounded via Pydantic.
  • Separate input/output schemas; extra="forbid"; no ORM model as request body.
  • All list endpoints paginated with a hard limit cap.
  • DB indexes + statement timeouts in place.
  • Generic errors with trace IDs; security events logged & alerted.
