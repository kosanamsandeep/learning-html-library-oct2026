Two great frameworks, different eras

FastAPI vs Flask — when to pick which

Flask (2010) was built when blocking, synchronous Python web apps were the only thing anyone wrote. FastAPI (2018) was built on top of ASGI and type hints after both became standard. They feel similar but they're optimized for very different worlds.

The story Why this matters

Story: a team built their API in Flask. Each request hit Postgres, then called a third-party billing API (~400 ms), then returned. With 4 gunicorn workers they topped out at ~10 req/s — the workers spent 95% of their time waiting for the billing API. They moved the same logic to FastAPI + async + httpx. Same hardware, same workers. New throughput: ~250 req/s. Nothing about the business logic changed — only that the framework let one worker do useful work while a request was waiting.

One-look comparison

Side-by-side code — the same endpoint

Flask

from flask import Flask, request, jsonify

app = Flask(__name__)
users = {}

@app.post("/users")
def create_user():
    body = request.get_json()
    # We have to validate manually
    if "name" not in body or not isinstance(body["name"], str):
        return jsonify({"error": "name required"}), 400
    if "age" not in body or not isinstance(body["age"], int):
        return jsonify({"error": "age must be int"}), 400
    if body["age"] < 0:
        return jsonify({"error": "age must be >= 0"}), 400

    user_id = len(users) + 1
    users[user_id] = body
    return jsonify({"id": user_id, **body}), 201

FastAPI

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()
users = {}

class UserIn(BaseModel):
    name: str
    age: int = Field(ge=0)

class UserOut(UserIn):
    id: int

@app.post("/users", response_model=UserOut, status_code=201)
def create_user(user: UserIn):
    user_id = len(users) + 1
    users[user_id] = user.model_dump()
    return {"id": user_id, **user.model_dump()}

Differences in the FastAPI version, all for free:

  • Validation done by Pydantic — bad input returns a structured 422 automatically.
  • OpenAPI schema generated — Swagger UI works at /docs.
  • The response type is documented and enforced.
  • Status code is part of the route declaration.

Where the throughput actually comes from

sequenceDiagram
    participant Client
    participant W as Worker (Flask sync)
    participant DB
    participant API as 3rd-party API
    Client->>W: GET /enrich
    W->>DB: SELECT (blocks worker)
    DB-->>W: row
    W->>API: HTTP (blocks worker 400ms)
    API-->>W: payload
    W-->>Client: 200
    Note over W: Worker was idle 95% of the time

Flask sync: one in-flight request per worker, even while waiting on I/O. Add more workers → more memory.

    participant Client
    participant W as Worker (FastAPI async)
    participant DB
    participant API as 3rd-party API
    Client->>W: GET /enrich
    W->>DB: SELECT (await)
    Note right of W: While awaiting,
worker serves other requests
    DB-->>W: row
    W->>API: HTTP (await)
    Note right of W: Same — other requests
get served in parallel
    API-->>W: payload
    W-->>Client: 200

FastAPI async: one event loop multiplexes hundreds of in-flight requests on one worker. Each await hands control back to the loop.

When Flask is still the right call

Pick Flask when

  • You have a synchronous-only library (some old SDKs, ML inference code).
  • You're building an admin panel or internal CRUD where 50 req/s is plenty.
  • The team only knows Flask and the project is short-lived.
  • You want zero magic — explicit imports, explicit blueprints.

Pick FastAPI when

  • The service does I/O (DB, HTTP, queues) on most requests.
  • You need OpenAPI docs your front-end team can use to generate clients.
  • You want validation, types, and IDE autocomplete to do real work for you.
  • You're building anything that might need WebSockets, streaming responses, background tasks, or scale.
Default in 2026: FastAPI. The benefits compound. Reach for Flask only when you have a concrete reason.

What about Django?

Django is a full web framework — ORM, admin, templates, auth, migrations. FastAPI is an API framework. If you're building a server-rendered website with forms and an admin panel, Django wins. If you're building a JSON API or microservice, FastAPI wins. Both can coexist (FastAPI for APIs, Django for the back-office admin).
