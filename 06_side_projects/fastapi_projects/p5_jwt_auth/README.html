Project 5 · Advanced · Auth done right

JWT authentication — OAuth2 password flow + role-based routes

A complete (small) auth system: passwords hashed with bcrypt, login issues a short-lived JWT, a current_user dependency validates the token on every protected route, and a second dependency layered on top enforces the "admin" role.

The problem we're solving

Three things tend to go wrong with auth in API tutorials:

  1. Passwords stored in plain text (or with weak hashes like MD5). One DB leak and every user's password is out.
  2. Auth checked manually in every route: if not request.headers.get("Authorization"): .... Easy to forget. Easy to get wrong.
  3. Bearer tokens validated badly — wrong algorithm, no expiration check, secrets in code.

FastAPI gives you battle-tested primitives for all three.

How FastAPI solves it

1. Passwords — bcrypt via passlib

from passlib.context import CryptContext

pwd_ctx = CryptContext(schemes=["bcrypt"], deprecated="auto")
hashed = pwd_ctx.hash("alice-pw")              # store this
pwd_ctx.verify("alice-pw", hashed)              # True

bcrypt is intentionally slow (CPU-bound). That's the feature — it slows down brute force. passlib upgrades you automatically when stronger schemes appear.

2. JWT issuance

def make_access_token(username: str) -> str:
    payload = {
        "sub": username,
        "exp": datetime.now(timezone.utc) + timedelta(minutes=30),
        "iat": datetime.now(timezone.utc),
    }
    return jwt.encode(payload, JWT_SECRET, algorithm="HS256")

3. Validation via a dependency

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

def current_user(token: str = Depends(oauth2_scheme)) -> UserInDB:
    try:
        payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])
    except JWTError:
        raise HTTPException(401, "bad token")
    user = USERS.get(payload.get("sub"))
    if not user: raise HTTPException(401)
    return user

@app.get("/me", response_model=UserOut)
def me(user: UserInDB = Depends(current_user)):
    return user

The route just declares "I need a user". Token parsing, signature validation, expiration check, user lookup — all happen in the dependency. Forgetting auth means leaving out the parameter, which is obvious in code review.

4. Role-based access — layered dependencies

def require_admin(user: UserInDB = Depends(current_user)) -> UserInDB:
    if user.role != "admin":
        raise HTTPException(403, "admin only")
    return user

@app.get("/admin/secret")
def admin_secret(_: UserInDB = Depends(require_admin)):
    return {"secret": "42"}

What if you DIDN'T do this?

Plain-text passwords

One SQL injection, one leaked backup — every user's password is exposed. And because people reuse passwords, you've also compromised their email, bank, and Netflix.

MD5 / SHA-256 password hashing

Fast hashes are GPU-crackable at billions of guesses per second. bcrypt / argon2 slow each guess to milliseconds — same security on the right side, vastly different attacker effort.

Sessions stored in app memory

Doesn't scale across multiple workers / pods. User logs in, next request hits a different pod, "not logged in". JWT is stateless — any pod can verify.

Manual auth checks in every route

One forgotten route = full data leak. Auth-via-dependency makes "forgotten" obvious (no Depends(current_user) parameter).

Run it

cd 06_side_projects/fastapi_projects/p5_jwt_auth
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload

# Get a token (form-encoded, OAuth2 password flow):
curl -X POST http://127.0.0.1:8000/auth/login \
    -d "username=alice&password=alice-pw"
# {"access_token": "eyJhbGciOi...", "token_type": "bearer"}

# Call /me with the token:
curl http://127.0.0.1:8000/me \
    -H "Authorization: Bearer eyJhbGciOi..."

# Try /admin/secret as bob (role=user) → 403.
# Same call as alice (role=admin) → 200.

Swagger UI has a special "Authorize" button (top-right) that knows the OAuth2 password flow. Click it, enter alice / alice-pw, and every "Try it out" will include the token automatically.

Production hardening checklist

  • Move JWT_SECRET to settings (env var, Vault, AWS Secrets Manager).
  • Use a strong, random secret — openssl rand -hex 32.
  • Short-lived access tokens (15-30 min) + longer-lived refresh tokens stored revocably (DB / Redis).
  • Add a token revocation list for logout.
  • Rate-limit /auth/login (slowapi) to slow brute force.
  • Force HTTPS in production. Set Secure on cookies if you use them.
  • Don't include sensitive claims in the JWT payload — it's only signed, not encrypted.
