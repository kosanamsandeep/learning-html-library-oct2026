Hello FastAPI — your first "wow"

3 endpoints. ~30 lines of code. You get a full interactive API explorer (Swagger UI), a second one (ReDoc), automatic input validation, typed responses, and an OpenAPI spec — for free. This is the project where FastAPI sells itself.

The problem we're solving

You're writing a new web API. Even a tiny one needs:

  • A way to define routes.
  • Validation of inputs (path params, query params, JSON bodies).
  • Documentation so consumers know what to call and what to expect.
  • Clean error messages when input is wrong.

FastAPI gives you all four from one source of truth: your Python type hints.

How FastAPI solves it

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="Hello FastAPI", version="1.0.0")

class Greeting(BaseModel):
    message: str
    name: str

@app.get("/")
def root():
    return {"hello": "world"}

@app.get("/greet/{name}", response_model=Greeting)
def greet(name: str) -> Greeting:
    return Greeting(message=f"Hello, {name}!", name=name)

@app.get("/add")
def add(a: int, b: int):
    return {"sum": a + b}

From these ~15 lines, FastAPI generates:

  • OpenAPI 3.1 schema at /openapi.json.
  • Swagger UI at /docs — try every endpoint in the browser.
  • ReDoc UI at /redoc — beautiful read-only reference.
  • Auto-422 errors if you call /add?a=2&b=foo.

What if you DIDN'T use FastAPI?

Vanilla Flask

  • Add flasgger or flask-smorest to get Swagger.
  • Add marshmallow or hand-write validation per route.
  • Manually return 400s with consistent error shape.
  • Manually convert query strings to int (or get TypeErrors).
  • ~3x the code for the same behaviour.

Plain WSGI / http.server

  • Write your own router.
  • Parse the query string yourself.
  • Forget Swagger entirely.
  • Re-invent four wheels per route.

You can do all of this. People have for 20 years. FastAPI just makes the boring parts disappear so you spend energy on the actual feature.

Run it

cd 06_side_projects/fastapi_projects/p1_hello_fastapi
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

uvicorn main:app --reload

# Then open in a browser:
#   http://127.0.0.1:8000/             → {"hello": "world"}
#   http://127.0.0.1:8000/greet/Sandeep
#   http://127.0.0.1:8000/add?a=2&b=5
#   http://127.0.0.1:8000/docs         ← Swagger UI
#   http://127.0.0.1:8000/redoc        ← ReDoc

Things to try

  1. Hit /add?a=2&b=hello. You get a structured 422 with the field name and why it failed. No code written.
  2. Open /docs, click "Try it out" on any endpoint. Click "Execute". See the live curl command, request URL, response.
  3. Add a new route: /multiply. Watch Swagger update on the next reload.
  4. Change response_model=Greeting to a model that doesn't match what you return — FastAPI will fail loudly. Type safety in action.

What you learned

  • How to create a FastAPI app and run it with uvicorn.
  • Path parameters ({name}) and query parameters (a: int) with type coercion.
  • Pydantic BaseModel as both input and output types.
  • How OpenAPI / Swagger UI is generated for free from your code.
