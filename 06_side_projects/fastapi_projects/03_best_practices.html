The stuff every FastAPI tutorial skips

FastAPI best practices — the things that matter once you ship

Tutorials show you @app.get("/") and stop. This page covers everything that happens between that and the first time your service runs in production: project layout, settings, dependency injection, error handling, Swagger customization, testing, observability.

1 · Project layout — the layout that scales

Don't put everything in main.py beyond ~150 lines. Split by feature, not by type.

app/
├── main.py              # FastAPI() + lifespan + include_routers
├── config.py            # Settings (pydantic-settings)
├── db.py                # engine, session factory, get_db dependency
├── deps.py              # cross-cutting dependencies (current_user, http_client)
├── exceptions.py        # custom exception classes + handlers
├── logging_setup.py
├── api/
│   ├── __init__.py
│   ├── health.py        # /health, /ready
│   ├── auth.py          # /auth/login, /auth/me
│   └── todos/
│       ├── router.py    # routes
│       ├── schemas.py   # Pydantic models
│       ├── service.py   # business logic (no FastAPI imports)
│       └── repo.py      # DB access
└── tests/
    ├── conftest.py
    └── test_todos.py

Key idea: routers stay thin. The route is "parse → call service → return". All business logic lives in service.py with no FastAPI imports — that's what makes it testable.

2 · Settings & secrets — pydantic-settings, not os.getenv everywhere

# app/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict
from functools import lru_cache

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_")

    app_name: str = "MyApp"
    debug: bool = False
    database_url: str
    jwt_secret: str
    jwt_ttl_minutes: int = 60
    upstream_timeout: float = 5.0

@lru_cache
def get_settings() -> Settings:
    return Settings()

Use it as a dependency in routes — that way you can override in tests.

from fastapi import Depends
from app.config import Settings, get_settings

@app.get("/info")
def info(settings: Settings = Depends(get_settings)):
    return {"app": settings.app_name}
Never commit .env. Add it to .gitignore and provide an .env.example instead.

3 · Dependency injection — the killer feature

Anything a route needs to do its job (DB session, current user, HTTP client, config) should arrive via Depends(). That makes the route trivially testable because you can override any dependency in tests.

def get_db() -> Iterator[Session]:
    db = SessionLocal()
    try: yield db
    finally: db.close()

def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db),
) -> User:
    user = decode_jwt_and_load(token, db)
    if not user: raise HTTPException(401)
    return user

@app.get("/me")
def me(user: User = Depends(get_current_user)):
    return user

For tests: app.dependency_overrides[get_db] = lambda: fake_db(). Done.

4 · Error handling — one shape for every error

Pick one error response shape and stick to it. Hide stack traces from clients but log them. Convert library exceptions to HTTPException via global handlers.

from fastapi import Request
from fastapi.responses import JSONResponse

class NotFound(Exception):
    def __init__(self, what: str): self.what = what

@app.exception_handler(NotFound)
async def not_found_handler(req: Request, exc: NotFound):
    return JSONResponse(
        status_code=404,
        content={"error": "not_found", "detail": exc.what, "path": req.url.path},
    )

Your service layer raises NotFound("todo 42"); the route doesn't even need a try/except. The handler turns it into a clean 404.

5 · Validation patterns

  • Use separate models for input vs output — TodoCreate, TodoUpdate, TodoOut. Never let the same model be both.
  • Add Field(..., max_length=200, examples=["Buy milk"]) — examples show up in Swagger.
  • Use response_model=TodoOut on routes so extra fields can't leak.
  • For query params with validation, use Query(...): page: int = Query(1, ge=1, le=1000).

6 · Swagger / OpenAPI — make it useful

  • Set title, version, description on FastAPI() — they show up in the doc.
  • Use tags=["todos"] on routes to group them in Swagger UI.
  • Use summary= and description= on routes, or the function's docstring (markdown supported).
  • Use responses={404: {"model": ErrorOut}} to document non-2xx shapes.
  • Move docs off the default path if it's a public service: docs_url="/internal/docs", openapi_url=None in production. 
app = FastAPI(
    title="Todos API",
    version="1.4.0",
    description="Manage your tasks. See [the repo](https://github.com/me/todos).",
    docs_url="/docs",
    redoc_url="/redoc",
    openapi_tags=[{"name": "todos", "description": "Operations on todos."}],
)

The spec itself is at /openapi.json — your front-end team can generate a fully-typed TS client from it in one command (openapi-typescript-codegen).

7 · Async rules — the things you MUST follow

  1. Inside async def routes, never call sync I/O libraries. Use async equivalents: httpx.AsyncClient, asyncpg, aioredis, async SQLAlchemy.
  2. If you must call something blocking, wrap it: await asyncio.to_thread(blocking_fn, args).
  3. Don't time.sleep() in async code — use await asyncio.sleep().
  4. For purely CPU-bound endpoints (math, parsing) you can define them as plain def — FastAPI will run them in a thread pool automatically.

8 · Background tasks

For short, fire-and-forget work after returning a response (sending a confirmation email, writing an audit log):

from fastapi import BackgroundTasks

@app.post("/signup")
def signup(user: UserIn, bg: BackgroundTasks):
    new_user = create_user(user)
    bg.add_task(send_welcome_email, new_user.email)
    return new_user
Don't use BackgroundTasks for anything important. They run in the same process; a crash loses them. For "must-happen" work use a real queue (Celery, RQ, Arq, Dramatiq).

9 · Testing — fast, isolated, real

# tests/conftest.py
import pytest
from fastapi.testclient import TestClient
from app.main import app
from app.deps import get_db

@pytest.fixture
def client(monkeypatch):
    app.dependency_overrides[get_db] = lambda: fake_session()
    with TestClient(app) as c:
        yield c
    app.dependency_overrides.clear()

# tests/test_todos.py
def test_create_todo(client):
    r = client.post("/todos", json={"title": "Buy milk"})
    assert r.status_code == 201
    assert r.json()["title"] == "Buy milk"

For async tests, use httpx.AsyncClient with ASGITransport(app=app) instead of TestClient.

10 · Observability — what to add before going live

  • Structured logging (JSON) with structlog or loguru.
  • Request ID middleware — generate or accept X-Request-ID; include it in every log line and every upstream call.
  • Metrics — prometheus-fastapi-instrumentator for request count, latency histogram, in-flight requests.
  • Tracing — OpenTelemetry auto-instrumentation for FastAPI, SQLAlchemy, httpx.
  • Health — /health (process alive) and /ready (deps reachable).

11 · Performance — what actually moves the needle

  1. Use async everywhere I/O happens. (Biggest win.)
  2. Reuse the httpx AsyncClient and DB engine across requests.
  3. Set timeouts on every upstream call. Slow upstream = slow you, otherwise.
  4. Run uvicorn with multiple workers: uvicorn app.main:app --workers 4. One worker per CPU is a fine default.
  5. For huge JSON responses, consider orjson as the response class.
  6. Profile before optimizing. Cache hot reads in Redis.

12 · Security baseline

  • HTTPS only in production (terminate at the load balancer; force the rest).
  • Set CORS explicitly — never allow_origins=["*"] with credentials.
  • Hash passwords with passlib[bcrypt] or argon2 — never store plain.
  • Use short-lived access JWTs + refresh tokens. Sign with a strong secret from settings.
  • Add rate limiting (slowapi or via your gateway).
  • Validate & size-limit every upload. Stream large bodies; never load to memory.
  • Disable Swagger docs on public production deployments if your API isn't public.

13 · Deployment

Run with uvicorn behind an ASGI process manager:

# production-ish
uvicorn app.main:app --host 0.0.0.0 --port 8000 \
    --workers 4 --proxy-headers --forwarded-allow-ips="*"

# behind gunicorn with uvicorn workers (more battle-tested)
gunicorn -k uvicorn.workers.UvicornWorker app.main:app \
    --bind 0.0.0.0:8000 --workers 4 --timeout 30

Then put nginx / a load balancer in front for TLS, gzip, static. Containerize with a slim Python base image; copy only what's needed; pin versions in requirements.txt (or use uv).

The pre-launch checklist

  • ✅ All routes have response_model.
  • ✅ All upstream calls have timeouts.
  • ✅ Settings come from env, secrets out of git.
  • ✅ Errors have a uniform shape; stack traces only in logs.
  • ✅ Health endpoints exist.
  • ✅ Structured logs with request IDs.
  • ✅ Tests cover the happy path of every route.
  • ✅ /docs is either intentionally public or disabled.
