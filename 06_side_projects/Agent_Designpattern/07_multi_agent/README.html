Chapter 07 — Multi-Agent Collaboration

Many specialist agents instead of one generalist. A coordinator decomposes the task and routes work.

MediatorFacadeOrchestrator-Worker

What is it?

Each agent has a narrow role (Researcher, Analyst, Writer, Critic, etc.) with its own tools and prompt. A coordinator (or shared message bus) decides who does what and when. The output is more cohesive than one giant prompt because each agent stays in-domain.

Mental model: a newsroom — reporters, fact-checkers, and editors all reporting to a managing editor.

2026 real-time scenario — Investment thesis crew

A fund's analyst desk launches a "thesis crew" in 2026. The Researcher pulls 10-K filings + news, the Analyst models DCF, the Risk Officer stress-tests, the Writer produces the memo. The Manager agent decomposes the brief, sequences agents, and rejects sub-outputs that don't cite sources.

Interview Q&A

When does multi-agent NOT help?
If the task is small enough for one prompt, multi-agent adds latency and cost. Use it when sub-tasks need different tools / domain prompts or when parallelism speeds things up.
How do you keep agents from looping forever?
Hard caps on rounds, a manager that watches for repeated outputs, and a "stop" signal in the shared state.
