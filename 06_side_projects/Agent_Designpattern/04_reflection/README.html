Chapter 04 — Reflection

Self-critique loop. The agent grades its own output (or another agent does), then revises.

Generator-CriticIteratorSelf-correction

What is it?

Output → Critique → Revise → repeat until quality threshold or max iterations. Two roles emerge: the Generator (produces) and the Critic (judges). Same LLM with two system prompts works fine for most tasks.

Mental model: a writer with an editor sitting next to them — every draft gets red ink before it ships.

2026 real-time scenario — PR-bot reviewing its own code

A 2026 dev workflow: the agent writes a Python function, then a critic role runs "do unit tests pass? are edge cases handled? is complexity acceptable?". If the score < 8/10, it rewrites. Production teams cap loops at 3 to bound latency & cost.

Interview Q&A

Why does reflection sometimes get worse?
Without an objective grading rubric, the critic chases subjective issues and the generator over-edits. Always pin a quantifiable score (rubric, unit tests, factuality check) and a stop condition.
How many iterations are reasonable?
2-3. Returns diminish quickly; cost scales linearly. Cap iterations and require the score to improve each round, otherwise stop.
