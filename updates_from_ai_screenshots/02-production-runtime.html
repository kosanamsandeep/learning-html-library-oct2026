Production Runtime: Why MCP Isn't Enough

High value MCP standardises how agents connect to tools. It does not give you identity, policy, observability, or control. That's the production control layer — and it's where enterprise agentic AI actually lives.

The analogy that sticks: "MCP is like a USB-C port; the control layer is the operating system." A port lets you plug things in. The OS decides who is allowed to, what they may do, how it's watched, and what happens when it goes wrong.

MCP Layer vs Production Control Layer

🔌 MCP Layer

What MCP actually gives you — and it stops there:

  • Standardised tool discovery
  • Standardised tool invocation
  • Uniform protocol across tools

That's it. A connection standard.

🏭 Production Control Layer

What every real deployment must add around MCP — 12 items:

  1. Agent Identity
  2. User-to-Agent Mapping
  3. Tool-Level Authorization
  4. Policy Enforcement
  5. Timeout Budgets
  6. Retry Strategy
  7. Structured Errors
  8. Observability Traces
  9. Audit Logs
  10. Human Approval
  11. Cost Controls
  12. Incident Response

The point: when an agent touches real enterprise systems (a ServiceNow ticket, a payment record), the horizontal capabilities — permissions, audit, cost, escalation — are first-class concerns, not afterthoughts. This is a design-review checklist for any agent you intend to put in front of production data.

Applying This to Your Projects

Checklist for your RAG chatbot

  • Tool-level authorization — before any tool executes, check the user's role against a permission policy (not the LLM's judgment).
  • Cost controls — per-user rate limits, per-session token budgets, and a circuit breaker so a runaway agentic loop can't burn money.
  • Audit logs — every tool call recorded with user_id, tool, args, result, timestamp. This is what makes "what did the agent do?" answerable.
  • Structured errors — tool failures surface as typed errors the orchestrator can handle (retry / degrade / abstain), never silent text.
  • Human approval gates — for any action with a high blast radius (writes, external calls, refunds).
Timely note: You're actively using MCP (Context7, your own integrations). The "MCP is not enough" framing isn't anti-MCP — it's "build the control layer, don't assume MCP is it."
