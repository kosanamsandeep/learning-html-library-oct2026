Agent Evolution: Frameworks → Harnesses

Verified The single most substantively important shift in the agent-tooling world — described by LangChain's own founder, Harrison Chase.

The Headline Shift

Harrison Chase (LangChain founder): "The agent industry has shifted from agent frameworks (langchain, ai sdk, llama index) to agent harnesses (deepagents, claude agent SDK, EVE)."

A framework gives you building blocks — chains, memory, tool bindings. A harness is a complete, opinionated runtime that already includes the agent loop, context management, and tool execution conventions. The trend: teams increasingly reach for a working harness and add structure only when evals prove it helps, rather than assembling raw primitives.

Workflows vs Agents — the Architectural Split

The 5 Workflow Patterns (Anthropic)

Boris Cherny's widely-quoted line — "You're not supposed to write code anymore. You're supposed to build a graph that writes itself" — distills the same idea: agent systems are graphs, and each pattern is a recognisable graph shape.

PatternShapeBest for
Prompt chainingStep → gate → step → gateLinear tasks, later steps depend on earlier output; trade latency for accuracy
RoutingClassify → dispatch to specialised handlerDistinct categories; different prompts, tools, or model tiers (cheap model for easy)
ParallelisationFan-out → aggregate (sectioning OR voting)Independent subtasks; multi-perspective reviews; guardrails alongside main answer
Orchestrator-workersCentral LLM delegates to dynamic workersSubtasks can't be predicted up front (e.g. refactor across unknown files)
Evaluator-optimiserGenerate → critique → loop until passClear rubric + iteration helps (translation, search, codegen)
Rule of thumb: fixed steps → chaining · known categories → routing · independent work → parallelisation · unknown shape → orchestrator-workers · needs iteration → evaluator-optimiser.

  • Turn-based — what you think of as "the chatbot loop." Classic request → respond.
  • Goal-based — the agent keeps working until an evaluator confirms the goal is met, or a retry budget is exhausted. Directly maps to your evaluator-node work.
  • Time-based — Claude Code's real /loop and /schedule features. Interval-triggered background work.
  • Proactive — event/schedule-triggered with no human present: triage → fix → review. This is Peter Steinberger's "maintain your repos, wake up every 5 minutes" workflow.

Nested Subagents — Context-Managed Delegation

Verified Boris Cherny shipped nested subagent support in Claude Code (v2.1.172, June 2026). The motivation is context management: each subagent gets a fresh context window, so deep work doesn't bloat the parent's context.

Key facts

  • Agents can kick off agents (orchestrator → worker → sub-worker).
  • Capped at depth = 5 — but independent testing showed the cap is a soft guideline, not a hard guarantee (testers probed to depth 9–30).
  • The practically-useful depth is 3 levels (orchestrator → worker → sub-worker) per field testing.
  • Each subagent's activity is observable (the "can we watch?" answer was "Yep!").
Why it matters: This is the exact pattern behind Anthropic's multi-agent research system — a parent agent delegates to sub-agents as tools, sub-agents run in parallel, and results roll back up. For your LangGraph Supervisor work, this is the canonical delegation model to replicate.

The over-communication failure mode: "Overbuilt multi-agent systems spend too much time talking back and forth… not making progress." The more sub-agents chat, the more tokens and latency burn without advancing the answer. Practical guidance: keep inter-agent communication minimal; delegate bounded, parallelisable work; let the parent do the synthesis. This is also why your RAG chatbot's orchestrator should keep sub-agent chatter on a budget.

When to Use a Fully Autonomous Agent

✅ Use an agent when the number of steps is unknown, the LLM must decide based on tool outputs, and the environment is trusted enough to let the loop run.
⚠️ Stay with a workflow when the steps are predictable — cheaper, faster, easier to debug.
🚫 Avoid an agent when the cost of a wrong action is high (irrevocable writes, real money) and you haven't invested in guardrails, sandboxing, and human-in-the-loop checkpoints.
📌 Takeaway for your projects: Agent systems should be built as workflows first (predictable paths), with the autonomous agent loop reserved for genuinely open-ended steps. When you do delegate, delegate to fresh-context subagents (the nested pattern), keep communication bounded, and always have a stop condition: max steps, time budget, or an explicit completion signal.
