🧠 The Library Analogy

Why three separate roles? Because searching is different from retrieving.

🔍

Query (Q) —
Your Search

"I'm looking for books about cat behavior." That's what each token wants to find in the other tokens.

🏷️

Key (K) —
The Labels

Each book has a dust-jacket summary: "This book covers feline psychology." Keys describe what each token contains.

📖

Value (V) —
The Content

The actual book text (not just the label). Values are the rich information each token contributes once matched.

⚡ Why all three? Separating Keys from Values allows a token to say "I contain information about X" (its Key) while carrying richer, more detailed information in its Value. This is why a model can match on concepts — the Key — and then blend detailed content — the Value — into the context.

🎯 Weighted Sum — A × V

Each token's new representation = weighted blend of all Values, weighted by attention scores.

Head_Out = A · V = [[10.0, 20.0], // "the" → just its own V [25.2, 35.2], // "cat" → 24% "the"'s V + 76% its own [32.6, 42.6]] // "sat" → 18% "the" + 51% "cat" + 31% itself

Notice how "sat" (row 3) now contains information from "cat" and "the". It has gathered context. This is the attention mechanism in action.

🔄 Project Back & Repeat

Head_out is (3×2). We concatenate all heads (e.g. 2 heads → 3×4) and project back via WO to restore the original embedding size. Then feed into the next layer.

Layer_Output = Concat(Head₁, Head₂) · WO // Shape: (3 × 4)
Then → Feed-Forward → Next Attention Layer → ...

Each layer refines the representation. Early layers capture syntax and proximity; deeper layers capture semantics, coreference, and reasoning.

🎯 The Loss Signal

Loss = how surprised the model was by the actual next token. If the model predicted "the" (70%) and the real token was "cat", loss is high. Gradients flow back through the entire chain, updating every WQ, WK, WV weight.

High Loss (early)
"the cat ? " → predicted "the" (not "sat")
→ Q didn't align with K properly
Gradient: "pay more attention to 'cat' when predicting the verb!"
Low Loss (trained)
"the cat ? " → predicted "sat" ✓
→ K of "cat" strongly matches Q of "sat"
Attention: "sat" attends 51% to "cat", 18% to "the" — correct context gathered

💡 The key insight: The loss is minimized not by memorizing sequences, but by learning which tokens should attend to which other tokens. QKV is the mechanism that makes this possible — it's a learnable routing system where tokens dynamically decide where to look for information.

💡 Why Separate Q, K, V? — The "Dictionary" View

Three roles, one unified purpose: context-aware token representations

🔍 Query — The Seeker

Each token asks: "What information do I need right now?"

The Query vector is a question. At position "sat" (predicting a verb), the query asks: "Which earlier tokens describe the subject doing this action?"

Different attention heads learn different questions: Who does this? What's the object? What's the tense?

🏷️ Key — The Label

Each token announces: "Here's what I contain."

The Key vector is like a catalog entry. "cat" projects a key that says: "I'm a noun, I'm the subject, I have animacy."

Keys allow efficient matching — a query scans all keys to find relevant tokens before reading their values.

📦 Value — The Content

Each token provides: "Here's my actual contribution."

Once matching is done (via Q·K), the Values are blended by attention weights. Value carries the full semantic payload — far richer than the label.

Q and K determine which tokens to mix; V determines what gets mixed.

🚀 Why This Triplet Design Wins

1. Information bottleneck
By projecting from n_embd → d_k (smaller dimension), the model is forced to distill the most important features. This prevents overfitting.
2. Content-addressable retrieval
Unlike RNNs (position-based memory), attention is content-based. A token finds relevant context anywhere, regardless of distance.
3. Parallelizable computation
Q·Kᵀ is a single matrix multiply — all pairwise comparisons in one shot. RNNs had to process sequentially; attention sees the full sequence at once.
4. Multi-perspective attention
Multiple heads = multiple QKV subspaces. Each head learns a different "relationship type" (subject-verb, adjective-noun, coreference, etc.).

🧩 Putting It All Together

From sentence to prediction — the full journey

📝 Example: "The cat sat on the mat"

Input tokens: ["the", "cat", "sat", "on", "the", "mat"]

At position 2 ("sat"): The query asks "Who sat?" The key of "cat" matches strongly → "sat" attends 51% to "cat" and 18% to "the". The value of "cat" (its detailed representation) flows into "sat"'s context. Now "sat" "knows" that a cat is the agent.

After all layers: Each token has gathered context from its relevant neighbors. The final layer's hidden states decode into vocabulary probabilities. If the next token after "mat" was period ".", the model should assign high probability to ".".

Q: "What's the subject?" K: "I'm the subject (cat)" V: {animacy: animate, number: singular, ...} → "sat" now conditioned on "cat"

🔮 How Models Actually Predict the Next Token

  • 1. Embed — Map each token to a high-dimensional vector (e.g., 4096 for GPT-3)
  • 2. For each of N layers:
  • a. Multi-Head Self-Attention — Each token computes Q, K, V → gathers context from all previous tokens
    b. Feed-Forward Network — Each token independently reasons over its gathered context
    c. Residual + Norm — Stabilize training and preserve information flow
  • 3. Unembed — Project final hidden state to vocabulary size (e.g., 50,257 tokens)
  • 4. Softmax — Convert logits to probability distribution over vocabulary
  • 5. Sample / Argmax — Pick the most likely next token (or sample for creativity)
⭐ The critical point: Every single token's prediction is shaped by QKV attention in every layer. Loss minimization directly tunes the WQ, WK, WV matrices so that queries find relevant keys, and the blended values produce the right next-token logits.
