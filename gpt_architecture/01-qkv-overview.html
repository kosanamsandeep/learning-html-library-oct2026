01 · Q·K·V Overview & The Library Analogy

Before diving into matrices and math, let's understand why a Transformer needs three separate roles — Query, Key, Value — and what problem each solves.

🎯 The Core Problem: A word like "sat" in "the cat sat on the mat" needs information from "cat" (the subject) and "the" (the determiner). But those words are far away in the sequence. QKV is the mechanism that lets tokens dynamically retrieve information from any earlier token.

📚 The Library Analogy

Imagine a library with thousands of books. You (a library visitor) want to find information about cat behavior.

🔍

Query (Q)

"I am looking for books about cat behavior." — That's the query. It expresses what you seek. In the Transformer, each token generates a Query vector that asks: "Which earlier tokens have information I need right now?"

🏷️

Key (K)

Each book has a dust-jacket summary: "This book covers feline psychology." That's the key. It announces what the book contains. In the Transformer, each token produces a Key vector describing: "Here's what information I carry."

📖

Value (V)

The full text of the book is the value. Once you match a book (via Q·K), you read its content (V). In the Transformer, the Value carries the detailed token representation that gets blended into other tokens' contexts.

🤔 Why Not Just One Vector?

Why separate Keys from Values? Couldn't a token use the same representation to announce what it contains and to contribute that content?

No — and here's why:

  • A token's label (Key) should be compact — just enough to match against queries. Think of it as a retrieval index.
  • A token's content (Value) needs to be rich — it carries the full semantic payload another token will absorb.
  • Separating them lets the model specialize: Keys optimize for match-ability; Values optimize for information-content.

💡 A Concrete Example

Consider the sentence: "The cat, which had been sleeping peacefully on the windowsill, sat up."

When the model processes "sat":

  1. Q ("sat"): "What is the subject of this verb? What noun performs this action?"
  2. K ("cat"): "I'm a noun, I'm animate, I'm singular, I'm the likely subject." (High match with Q)
  3. K ("windowsill"): "I'm a noun, I'm inanimate, I'm a location." (Lower match with Q)
  4. V: "cat"'s Value vector carries detailed features — concept of cat, singular agreement, etc. — which gets blended into "sat"'s representation.

After this attention step, "sat" knows that a singular cat performed the sitting action. The model can now confidently predict the next word correctly.

🧩 The Big Picture

In the Transformer, every token simultaneously plays all three roles:

  • It queries all earlier tokens: "Who has what I need?"
  • It offers a key to later tokens: "Here's what I contain."
  • It offers a value to later tokens: "Here's my semantic contribution."

The Q, K, V vectors are learned projections of the same underlying token embedding — each extracted by multiplying the embedding by a different weight matrix (WQ, WK, WV). We'll see exactly how in the next file.

🔑 Key takeaway: Q = "what I seek" · K = "what I contain" · V = "what I provide". Separating them lets attention be a learned content-addressable retrieval system, not just a similarity score.
