Drop Codex into a real Python repo — AGENTS.md + a small Agents-SDK orchestrator

Two ways to use Codex on the same repo

Surface What it is When to reach for it
Codex CLI An interactive terminal agent (npm i -g @openai/codex or brew install codex) that opens a session in your repo and reads AGENTS.md. Local refactors, scaffolding, one-off "explain this script" sessions, sandboxed experiments.
OpenAI Agents SDK A Python package — pip install openai-agents — to build agents that ship with your application. Anything that runs in production: support bots, automated reviewers, RAG agents, ETL helpers.
One contract, two surfaces: a well-written AGENTS.md plus narrow, well-named tools work for both.

AGENTS.md — what we put in it

The convention is simple: a top-level file describing the repo, its commands, and its conventions. Codex CLI loads it automatically; you can also pass it as a system prompt fragment when invoking the Agents SDK.

# Project: review-bot

## What this is
A small example of an automated code reviewer using the OpenAI Agents SDK.

## Build & test
- Python 3.11+
- Install: `pip install -r requirements.txt`
- Run smoke tests: `pytest -q`

## Conventions
- Type hints on every public function.
- Tools live in `src/` next to the agent that owns them.
- All file paths passed to tools must be absolute (lessons from Anthropic's
  SWE-bench post — relative paths break when the agent changes directory).

## Don't touch
- `src/reviewer.py:SYSTEM_PROMPT` — owned by the prompt-eval CI job.

## When in doubt
Open a PR. Never run a tool against production data from this repo.

The reviewer agent — built with the SDK

src/reviewer.py sketches a one-agent workflow that reads a diff, runs tests, and writes a review. It uses @function_tool to expose three Python functions to the model.

Why this shape?

  • Augmented LLM first (one agent + tools) — start simple per Anthropic's guidance.
  • Junior-developer docstrings on every tool (when to use, when not to use, an example).
  • Absolute paths for file arguments — poka-yoke against the relative-path failure mode.
  • Stop conditions — the runner caps turns; the reviewer agent has a single explicit "I'm done" tool to call.

Hello-world flow

  1. Set OPENAI_API_KEY.
  2. Run python -m src.reviewer review path/to/diff.patch from this folder.
  3. The agent reads the diff, runs tests, drafts a review, and prints it.
  4. You read the review, decide what to merge, and (in your real repo) post the comments via your CI.

In this sample we keep the entry point as a __main__ stub and don't actually call the OpenAI API — the file is a template. The smoke test confirms the structure without spending tokens.

Adoption checklist for your real repo

  1. Add AGENTS.md at root with the build/test commands.
  2. If you use Codex CLI, install it (npm i -g @openai/codex) and run codex in the repo. Check that it reads AGENTS.md on the first turn.
  3. Pick one in-app agentic feature (a reviewer, a Q&A bot, a deploy assistant) and build it with the Agents SDK as a single agent first.
  4. Add tracing — when an agent goes wrong in production, the trace is your debugger.
  5. Add a guardrail before going live: a small parallel check that refuses unsafe input or schema-invalid output.
