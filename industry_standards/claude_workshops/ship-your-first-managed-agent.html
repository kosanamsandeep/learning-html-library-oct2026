CWC · Workshop 4

Ship your first managed agent: seven small functions and an SRE that fixes Incident‑2277

The "hello world" of Claude Managed Agents. You fill in seven thin wrappers over the client.beta.* SDK in one agent.py (~34 lines of meaningful code). The agent greps a 70k-line log inside its sandbox and pins the regression to commit a3f9c21 — an N+1 query that pushed p99 from 65 ms to 3600 ms.

1 · What you build

  • A Streamlit chat UI in front of a Managed Agent.
  • An agent.py module with seven functions:
    1. setup_agent → client.beta.agents.create(…)
    2. setup_environment → client.beta.environments.create(…)
    3. upload_log → client.beta.files.upload(…)
    4. start_session → client.beta.sessions.create(…)
    5. stream_reply → events.stream(…) + events.send(…)
    6. handle_tool — local handler for the gated tool calls
    7. delete_session — cleanup
  • The shipped artifact runs the SRE incident end-to-end: log goes in, root-cause commit comes out.

2 · The stack

Agent (configured once)
→
Environment (sandbox + files)
→
Session (one chat)
→
Events (stream + send)

This is the model you re-use in every later workshop. Agent is the persistent configuration; environment is what the agent can see and run; session is a single conversation; events are the streaming protocol both sides write to.

3 · Levers the workshop teaches

Agent = configuration, not state

Create the agent once; reuse across sessions. Model, system prompt, tool list, default skills live here.

Environment = what the agent sees

The sandbox filesystem, the uploaded files, the network policy. Everything that needs to outlive a single chat goes in the environment.

Session = one conversation

Cheap, ephemeral, attached to an environment. Resources (memory store, files) are attached at session creation, not later.

Events = the streaming protocol

You send user messages and you stream assistant + tool events back. Tool confirmations are also events.

Files in the sandbox

The 70k-line log is uploaded once, lives in the environment, and the agent runs grep / Python inside the sandbox instead of attaching the whole log to the prompt.

Streamlit shell

Just enough UI to demonstrate the streaming events. The model is "the UI is a renderer over the event stream".

4 · Use vs don't use — the trade-offs

Lever If you use it If you skip it
Claude Managed Agents (vs DIY loop) Anthropic runs the loop, the sandbox, the tool gateway, the streaming. Your code is seven small functions. You write your own retry, sandbox, file storage, event protocol, and tool-confirmation gating — and re-write it for every project.
Environment with uploaded files The 70k-line log is searchable by the agent without ever crossing the context window. grep "p99" runs inside the sandbox. You attach the log to the prompt, blow the context window in one turn, and pay for tokens on every retry.
Sessions (vs long-lived chats) You can spin up parallel sessions for parallel incidents, throw failed ones away, and keep the agent + environment definition stable. One long chat accumulates context, slows down, and a bad turn poisons every later one.
Attach resources at session-create Memory store and uploaded files are guaranteed available from event 1. You try to attach mid-session, the API refuses, and you ship a workaround that leaks state.
Streaming events The UI shows reasoning and tool calls as they happen. You can intercept tool-confirmation events to add policy. The chat hangs until the final message, the SRE thinks it's broken, and you have no place to insert approvals.
The lesson: the four-noun mental model (agent · environment · session · events) is the entire CMA surface area. Once you have it, every later workshop is "use the same four nouns with more interesting content."

5 · Adoption playbook for your repo

  1. Pin one operational pain (a real incident, a real triage flow) and write its 70k-line input down as a file.
  2. Build the seven-function agent.py. Don't add anything else until it runs end-to-end.
  3. Wrap it in a 50-line Streamlit (or any) UI so non-engineers can use it.
  4. Put the agent definition under version control. The system prompt is code now.
  5. Only after the loop is healthy: add Skills, sub-agents, memory. The W4 stack is intentionally the floor.
