Scenario playbook

Six concrete scenarios — pick a pattern, pick a framework, ship

Reading the best-practice posts is one thing. Mapping them to your problem is another. Below are six recurring scenarios with the pattern, the tool design, and the framework choice already worked out.

Scenario 1 — Customer support bot

Profile: open-ended conversation, needs to look up orders, issue refunds, escalate hard cases.

Pattern (Anthropic) Routing + agent. Cheap classifier picks "FAQ", "order lookup", "refund", "escalate". Refund/escalate routes go to an agent with tools.
Tool design get_order(query), create_refund(order_id, amount, reason), escalate_to_human(summary). Each has explicit "use this when" guidance and example calls.
Framework OpenAI Agents SDK with handoffs (FAQ agent ↔ Refunds agent ↔ Human-handoff agent), guardrails for unsafe inputs, sessions for the conversation.
Watch out for Compensating actions on refund failure (saga shape — see Case Study P4), idempotency keys on every refund (see Fundamentals P4).

Scenario 2 — Code reviewer / bug fixer

Profile: takes a PR, reviews it, may apply small fixes, flags risks.

Pattern (Anthropic) Evaluator-optimiser. One agent drafts a review, another critiques. Iterate until the critic stops finding issues.
Tool design read_diff(pr_id), read_file(path), run_tests(), post_comment(line, text). Use absolute paths always (Anthropic's SWE-bench lesson).
Framework OpenAI Agents SDK Sandbox agents with filesystem + shell capability, OR GitHub Copilot's coding agent on a tagged issue. Claude Code with a review skill if your team is on Claude.
Watch out for Don't let the agent push to main. Always open a PR. Run tests inside the sandbox; never on production data.

Scenario 3 — RAG knowledge bot for an internal wiki

Profile: answers questions grounded in a private corpus, must cite sources.

Pattern (Anthropic) Augmented LLM (single call) with retrieval. Not an agent unless multi-hop questions are common.
Tool design One search_knowledge_base(query, top_k) tool returning (doc_id, snippet, score). The model is instructed to cite [doc_id] in every claim.
Framework Either Responses API directly or the Agents SDK with a single agent + the search tool. Add a guardrail that refuses out-of-scope categories (medical / legal / investment advice).
Watch out for Faithfulness ≠ correctness — see AI P5. Pair faithfulness scoring with a minimum top-1 similarity threshold.

Scenario 4 — Data ETL agent that fixes broken pipelines

Profile: a daily batch fails, the agent diagnoses the failure, applies known remediations, opens a PR for novel cases.

Pattern (Anthropic) Orchestrator-workers. Orchestrator reads logs, decides which remediation to attempt; workers (one per category — schema drift, auth, quota) execute the fix.
Tool design fetch_logs(job_id, since), describe_schema(table), retry_step(step_id, with_param), open_runbook_pr(title, body). Each tool returns a structured result and an explanation the agent can quote.
Framework OpenAI Agents SDK with handoffs into specialist worker agents, sessions for incident state, tracing wired into your alert tool.
Watch out for Bound the number of retries. Capture every action in an audit log. Add a kill switch for any tool that mutates production.

Scenario 5 — Multi-agent research crew

Profile: a deep-dive on a topic — gather sources, summarise each, write a brief, critique.

Pattern (Anthropic) Manager (agent-as-tool). Researcher → Writer → Critic. The manager owns control flow.
Tool design web_search(query) for the researcher, read_url(url) for the reader, save_brief(title, body) for the writer.
Framework OpenAI Agents SDK with three agents wired as tools to a manager. AI P2 multi-agent shows the same shape from scratch.
Watch out for Cap reflection iterations — critic loops can spiral. Two retries is usually enough.

Scenario 6 — Voice assistant for an internal app

Profile: low-latency, push-to-talk, looks up data and reads short answers.

Pattern (Anthropic) Augmented LLM with tools, kept simple. The latency budget is the design constraint.
Tool design Tools must return small, voice-friendly strings — not JSON dumps. Add a tool that says "I don't know, please open the dashboard" so the agent has a clean fallback.
Framework OpenAI Agents SDK Realtime agents with gpt-realtime-2 and built-in interruption handling, OR a voice pipeline (STT → agent → TTS) when the realtime path is overkill.
Watch out for Confirm before any write. Voice mishears more than text. Always read back the action ("OK — refunding $89, confirm yes/no").

Decision matrix — which framework should I pick?

If you need… Pick
Tightest possible loop, full control. OpenAI Responses API or Anthropic Messages API directly.
A managed agent runtime (loop, tools, handoffs, sessions). OpenAI Agents SDK.
Reusable, packaged "skills" Claude can load on demand. Anthropic Skills + Claude Agent SDK / Claude Code.
An agent that lives in the editor and writes code with you. GitHub Copilot (chat, inline) or Claude Code or Codex CLI.
An agent that lives on a GitHub issue and opens PRs. GitHub Copilot coding agent.
Cross-vendor tool integration (your tools, any LLM). Model Context Protocol (MCP) — supported by both Anthropic and OpenAI Agents SDK.
