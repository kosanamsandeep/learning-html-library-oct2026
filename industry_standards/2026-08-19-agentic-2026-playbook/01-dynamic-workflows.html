Dynamic Workflows: Claude writes its own harness

Anthropic's biggest 2026 methodology leap. In late May / June 2026, Claude Code gained the ability to write and orchestrate its own multi-agent JavaScript harness at runtime — one task, one custom harness, instead of a human authoring a fixed pipeline. It's the shipped, official version of what Boris Cherny described abstractly at the Opus 5 launch.

Why it was needed — the three single-context failure modes

The default Claude Code harness plans and executes in one context window. That works for routine coding but breaks down on long, parallel, or adversarial tasks. Anthropic named three structural failure modes:

Failure modeWhat it looks likeWhy prompting can't fix it
Agentic lazinessStops early and declares completion — "addressed 35 of the 50 items" in a security review.More prompt text doesn't change the incentive to stop at diminishing returns.
Self-preferential biasFavors its own results when judging them against a rubric.A model grading its own work is a conflict of interest; you need a separate skeptic.
Goal driftAcross many turns and context compactions, edge-case constraints like "don't do X" get lost.Constraints decay with distance; they need to be re-checked in fresh context.
Key insight: workflows fix these structurally — isolated context windows, focused goals, adversarial verifiers — not by writing longer prompts.

The six core workflow patterns

PatternShapeUse when
Classify-and-actA classifier routes the task to the right agent/behavior — or judges the final output.Tasks that split by type (bug vs feature; simple vs complex).
Fan-out-and-synthesizeSplit work into small steps, one agent per step in clean context, then a synthesize barrier merges structured outputs.Migrations, sweeps, anything parallelizable.
Adversarial verificationEvery producing agent gets a separate verifier that checks output against a rubric — it never trusts the producer.High-stakes output that must be audited.
Generate-and-filterGenerate many ideas, then filter by rubric + verification + dedupe; return only the highest-quality tested ones.Design/naming exploration, option generation.
TournamentN agents attempt the same task differently; a judge compares results pairwise until a winner emerges.Ranking/sorting where absolute scoring degrades — e.g. 1,000+ rows in one prompt fails; pairwise works.
Loop until doneSpawn agents repeatedly until a stop condition (no new findings, no more errors), not a fixed number of passes.Unknown-size discovery: bug hunts, review sweeps.

How it works under the hood

  • A workflow is a JavaScript file with special functions for spawning and coordinating subagents, plus standard JS (JSON, Math, Array) for data processing, loops, and branching.
  • Per-agent model choice — subagents can each run a different model (Opus for heavy work, Sonnet/Haiku for light) and can run in their own git worktree to avoid workspace conflicts.
  • Coordination runs outside the main context — the main session doesn't track every branch detail; it reads the funneled result.
  • Resumable — if you interrupt or quit the terminal, resuming picks the workflow back up from its breakpoint.
  • Cap the token budget explicitly, e.g. use 10k tokens.

How to trigger it

  • Natural language: "Create a workflow to…" with clear goals, scope, and acceptance criteria.
  • The trigger word ultracode: include it in a prompt (or set effort to xhigh) and Claude Code auto-generates a workflow for substantive tasks — the first trigger shows a plan for confirmation.

Real deployments

  • Bun's Zig→Rust rewrite (Jarred Sumner) — a 100K-line codebase fan-out: one subagent per module in a worktree, adversarial review, per-module merge.
  • /deep-research — a skill that fans out web searches, fetches sources, adversarially verifies claims, and synthesizes a cited report.
  • Race-condition triage — "this test fails maybe 1 in 50 runs…" spawns a loop-until-done investigation.
  • Deep verification — one agent enumerates every factual claim; subagents check each; an auditor scores source quality.
  • Memory / rule adherence — mine sessions for recurring corrections and distill them into CLAUDE.md.
Operational tips from the field: pair repeatable workflows with /loop for continuous operation and /goal for a hard completion requirement; save workflows with s into ~/.claude/workflows or distribute via a skill; use the quarantine pattern — agents that read untrusted public content are barred from high-privilege actions.
⚠️ The trap: this is powerful and expensive. Fan-out + adversarial verification can multiply token spend several-fold. Reserve it for tasks where the stakes justify test-time compute; don't wrap routine edits in a 12-agent harness. See the verification funnel for right-sizing.
