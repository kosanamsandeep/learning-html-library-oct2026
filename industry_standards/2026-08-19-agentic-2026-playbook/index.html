The Agentic Engineering Playbook

The methodologies that came into the light over mid-2026 and are already paying off: Claude Code Dynamic Workflows (Claude writes its own multi-agent harness), Spec-Driven Development (the spec is the source of truth, not the prompt), the 80% problem and context infrastructure, and a cost-ordered verification funnel. Plus the Codex-side playbook for the same shift.

Compiled 2026-08-19. Sources: claude.com engineering blog (Dynamic Workflows, GA Jun 2026), GitHub Spec Kit / Agent Patterns Catalog (SDD), Sourcegraph · Sogeti Labs · Microsoft Learn (2026 agentic-coding field reports). Links on each module page.
⚡ The one-line thesis: 2026's winning teams stopped treating the prompt as the product. They treat the spec, the harness, the context, and the verification environment as first-class products — and the human's job is steering and auditing, not typing. This module is the concrete playbook for that shift.

Learning Path — 5 Modules

01

Dynamic Workflows (Anthropic, GA Jun 2026)

Claude Code now writes and orchestrates its own multi-agent JS harness at runtime — ultracode trigger, six core patterns (classify-and-act, fan-out-and-synthesize, adversarial verification, generate-and-filter, tournament, loop-until-done), and the three single-context failure modes it fixes: agentic laziness, self-preferential bias, goal drift.

Learn: the six patterns · static vs dynamic · trigger & budget mechanics · Bun's Zig→Rust rewrite
02

Spec-Driven Development & GitHub Spec Kit

The "brilliant intern problem": agents fill vague briefs with confident guesses. SDD inverts the order — constitution → specify → clarify → plan → tasks → implement — so the spec, not the prompt, drives the agent. Change the spec and regenerate; never hand-patch generated code.

Learn: six stages · the clarify pass · maturity levels 1→4 · the two failure modes
03

The 80% Problem & Context Infrastructure

Agents reliably finish the visible 80% of a task and miss the invisible 20% — auth middleware, API DTOs, audit logs, sibling-repo integration tests. Framing it as a context infrastructure problem, not a model problem. The fix: scope → equip → loop → review like a human PR → gate on CI → audit.

Learn: symbol-usage search · senior-scoped tasks · the brute-squad developer role
04

The Verification Funnel

"The skill isn't who writes better — it's who can prove it's right." The Verification Horizon (faithfulness · robustness · scalability), a cost-ordered multi-layer funnel, structured evidence over scores, and Agentic TDD's 8-pass state machine as a working template.

Learn: the 3-axis trade-off · cost-ordered checks · 8-pass agentic TDD · verdicts over scores
05

The Codex & Cross-Tool Playbook

The same 2026 shift on the OpenAI side: plan-first decision rule, git worktrees for parallel sessions, /goal for multi-day tasks, the OMX clarify→plan→own→team layer, CodexLoop's external memory, and AGENTS.md vs Skills vs Subagents.

Learn: the plan-first rule · worktrees · /goal · OMX layers · external memory for long tasks

⚠️ Cost reality check: dynamic workflows and deep verification are forms of test-time compute — they deliberately spend tokens to buy reliability. Adversarial verification alone can double or triple a task's token bill. The patterns transfer to any budget; the scale (thousands of agents, 11-day codebase rewrites) needs real spend. Right-size: funnel cheap checks first, use workflows where stakes justify them.
