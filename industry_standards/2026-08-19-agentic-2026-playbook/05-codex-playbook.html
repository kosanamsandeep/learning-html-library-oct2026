The Codex & Cross-Tool Playbook

The same 2026 shift on the OpenAI side — from "Prompt → Code" to "Goal → Loop → Review → Iterate → Converge" — plus the practical discipline of running several agent tools side by side.

The plan-first decision rule

The rule that saves half an hour of bad diffs:
  • Simple, single-file changes go direct — "if you can name the file and the change in one sentence, skip planning." (Add a debounce to SearchBar.tsx.)
  • Complex or cross-cutting tasks use plan mode first — "if you find yourself writing a paragraph to explain the task, plan mode will save you." (Refactor the auth flow.)
Start with "show me the plan first" before "implement this."

Worktrees for parallel sessions

Running 4–6 Codex sessions per codebase is now ordinary. The recommended pattern is git worktrees, not branch-switching:

git worktree add ../proj-feat-auth feat/auth
git worktree add ../proj-fix-cors  fix/cors
(cd ../proj-feat-auth && codex)
  • Each worktree gets its own node_modules, build cache, and test cache — sessions don't thrash each other.
  • Trade-off: significantly more disk (10 GB+ on a 2 GB repo with 5 worktrees).

/goal for multi-day tasks

  • Enable via goals = true under [features] in ~/.codex/config.toml.
  • /goal <objective> declares a goal; bare /goal checks status; /goal pause / /goal resume / /goal clear manage the thread.
  • Best for: large migrations touching 40+ files, incident postmortems, spikes you must drop and resume without re-explaining.
  • Overkill for anything finishable in one sitting — codex resume --last suffices.

A community methodology layered on Codex with four fixed entry points that enforce an action order: don't start coding immediately — clarify first, lock the plan, then decide between one agent pushing through or a parallel team.

External memory & loops — CodexLoop

Community tooling that fixes two known failure modes of long AI tasks — goal degradation (models take the shortest path, producing demos without tests/docs) and long-task amnesia:

  • Persistent checklists — the AI reviews results each round, discovers new work, updates a todo list.
  • Automatic review loops — Review → Decide → Act, evaluating whether output matches the goal.
  • Deferred ideas file (deferred.md) — captures new ideas without letting the agent diverge.
  • Audit logs — every action, decision, and reason recorded for traceability.
  • Explicit gates / reviews / checklists as "engineering constraints" against shortcut-taking (mocks instead of real implementations, skipped tests).

Cross-tool & governance practice

  • Cross-tool workflows: e.g. Claude Code coordinates while Codex applies mechanical changes; Codex code-review/code-remediate run as self-contained local loops reading PR evidence via gh.
  • AI gateways route agent CLI requests across providers with failover chains, per-call audit trails, cost budgets, and guardrail scanners — secret detection, prompt-injection detection (critical since agents read third-party code), PII, and hallucination detection with tool-call results as ground truth.
  • Skills are now first-class: workspace plugin sharing with access controls, marketplace install/upgrade, remote plugin bundle caching.
  • Large-repo hygiene: ask for a map before edits ("map the repo, list entrypoints and test commands. Do not edit."), constrain search scope, define done criteria explicitly (weak "improve this page" vs strong "shorten the intro, keep H2 structure, no code blocks"), and include scope + non-goals.
⚠️ The trap: the same 2026 lesson applies across every tool — structure beats raw capability. Teams extracting the most value aren't the ones with the most expensive models; they're the ones with disciplined workflows that play to agent strengths and design around their weaknesses.
