Chains of nodes, not contiguous memory

Linked Lists — when insertion/deletion in the middle must be O(1)

A linked list is a chain of nodes. Each node holds a value and a pointer to the next (and optionally previous). Unlike arrays, the nodes aren't contiguous in memory.

Story Why this matters

Story: you build an LRU cache with a Python list. Every "move to front" is O(n) because the list shifts elements. With a doubly linked list + hash map, it's O(1). This exact trick is the LeetCode 146 "LRU Cache" question — and it's also how Redis, Caffeine, and most production caches are built.

Variants

Variant Each node has Use for
Singly linked val, next Stacks, simple queues, when you only walk forward.
Doubly linked val, next, prev LRU cache, deques, anywhere you delete a known node in O(1).
Circular Last node's next points back to head Round-robin schedulers, ring buffers.

Complexity

Operation Linked list Array (for comparison)
Access kth element O(k) O(1)
Insert/delete at head O(1) O(n)
Insert/delete at tail (with tail pointer) O(1) Amortized O(1)
Insert/delete at known node (doubly) O(1) O(n)
Search for value O(n) O(n)

Skeleton in Python

class Node:
    def __init__(self, val):
        self.val = val
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, val):
        n = Node(val); n.next = self.head; self.head = n

    def reverse(self):
        prev, cur = None, self.head
        while cur:
            cur.next, prev, cur = prev, cur, cur.next
        self.head = prev

Classic patterns

1. Fast / Slow pointers (Floyd's tortoise & hare)

Detect a cycle, find the middle, find the kth from end — all with two pointers moving at different speeds.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast: return True
    return False

2. Dummy head

Almost every linked-list problem becomes simpler if you create a dummy node before the head. You never have to special-case "deleting the head".

def remove_value(head, target):
    dummy = Node(0); dummy.next = head
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        else:
            prev = cur
        cur = cur.next
    return dummy.next

3. Reverse in groups

"Reverse every k nodes" — common medium/hard question. Combines dummy head + iterative reversal.

When to use vs when NOT

Use when

  • You insert/delete at known positions frequently.
  • You can't waste memory on resizing.
  • You're building an LRU cache, deque, or undo-log.

Don't use when

  • You access by index a lot — every access is O(n).
  • Cache locality matters — pointer chasing is brutal for CPU caches.
  • The problem is solvable with an array and an index. Most "I need fast inserts" problems are actually solvable with a deque from the standard library.
Reality check: in production Python/Java, you almost never implement a linked list. You use collections.deque or java.util.LinkedList. The reason to learn linked-list manipulation is interview pattern-recognition, not daily code.
