LIFO and FIFO — the two basic flow patterns

Stacks & Queues — disciplined ways to add and remove

A stack only lets you add and remove at one end (LIFO — last in, first out). A queue adds at one end and removes from the other (FIFO — first in, first out). Trivial-sounding rules, hugely common in interview problems.

Story Why this matters

Story: compilers parsing brackets. Browsers' back-button. Function call stack itself. Print queues. BFS over a graph. Undo history. Every one of these is a stack or a queue — once you see the shape, the right tool is obvious.

Stack

Operations: push (add on top), pop (remove from top), peek (look at top). All O(1).

Implementation in Python

stack = []
stack.append(x)    # push
top = stack[-1]    # peek
x = stack.pop()    # pop

Pattern 1 — bracket / paired matching

def is_valid(s):
    pairs = {')':'(', ']':'[', '}':'{'}
    stk = []
    for c in s:
        if c in '([{':
            stk.append(c)
        else:
            if not stk or stk.pop() != pairs[c]: return False
    return not stk

Pattern 2 — monotonic stack

Keep the stack always sorted (e.g., strictly decreasing). Used for "next greater element", "largest rectangle in histogram", "daily temperatures".

def next_greater(nums):
    res = [-1] * len(nums)
    stk = []   # indices; values in nums[stk] are strictly decreasing
    for i, x in enumerate(nums):
        while stk and nums[stk[-1]] < x:
            res[stk.pop()] = x
        stk.append(i)
    return res

When to use a stack

  • You're tracking nested context (brackets, scopes, recursion).
  • You want "the last thing I haven't resolved yet".
  • You're doing DFS iteratively (instead of recursion).

Queue

Operations: enqueue (add at back), dequeue (remove from front). O(1) with the right backing structure.

Pitfall: Python's list.pop(0) is O(n) — it shifts everything. Always use collections.deque for queues.
from collections import deque
q = deque()
q.append(x)      # enqueue
x = q.popleft()  # dequeue O(1)

Pattern 1 — BFS

BFS over a tree or graph uses a queue to process nodes level by level.

def level_order(root):
    if not root: return []
    q = deque([root]); levels = []
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        levels.append(level)
    return levels

Pattern 2 — sliding window max with a deque

Monotonic deque keeps maximum candidates of the window in O(n) total.

Deque — the swiss-army knife

A double-ended queue. O(1) push/pop on both ends. In Python: collections.deque. Use it for: queues, stacks, sliding windows, undo/redo with size limits, work-stealing pools.

Priority Queue (heap) — a teaser

A priority queue pops the smallest (or largest) element, not the oldest. It's not really a queue — it's a heap, covered in DS 06 — Heaps.

When to use vs when NOT

Use a stack when

  • Order is LIFO.
  • You're tracking nesting / undo.
  • You need to find next-greater / next-smaller.

Use a queue when

  • Order is FIFO.
  • You're doing BFS.
  • You're buffering between producer and consumer at the same rate.

Don't

  • Use list.pop(0) as a queue in Python — it's O(n).
  • Reach for a stack when a single variable would do (e.g., "max so far").
  • Use BFS where DFS would be simpler (or vice versa) — pick based on what you need (shortest path → BFS; pathfinding with backtracking → DFS).
