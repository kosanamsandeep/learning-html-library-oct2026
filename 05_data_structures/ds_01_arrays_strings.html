The most fundamental data structure

Arrays & Strings — the foundation of every other DS

An array is a contiguous block of memory holding elements of the same type. Strings are arrays of characters. Almost every other data structure either uses arrays internally (hash tables, heaps, dynamic arrays, trees as flat arrays) or compares itself to arrays.

The story Why this matters

Story: a junior engineer scans an array 100,000 times in a triple-nested loop. The PR reviewer asks "have you considered a hash set?" — and a 30-second fix turns a 5-hour batch job into 0.4 seconds. That's the move — recognizing which cheap structure replaces an expensive search.

Operations & complexity

Operation Static array Dynamic array (Python list, Java ArrayList)
Access by index O(1) O(1)
Search by value (unsorted) O(n) O(n)
Insert at end O(1) if space Amortized O(1)
Insert at start / middle O(n) — shift everything O(n)
Delete at end O(1) O(1)
Delete at start / middle O(n) O(n)

Why amortized O(1) for append? Dynamic arrays double capacity when full. Most appends are O(1); occasional doubling is O(n) but averaged out it's still O(1) per call.

Common patterns on arrays

1. Two pointers

Two indices walk through the array — same direction or opposite ends. Replaces many O(n²) brute-force approaches with O(n).

# Is the string a palindrome?
def is_palindrome(s):
    i, j = 0, len(s) - 1
    while i < j:
        if s[i] != s[j]: return False
        i += 1; j -= 1
    return True

2. Sliding window

Maintain a window [left, right] and a running aggregate. Expand right, contract left when condition broken.

# Longest substring without repeating chars
def longest_unique(s):
    seen = {}; left = 0; best = 0
    for right, c in enumerate(s):
        if c in seen and seen[c] >= left:
            left = seen[c] + 1
        seen[c] = right
        best = max(best, right - left + 1)
    return best

3. Prefix sums

Precompute cumulative sums so any range sum is O(1) instead of O(n).

prefix = [0]
for x in arr:
    prefix.append(prefix[-1] + x)

# sum of arr[l..r] (inclusive):
range_sum = prefix[r+1] - prefix[l]

4. In-place reversal / rotation

# Rotate array by k to the right, in O(1) extra space
def rotate(arr, k):
    k %= len(arr)
    arr.reverse()
    arr[:k] = reversed(arr[:k])
    arr[k:] = reversed(arr[k:])

When to use vs when NOT to use

Use an array when

  • You know the size up front or appends dominate.
  • You access by index often.
  • Memory locality matters (CPU caches love arrays).
  • You're iterating in order.

Don't use an array when

  • You insert/delete in the middle frequently → use linked list or deque.
  • You need fast lookup by key → use hash table.
  • You need sorted order with fast insert → use BST or sorted container.
  • You need to push and pop from both ends → use deque.

Strings — a few quirks

  • In Python, strings are immutable. s += "x" in a loop is O(n²) because each concatenation creates a new string. Use "".join(list_of_chars) instead — O(n) total.
  • For substring search, Python's in uses a good built-in algorithm; for very long patterns consider KMP / Rabin-Karp.
  • Compare characters by ASCII for the trick ord(c) - ord('a') when you need a size-26 array (e.g., anagram check).
