Trees — when your data has hierarchy

A tree is a connected graph with no cycles, organized as a parent-children hierarchy. The most common variant: binary tree (each node has ≤ 2 children). A BST keeps them ordered: left < root < right.

Vocabulary

Term Meaning
Root The top node, no parent.
Leaf A node with no children.
Depth Distance from root (root has depth 0).
Height Longest path from node down to a leaf.
Balanced Heights of left & right subtrees differ by ≤ 1 at every node.
Complete All levels full except possibly the last, which fills left-to-right.

Binary tree node

class TreeNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

Traversals — know all four cold

DFS variants (recursive)

def inorder(node, out):    # left, root, right  — for BST gives sorted order
    if not node: return
    inorder(node.left, out)
    out.append(node.val)
    inorder(node.right, out)

def preorder(node, out):   # root, left, right — for copying / serializing
    if not node: return
    out.append(node.val)
    preorder(node.left, out); preorder(node.right, out)

def postorder(node, out):  # left, right, root — for deleting, computing sizes
    if not node: return
    postorder(node.left, out); postorder(node.right, out)
    out.append(node.val)

BFS (level order, iterative with queue)

from collections import deque

def level_order(root):
    if not root: return []
    q = deque([root]); res = []
    while q:
        level = []
        for _ in range(len(q)):
            n = q.popleft(); level.append(n.val)
            if n.left:  q.append(n.left)
            if n.right: q.append(n.right)
        res.append(level)
    return res

Binary Search Tree (BST)

Invariant: for every node, all values in the left subtree are smaller, all in the right subtree are larger.

Op Balanced BST Unbalanced BST
Search O(log n) O(n) — degenerates to linked list
Insert O(log n) O(n)
Delete O(log n) O(n)
In-order traversal O(n) O(n)
Insert in sorted order into a plain BST → becomes a linked list, all ops O(n). Real systems use self-balancing trees (AVL, Red-Black) to keep ops at O(log n).

BST search

def search(node, target):
    while node:
        if target == node.val: return node
        node = node.left if target < node.val else node.right
    return None

Self-balancing trees you should know by name

  • AVL Tree — strict balance, fastest lookups, slower inserts.
  • Red-Black Tree — looser balance, faster mutations. Backs Java TreeMap, C++ std::map.
  • B-Tree / B+Tree — many children per node, optimized for disk reads. Backs every relational database index.

For interviews you almost never implement these. Knowing what each is for and when each wins is enough.

When to use a tree vs a flat structure

Use a tree when

  • Data is hierarchical (file system, org chart, DOM, JSON, AST).
  • You need ordered + fast insert/delete + range queries → BST.
  • Building heaps, tries, segment trees — all are tree-based.

Don't use when

  • You only need fast lookups by key, no ordering → hash table.
  • Data is flat and indexed → array.
  • You'd build a BST without balancing — you'll regret it; use a sorted container.
