Recursion & Dynamic Programming — the hardest skill, broken down

DP scares most candidates. It shouldn't — every DP problem is just recursion + memo. Master the 5 shapes on this page and you'll recognize 80% of DP problems on sight.

Recursion — the base / recursive case template

Every recursive function has two parts:

  1. Base case — when do we stop?
  2. Recursive case — how do we reduce the problem to a smaller one?
def factorial(n):
    if n <= 1: return 1            # base case
    return n * factorial(n - 1)    # recursive case
Stack overflow happens when recursion depth exceeds the call stack limit (Python: ~1000). For deep recursion (trees with millions of nodes, linked lists), use iteration or tail-call simulation with a stack.

Backtracking — recursion that explores possibilities

Try a choice; recurse; if it doesn't lead to a solution, undo and try another.

def permutations(nums):
    out, path = [], []
    used = [False] * len(nums)
    def dfs():
        if len(path) == len(nums):
            out.append(path[:])    # make a copy
            return
        for i, x in enumerate(nums):
            if used[i]: continue
            used[i] = True; path.append(x)
            dfs()
            path.pop(); used[i] = False    # undo
    dfs()
    return out

Use backtracking for: permutations, combinations, subsets, N-queens, sudoku, word search, generating all valid expressions.

Dynamic Programming — what it actually is

DP applies when:

  1. The problem has optimal substructure — the answer for size n is built from answers for smaller sizes.
  2. It has overlapping subproblems — the naive recursion re-computes the same subproblems many times.
Story: naive recursive Fibonacci computes fib(30) = fib(29) + fib(28), and both recompute fib(27), and so on. fib(40) takes seconds. With memoization, microseconds. Same code, one decorator added. 
# O(2^n) — naive
def fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)

# O(n) — memoized
from functools import lru_cache
@lru_cache(maxsize=None)
def fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)

Memoization vs Tabulation

Style Direction Pros Cons
Memoization (top-down) Recursive + cache Easy to write; only computes needed states. Recursion stack; can hit limits.
Tabulation (bottom-up) Fill a table iteratively No stack; often more efficient. Need to figure out fill order.

Same problem, both styles — climbing stairs

# Memoization
@lru_cache(maxsize=None)
def climb(n):
    if n <= 2: return n
    return climb(n - 1) + climb(n - 2)

# Tabulation
def climb(n):
    if n <= 2: return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

# Space-optimized — only need last two
def climb(n):
    a, b = 1, 2
    for _ in range(n - 2):
        a, b = b, a + b
    return b if n > 1 else 1

The 5 DP shapes — 80% of all problems

Shape 1 — Linear DP on a sequence

State dp[i] depends on a few earlier dp[j].

Examples: Climbing Stairs, House Robber, Min Cost Climbing Stairs, Longest Increasing Subsequence.

Shape 2 — DP on a grid / 2D

State dp[i][j] from dp[i-1][j], dp[i][j-1], etc.

Examples: Unique Paths, Min Path Sum, Edit Distance, Longest Common Subsequence.

Shape 3 — Knapsack family

Given items with weights/values, fit into a capacity. Two flavors: 0/1 (each item once) and unbounded (repeat allowed).

Examples: 0/1 Knapsack, Coin Change, Partition Equal Subset Sum, Target Sum.

Shape 4 — Interval / Range DP

State dp[i][j] over a range [i..j]; combine over a split point k.

Examples: Matrix Chain Multiplication, Burst Balloons, Palindrome Partitioning.

Shape 5 — DP on trees / graphs

Compute an answer for a node from answers for its children. Often combined with DFS.

Examples: House Robber III (binary tree), Diameter, Longest Path in DAG.

How to attack a new DP problem (interview recipe)

  1. Write the brute-force recursion first. Don't try to "jump" to DP.
  2. Identify the parameters that change. Those become your DP state.
  3. Add @lru_cache on the recursive function. You now have a working memoized solution.
  4. (Optional) convert to tabulation for performance and to escape the recursion limit.
  5. (Optional) space-optimize if only last few rows / cols are needed.

Saying this out loud in an interview signals senior thinking. You don't need to nail the optimal version on the first try.
