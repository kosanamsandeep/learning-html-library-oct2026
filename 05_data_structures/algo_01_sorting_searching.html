The first two algorithms every engineer knows

Sorting & Searching — the universal pre-processing step

If you sort first, half your problems become easier. If you binary-search, your O(n) becomes O(log n). Mastering when each applies turns interview "medium" problems into "easy" ones.

Sorting algorithms — know all by complexity, master 2 by code

  • Stable means equal elements keep their relative order. Matters when sorting by one key then another.
  • Python's sorted() uses Timsort — O(n log n), stable, very fast on real-world (partially sorted) data. Always use it.

Two sorts to know by heart

Merge sort — the textbook divide and conquer

def merge_sort(a):
    if len(a) <= 1: return a
    mid = len(a) // 2
    left  = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    return merge(left, right)

def merge(l, r):
    out, i, j = [], 0, 0
    while i < len(l) and j < len(r):
        if l[i] <= r[j]: out.append(l[i]); i += 1
        else:            out.append(r[j]); j += 1
    out += l[i:]; out += r[j:]
    return out

Quicksort — the in-place workhorse

def quicksort(a, lo=0, hi=None):
    if hi is None: hi = len(a) - 1
    if lo >= hi: return
    pivot = a[(lo + hi) // 2]
    i, j = lo, hi
    while i <= j:
        while a[i] < pivot: i += 1
        while a[j] > pivot: j -= 1
        if i <= j:
            a[i], a[j] = a[j], a[i]
            i += 1; j -= 1
    quicksort(a, lo, j); quicksort(a, i, hi)

Binary search — the most common O(log n)

Pre-condition: the array must be sorted. Each step halves the search space.

def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target: return mid
        if a[mid] < target:  lo = mid + 1
        else:                 hi = mid - 1
    return -1

The two pitfalls

  • Off-by-one. Use the template religiously: while lo <= hi, update lo = mid + 1 / hi = mid - 1.
  • Integer overflow in (lo + hi) // 2 — in Python no issue, in C/Java use lo + (hi - lo) // 2.

Variants you must know

  • Lower bound: first index where a[i] >= target.
  • Upper bound: first index where a[i] > target.
  • Search in rotated sorted array.
  • Binary search on the answer — for problems like "smallest capacity that lets Koko eat all bananas in H hours".

Python's bisect module has bisect_left / bisect_right built in.

Binary search on the answer — the unlock

Story: "find the minimum eating speed K such that Koko finishes N piles of bananas in H hours". Brute force tries every K. Insight: if K=10 works, K=11 works too. So the set of "works" / "doesn't" is monotonic — binary-search over K.
def koko(piles, h):
    def hours_at(k):
        return sum((p + k - 1) // k for p in piles)
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if hours_at(mid) <= h: hi = mid
        else:                   lo = mid + 1
    return lo

Any time you can ask "is X feasible?" with a monotonic answer in X, binary-search instead of brute-force.

When to sort vs when not

Sort first when

  • You need pairs / triplets summing to target (after sort, two-pointer is O(n)).
  • You're looking for duplicates / nearest values.
  • You need to apply two-pointer or binary search.
  • You're computing a greedy answer ("schedule jobs by deadline").

Don't sort when

  • A hash table solves it in O(n) without sorting.
  • Order in the input is the answer (don't destroy it).
  • You only need top-K — heap is O(n log k), beats O(n log n) sort.
