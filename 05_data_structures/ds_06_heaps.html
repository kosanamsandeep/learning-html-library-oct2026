When you keep asking "what's the smallest right now?"

Heaps — the O(log n) "top of the pile" data structure

A heap is a complete binary tree where each parent is ≤ its children (min-heap) or ≥ (max-heap). Implemented as a flat array. Used for: top-K problems, k-way merges, Dijkstra, median in a stream, scheduling.

Story Why this matters

Story: you stream prices from 100 stock tickers and want the top 10 highest right now. Sorting the full list every tick is O(n log n) repeatedly. With a min-heap of size 10: each tick is O(log 10) — basically O(1). Same trick is how K-largest / K-smallest problems are solved.

Operations & complexity

Operation Complexity
Peek min/max O(1)
Push O(log n)
Pop min/max O(log n)
Heapify (build from array) O(n)
Arbitrary delete / update O(n) without extra index, O(log n) with

Python heapq

Python's heapq is a min-heap over a regular list. There's no built-in max-heap — negate values to simulate it.

import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
heapq.heappop(h)    # 1
heapq.heappop(h)    # 3

# heapify in O(n)
arr = [5, 2, 8, 1, 3]
heapq.heapify(arr)

# top-K largest
heapq.nlargest(3, [5, 2, 8, 1, 9, 4])   # [9, 8, 5]

# max-heap trick — negate
heap = []
for v in [5, 1, 7]:
    heapq.heappush(heap, -v)
biggest = -heapq.heappop(heap)   # 7

Classic patterns

1. Top-K elements

Maintain a min-heap of size K. For each new element: if heap is smaller than K push, otherwise if element is larger than heap top, pop and push.

def top_k(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)
    return h

2. K-way merge

Merge K sorted lists. Put one element per list in a heap; pop smallest; push the next from that list.

3. Median in a stream

Two heaps: max-heap for the lower half, min-heap for the upper half. Median = top of the larger heap (or average of both tops if equal size).

4. Dijkstra's shortest path

Min-heap keyed by "distance so far". See graphs.

When to use vs when NOT

Use a heap when

  • You repeatedly need the minimum / maximum from a changing set.
  • Top-K problems.
  • Scheduling by priority.
  • Building Dijkstra / Prim's MST.

Don't use when

  • You need lookup by key — heap can't search in O(log n), only pop the top.
  • You need full sorted order, not just the top — use sort or a sorted container.
  • You need to iterate in order without destroying the heap.
