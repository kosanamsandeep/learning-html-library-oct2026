The O(1) workhorse

Hash Tables — the most-used data structure on Earth

A hash table maps keys to values, with average-case O(1) for insert, lookup, and delete. It is by far the most important data structure to master after arrays — and the most common "trick" to turn an O(n²) interview problem into O(n).

Story Why this matters

Story: "find two numbers that sum to a target". Naive: nested loop, O(n²). With a hash set: one pass, for each number check if target - x has been seen. O(n). Same idea, 1000× faster. If you only learn one optimization trick, learn this one.

How it works under the hood

  1. You have an array of buckets (say, size 16).
  2. To insert key k: compute hash(k) % 16 → that's the bucket index.
  3. Put the (key, value) pair into that bucket.
  4. If two keys land in the same bucket (a collision), store them in a list or open-address into the next bucket.
  5. When the table gets too full (load factor > ~0.75), resize: allocate a bigger array and rehash everything. O(n) one-time cost; amortized to O(1) per op.

Two collision strategies

Strategy What happens Used by
Separate chaining Each bucket holds a linked list / tree of entries. Java's HashMap
Open addressing On collision, probe the next bucket(s) by some rule. Python's dict (open addressing)

Complexity

Operation Average Worst
Insert O(1) O(n) — pathological hash collisions
Lookup O(1) O(n)
Delete O(1) O(n)
Space O(n) O(n)

Worst case happens only with adversarial inputs (e.g., attacker chooses keys that all collide). Modern languages use randomized hash seeds to defeat this.

Hash set vs hash map

  • Set — just the keys, no values. "Have I seen this?"
  • Map (a.k.a. dictionary) — keys → values. "What's associated with this?"

Both have the same O(1) average behavior. Choose based on whether you need an associated value.

Common patterns

1. Lookup with complement

def two_sum(nums, target):
    seen = {}   # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i

2. Frequency count

from collections import Counter
counts = Counter("statistics")  # {'s':3, 't':3, 'a':1, ...}

3. Grouping

from collections import defaultdict
groups = defaultdict(list)
for word in words:
    key = "".join(sorted(word))   # sorted letters = anagram key
    groups[key].append(word)

4. Seen-set memoization

Mark visited nodes in a graph, seen states in a search — anywhere you'd otherwise revisit work.

When to use vs when NOT

Use a hash table when

  • You need fast lookup by key.
  • You're counting frequencies, grouping, or de-duplicating.
  • You're caching computed results (memoization).

Don't use when

  • You need ordered traversal — use a sorted container or BST.
  • You need range queries ("all keys between 10 and 50") — use BST / sorted structure.
  • Keys aren't hashable (mutable objects in Python).
  • Memory is tight — hash tables have overhead (typically 1.3–2× the raw data).

Bonus — LRU Cache with hash + doubly linked list

The classic LeetCode 146. Hash gives O(1) lookup by key; doubly linked list gives O(1) move-to-front. Together: an LRU cache with O(1) get and put.

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.cache = OrderedDict()
    def get(self, key):
        if key not in self.cache: return -1
        self.cache.move_to_end(key)
        return self.cache[key]
    def put(self, key, val):
        if key in self.cache: self.cache.move_to_end(key)
        self.cache[key] = val
        if len(self.cache) > self.cap:
            self.cache.popitem(last=False)
