Track 2 · Case Studies

Five tiny versions of real systems

Each project picks one famous pattern — sharded counters, real-time leaderboards, presence, sagas, geo lookups — and implements just enough to make the design decisions visible.

Project order

P1 · DISTRIBUTED COUNTERSharded counters with read aggregation. The pattern behind YouTube view counts and post likes. P2 · REAL-TIME LEADERBOARDSorted set with top-N and rank-of-user queries. The pattern behind game leaderboards. P3 · PRESENCE SERVICEHeartbeats with TTL. The pattern behind Slack / WhatsApp "online now". P4 · SAGA ORCHESTRATORStep-by-step distributed transaction with compensations. The pattern behind booking flows. P5 · NEARBY DRIVERSGeohash bucketing for "drivers within 2 km". The pattern behind Uber / Swiggy dispatch.

Why toy versions?

A 100-line implementation forces you to choose: bucket size, refresh interval, compensating action, fan-out path. Those are the conversations interviewers actually want — far more useful than memorising "they use Cassandra".
