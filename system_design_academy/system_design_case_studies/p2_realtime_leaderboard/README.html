Real-time leaderboard — top-N, rank, and "around me"

Game leaderboards live or die on three operations: update score, top N, rank of one user. Redis ZSET makes all three O(log N). Here we build the same shape in Python so the design choices are visible.

The story

Your mobile game has a million daily players. Every match updates a score. The home screen needs top 10 in <50ms, and the profile screen needs "your rank is #28,432" plus the players just above and below you.

Three operations, one data structure

Operation Why it's tricky How sorted set solves it
submit(user, score) Must remove the old entry to keep order valid. O(log N) remove + O(log N) insert.
top(N) Naive scan is O(total). Slice first N entries in order.
rank(user) Want position without scanning everything. Skip list indexes; O(log N) in Redis ZSET.

Our Python demo uses bisect.insort for clarity — Redis uses a skip list for the same shape at internet scale.

Mental model

match ends
->
ZADD leaderboard score user
->
ZREVRANGE 0 9 WITHSCORES (top 10)
->
ZREVRANK user (their rank)

Production notes

  • Use one ZSET per leaderboard (global / weekly / friends-only).
  • Cap memory with an expiring weekly key, and snapshot all-time on Sunday.
  • For "around me" use ZREVRANGE rank-window to rank+window — O(log N + 2*window).

Run it

cd system_design_academy/system_design_case_studies/p2_realtime_leaderboard
python main.py

You will see the top 5, the rank of two players, and a five-line "around you" view.

Interview-ready answer

"I use a Redis sorted set keyed by score. Update score = ZADD, top N = ZREVRANGE, individual rank = ZREVRANK — each O(log N) thanks to the skip list. For multiple boards I keep one ZSET per board, and the 'players near you' view is just ZREVRANGE with a small window around the user's rank."
