AI Engineering · Project 3

Agent memory — short-term, long-term, episodic

LLMs forget everything between calls. Real agents fake memory by stitching three things into every prompt: the current chat, durable facts retrieved by similarity, and summaries of past sessions.

The three memory types

Type Stored as Lives for Used for
Short-term Last N turns in a deque. The current session. Coherent conversation, references to "what I just said".
Long-term Embedding-indexed facts in a vector DB. Forever (until you delete). "Remember that I am vegetarian", user preferences, durable knowledge.
Episodic One summary line per past session. Across sessions. "Last week we worked on auth"; long-horizon context.

Prompt assembly

user message
->
recall top-K long-term facts
->
get N recent episodic summaries
->
attach short-term buffer
->
send to LLM

The agent never sends "everything it knows" — only what is relevant to this turn. That is what keeps token cost sane.

What to write to memory

Write facts the user explicitly shares ("I live in Bengaluru", "my project is X"), or that the agent infers and the user confirms.
Write preferences the user repeats ("short answers please", "no markdown lists").
Don't write every chat turn into long-term memory — it just adds noise. Use periodic summarisation instead.

Run it

cd system_design_academy/ai_engineering/p3_ai_agent_memory
python main.py

You will see two sessions. The second session starts with no short-term memory but still recalls user facts and the previous session's summary.

Interview-ready answer

"I split agent memory into three layers. Short-term is just the last N chat turns. Long-term is a vector index of durable facts I recall by similarity at each turn. Episodic is one summary line written at the end of each session so the next session can reference it. The prompt is assembled fresh each turn — recall first, then format — which keeps tokens predictable as memory grows."
