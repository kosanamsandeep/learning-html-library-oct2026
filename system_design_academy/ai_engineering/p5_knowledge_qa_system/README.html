AI Engineering · Project 5

Knowledge Q&A — RAG, citations, guardrails, evaluation

A demo-quality RAG is retrieve + LLM. A production RAG adds three things: grounded citations, a refusal guardrail, and an automated faithfulness score on every answer.

The story

You ship a RAG bot to support. Real users ask anything — including "give me medical advice". You need to refuse those. Real users also ask things outside your corpus — you must say "I don't know" instead of inventing. And on every real answer you want a score that says "yes, this is supported by the sources" — so you can detect drift in CI.

End-to-end pipeline

guardrail (refuse?)
->
retrieve top-k
->
generate with citation
->
evaluator scores faithfulness

Each stage is small and replaceable. The evaluator returns a number you can graph over time.

What each component does

Component Job Production version
Guardrail Refuse questions in banned categories. Classifier model + blocklist + policy doc.
Retriever Pick top-k source chunks for the query. Vector DB (FAISS / pgvector / Milvus) + reranker.
Answerer Generate grounded prose with source IDs. LLM with "cite [doc-id]" instruction + JSON schema.
Evaluator Score faithfulness of answer vs sources. LLM-as-judge or Ragas / TruLens; persist scores per query.

Why citations matter

If the model cites [source: doc-3] you can:
  • Show the user where the claim came from.
  • Auto-check that the claim actually appears in doc-3.
  • Roll back or re-train when too many answers cite the wrong doc.
Citations are the cheapest way to make a RAG system auditable.

Run it

cd system_design_academy/ai_engineering/p5_knowledge_qa_system
python main.py

Three questions go through the pipeline. One is answered with sources and a faithfulness score, one is out of scope, one is refused by the guardrail.

Watch the second question. "What is the population of Saturn?" returns a grounded-looking answer about consistent hashing — because the retriever picks the closest doc even when nothing is actually relevant. Faithfulness ≠ correctness. Production systems pair faithfulness with a minimum similarity threshold (refuse if top-1 score is below, say, 0.3).

Interview-ready answer

"For knowledge Q&A I always wrap RAG with three things: a guardrail to refuse banned categories, mandatory source citations in the answer, and an automated faithfulness evaluator that scores every response. The evaluator runs in CI on a golden question set and in production on a sample of live traffic — that is how you detect drift before users do."

How this extends our existing RAG project

The genai_rag_platform project is a more complete RAG architecture with chunking, embeddings, and providers. This page adds the eval + guardrail layer that turns it from "it answers" into "I trust it in production".
