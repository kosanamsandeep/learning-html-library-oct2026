AI Engineering · Project 4

Context engineering — fit the most useful text into the budget

Prompt engineering picks the words you write. Context engineering picks the text the model sees. Most production LLM bugs are not bad prompts — they are too much (or wrong) context.

The four jobs of a context pipeline

Step Goal
Retrieve Pull candidate chunks from your sources.
Dedupe Drop near-identical chunks so the same paragraph does not fill the window twice.
Compress Summarise or truncate long chunks before they spend the budget.
Fit to budget Greedy pack by combined relevance + recency until tokens run out.

Why this matters more than prompt wording

Too much context = the model gets confused, latency rises, cost rises, and quality often falls (lost-in-the-middle problem).
Wrong context = the model confidently quotes irrelevant material.
Right context, tight = better answers, faster, cheaper.

Ranking signal

score = 0.7 * relevance + 0.3 * recency

The exact weights vary by domain. News-heavy systems weigh recency higher; reference manuals weigh relevance higher.

Run it

cd system_design_academy/ai_engineering/p4_context_engineering
python main.py

You will see five candidate chunks shrink through dedupe + compress, then greedy-pack into a 40-token window.

Interview-ready answer

"For any LLM feature past a toy I set an explicit token budget and write the retrieval → dedupe → compress → fit pipeline as four named steps. Ranking is a small weighted score of relevance and recency. Long chunks are summarised before they enter the budget, never after. This makes cost predictable and avoids the lost-in-the-middle quality drop."
