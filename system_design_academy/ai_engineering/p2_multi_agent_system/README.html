AI Engineering · Project 2

Multi-agent system — supervisor + specialists

One agent doing everything is a generalist that makes generalist mistakes. Split the work into role-flavoured agents — researcher, writer, critic — and coordinate them with a supervisor. This is the shape behind LangGraph, CrewAI, AutoGen.

The story

You ask the assistant: "explain consistent hashing in one paragraph". A single-agent answer is hit or miss. Split it: researcher pulls the fact from a knowledge base, writer turns it into prose, critic checks it — if the critic flags the draft, the writer expands. Three small calls beat one giant one.

Mental model

user question
->
Supervisor
->
Researcher (facts)
->
Writer (draft)
->
Critic (verdict)
->
retry or ship

Why this beats a single agent

Each role has a tight prompt. The researcher prompt is short and only about retrieval. The writer prompt only knows facts → prose. Clear prompts get better outputs.
Critic catches errors. A second LLM call playing devil's advocate catches things a single drafting pass misses.
3× the calls. More tokens, more money. Use this pattern only where quality matters more than latency or cost.

Code skeleton

facts    = researcher.act(question)
draft    = writer.act(facts)
critique = critic.act(draft)
if "ok" not in critique.lower():
    draft = writer.act(f"{facts}\nNOTE: {critique}\nExpand to 2 sentences.")
return draft

Run it

cd system_design_academy/ai_engineering/p2_multi_agent_system
python main.py

Two questions go through the pipeline. The second one triggers a writer retry because the critic flags it as too short.

Interview-ready answer

"I use a supervisor + specialists pattern when the task naturally decomposes into roles — research, write, review, execute. The supervisor owns control flow; specialists each have a short, focused system prompt. I add a critic agent for quality-sensitive output, but I cap iterations because reflection loops can spiral. Frameworks like LangGraph give this shape a state machine; that is what production multi-agent systems use today."
