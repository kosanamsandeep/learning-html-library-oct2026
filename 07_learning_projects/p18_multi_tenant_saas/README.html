Project 18 simplified

Multi-tenant SaaS means: many companies share one app, but data stays separated

This project models a SaaS product where Acme, Globex, and Wayne Enterprises all use the same code and storage, but each tenant can only see its own records. It also shows plans, limits, and feature flags.

The story

You are building a project management SaaS. Every customer company is a tenant. All tenants use the same application, but tenant data must never leak.

Without tenant isolation

A bug in a query can show Globex data to Acme. That is a severe security and trust failure.

With tenant isolation

The tenant is resolved once per request. The storage layer automatically scopes every insert, find, count, and delete.

The mental model

request arrives
->
resolve tenant
->
set TenantContext
->
business logic runs
->
store filters by tenant
Important: business code does not manually pass tenant_id everywhere. It asks TenantContext who the current tenant is, and the storage layer uses that automatically.

The key idea: tenant context

TenantContext stores the current tenant for the current request. In a real FastAPI or Django app, middleware would set this from a header, subdomain, token, or route.

TenantContext.set_current(acme)
store.insert("projects", "proj-1", {"name": "Website Redesign"})

TenantContext.set_current(globex)
store.insert("projects", "proj-1", {"name": "Laser Cannon"})

Both tenants can use the same record id proj-1, because the store internally saves records as tenant_id:record_id.

How storage isolation works

tenant = TenantContext.require_current()
key = f"{tenant.tenant_id}:{record_id}"
self._data[collection][key] = record

When Acme calls find_all("projects"), the store returns only records where record.tenant_id == "acme". Globex records exist in the same collection, but Acme cannot see them.

Plan limits in plain English

Plans answer: "What is this tenant allowed to use?"

Plan concept Example in this project
Max users Free plan allows 3 users. Enterprise allows many more.
Storage Free gets 100 MB. Professional gets 10 GB.
API calls Higher plans get more API calls per day.
Features SSO and audit logs are only available in higher plans.

Feature flags in plain English

Feature flags answer: "Should this tenant see this feature right now?"

Strategy Meaning Example
BOOLEAN On or off for everyone. Kill switch for a broken feature.
PLAN_BASED Only certain plans can use it. AI suggestions for Professional and Enterprise.
PERCENTAGE Roll out to a stable percentage of tenants. New dashboard for 30% of tenants.
TENANT_LIST Only a whitelist of tenant IDs can use it. Beta Gantt chart for Acme and Wayne.
Deterministic rollout: percentage flags use a hash of tenant_id, so the same tenant always gets the same result. The feature will not flicker on and off randomly.

Interview answer in simple words

Use this when someone asks, "How do you design multi-tenant SaaS?"

In a multi-tenant SaaS app, many customers share the same application, but every request must be scoped to exactly one tenant. I resolve the tenant at request entry, store it in a request-safe context, and make the data layer automatically filter by tenant. Plans and feature flags then control what each tenant is allowed to use without duplicating the application.
