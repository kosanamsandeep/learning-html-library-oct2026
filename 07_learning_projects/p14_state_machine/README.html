Project 14: State Machine - E-Commerce Order Workflow

Finite State Machine State Pattern Guard Conditions Observer Pattern Fluent Interface

Story: You're building an e-commerce platform. Orders go through complex lifecycle states (draft, payment, processing, shipping, delivery). A state machine prevents impossible transitions and enforces business rules — no more "shipped but never paid" bugs.

State Diagram - Order Lifecycle

stateDiagram-v2 [*] --> draft draft --> pending_payment: submit [total > 0] draft --> cancelled: cancel pending_payment --> paid: pay pending_payment --> payment_failed: payment_fail pending_payment --> cancelled: cancel payment_failed --> pending_payment: retry_payment [attempts < 3] payment_failed --> cancelled: cancel paid --> processing: start_processing paid --> cancelled: cancel paid --> refunded: refund (100%) processing --> shipped: ship [address exists] processing --> cancelled: cancel processing --> refunded: refund (100%) shipped --> delivered: deliver delivered --> refunded: refund (80%) cancelled --> [*] delivered --> [*] refunded --> [*]

Guard Conditions (Business Rules)

Transition Guard Business Rule
draft → pending_payment total_amount > 0 Can't submit empty cart
processing → shipped shipping_address != "" Need address to ship
payment_failed → pending_payment payment_attempts < 3 Max 3 retry attempts
shipped → cancelled (no transition defined) Can't cancel after shipping
Why Guards? Without guards, you rely on scattered if/else checks throughout the codebase. With guards, the state machine itself enforces business rules — it's impossible to reach an invalid state.

FSM vs If/Else Comparison

Aspect If/Else Approach State Machine
State tracking String/enum field, checked everywhere Single source of truth
Valid transitions Scattered checks, easy to miss Centralized, declarative
Adding new state Hunt for all if/else blocks Add state + transitions
Documentation Manual, gets outdated Diagram IS the code
Testing Combinatorial explosion Test each transition
Business visibility Hidden in code Visual state diagram

Real-World Inspirations

XState (JavaScript)

The gold standard for frontend state machines. Uses statecharts (hierarchical FSM). Powers complex UI workflows, form wizards, and animation states.

django-fsm

Adds FSM behavior to Django models. Transitions are decorated methods with guards. Integrates with Django admin for visual state management.

AWS Step Functions

Serverless workflow orchestration using state machines (Amazon States Language). Each state can be a Lambda, wait, choice, or parallel execution.
