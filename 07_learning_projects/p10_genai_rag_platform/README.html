🧠 What is RAG?

Retrieval-Augmented Generation

LLMs hallucinate. RAG grounds them in YOUR data.

Without RAG

User asks → LLM guesses from training data → May hallucinate → No citations

With RAG

User asks → Find relevant docs → Add to prompt → LLM answers from YOUR data → Cites sources

RAG = Three Steps

R
RETRIEVE - Find relevant document chunks via embedding similarity search
A
AUGMENT - Add retrieved chunks as context to the LLM prompt
G
GENERATE - LLM produces an answer grounded in the retrieved context

🔑 Key Technical Concepts

Embeddings & Vector Similarity

An embedding converts text into a list of numbers (vector) that captures meaning. Similar texts have similar vectors.

# "Python programming" → [0.12, -0.34, 0.56, ...]  (128 dimensions)
# "Java coding"         → [0.11, -0.32, 0.54, ...]  (similar! both programming)
# "Cooking recipe"      → [-0.45, 0.78, -0.12, ...] (different! unrelated topic)

# Cosine similarity:
# "Python programming" vs "Java coding" → 0.92 (very similar)
# "Python programming" vs "Cooking"     → 0.15 (not similar)

Chunking Strategy

Chunking splits large documents into searchable pieces. Too large = noisy retrieval. Too small = lost context.

# A 10-page document with chunk_size=400, overlap=50:
#
# Chunk 1: [paragraph 1 + paragraph 2]     ← 380 chars
# Chunk 2: [last 50 of chunk 1 + para 3]   ← overlap ensures continuity
# Chunk 3: [last 50 of chunk 2 + para 4]   ← no sentence is "lost"
#
# Each chunk gets its own embedding → independently searchable

Cosine Similarity Formula

# cos(A, B) = (A · B) / (||A|| × ||B||)
#
# Where:
#   A · B    = dot product = Σ(ai × bi)
#   ||A||    = magnitude = √(Σ(ai²))
#
# Result range: -1 to 1
#   1.0  = identical direction (same meaning)
#   0.0  = perpendicular (unrelated)
#  -1.0  = opposite direction (opposite meaning)

🎯 SOLID Principles in This Project

Principle Application
S - Single Responsibility ChunkingService ONLY chunks. EmbeddingProvider ONLY embeds. VectorStore ONLY stores. Each class has ONE job.
O - Open/Closed Add new embedding models (OpenAI, Cohere) without changing services. Just create a new provider class.
L - Liskov Substitution Any EmbeddingProvider works wherever the interface is expected. LocalEmbedding or OpenAIEmbedding — both valid.
I - Interface Segregation Three focused interfaces: EmbeddingProvider, LLMProvider, VectorStore. Not one giant AIProvider.
D - Dependency Inversion Services depend on EmbeddingProvider (abstract), never on LocalEmbeddingProvider (concrete).

🚀 Extending to Production

To make this production-ready, swap providers:

Component Demo (This Project) Production
Embedding LocalEmbeddingProvider (hash-based) OpenAI text-embedding-3-large / Cohere embed-v3
LLM MockLLMProvider (template-based) OpenAI GPT-4 / Anthropic Claude / Local Llama
Vector Store MemoryVectorStore (dict + cosine) Pinecone / Qdrant / ChromaDB / pgvector
Chunking Paragraph-based with overlap Semantic chunking / Recursive text splitter

✅ ZERO changes to RAGService, RetrievalService, or IngestionService — just swap providers!
