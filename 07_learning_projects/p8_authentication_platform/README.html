⚡ Dependency Inversion Principle (DIP)

The Rule

"High-level modules should NOT depend on low-level modules. Both should depend on abstractions."

graph TD subgraph "❌ Without DIP" A[AuthService] -->|directly depends on| B[LocalAuthProvider] A -->|directly depends on| C[OAuthProvider] Note1[Adding new provider = change AuthService!] end
graph TD subgraph "✅ With DIP" D[AuthService] -->|depends on| E[AuthProvider Interface] F[LocalAuthProvider] -->|implements| E G[OAuthProvider] -->|implements| E H[ApiKeyProvider] -->|implements| E Note2[Adding new provider = just implement interface!] end

🔌 Plug and Play Design

Adding a New Auth Provider

# Step 1: Create new provider (implement interface)
class OAuthProvider(AuthProvider):
    def authenticate(self, credentials):
        code = credentials["code"]
        # Exchange code for token with Google/GitHub
        ...
    
    def validate_token(self, token): ...
    def revoke_token(self, token): ...
    def get_provider_name(self): return "oauth"

# Step 2: Register it (ONE line change!)
auth_service.register_provider(OAuthProvider())

# Step 3: Use it
auth_service.authenticate("oauth", {"code": "abc123"})

# NOTHING ELSE CHANGES! Not the service, not other providers, nothing.

🔄 Authentication Flow

sequenceDiagram participant Client participant Service as AuthService participant Provider as AuthProvider (any) participant Hasher as PasswordHasher participant Store as TokenStore Client->>Service: authenticate("local", {user, pass}) Service->>Service: Find provider by name Service->>Provider: provider.authenticate(credentials) Provider->>Hasher: verify_password(pass, hash) Hasher-->>Provider: True/False Provider->>Store: store_token(new_token) Provider-->>Service: AuthResult(success, user, token) Service-->>Client: AuthResult Note over Client,Store: Same flow works for ANY provider!

🎯 Key Takeaways

  1. Interfaces define WHAT, implementations define HOW
  2. DIP: Both high and low level depend on abstractions
  3. Plug & Play: New providers need zero changes to existing code
  4. Multiple interfaces: AuthProvider + PasswordHasher + TokenStore
