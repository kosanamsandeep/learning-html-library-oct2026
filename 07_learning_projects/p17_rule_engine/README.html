Project 17 simplified

A rule engine means: move business if/else logic into small named rules

This project calculates insurance premiums. The simple idea is: instead of writing one huge function with hundreds of conditions, define many small rules. Each rule says, "when this condition is true, apply this action."

The story

Insurance pricing has many rules: vehicle type, driver age, accidents, DUI violations, location risk, mileage, loyalty, and discounts.

Without a rule engine

You get a giant premium function full of nested if statements. It becomes hard to test, hard to explain, and risky to change.

With a rule engine

Each business rule becomes a small object. You can list rules, test rules, reorder rules, and explain exactly why a premium changed.

The mental model

facts: driver data
->
rules: conditions + actions
->
engine checks every rule
->
results: base, multipliers, discounts
->
final premium
Important: the rule engine does not know insurance. It only knows how to evaluate rules. Insurance knowledge lives in rules/insurance_rules.py.

What each file does

File Simple meaning Focus on
main.py Runs demos showing specifications, premium calculation, risk profiles, and dynamic rule changes. demo_1_specification_pattern(), demo_2_rule_evaluation()
engine/rule_engine.py Generic rule engine. It can be used for insurance, discounts, fraud, eligibility, or any rule-based decision. Specification, Rule, RuleEngine.evaluate_all()
rules/insurance_rules.py Insurance-specific rules: base premiums, surcharges, discounts, and final premium calculation. create_insurance_engine(), calculate_premium()

The core objects

Object Meaning Example
facts The input data being evaluated. {"driver_age": 35, "vehicle_category": "sedan"}
Specification A condition that returns true or false. LessThan("driver_age", 21)
Rule A condition plus an action. If vehicle is sports, set base premium to 1800.
RuleEngine Runs rules in priority order and collects results. engine.evaluate_all(driver)

The rule shape, simplified

Rule(
    name="young_driver_high_risk",
    condition=LessThan("driver_age", 21),
    action=lambda facts, results: results.setdefault("multipliers", []).append(
        ("Young driver (<21)", 1.6)
    ),
    priority=20,
)

Read it like English: when driver age is less than 21, then add a 1.6x multiplier.

How premium calculation works

  1. Base premium rule fires first, based on vehicle_category.
  2. Risk multiplier rules add surcharges for age, accidents, DUI, speeding, and high-risk area.
  3. Discount rules add discounts for clean record, loyalty, multiple policies, safe vehicle, or low mileage.
  4. calculate_premium() applies multipliers first, then discounts.
  5. Discounts are capped at 40%, so the system cannot accidentally give away too much discount.
base premium = 900
apply multipliers: 900 * 1.3
apply discounts: premium * (1 - total_discount)
final premium = rounded result

Interview answer in simple words

Use this when someone asks, "Why use a rule engine?"

A rule engine helps when business decisions have many changing conditions. Instead of hardcoding a large if/else chain, I model each condition as a small rule with a name, priority, condition, and action. The engine evaluates rules against facts and records which rules fired, making the system easier to test, change, and explain.
