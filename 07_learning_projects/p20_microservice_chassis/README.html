A microservice chassis means: the reusable starter kit every service needs

Business logic is only part of a microservice. Real services also need configuration, logging, health checks, service discovery, and graceful startup/shutdown. This project builds those common pieces as a reusable chassis.

The story

Imagine you build ten microservices: order, payment, inventory, shipping, notification, pricing, catalog, user, audit, and reporting.

Without a chassis

Every team rewrites config loading, logging, health endpoints, service discovery, and shutdown logic differently. Operations become inconsistent.

With a chassis

Every service starts with the same production-ready foundation. Teams focus on business code instead of repeating infrastructure code.

What each file does

File Simple meaning Focus on
main.py Runs demos for config, logging, health checks, service registry, and lifecycle. All five demo functions
chassis/config.py Loads configuration from defaults, file values, environment variables, and runtime overrides. ConfigManager.get(), override()
chassis/logging.py Structured logs with correlation IDs and bound context. StructuredLogger, set_correlation_id()
chassis/health.py Liveness/readiness checks for Kubernetes-style health probes. HealthRegistry, FunctionHealthIndicator
chassis/registry.py Service registration, discovery, heartbeat, and load balancing. ServiceRegistry.resolve()
chassis/lifecycle.py Starts components in order and stops them in reverse order. LifecycleManager.start(), stop()

Configuration in plain English

Configuration values can come from multiple places. Higher priority sources win.

defaults
->
file config
->
environment
->
runtime override
config.define("server.port", 8080)
config.load_dict({"server.port": 8081})
os.environ["MYAPP_SERVER_PORT"] = "9090"
config.override("feature.dark_mode", True)

In this project, environment beats file, and runtime override beats everything.

Structured logging in plain English

Plain logs are hard to search. Structured logs are key-value data that log tools can filter.

set_correlation_id("req-abc123")
logger.info("Request received", method="POST", path="/orders")
db_logger = logger.bind(component="database")
db_logger.info("Query executed", duration_ms=12)

The correlation ID connects logs across services for one request. If order service calls payment service, both can log req-abc123.

Health checks in plain English

Probe Question What happens if it fails?
Liveness Is the process alive? Kubernetes may restart the container.
Readiness Can this service serve traffic right now? Load balancer stops sending traffic to it.
A service can be alive but not ready. Example: the process is running, but database connection is down.

Service registry in plain English

When there are multiple instances of a service, clients need a way to find one healthy instance.

registry.register("order-service", "order-1", "10.0.1.1", 8080)
registry.register("order-service", "order-2", "10.0.1.2", 8080)
instance = registry.resolve("order-service", LoadBalanceStrategy.ROUND_ROBIN)
Strategy Meaning
ROUND_ROBIN Send calls to instance 1, then 2, then 3, then repeat.
RANDOM Pick a healthy instance randomly.
LEAST_CONNECTIONS Pick the instance doing the least work.
CONSISTENT_HASH Use a key, such as customer ID, so the same key tends to hit the same instance.

Lifecycle in plain English

Services should start dependencies first and stop user-facing traffic first.

Startup order

Database -> cache -> message queue -> HTTP server. The HTTP server starts last because traffic should arrive only after dependencies are ready.

Shutdown order

HTTP server -> message queue -> cache -> database. Stop accepting traffic first, finish work, then close dependencies.

Interview answer in simple words

Use this when someone asks, "What belongs in a microservice chassis?"

A microservice chassis provides reusable cross-cutting infrastructure for every service: configuration, structured logging, health checks, service discovery, and lifecycle management. It keeps these concerns consistent across services, so product teams can focus on business logic while operations get predictable behavior in production.
