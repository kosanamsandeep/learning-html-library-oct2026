Project 19 simplified

A data pipeline means: pass data through small stages, one stage at a time

This project builds an ETL framework. ETL means extract, transform, load. Raw data enters the pipeline, each stage does one job, and the final stage returns clean, useful output.

The story

You receive messy CSV or JSON data. It has strings where numbers should be, duplicate rows, invalid records, inconsistent casing, and missing computed fields.

Without a pipeline

You write one long script that parses, cleans, validates, enriches, aggregates, logs, retries, and saves data all in one place.

With a pipeline

Each step becomes a stage. You can reorder stages, reuse stages, observe stages, retry stages, and test stages independently.

The mental model

raw data
->
parse
->
cast types
->
clean + validate
->
derive fields
->
collect or aggregate
Important: a pipeline stage should do one thing. Good stage names make your data flow readable.

The builder syntax, simplified

pipeline = (
    PipelineBuilder("Employee ETL")
    .from_csv()
    .cast_types({"salary": int, "age": int})
    .normalize(["department"])
    .validate({"salary": lambda s: s > 0})
    .derive("tax_bracket", lambda r: "high" if r["salary"] > 100000 else "standard")
    .collect()
    .build()
)

Read it like English: parse CSV, cast fields, normalize text, validate records, add a computed field, collect the output.

How the engine runs a stage

for stage in pipeline.stages:
    emit("stage_started")
    result = stage.process(current_data)
    current_data = result
    emit("stage_completed")

The real project adds useful production behavior around that simple loop: timing, retries, failure results, and observer events.

Core ideas in plain English

Concept Meaning Where it appears
Pipeline Pattern Output of one stage becomes input to the next stage. Pipeline.run()
Builder Pattern Create complex pipelines with readable chained methods. PipelineBuilder
Observer Pattern Logging and metrics get events without changing stage code. LoggingObserver, MetricsObserver
Retry If a flaky stage fails, try it again before failing the pipeline. StageConfig(retries=3)
MapReduce Map each item, then reduce many items into one result. MapStage, ReduceStage

Interview answer in simple words

Use this when someone asks, "Why use a pipeline architecture?"

A pipeline architecture breaks data processing into small sequential stages. Each stage has one responsibility, receives input, and returns output for the next stage. This makes ETL code easier to test, reuse, observe, retry, and extend. A builder can make pipeline construction readable, while observers collect logs and metrics without mixing monitoring into business logic.
