🔄 Complete Request Flow

sequenceDiagram participant Client participant API as API Layer participant DTO as DTO Layer participant Service as Service Layer participant Repo as Repository participant Model as Domain Model Client->>API: POST /health-records {json} API->>DTO: Create CreateHealthRecordDTO DTO->>DTO: validate() → check rules API->>Service: create_record(dto) Service->>Model: Create HealthRecord Service->>Repo: save(record) Repo->>Repo: Store in memory/file/db Repo-->>Service: Return saved record Service->>DTO: HealthRecordResponseDTO.from_model(record) DTO-->>Service: Return response DTO Service-->>API: Return DTO API-->>Client: {status: 201, data: {...}}

🔑 The Key Rule: Each layer only talks to its immediate neighbor!

API → Service → Repository. Never API → Repository directly!

    └── health_record.py ← Core entities + business rules

🎯 Key Takeaways

  1. Layers communicate through defined interfaces - not direct access
  2. Data flows DOWN (request) and UP (response)
  3. Each layer has ONE job - change one without affecting others
  4. Dependency Injection wires the layers together in main.py
  5. Next: Project 8 explores Abstract Classes and Dependency Inversion more deeply
