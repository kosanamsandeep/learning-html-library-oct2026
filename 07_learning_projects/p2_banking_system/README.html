🧠 Core Concepts

INHERITANCE = "IS-A" Relationship

Test: "Is a [child] a [parent]?"

  • SavingsAccount IS-A Account ✅ → Inheritance works!
  • Car IS-A Vehicle ✅ → Inheritance works!
  • Engine IS-A Car ❌ → Don't inherit! (Engine is PART OF car → Composition, Project 3)

POLYMORPHISM = "Many Forms"

Same method name, different behavior depending on the object type.

accounts = [savings_acc, checking_acc]
for acc in accounts:
    acc.withdraw(100)  # Each executes ITS OWN version of withdraw()!

You don't need to check "is this savings or checking?" - the object KNOWS how to behave.

METHOD OVERRIDING = "My version is better for me"

Child class REPLACES parent's method with its own version.

Account.withdraw() → simple balance check

SavingsAccount.withdraw() → balance check + monthly limit

CheckingAccount.withdraw() → balance check + overdraft allowed

Why Is This Powerful?

Without polymorphism, you'd write:

def withdraw(account, amount):
    if isinstance(account, SavingsAccount):
        # savings logic...
    elif isinstance(account, CheckingAccount):
        # checking logic...
    elif isinstance(account, BusinessAccount):
        # business logic...
    # Gets worse with every new account type!

With polymorphism:

def withdraw(account, amount):
    account.withdraw(amount)  # That's it! Object knows what to do.

⚔️ Inheritance vs No Inheritance

Aspect Without Inheritance With Inheritance
Code duplication deposit() copied in every account type deposit() written ONCE in Account
Adding new account type Copy-paste everything, modify Just override what's different
Bug in deposit logic Fix in N places Fix in ONE place (Account)
Polymorphism Need isinstance() checks everywhere Just call the method, it works!

🐛 Debugging Exercises

Bug 1: Forgot super().__init__()

class SavingsAccount(Account):
    def __init__(self, account_number, owner_name, balance):
        # OOPS! Forgot to call super().__init__()
        self._interest_rate = 0.04

What happens? SavingsAccount has no _balance, no account_number! AttributeError when you try to use it.

Lesson: ALWAYS call super().__init__() when extending a parent.

Bug 2: Infinite Recursion

class SavingsAccount(Account):
    def withdraw(self, amount):
        # OOPS! Calling self.withdraw() instead of super().withdraw()
        if self._monthly_withdrawals < 6:
            return self.withdraw(amount)  # Calls ITSELF forever!

Lesson: Use super().withdraw() to call the PARENT version.

🎯 Key Takeaways

  1. IS-A test before using inheritance
  2. super() calls the parent's version
  3. Override only what needs to change
  4. Polymorphism eliminates type-checking if/else chains
  5. Next: Project 3 shows when inheritance is WRONG and Composition is better
