🛠️ Agent Development Kits & Cloud AI Platforms

Google ADK, AWS Bedrock Agents, Azure AI Agent Service — building agents with cloud-native tooling

The Cloud Agent Platform Landscape

Every major cloud provider now offers a dedicated platform for building AI agents. These differ from open-source frameworks (LangGraph, AutoGen) in that they provide managed infrastructure: hosting, scaling, monitoring, security, and integration with cloud services out of the box.

Key Insight: Open-source frameworks give you control and flexibility. Cloud platforms give you scale and managed operations. Many production systems use BOTH: an open-source framework for agent logic + a cloud platform for deployment and infrastructure.

Google Cloud: Vertex AI + ADK + Gemini + A2A Protocol
AWS: Bedrock Agents + Nova + Lambda + Knowledge Bases
Azure: AI Agent Service + OpenAI + Semantic Kernel + Foundry

🟢 Google Agent Development Kit (ADK) — Deep Dive

Google ADK

"An open-source, code-first Python framework for building, evaluating, and deploying sophisticated AI agents"
Released April 2025, Google ADK is designed for building multi-agent systems that work together. It's model-agnostic (not just Gemini) and integrates deeply with Vertex AI for production deployment.
Core Architecture:

• Agent class: Base unit — wraps an LLM with tools, instructions, and sub-agents

• Tools: Function tools, built-in tools (Search, Code Execution), MCP tools, OpenAPI tools

• Multi-Agent: Agents can delegate to sub-agents (hierarchical orchestration)

• Sessions: Built-in memory and state management per conversation

• Runners: Execute agents locally (InMemoryRunner) or in cloud (VertexAiRunner)

Key Advantages

  • Multi-Agent by Default: First-class support for agent hierarchies — parent agents delegate to specialized sub-agents
  • A2A Protocol: Agent-to-Agent protocol for cross-platform agent communication (open standard)
  • Model Agnostic: Works with Gemini, GPT-4, Claude, Llama — any LiteLLM-compatible model
  • Built-in Evaluation: Test agents against ground truth with eval framework
  • MCP Support: Native Model Context Protocol integration for tool interop
  • Local → Cloud: Develop locally with InMemoryRunner, deploy to Vertex AI with one config change
  • Streaming: Real-time streaming of agent responses and tool calls
  • Open Source: Apache 2.0 license, community-driven
# Google ADK: Multi-agent weather assistant from google.adk.agents import Agent from google.adk.runners import InMemoryRunner from google.adk.sessions import InMemorySessionService def get_weather(city: str) -> dict: """Get current weather for a city.""" return {"city": city, "temp": "22°C", "condition": "Sunny"} def get_forecast(city: str, days: int) -> dict: """Get weather forecast.""" return {"city": city, "forecast": [f"Day {i}: Sunny" for i in range(1, days+1)]} # Create specialized sub-agents current_weather_agent = Agent( name="current_weather", model="gemini-2.0-flash", instruction="You provide current weather data only.", tools=[get_weather] ) forecast_agent = Agent( name="forecast", model="gemini-2.0-flash", instruction="You provide multi-day forecasts.", tools=[get_forecast] ) # Parent orchestrator delegates to sub-agents root_agent = Agent( name="weather_orchestrator", model="gemini-2.0-flash", instruction="Route weather queries to the appropriate specialist.", sub_agents=[current_weather_agent, forecast_agent] ) # Run locally runner = InMemoryRunner(agent=root_agent, app_name="weather_app") session = await runner.session_service.create_session(app_name="weather_app", user_id="u1") response = runner.run(user_id="u1", session_id=session.id, new_message="What's the weather in London?")

A2A Protocol (Agent-to-Agent)

Open standard for agents to discover and communicate with each other across platforms
Google's A2A protocol allows agents built on ANY framework to communicate. An ADK agent can talk to a LangGraph agent or a CrewAI agent — as long as they expose an A2A-compatible endpoint.
How A2A Works:

1. Agent Card: JSON metadata describing what the agent can do (capabilities, skills)

2. Task Protocol: Standardized request/response format for agent interactions

3. Discovery: Agents can discover each other via agent cards (like APIs have OpenAPI specs)

4. Streaming: Support for long-running tasks with progress updates

  • Why it matters: No more vendor lock-in for agents. Your agents become interoperable services.
  • Analogy: HTTP is to web services what A2A is to AI agents — a common protocol

🟠 AWS Bedrock Agents

Amazon Bedrock Agents

"Fully managed agents that plan, execute, and iterate — no infrastructure to manage"
AWS's approach: you define an agent's instructions, knowledge bases, and action groups (tools). Bedrock handles the orchestration loop (ReAct-style) automatically. Zero server management.
Architecture:

• Foundation Model: Choose from Claude, Llama, Nova, Mistral on Bedrock

• Knowledge Bases: Managed RAG — upload docs, auto-chunks, auto-embeds, auto-indexes

• Action Groups: Tools defined as OpenAPI specs → backed by Lambda functions

• Guardrails: Built-in content filtering, PII redaction, topic blocking

• Memory: Managed conversation memory with session persistence

  • Pros: Zero infrastructure, managed RAG, built-in guardrails, auto-scaling
  • Pros: Multi-agent collaboration support (agent can invoke other agents)
  • Pros: Deep AWS integration (S3, Lambda, DynamoDB, OpenSearch)
  • Cons: AWS lock-in, limited customization of orchestration logic
  • Cons: Can't implement custom agent patterns (e.g., Plan-Execute)
  • Cons: Debugging agent decisions can be opaque
  • Best for: AWS-native teams wanting quick agent deployment without infrastructure concerns

🔵 Azure AI Agent Service

Azure AI Agent Service (Preview)

"Enterprise-grade agent platform with Azure OpenAI, Semantic Kernel, and Azure Foundry"
Microsoft's answer: deeply integrated with Azure OpenAI, built on Semantic Kernel, and designed for enterprise compliance. Supports OpenAI Assistants API format for portability.
Architecture:

• Azure AI Foundry: The platform layer (model catalog, evaluations, deployment)

• Agent Service: Managed agent runtime (built on Assistants API pattern)

• Semantic Kernel: Orchestration framework (C#/Python) for agent logic

• Tools: Code Interpreter, File Search, Azure Functions, Bing Search, Azure AI Search

• Models: GPT-4o, GPT-4, o1, o3 + open models (Llama, Mistral) via catalog

  • Pros: Enterprise security (Azure AD, RBAC, private endpoints)
  • Pros: OpenAI Assistants API compatible (easy migration)
  • Pros: Multi-model support via Azure AI model catalog
  • Pros: Integrated evaluation and monitoring
  • Cons: Azure-dependent, complex pricing
  • Cons: Still in preview (features may change)
  • Best for: Enterprise Microsoft shops needing compliance + AI agents

🎯 Decision Framework

Choose Your Agent Platform:

🟢 Want full control + open source + multi-agent → Google ADK

🟢 Need cross-platform agent communication → Google ADK (A2A protocol)

🟠 Want zero infrastructure + quick deployment → AWS Bedrock Agents

🟠 Already on AWS with S3 data → AWS Bedrock Agents + Knowledge Bases

🔵 Enterprise Microsoft shop + compliance needs → Azure AI Agent Service

🔵 Need .NET support → Azure + Semantic Kernel

🟣 Maximum flexibility (but self-manage) → LangGraph or AutoGen (open-source only)

🧠 Pro Thinker Analysis

The future is multi-agent + interoperable. Google's ADK + A2A protocol is the most forward-thinking approach: agents shouldn't be locked into one platform. The A2A protocol is analogous to how HTTP standardized web communication — it could standardize agent communication. AWS Bedrock Agents is the most "batteries included" (managed RAG, guardrails, zero infra), but you sacrifice customization. Azure sits in between with Semantic Kernel providing flexibility and the managed service providing scale. My recommendation: Learn Google ADK for its clean architecture and multi-agent patterns. Use a cloud platform (Bedrock/Azure) when you need managed ops. They're complementary, not competing — ADK agents can run ON Vertex AI, just like LangGraph agents can run on LangSmith Cloud.
