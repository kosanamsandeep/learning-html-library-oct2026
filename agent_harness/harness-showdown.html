The harness showdown — the coding agents, compared on the same axes

The landscape changes monthly, so instead of a stale feature table this page gives you a durable way to compare: for each harness ask the same six questions (what loop, what tools, how trusted, how extensible, how it remembers, how it plugs in). We apply the template to the mainline harnesses — Claude Code, Codex CLI, Gemini CLI, Cursor, Copilot, and the open-source set — and flag the trade-offs that matter in practice.

Read this disclaimer first. Coding agents are the fastest-moving product category in software. Any specific capability named here can ship, move, or disappear within a quarter. Use the table to understand the shape of each harness and to know what to verify yourself — not as a buying decision frozen in time.

1 · The six questions that separate harnesses

  1. Loop & mode: Is it a terminal agent, an IDE-native agent, or both? Plan-first or go? How does it recover from failure?
  2. Tool surface: repo read/edit/run, web, image, and — importantly — can you add your own tools?
  3. Trust model: ask-everything, auto-run, read-only plan mode, sandboxing, worktrees?
  4. Extensibility: skills/personas/rules you can package; custom commands.
  5. Memory: project instruction files (CLAUDE.md/AGENTS.md), persistent memory, session resume.
  6. Plug-in protocol: MCP support, subagents/parallelism, hooks/events, CI-drivability.

Every harness below is a real answer to those six — comparing on the six is comparing apples to apples even when the marketing changes.

2 · The mainline harnesses

Harness Shape Distinctive strength Trade-off to know
Claude Code Terminal-first agent (+ IDE/desktop/web) built on Claude Deep harness: subagents, skills, hooks, MCP, dynamic workflows, strong permissions model Best unlocked inside a rich repo + explicit guardrails; powerful enough to need them
OpenAI Codex CLI Terminal agent for OpenAI models (open source) Tight pairing with the OpenAI toolchain; AGENTS.md conventions; plan-first workflow Ecosystem smaller than Claude Code's; capabilities track OpenAI model releases
Gemini CLI Open-source terminal agent for Gemini models Long-context Gemini models; MCP support; free tier for personal use Fewer battle-tested enterprise features than the incumbents
Cursor IDE-native agent (VS Code fork) + background agents Best-in-class inline editing + multi-file diff UX in the editor Loop is tied to the editor; lighter on external, headless automation
GitHub Copilot coding agent IDE + terminal + GitHub-native, model-agnostic Runs where the PR lives (tasks, code review, Actions); model choice Breadth over depth; agentic autonomy lags the dedicated harnesses

3 · The open-source & niche set

Harness Shape Why people pick it
opencode Open terminal agent (no SSH needed), many model providers Model freedom + MCP + a clean TUI; popular for BYO-model setups
aider Terminal pair-programmer with git-first diffs Minimal, reviewable, map-of-repo context; beloved for its simplicity
goby Open-source VS Code agent Free IDE-native alternative; strong out-of-the-box tools
Roll-your-own (SDK) Claude Agent SDK / OpenAI Agents SDK wiring your own loop You need the agent inside your product, not in your editor
Managed/sandbox agents Hosted agents (Anthropic Managed Agents, OpenAI sandbox agents) No local setup; server-side sandboxes; good for apps & CI
Pattern worth noticing: the open set converges on the same harness ideas (MCP, git-first diffs, permission gating, instruction files) while diverging on model. That convergence is the whole thesis of this track: the harness shape is becoming a commodity, standardised layer — and MCP is the protocol glue making it portable.

4 · Choosing with the six questions

  • Already live in one? The marginal switch cost is real — instruction files, hooks, and muscle memory all transfer, so only move for a capability you've verified (not one you've heard about).
  • Team safety review? Weight the trust model (permissions, sandbox, hooks) above raw coding skill. The best model in the world is a liability in an unaudited auto-run loop.
  • Shipping into a product? You're not choosing a coding agent, you're choosing an SDK harness layer — that's page 3's decision, not this page's.
  • Vendor lock-in fear? Prefer harnesses strong on MCP and open instruction formats so your config (skills, rules, tools) survives a model or vendor swap.
