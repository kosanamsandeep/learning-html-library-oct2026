06 · Prompt Engineering vs Fine-Tuning vs RAG

Three fundamentally different ways to adapt an LLM to a task. Which one should you use? The answer is often more than one.

🧭 Decision Framework

🤔 Does the task require factual knowledge your model doesn't have?
Yes → RAG. The model knows language but not your specific documents. A vector database + retrieval pipeline is the right tool.
🤔 Does the task require a specific output format or style?
Yes → Prompt Engineering first. Can you get 90% of the way there with a well-crafted prompt and a few examples? If yes, stop there.
🤔 Does the task need the model to internalize a behavior or pattern?
Yes → Fine-Tuning. "Always output JSON", "Write in the style of this author", "Use these domain terms precisely" — these benefit from weight changes.
🤔 Do you need all three?
Often, yes. A production system typically uses prompt engineering for system instructions, RAG for grounding, and fine-tuning for output structure. They're complementary, not competitive.

🏗️ The Critical Distinction: Frontier vs Open-Source Models

🚫 You cannot download frontier model weights. GPT-4o, Claude Opus/Sonnet, Gemini Ultra — these are only accessible via API. Their weights are never on your machine. This means local fine-tuning (LoRA/QLoRA) is impossible with these models. You can only use Prompt Engineering + RAG with them.

Fine-tuning via API: Both OpenAI and Anthropic offer fine-tuning APIs, but:

  • OpenAI: GPT-4o fine-tuning costs $25/1M tokens (training) + $10/1M tokens (inference). A single training job can cost $500–$5000+ depending on data volume.
  • Anthropic: Claude fine-tuning is available via Claude for Work / enterprise — also priced at premium rates.
  • You're still sending data to their servers — no privacy benefit.
  • You get a custom model ID, but no weight access — you can't run it offline, can't serve it yourself, and are locked into that provider.
💡 Bottom line for frontier models: Prompt engineering + RAG covers 90%+ of use cases. Only consider API fine-tuning if you have a very specific formatting/behavior need AND the budget. You're usually better off switching to an open-source model + LoRA instead.

🎯 Example: A legal document summarizer using Llama 3 8B + LoRA:
• Fine-tuned with LoRA (cost: ~$2 on a single GPU) to output structured JSON in legal format
• RAG retrieves relevant case law and statutes to ground the summary
• Prompt instructs the model on the specific user's preferences and current task
• Total cost: ~$2 for training + standard inference compute. Fully offline.

📈 When Each One Shines

✅ Prompt Engineering Wins When:

  • The task is simple classification or formatting
  • You're prototyping or A/B testing
  • You have no training data
  • The model already "knows" the domain (e.g., a general Q&A bot)

✅ RAG Wins When:

  • The knowledge changes frequently (news, products, policies)
  • You need to cite sources for compliance
  • The knowledge base is too large to fit in a prompt
  • You want zero training overhead

✅ Fine-Tuning Wins When:

  • You need consistent output format (JSON, specific schema)
  • The model's "default" behavior doesn't match your domain
  • You have a distinct style, tone, or vocabulary
  • You want to reduce prompt length (bake behavior into weights)
  • Prompt engineering hits diminishing returns
⚠️ CRITICAL caveat — This applies ONLY to open-source models you can download. With frontier API models (GPT-4o, Claude), fine-tuning is either impossible or prohibitively expensive. For those, prompt engineering + RAG is your only practical stack. If you hit diminishing returns there, your move isn't "pay for API fine-tuning" — it's switch to an open-source model + LoRA fine-tuning instead.

⭐ Best practice in 2025:
• With frontier APIs (GPT-4o, Claude): Use prompt engineering + RAG. Don't fine-tune — you're locked in and overpaying.
• With open-source models (Llama 3, Mistral): Use prompt + RAG + LoRA fine-tuning for maximum quality, all offline.
• The hybrid move: Prototype with GPT-4o (prompt + RAG), then distill into a fine-tuned open-source model for production — best of both worlds.
