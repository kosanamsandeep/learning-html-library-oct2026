05 · Other PEFT Methods

LoRA is the most popular, but it's not the only parameter-efficient fine-tuning method. Here's a tour of the landscape.

🧩 The PEFT Taxonomy

All PEFT methods fall into one of three categories:

  • Additive — Add new trainable parameters (Adapter layers, LoRA, Prefix Tuning)
  • Selective — Select a subset of existing parameters to update (bitfit, attention-only)
  • Reparametrization — Reparameterize existing weights with a low-rank decomposition (LoRA — which is both additive and reparameterization)

1️⃣ Prefix Tuning (Li & Liang, 2021)

How It Works

Instead of modifying weights, Prefix Tuning prepends a set of learnable "virtual tokens" to the key and value matrices in every attention layer. These virtual tokens don't correspond to real words — they're continuous vectors that the model learns to use as attention biases.

// Normal attention: Attn(XWQ, XWK, XWV) // Prefix Tuning: Attn(XWQ, [Pk; XWK], [Pv; XWV]) // Pk and Pv are learned prefix vectors of length L // The prefix shifts the attention distribution — no weight changes needed.
Prefix TuningLoRA
Parameters trained~0.01–0.1%~0.01–0.1%
Inference latency+L tokens of compute (shorter context)None (merged) / Tiny (unmerged)

📌 Prefix Tuning is less popular than LoRA because the prefixes consume sequence length — the longer the prefix, the shorter your usable context. It also can't be merged into weights, so inference always has overhead.

2️⃣ P-Tuning (Liu et al., 2022)

How It Works

Similar to Prefix Tuning, but instead of modifying attention keys/values, P-Tuning injects learnable "prompt embeddings" into the input embedding layer. A small LSTM or MLP generates the embeddings to capture dependencies between virtual tokens.

// P-Tuning: replaces discrete prompt tokens with learned continuous embeddings // Input embedding: [eprompt_1, eprompt_2, ..., eprompt_L, eword_1, ...] // The eprompt are learned (optionally via a prompt encoder network)
🧪 P-Tuning v2 showed that deeper prompt tuning (applied to all layers, not just the input) matches fine-tuning quality on many tasks. But PoRA (LoRA) still gets more adoption because it's simpler and doesn't reduce sequence length.

3️⃣ Adapter Layers (Houlsby et al., 2019)

How It Works

Insert small bottleneck MLP layers after each Transformer sublayer (attention + FFN). The adapter is a down-projection → activation → up-projection, with a residual connection:

// Adapter inserted after attention or FFN: h' = LayerNorm(h + Adapter(h)) Adapter(h) = Wup · σ(Wdown · h) // bottleneck: d → dbottleneck → d // dbottleneck is typically 64–256 for a 768-dim model.
AdapterLoRA
Parameters trained~3–5% (more than LoRA)~0.01–0.1%
Inference latency+10–30% (extra layers in the graph)None (merged)
Added layersYes — modifies the architectureNo — only weight updates
Parallel computationSequential (added after main layer)Parallel (BA runs alongside W)
📌 Adapters were the first major PEFT method and work well, but their inference overhead and higher parameter count have made LoRA the preferred choice in most modern applications.

4️⃣ IA³ (Infused Adapter by Inhibiting and Amplifying Inner Activations)

How It Works

IA³ (Liu et al., 2022) is the simplest PEFT method: it learns a single scaling vector per layer that element-wise multiplies the keys, values, and FFN activations:

// IA³: learn three vectors lK, lV, lFF per layer K' = K ⊙ lK // element-wise scaling of keys V' = V ⊙ lV // element-wise scaling of values FF' = FF ⊙ lFF // element-wise scaling of FFN output // l vectors have dimension d_k — that's it!

Total parameters added: For a model with L layers and dmodel = 4096: L × 3 × 4096 = ~1.5M for a 40-layer model. That's 0.003% of 7B parameters.

⚡ IA³ is the most parameter-efficient method. It adds the fewest parameters and has the lowest memory overhead. It works surprisingly well for classification and summarization tasks, though LoRA tends to edge it out on complex reasoning.

5️⃣ DoRA — Weight-Decomposed Low-Rank Adaptation

How It Works

DoRA (Liu et al., 2024) decomposes the pretrained weight into magnitude and direction components and applies LoRA only to the direction:

// DoRA: W' = m · (W + BA) / ||W + BA|| // m = learnable magnitude vector (one per output dimension) // (W + BA) normalized by direction, then scaled by m

This mirrors how fine-tuning naturally behaves — magnitude changes are often global, while direction changes capture task-specific adaptation. DoRA consistently outperforms LoRA with the same rank across benchmarks.

📊 DoRA is a drop-in replacement for LoRA with ~1% more parameters (the magnitude vector). It's available in Hugging Face PEFT and is a strong default choice in 2025.
