📐 The Core LoRA Equation

W' = W + BA · (α / r)
SymbolMeaningTypical Value
WPretrained weight matrix (frozen)Shape: (d × k)
BDown-projection matrix (trainable)Shape: (d × r), initialized to zero
AUp-projection matrix (trainable)Shape: (r × k), initialized via Kaiming Normal
rRank of the adaptation8 (default), 16–64 (complex tasks)
αScaling factorTypically 2× r = 16 for r=8
// Forward pass with LoRA: h = Wx + (α / r) · BAx // During inference (merged): W_merged = W + (α / r) · BA h = W_merged · x // Same as original model — no extra compute

🧠 Which Fine-Tuning Method Should I Use?

If you have...UseWhy
A consumer GPU (6–12 GB)QLoRA (4-bit)Fits a 7B model in under 10 GB. You can fine-tune on an RTX 3060.
A mid-range GPU (16–24 GB)LoRA (FP16) or QLoRAYou have options. Try LoRA first for quality, fall back to QLoRA if OOM.
A high-end GPU (48–80 GB)LoRA (FP16)Fine-tune 8B–70B models. Full FT only if you have specific quality needs.
Multiple GPUs (cluster)Full FT or LoRAYou have the budget for full FT. Still consider LoRA for rapid iteration.
Very small dataset (<100 examples)Prompt engineering firstFine-tuning <100 examples is risky. Use few-shot prompting instead.
Huge dataset (1M+ examples)Full FT or high-rank LoRAWith enough data, full FT can specialize the model more thoroughly.
Dynamic/evolving knowledgeRAG (not fine-tuning)Fine-tuning is for behavior, not facts. Use RAG for knowledge.
