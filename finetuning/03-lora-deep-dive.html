03 · LoRA — Low-Rank Adaptation

The paper that changed open-source fine-tuning forever: "LoRA: Low-Rank Adaptation of Large Language Models" (Hu et al., 2021).

🎯 The Core Idea

Instead of updating the full weight matrix W (which is (d × k) — potentially billions of parameters), LoRA freezes W and injects a small trainable pair of matrices A and B whose product BA approximates the update ΔW.

// Full fine-tuning would update every element of W: W' = W + ΔW   // ΔW is (d × k) — same size as W // LoRA decomposes ΔW into two smaller matrices: W' = W + BA   // B: (d × r), A: (r × k), where r << min(d, k) // Only A and B are trained. W is frozen.
💡 "Low-rank" means: Instead of learning N2 parameters (the full matrix), we learn 2×N×r parameters. With r = 8 and N = 4096 (GPT-3 dimension), that's 65,536 vs 16,777,216 — a 256× reduction.

📌 Forward pass with LoRA: h = Wx + BAx. The frozen W handles the pretrained computation; BA adds the task-specific adaptation. At inference, you can merge BA into W: W' = W + BA (no extra latency).

🧠 Why Does Low-Rank Work?

This is the most important conceptual question. The answer:

The Intrinsic Dimensionality Hypothesis

Fine-tuning makes small, structured changes to the weights. The update ΔW doesn't need the full parameter space — it lives in a much lower-dimensional subspace.

  • Pretrained models are over-parameterized — the model has far more parameters than needed for any single task.
  • Task-specific adaptation is "narrow" — learning to follow instructions or write in a specific style only requires adjusting a few directions in weight space.
  • Empirical evidence — The LoRA paper showed that even r = 1 (a single rank) captures meaningful adaptation, with diminishing returns after r = 8–64 depending on model size.
🔬 What the paper found: The learned ΔW (full fine-tuning update) has a much higher effective rank than random noise. LoRA with r=64 captures ~90% of the full fine-tuning performance. For most tasks, r=8 is the sweet spot.

🔧 Where to Apply LoRA

LoRA can be applied to any weight matrix in the Transformer. The paper found the best results when targeting attention projection matrices:

WQ + LoRA
+
WK + LoRA
+
WV + LoRA
+
WO + LoRA

In practice, applying LoRA to all four attention matrices (Q, K, V, O) at r=8 works well. Some recipes also target the FFN layers, but the gains are usually marginal.

// Typical LoRA config for Llama-2 7B: // Targets: q_proj, k_proj, v_proj, o_proj // Rank r = 8, alpha = 16, dropout = 0.05 // Trainable parameters: ~4.2M out of 6.7B (0.06%) // Memory: ~16 GB vs ~112 GB for full FT

📐 Scaling α (Alpha)

LoRA has a scaling hyperparameter α (alpha) that controls the magnitude of the adaptation:

h = Wx + α/r · BAx // The scaling factor α/r controls how much the LoRA update influences the output. // Typical: α = 16 for r = 8 (scale = 2). // Think of α as the "learning rate" for the LoRA adapter's contribution.

Rule of thumb: Set α = 2× r as a starting point. If the model isn't adapting enough, increase α. If it's forgetting pretrained knowledge, decrease α.

💾 Inference: The "No Extra Cost" Trick

At inference time, LoRA adds zero latency. Here's why:

// After training, you merge the adapter into the weights: W_merged = W + (α/r) · BA // The forward pass is just: h = W_merged · x // Same computation as the original model!
🎯 This is a killer feature: You can fine-tune 100 different tasks, merge each adapter into a separate copy of the base model (or swap them at load time), and serve all 100 with the same inference latency as the single base model. Adapter files are megabytes, not gigabytes.
