04 · QLoRA — Quantized LoRA

What happens when you combine LoRA with 4-bit quantization? You get the ability to fine-tune a 65B model on a single 48GB GPU.

🎯 The Problem QLoRA Solves

LoRA already reduces trainable parameters by ~100×. But the base model weights are still loaded in FP16 — for a 65B model, that's 130 GB of GPU memory just to hold the frozen base. Most people don't have that kind of hardware.

QLoRA (Dettmers et al., 2023) introduces three innovations to shrink the base model to a fraction of its size while maintaining quality:

  1. 4-bit NormalFloat (NF4) — A novel quantization data type optimized for normally distributed weights
  2. Double Quantization — Quantize the quantization constants themselves
  3. Paged Optimizers — Use CPU RAM as overflow for GPU memory spikes via unified memory

🧮 How NormalFloat (NF4) Works

Standard quantization (INT4) assumes uniformly distributed values. But neural network weights follow a normal distribution — most values cluster near zero with a few outliers.

// Standard INT4: divides the range [-max, max] into 16 equal bins // Problem: most weights fall into the same bin → high quantization error // NF4: divides the range into 16 bins where each bin has EQUAL PROBABILITY // under a normal distribution. More bins near zero, fewer at the tails. // Result: NF4 preserves more information than INT4 for normally distributed weights.
📊 The improvement: NF4 reduces quantization error by ~50% compared to standard INT4 for normally distributed data. For LLM weights (which are approximately normal), this is a free quality boost.

🔁 Double Quantization

When you quantize a weight from FP16 to INT4, you need a scale factor (a floating-point number) per group of weights to dequantize them. These scale factors take memory too.

// Standard 4-bit: groups of 64 weights share one FP32 scale factor // Overhead: 1 FP32 per 64 weights = 0.5 bits per weight extra // Double quantization: quantize the scale factors themselves! // Scale factors are also approximately normally distributed. // Quantize them to FP8 → overhead drops from 0.5 to 0.127 bits per weight.

📄 Paged Optimizers

During training, GPU memory usage spikes during the backward pass (activations are stored for gradient computation). If the spike exceeds GPU memory, the training crashes.

QLoRA uses NVIDIA's unified memory feature to page optimizer states to CPU RAM when they're not immediately needed, then page them back when required:

GPU Memory
← page →
CPU RAM
  • During forward pass: optimizer states can live on CPU (not needed for forward computation)
  • At gradient computation: optimizer states are paged back to GPU
  • After weight update: optimizer states can return to CPU
🔄 This is transparent to the user. PyTorch's unified memory handles the paging. The trade-off is speed — paging adds latency. But for the ability to fine-tune a 65B model on one GPU, it's worth it.

🧪 QLoRA Performance

The QLoRA paper's key result — a 4-bit model is statistically indistinguishable from the 16-bit version after fine-tuning:
