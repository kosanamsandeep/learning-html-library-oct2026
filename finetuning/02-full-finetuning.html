02 · Full Fine-Tuning

The traditional approach — updating every parameter of the pretrained model. Let's understand how it works and why it's so expensive.

⚙️ How Full Fine-Tuning Works

Full fine-tuning treats the pretrained model as an initialization rather than a fixed feature extractor. You take the pretrained weights W0 and continue training on your task-specific dataset. Every weight receives a gradient update.

// Pretrained weights (frozen during inference) W0 = [w₁, w₂, ..., wN]   // N = total parameters (7B, 13B, 70B...) // After fine-tuning WFT = W0 - η · ∇W ℒtask(W0) // Every single parameter changes (hopefully by a small amount) ΔW = WFT - W0   // ΔW is the same size as the full model
⚠️ Important: Full fine-tuning doesn't train from scratch — it starts from the pretrained weights. The learning rate is typically much lower (1e-5 vs 3e-4) because the model is already near a good optimum. The goal is a gentle nudge, not a wholesale retraining.

💰 The Memory Problem

The single biggest obstacle to full fine-tuning is memory. During training, you need to store:

🤯 Full FT a 70B model requires ~1.1 TB of GPU memory. That's 8× A100-80GB GPUs just for the optimizer states — before any activations. This is why full fine-tuning is reserved for well-funded labs, and everyone else uses PEFT.

📉 Why So Much Memory?

The optimizer states are the hidden killer. Adam (the standard optimizer) maintains two additional values per parameter:

  • First moment (m): running average of gradients — helps momentum
  • Second moment (v): running average of squared gradients — helps adaptive learning rates

Both are stored in FP32 for numerical stability, meaning 8 bytes per parameter of the full model — even if you're using mixed-precision training.

// For a 7B model with Adam in FP32: Weights (FP16):   7B × 2 bytes = 14 GB Gradients (FP16):   7B × 2 bytes = 14 GB Adam m (FP32):   7B × 4 bytes = 28 GB Adam v (FP32):   7B × 4 bytes = 28 GB ────────────────────────────── Total: 84 GB (+ activations ≈ 112 GB)

✅ When Full Fine-Tuning Makes Sense

SituationWhy Full FT?
Domain-adapted foundation modelYou're creating a base model for an entire domain (legal, medical, code) that will be further adapted with PEFT later.
Teaching entirely new behaviorIf the task requires the model to change its internal representations fundamentally (e.g., learning a new language or notation system).
Maximum possible qualityWhen you have the budget and need every fraction of a percent in benchmark scores. Full FT can (theoretically) achieve the lowest loss.
Continued pretrainingTraining on a large corpus (billions of tokens) for domain adaptation. This is essentially further pretraining, not task fine-tuning.
📌 Reality check: For 70–90% of practical use cases, LoRA or QLoRA matches full fine-tuning quality while costing a fraction of the memory. The gap has narrowed dramatically as PEFT methods improved. Always start with LoRA — it's faster to iterate, easier to experiment, and the results often surprise you with how close they are to full FT.
