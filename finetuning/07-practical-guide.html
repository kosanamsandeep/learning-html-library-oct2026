07 · Practical Guide — Choosing & Running a Fine-Tune

From dataset to deployed adapter — the real-world workflow for fine-tuning with LoRA/QLoRA.

📋 The End-to-End Workflow

Define Your Task & Gather Data

Fine-tuning starts with data, not with code. Ask:

  • What input → output mapping do I need? (e.g., "customer query → structured response in JSON")
  • How many examples do I have? LoRA works well with as few as 100–500 high-quality examples. More is better, but quality beats quantity.
  • What format? Most fine-tuning uses the chat template format: [INST] instruction [/INST] response
📌 Data quality rules: 500 clean, diverse, correctly-formatted examples beat 10,000 noisy ones. Deduplicate, check for contradictions, and ensure your examples represent real use cases — not edge cases you won't encounter.

Configure Hyperparameters

// Starting point for Llama-3 8B with LoRA (Hugging Face PEFT) lora_r = 8 // Rank — start here, increase to 16 if underfitting lora_alpha = 16 // Scaling = alpha/r = 2 lora_dropout = 0.05 // Helps prevent overfitting with small datasets target_modules = ["q_proj", "k_proj", "v_proj", "o_proj"] // Training hyperparameters learning_rate = 2e-4 // Higher than full FT (which uses ~1e-5) batch_size = 4 // Per GPU—use gradient accumulation for effective batch num_epochs = 3 // 1–5 depending on dataset size optimizer = "adamw_8bit" // 8-bit Adam saves memory warmup_steps = 100
⚠️ The biggest mistake: Using a learning rate that's too high (same as pretraining). LoRA can use higher LR than full FT (2e-4 vs 1e-5), but still needs to be tuned. If loss spikes or goes to NaN, reduce LR by 10×.

Train & Monitor

During training, watch these metrics:

  • Training loss — should decrease smoothly. If it oscillates wildly, LR is too high.
  • Evaluation loss — should track training loss. If it diverges upward, you're overfitting (increase dropout, reduce epochs, add data).
  • Gradient norms — should stay reasonable (not spike to >10).
⏱️ Expected time: A LoRA fine-tune on Llama-3 8B with 1000 examples takes ~15–30 minutes on an RTX 4090 (24 GB) with QLoRA. Full fine-tuning the same model takes hours.

Evaluate & Iterate

Don't just look at loss. Test on real examples:

  1. Qualitative: Generate 20–50 outputs, manually review for quality, format compliance, hallucinations
  2. Quantitative: If you have a labeled test set, compute accuracy / BLEU / ROUGE / F1
  3. A/B test: Compare base model vs fine-tuned on the same prompts, blind

If results aren't good enough:

  • Check data quality first (most common issue)
  • Try higher rank (r=16 or r=32)
  • Train for more epochs (but watch for overfitting)
  • Add more diverse examples to your dataset

Export & Serve

// Option 1: Save adapter only (recommended — keep base model separate) model.save_pretrained("my-lora-adapter/") tokenizer.save_pretrained("my-lora-adapter/") // Adapter file: ~2–50 MB // Option 2: Merge adapter into base weights (for deployment) merged_model = model.merge_and_unload() merged_model.save_pretrained("my-merged-model/") // Full model: ~4–16 GB (same as base — zero extra inference cost) // At inference, load adapter: model = PeftModel.from_pretrained(base_model, "my-lora-adapter/")
🚀 Swapping adapters: You can load multiple adapters onto one base model and switch between them at runtime — no model reload needed. This enables serving 100+ fine-tuned variants from one GPU.

🧠 Common Pitfalls & How to Avoid Them

PitfallSymptomFix
OverfittingLow train loss, high eval loss, repetitive outputsIncrease dropout, reduce epochs, add more data
Catastrophic forgettingModel loses general knowledge, can't answer basic questionsReduce learning rate, use lower LoRA alpha, mix general data with task data
Format not followedModel outputs free text instead of expected formatAdd more format examples, ensure all training examples follow the format strictly
Loss not decreasingFlat training lossLearning rate too low, data too noisy, rank too low
Out of memoryCUDA OOM during trainingUse QLoRA, reduce batch size, use gradient checkpointing, reduce sequence length
Degenerate outputsRepeating tokens, gibberishCheck for data contamination, reduce learning rate, lower alpha/r ratio
🎯 Final advice: Your first fine-tune won't be perfect. Plan for 3–5 iterations. Each iteration: improve data → retrain → evaluate → improve data. The model quality is bounded by your data quality, not the fine-tuning method.
