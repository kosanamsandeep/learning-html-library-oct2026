Advanced 03 · Data Analyst (ReAct)

Six async skills, conversational memory keyed by session_id, served as a real FastAPI service.

📖 Story mode — the finance office on the 8th floor

The scene. The boss walks into a small finance office and slides a CSV across the desk: “Why did Q3 sales drop in the South? Draw me a chart by tomorrow.” The office has three people: an Analyst (knows SQL), a Data Scientist (knows pandas/matplotlib), and a Senior Partner (the critic who never lets bad work leave the office). The Analyst remembers your previous questions in a notebook with your name on it (per-session memory) so follow-ups don’t start from zero.

What happens when you press “Ask”

  1. App boots: core/bootstrap.py creates a demo sales.csv if missing, then loads it into a fresh SQLite file. The office has data before the boss arrives.
  2. You type: POST /ask { "question": "…", "session_id": "raj" }.
  3. Session lookup: the agent finds (or creates) Raj’s personal AgentExecutor with its own ConversationBufferMemory.
  4. Thought 1: “I need to see what tables exist.” → list_tables() → [sales].
  5. Thought 2: “What columns?” → describe_table("sales") → region, qty, revenue, date.
  6. Thought 3: “Run SQL.” → run_sql("SELECT region, SUM(revenue) ... WHERE quarter=3 GROUP BY region") → a small table.
  7. Thought 4: “I want a bar chart.” → chart_skill → matplotlib (Agg backend) writes a PNG, returns the file path.
  8. Thought 5 (the Senior Partner): self_critique(answer) — LLM checks “did we answer the question? any units missing? is the chart labelled?” If not, the agent loops back.
  9. Answer: JSON with the narrative + path to the PNG. Next time Raj asks “now break it down by month”, the buffer memory remembers the SQL and the chart that came before.

One-line recall trick: “Schema → SQL → pandas → chart → critic, with a notebook per visitor.” That’s the entire 03 project. Memory is per session, not global.

Why six skills?

SkillWhy separate
list_tables / describe_tableForces grounding before the LLM writes SQL — kills column hallucinations.
run_sqlRight tool for joins / aggregations.
run_pythonRight tool for rolling windows, ML, anything SQL is awkward at.
make_chartA picture beats a number for trends.
self_critiqueQuality gate — agent rejects its own bad drafts before answering.

Why this is "advanced"

CapabilityWhere
Per-user memoryExecutor cache keyed by session_id in DataAnalystAgent
Multi-tool reasoningLLM picks SQL vs pandas vs chart per question
Self-critique loopself_critique skill
Lifespan bootstrapCSV→SQLite happens once on app start, not per request
Async I/O everywhereSQLite, pandas, matplotlib all run via asyncio.to_thread
Security: run_python uses exec. For production, sandbox via RestrictedPython, e2b, or a separate worker container.
