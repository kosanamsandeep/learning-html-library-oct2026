Intermediate 02 · Research Assistant (LangGraph)

A custom StateGraph with deterministic stages and a search/read loop.

📖 Story mode — the research assembly line

The scene. Same journalism job, but instead of one journalist running around, you’ve built a small factory with five workstations on a conveyor belt: Planning Desk → Search Bay → Reading Bay → Drafting Bay → Filing Cabinet. A shared clipboard (the ResearchState) rides along with the work and every station scribbles on it. A routing arm after the Reading Bay decides: “still more sub-topics? → send back to Search Bay. Done? → forward to Drafting.”

What happens when you press “Research”

  1. You type: POST /research { "topic": "…" }.
  2. Clipboard born: ResearchState = {topic, plan=[], step_idx=0, notes=[], report="", file_path=""}.
  3. Planning Desk (_plan): LLM fills plan with 3–5 sub-topics.
  4. Search Bay (_search): takes plan[step_idx], queries DuckDuckGo, returns URLs.
  5. Reading Bay (_read): fetches each URL (httpx async), summarises, appends to notes (note: Annotated[list, operator.add] means each return is concatenated, not replaced), increments step_idx.
  6. Routing arm (_route): if step_idx < len(plan) → loop back to Search; else → Drafting.
  7. Drafting Bay (_write): LLM turns notes into the final report.
  8. Filing Cabinet (_save): aiofiles writes report.md, fills file_path → END.
  9. Output: JSON with the report text and the path on disk.
flowchart LR Start(["🚪 POST /research"]) --> Plan["📋 _plan"] Plan --> Search["🔍 _search"] Search --> Read["📖 _read"] Read --> Route{"more steps?"} Route -- yes --> Search Route -- no --> Write["✍️ _write"] Write --> Save["💾 _save"] Save --> End(["🏁 END → JSON"])
One-line recall trick: “Plan, Search, Read, (loop), Write, Save — with one shared clipboard.” The ReAct version did the same work via a prompt; LangGraph makes the loop an actual edge in the diagram.

Why a hand-built graph here?

For research the workflow shape is known (plan → loop search/read → write → save). A graph encodes that shape so the LLM only does what it's good at: planning text and writing prose.

State schema

KeyTypePurpose
topicstrUser's research topic.
planlist[str]3 search queries made by the LLM.
step_idxintLoop counter.
noteslist[str] (additive)Accumulated excerpts. Reducer = operator.add.
reportstrFinal markdown.
file_pathstrSaved report path.

ReAct vs LangGraph for this workflow

ConcernReActLangGraph
DeterminismLLM might skip save_reportSave is a node — guaranteed to run.
Token costRe-sends all observations every stepEach node sees only the slice it needs.
Recovery from failureRestart whole loopRe-run a single node with checkpoint state.
Adding a critique stepAdd a tool, hope LLM uses itInsert a node + edge.
Use ReAct when tool ordering is unknown; use LangGraph when ordering is mostly known but each step is itself LLM-driven.
