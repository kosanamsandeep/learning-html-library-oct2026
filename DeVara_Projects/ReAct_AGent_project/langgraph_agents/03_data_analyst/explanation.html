Advanced 03 · Data Analyst — Supervisor + Specialists (LangGraph)

A multi-agent team: a Supervisor LLM routes work to a SQL specialist, a Python specialist, and a Critic.

📖 Story mode — the trading floor with a Supervisor

The scene. Imagine a trading floor. At the centre stands the Supervisor. Around her sit three specialists: SQL Desk (queries the database), Python Desk (runs pandas + draws charts), and the Critic (a senior who checks the answer). Every time a specialist finishes, they walk back to the Supervisor with their result. The Supervisor decides who goes next — or whether the work is done and the customer can be billed. A janitor (MemorySaver) keeps a folder per thread_id so a returning customer doesn’t restart from zero.

What happens when you press “Ask”

  1. You type: POST /ask { "question": "…", "thread_id": "raj" }.
  2. Boot: bootstrap.py creates the demo CSV and SQLite if missing.
  3. Supervisor node: LLM with with_structured_output(Router) emits one of sql_agent | python_agent | critic | FINISH.
  4. If sql_agent: a prebuilt ReAct agent with list_tables/describe_table/run_sql tools runs, returns rows → edge back to Supervisor.
  5. If python_agent: another prebuilt ReAct with pandas + matplotlib tools crunches/plots → back to Supervisor.
  6. If critic: a plain LLM node grades the draft — if shaky, the Supervisor re-routes to a specialist; if good, sets next="FINISH".
  7. Routing function: _route returns END when next == "FINISH" — graph exits.
  8. Output: JSON with answer text + any chart paths. Memory persists for Raj’s next question.

(Router LLM)"] Sup -- sql_agent --> SQL["🗄️ SQL Desk"] Sup -- python_agent --> PY["🐍 Python Desk"] Sup -- critic --> CR["🧐 Critic"] Sup -- FINISH --> End(["🏁 END → JSON"]) SQL --> Sup PY --> Sup CR --> Sup
One-line recall trick: “One Supervisor, three desks, every desk walks back to her.” This is the supervisor multi-agent pattern — the LangGraph equivalent of react_agents/03, but with explicit routing instead of one big ReAct loop.

The supervisor pattern

Inspired by the official langgraph "multi-agent supervisor" cookbook. The supervisor LLM emits a structured Router choice each turn: which specialist runs next, or FINISH.

Graph

flowchart LR Start((start)) --> Sup[supervisor
structured-output LLM] Sup -->|next=sql_agent| SQL[sql_agent
ReAct + sql tools] Sup -->|next=python_agent| Py[python_agent
ReAct + pandas/chart tools] Sup -->|next=critic| Cr[critic
LLM grader] Sup -->|next=FINISH| End((END)) SQL --> Sup Py --> Sup Cr --> Sup

Why structured-output for the supervisor?

We force the supervisor's reply through a Pydantic schema (Router with a Literal), which means the routing decision is always valid — no parsing errors, no infinite loops over typos.
