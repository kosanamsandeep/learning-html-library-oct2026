Basic 01 · Calculator + Wikipedia (LangGraph)

Same logic as ReAct 01 — but the agent is a graph with a checkpointer, so memory is free per thread_id.

📖 Story mode — same Helper Friend, but now in a building with rooms

The scene. Same friend, same two pockets (calculator + Wikipedia). But this time he doesn’t freestyle in a café — he works inside a small building with three doors clearly labelled: AGENT (thinking room), TOOLS (where the pockets live), and END (exit with the answer). A janitor (MemorySaver) sits at the entrance with a clipboard, writes down everything that happens in your file (keyed by thread_id), so when you come back later he hands the friend the full history.

What happens when you press “Ask”

  1. You type: POST /ask { "question": "…", "thread_id": "raj" }.
  2. Janitor pulls Raj’s file from MemorySaver → attaches it as the running message list.
  3. Door 1 — AGENT room: the LLM looks at the messages and either (a) decides to use a tool, or (b) says “I’m done.”
  4. If a tool: goes to Door 2 — TOOLS room, where @tool-decorated functions (calculate, wiki_summary) actually run. The result becomes a new ToolMessage.
  5. Back to AGENT room with the new observation — loop continues until the LLM emits no more tool calls.
  6. Door 3 — END: the final AIMessage is returned. The janitor saves the whole updated thread.
  7. Output: JSON answer to your browser. Next time Raj asks a follow-up with the same thread_id, the friend already knows what was discussed.

One-line recall trick: “Building with three rooms and a janitor who remembers you.” Same ReAct loop as react_agents/01, but it’s now an explicit graph with a checkpointer — the LangGraph way.

Why LangGraph here?

FeatureUsed by this project
Typed message stateEvery step appends to messages — easy to inspect.
Conditional edgeBuilt-in: route to tools node when LLM emits tool calls.
MemorySaver checkpointerPass thread_id via configurable → conversation persists automatically.
Streaminggraph.astream yields after each node — UI-friendly.
