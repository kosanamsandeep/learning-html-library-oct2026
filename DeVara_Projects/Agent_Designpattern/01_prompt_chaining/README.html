Chapter 01 — Prompt Chaining

Also called the Pipeline pattern. Big task → smaller prompts → output of one feeds the next.

PipelineChain of ResponsibilityDecomposition

What is it (in plain English)?

An LLM is bad at solving a huge, fuzzy task in one shot. Prompt chaining splits the task into ordered focused steps. Each step has one job, one prompt, one schema-checked output. The next step receives that output as its input.

Mental model: a factory assembly line. Each station does one thing well; the part keeps moving forward.

2026 real-time scenario — Quarterly Earnings Brief

A buy-side analyst on June 2026 drops a 90-page Q1 earnings PDF into an internal app at 6:55 AM and needs a one-page brief by 7:15 AM, before the morning call. A monolithic prompt fails (truncates, hallucinates numbers). A chain wins:

Interview Q&A

When should I NOT use prompt chaining?
When the task fits comfortably in one prompt and a single round-trip is cheaper. Chaining adds latency = N × call. Also avoid when steps are independent — use Parallelization (Ch. 3) instead.
How do you stop error propagation between steps?
Validate each stage's output (Pydantic schema or regex), retry/fallback inside the stage, and pass a typed DTO between stages so a downstream step can reject malformed input early.
Chaining vs LangGraph — what's different?
Pure chaining is a DAG with no cycles. LangGraph adds explicit state, branches, and loops, so reflection and human-in-the-loop become natural extensions of the chain.
