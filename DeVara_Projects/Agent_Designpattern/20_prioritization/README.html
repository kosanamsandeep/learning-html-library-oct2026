Chapter 20 — Prioritization

Many things to do, finite time. Score → rank → execute the highest-value work first.

StrategyPriority QueueWSJF

What is it?

An agent juggling tasks needs a deterministic ordering rule. Common scoring schemes:

  • Eisenhower — urgent × important.
  • WSJF — (business value + time criticality + risk reduction) ÷ job size.
  • Custom — domain-specific weights (deadline, dependency depth, customer tier).
Mental model: a hospital's triage nurse — chest pain before stitches, regardless of arrival time.

2026 real-time scenario — Incident-response copilot

A 2026 SRE copilot watches alerts from 60 services. At 3 AM it gets P0 (DB down), P2 (slow log shipper), and P3 (disk usage 78%). Prioritization scores each by impact × revenue × deadline; the agent pages the on-call for P0 first, schedules an automation for P2, files a Jira for P3.

Interview Q&A

How do you avoid starvation of low-priority tasks?
Boost a task's score by age (aging factor) so old low-priority items eventually surface; or reserve a small fraction of capacity for them.
Static priority vs dynamic?
Production systems re-score continuously: an alert that started P3 may climb to P0 if errors per minute spike. Reflect this with a recompute-on-each-pop policy.
