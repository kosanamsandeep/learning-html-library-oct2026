Chapter 16 — Resource-Aware Optimization

Pick the smallest model / cheapest path that meets the SLA. Don't pay GPT-flagship prices for "what's 2+2?".

StrategyDecoratorCost-aware

What is it?

Each request has constraints: latency budget, cost budget, accuracy floor. A resource-aware router picks the model + reasoning depth that fits. Fall back to a cheaper model when the expensive one is rate-limited.

Mental model: a logistics planner — you don't always send Fedex Priority; sometimes ground shipping meets the deadline at 1/3 the cost.

2026 real-time scenario — Customer-support copilot

A 2026 SaaS support tool gets 50k tickets/day. 70% are FAQs (small model, ₹0.001/ticket); 25% need account context (mid model, ₹0.02); 5% are complex billing disputes (flagship, ₹0.30). Resource-aware routing cuts monthly LLM bill from $48k → $9k while preserving CSAT.

Interview Q&A

How do you decide a request is "trivial"?
Length, presence of action verbs, named entities, history of past similar tickets. Train a tiny classifier (or distil one) — much cheaper than calling the LLM to find out.
Won't fallbacks reduce quality?
Sometimes. Pair fallbacks with a quality check (regex, secondary critic) — if the cheap answer fails, escalate. Track quality-adjusted cost, not just cost.
