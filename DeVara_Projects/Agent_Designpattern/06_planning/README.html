Chapter 06 — Planning

Goal in → multi-step plan out. Then execute, observe, replan.

Template MethodCompositeReplan

What is it?

Planning is "decide the how from the what." A planner LLM emits an ordered list of steps (each step usually a tool call or sub-task). An executor runs them, and a re-planner can rewrite the remaining steps if reality diverges.

Mental model: a project manager who breaks a delivery into Jira tickets, then re-orders them when a dependency slips.

Pattern flow

flowchart TD G([Goal]) --> P[Planner LLM] P --> PL[Plan: step1 → step2 → step3] PL --> E[Executor] E -->|"observe result"| M{Goal met?} M -->|"yes"| O([Done]) M -->|"no"| RP[Re-planner] RP --> E

2026 real-time scenario — Office relocation agent

"Move my team of 30 from BLR to HYD by Aug 1, 2026 within ₹4M." The planner emits 11 steps (book site visit, negotiate lease, IT migration, vendor change-of-address, employee relocation comms, etc.). When the lease quote comes in over budget, the re-planner drops the gym-membership perk and re-orders the IT migration to start a week earlier.
flowchart LR G[Goal: move team] --> P[Planner] P --> S1[Site visit] S1 --> S2[Lease negotiation] S2 --> S3{Budget OK?} S3 -->|"no"| RP[Replan: trim perks] S3 -->|"yes"| S4[IT migration] RP --> S4 S4 --> S5[Comms + relocation] S5 --> D([Done])

Interview Q&A

Plan-once vs ReAct?
Plan-once is cheap and predictable but brittle when the world changes. ReAct interleaves think/act/observe per step — slower but adaptive. Modern systems combine: an upfront plan + per-step ReAct.
How do you bound the plan?
Constrain the planner to a fixed tool catalog, set a max-step limit, and validate each step against a schema before execution.
