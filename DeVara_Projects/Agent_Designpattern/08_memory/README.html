Chapter 08 — Memory Management

Short-term context window + long-term persistent memory. Agents need both.

RepositoryMementoVector DB

What is it?

Two kinds of memory:

  • Short-term — last N turns / tool results held in the LLM's context window. Volatile.
  • Long-term — facts / preferences / past episodes persisted in a vector store, key-value store, or graph DB. Retrieved on demand.
Mental model: RAM (context) vs SSD (vector DB). You compress RAM into SSD when it overflows; you load relevant SSD chunks back into RAM when the topic resurfaces.

2026 real-time scenario — Wellness coach app

A 2026 wellness app remembers across months that the user is lactose-intolerant, prefers Tamil-language meal plans, and has a knee injury. Today's chat (short-term) is one week of meals; long-term memory holds those preferences and past episodes. Without long-term memory, the app would re-ask "are you vegetarian?" every Monday.

Interview Q&A

How do you summarize without losing facts?
Hybrid: keep raw recent turns + a rolling summary + key-value extraction (entities, preferences). Vector store the summaries; raw key-values stay in a structured store for exact lookup.
How do you handle memory privacy?
Per-user namespace, encrypted at rest, TTL on entries, explicit "forget" command, and don't log raw memory in traces.
