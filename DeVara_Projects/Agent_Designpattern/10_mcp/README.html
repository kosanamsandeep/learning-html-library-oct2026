Chapter 10 — Model Context Protocol (MCP)

Open standard. One protocol so any LLM can plug into any tool / data / prompt server.

AdapterProxyOpen standard

What is it?

Before MCP every team wrote bespoke connectors per LLM × per tool. MCP defines a JSON-RPC protocol with three primitives an MCP server can expose:

  • Resources — read-only data (files, DB rows, API payloads).
  • Tools — actions the LLM can invoke (function calling).
  • Prompts — reusable prompt templates the host can offer to the user.
Mental model: USB-C for LLMs. Same plug; many devices.

2026 real-time scenario — Cursor / Claude Desktop with MCP

By mid-2026, Anthropic, OpenAI, Microsoft, and Google all support MCP. A developer's IDE has 6 MCP servers running: Postgres, GitHub, Linear, Sentry, AWS, internal-knowledge-base. The LLM can list tickets, query prod logs, and open a PR — all over the same protocol. No custom plug-ins per LLM vendor.

Interview Q&A

MCP vs A2A?
MCP = LLM ↔ tools/data. A2A = agent ↔ agent. Complementary: an A2A agent can itself expose tools via MCP.
What does MCP solve that OpenAPI doesn't?
MCP is LLM-native: it bundles tool descriptions, resource discovery, and prompt templates in a model-friendly schema, with capability negotiation and session lifecycle.
