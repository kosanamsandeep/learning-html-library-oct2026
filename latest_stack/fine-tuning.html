Fine-tuning — full, LoRA, QLoRA, adapters, DPO

Fine-tuning means continuing to train a pre-trained model on your own data so it picks up your task / style / vocabulary. The 2026 default is parameter-efficient fine-tuning (PEFT) — almost always LoRA or QLoRA — because it gets ~95% of full-finetune quality at <5% of the cost.

1 · What "fine-tuning" actually is

flowchart LR
  base[Pre-trained base
e.g. Llama-3-8B] --> ft{Fine-tune}
  data[(Your dataset
prompt → completion pairs)] --> ft
  ft --> tuned[Tuned model
specialised to your task]

You feed the model your input/output pairs, run a few epochs of supervised next-token prediction (or DPO / KTO for preference data), and end up with weights that prefer your style and schema. Cheaper alternatives — prompting, RAG, few-shot — should be exhausted first.

2 · Full fine-tuning vs PEFT (LoRA / QLoRA / adapters)

Approach What it updates VRAM (7B model) Quality Artifact
Full fine-tune Every weight ~80 GB (bf16) Highest ceiling Whole new 14 GB model
LoRA Low-rank adapters on attention proj ~24 GB ~95% of full ~10–200 MB adapter
QLoRA LoRA on top of a 4-bit quantised base ~10–16 GB ~95% of full ~10–200 MB adapter
Adapters (Houlsby) Tiny MLPs injected per layer ~20 GB ~90% of full ~5–50 MB adapter
DPO / KTO Preference-tunes on pairs of "better/worse" answers ~24 GB w/ LoRA Improves style + helpfulness Adapter
Prompt-tuning Only a short learned prefix embedding <8 GB Limited; works on simple tasks <1 MB

3 · How LoRA works in one diagram

flowchart LR
  x[Input x] --> W[Frozen pre-trained
weight W]
  x --> A[LoRA A
down-project] --> B[LoRA B
up-project]
  W --> add((+))
  B --> add
  add --> y[Output]

LoRA freezes the original weight matrix W and learns a low-rank update ΔW = B·A with rank = r (typically 8–64). Trainable params drop by ~1000×; the adapter can be merged into W at inference for zero overhead.

4 · When to pick which

Scenario Pick Why
You need it tomorrow on a 24 GB GPU QLoRA 4-bit base + LoRA fits on one card.
You have hundreds of customers, each with their own data LoRA One frozen base + tiny per-customer adapters. Hot-swap at request time.
Massive distribution shift (new language, new domain) Full fine-tune (or continued pre-training) LoRA's low rank can't move the model far enough.
Make the model prefer one answer style over another DPO with LoRA Preference data is cheaper than gold labels.
Task is solvable with prompt + 5 examples Don't fine-tune Prompting + RAG ship today; fine-tuning is a 2-week detour.
You need provable IP separation Full fine-tune One model per customer; adapter swap is harder to audit.
Default in 2026: reach for QLoRA first. Move to full fine-tune only when an eval shows LoRA hitting a ceiling.

5 · Working QLoRA example (Hugging Face PEFT + TRL)

# pip install transformers peft trl bitsandbytes accelerate datasets
import torch
from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer, SFTConfig

BASE = "meta-llama/Llama-3.2-3B-Instruct"   # any HF causal LM works

# 1. Load base in 4-bit (QLoRA)
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)
tok = AutoTokenizer.from_pretrained(BASE)
tok.pad_token = tok.eos_token
model = AutoModelForCausalLM.from_pretrained(BASE, quantization_config=bnb, device_map="auto")
model = prepare_model_for_kbit_training(model)

# 2. Attach LoRA adapters
lora = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    bias="none", task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora)
model.print_trainable_parameters()
# trainable params: 12,058,624 || all params: 3,224,000,000 || trainable%: 0.37%

# 3. Tiny demo dataset — replace with your own JSONL
ds = load_dataset("HuggingFaceH4/no_robots", split="train_sft").select(range(500))

def fmt(row):
    msgs = row["messages"]
    return {"text": tok.apply_chat_template(msgs, tokenize=False)}
ds = ds.map(fmt)

# 4. Train
trainer = SFTTrainer(
    model=model,
    train_dataset=ds,
    args=SFTConfig(
        output_dir="lora-out",
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        num_train_epochs=1,
        learning_rate=2e-4,
        bf16=True,
        logging_steps=10,
        save_steps=200,
        max_seq_length=1024,
    ),
)
trainer.train()
trainer.save_model("lora-out")  # ~50 MB adapter

Load and use the adapter

from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained(BASE, device_map="auto", torch_dtype=torch.bfloat16)
mdl  = PeftModel.from_pretrained(base, "lora-out")           # hot-attach
# or: mdl = mdl.merge_and_unload()                            # bake into base for zero overhead
