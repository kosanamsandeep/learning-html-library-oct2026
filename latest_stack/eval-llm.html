Evaluating LLM responses — pick the right scorer for the right question

"How do I know my LLM is good?" splits into three families: reference-based metrics (you have a gold answer), reference-free metrics (you don't), and human evaluation. The mature workflow uses all three: cheap automatic checks on every CI run, an LLM-judge for nuance, and periodic human spot-checks to calibrate the judge.

2 · Reference-based (automatic) metrics

Metric What it measures Use for
exact_match 1 if string == gold else 0 Classification, JSON keys, intent
regex_match Pattern matches Extracted entities, dates
set_match / subset_match Set equality / inclusion Tool-call arguments, tags
json_schema_match Parses and validates against schema Structured output
BLEU n-gram overlap with reference Translation
ROUGE-L Longest common subsequence Summarisation
BERTScore Cosine similarity of contextual embeddings Paraphrase quality
Perplexity How surprised the model is by held-out text Base-model comparison; not for chat quality
pass@k Fraction of problems solved in k tries Code (HumanEval, MBPP, SWE-bench)

3 · Reference-free metrics — LLM as judge

When you don't have a gold answer (open-ended chat, RAG answers), you ask a strong LLM to score with a rubric. The pattern that works:

  1. Give the judge a specific rubric (1–5 scale, with concrete anchors for each score), not a vague "rate quality."
  2. Use a different model as the judge than the one being evaluated.
  3. Ask for reasoning first, score last — chain-of-thought makes judges more consistent.
  4. For pairwise (A vs B) judging, swap the order and average — fights position bias.

5 · Human evaluation — when and how

  • Calibration: 50–100 examples scored by humans + the LLM-judge. Compute correlation. If < 0.7, fix the rubric.
  • Pairwise A/B: rank two models on the same prompts. Cheaper and more reliable than absolute scoring.
  • Likert + reason: 1–5 score plus a one-sentence reason. The reasons reveal failure modes the metric can't.
  • Red-teaming: humans actively try to break the agent (jailbreak, PII leak, harmful output).
  • Sample size: 100–300 examples is enough to detect 5 pt differences with confidence.

6 · A working evaluator in 15 lines (DeepEval)

# pip install deepeval
from deepeval import evaluate
from deepeval.test_case import LLMTestCase
from deepeval.metrics import (
    AnswerRelevancyMetric,
    FaithfulnessMetric,
    HallucinationMetric,
)

case = LLMTestCase(
    input="What's our refund window?",
    actual_output="You can request a refund within 30 days of purchase.",
    expected_output="30 days",
    retrieval_context=["Customers may request refunds up to 30 days after purchase."],
    context=["Customers may request refunds up to 30 days after purchase."],
)

results = evaluate(
    test_cases=[case],
    metrics=[
        AnswerRelevancyMetric(threshold=0.8),
        FaithfulnessMetric(threshold=0.8),
        HallucinationMetric(threshold=0.3),
    ],
)

Or with RAGAS

# pip install ragas
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision
from datasets import Dataset

ds = Dataset.from_dict({
    "question":  ["What's the refund window?"],
    "answer":    ["You can request a refund within 30 days."],
    "contexts":  [["Refunds allowed within 30 days of purchase."]],
    "ground_truth": ["30 days"],
})
print(evaluate(ds, metrics=[faithfulness, answer_relevancy, context_precision]))

7 · The production pattern

flowchart LR
  ci[CI / PR] --> auto[Automatic scorers
exact_match, JSON, RAGAS, DeepEval]
  auto -->|gate| merge[Merge]
  merge --> can[Canary 1% traffic] --> log[Log prompts + outputs]
  log --> sample[Sample 50/day] --> human[Human scorer]
  human --> cal[Recalibrate LLM-judge
monthly]
  cal --> auto

Every PR runs deterministic + LLM-judge scorers on a frozen eval set. Production samples are human-scored weekly and used to recalibrate the judge.
