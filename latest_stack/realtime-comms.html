WebSockets vs WebRTC — pick on latency budget and topology

WebSocket is a long-lived TCP connection (RFC 6455) for bi-directional text/binary messages between a client and a server. WebRTC (W3C) is a peer-to-peer stack for low-latency audio, video, and data over UDP with NAT traversal built in. They look similar from 50,000 ft and solve very different problems up close.

2 · The differences that actually matter

Property WebSocket WebRTC
Transport TCP (ordered, reliable) UDP (DTLS / SRTP); optional reliable DataChannel
Topology Client ↔ server Peer ↔ peer (or via SFU)
Typical latency 50–200 ms RTT 20–150 ms one-way
Head-of-line blocking Yes (TCP) No (UDP) — old audio packets are dropped, not retransmitted
Native audio / video No — you ship raw bytes yourself Yes — codecs, jitter buffer, echo cancellation built in
NAT traversal None needed (server-side) ICE + STUN + TURN
Browser API new WebSocket(url) RTCPeerConnection, getUserMedia
Server complexity Low (one TCP port, plain handlers) High (signalling + SFU + TURN; or use Daily, LiveKit, Twilio)
Scale model 1 server → many clients Peer-mesh, SFU, or MCU

3 · When to pick which

Pick WebSocket

  • Chat & notifications
  • Live dashboards / tickers
  • Streaming LLM tokens to the browser
  • Streaming STT transcripts (text)
  • Collaborative editing (Yjs uses both, but WS is the baseline)

Pick WebRTC

  • Voice / video calls
  • Live coaching, telemedicine, podcasting
  • Cloud gaming, remote desktop
  • P2P file transfer
  • Voice agents where the audio is bidirectional (OpenAI Realtime, LiveKit Agents, Pipecat)

Pick both

Voice agents commonly use WebRTC for audio + WebSocket for control / metadata / partial transcripts.

4 · Tiny WebSocket example (browser ⇄ FastAPI)

# server.py — pip install fastapi uvicorn websockets
from fastapi import FastAPI, WebSocket
app = FastAPI()

@app.websocket("/echo")
async def echo(ws: WebSocket):
    await ws.accept()
    while True:
        msg = await ws.receive_text()
        await ws.send_text(f"echo: {msg}")

// client.js
const ws = new WebSocket("ws://localhost:8000/echo");
ws.onopen   = () => ws.send("hello");
ws.onmessage = (e) => console.log(e.data); // "echo: hello"

5 · Minimal WebRTC sketch (browser side)

// 1. Get the mic
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

// 2. Create a peer connection
const pc = new RTCPeerConnection({
  iceServers: [{ urls: "stun:stun.l.google.com:19302" }]
});
stream.getTracks().forEach(t => pc.addTrack(t, stream));

// 3. Exchange SDP offer/answer with the other peer through your signalling server
const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
signaling.send({ type: "offer", sdp: offer.sdp });

signaling.on("answer", async ({ sdp }) => {
  await pc.setRemoteDescription({ type: "answer", sdp });
});

// 4. Receive remote audio
pc.ontrack = (ev) => { audioEl.srcObject = ev.streams[0]; };

In production, use LiveKit, Daily, Twilio, or OpenAI's Realtime API to skip the SFU + TURN setup.

6 · Latency budget cheat sheet for voice agents

Hop Budget
Mic capture → first STT partial ~150 ms
STT final → LLM first token ~250 ms
LLM token → TTS first audio chunk ~150 ms
TTS chunk → speaker ~50 ms
Total user-perceived ~600 ms (the "human" threshold)

WebRTC's UDP path saves 50–150 ms over WebSocket by avoiding TCP head-of-line blocking. That's often the difference between "feels alive" and "feels like a phone tree."
