Performance optimisation — making LLMs fast and cheap

LLM inference is dominated by two costs: memory bandwidth (reading the weights and KV cache from GPU HBM every token) and compute (matrix multiplies). Every optimisation either shrinks the weights, reuses computation, or processes more requests per forward pass.

2 · Quantisation — the biggest single win

Replace 16-bit weights with 8-, 4-, or 2-bit integers. Memory drops linearly, bandwidth-bound layers speed up almost as much, quality loss is small if you use a good scheme.

Format Bits Speed vs FP16 Quality Use case
FP16 / BF16 16 1× Reference Training, baseline
FP8 (Hopper / Blackwell) 8 ~1.7× Very close to FP16 New GPUs (H100, B200)
INT8 (SmoothQuant, LLM.int8()) 8 ~1.8× Near-FP16 Any GPU
INT4 (GPTQ, AWQ) 4 ~2.5–3× ~1–2 pt benchmark drop Single-GPU serving
GGUF Q4_K_M / Q5_K_M ~4–5 Runs on CPU Good llama.cpp / Ollama / edge
BitNet / 1.58-bit ~1.6 Massive Requires native-trained models Research / future edge

3 · Throughput tricks (server side)

Continuous batching

Add new requests into the batch every token, evict finished ones. vLLM / TGI / TensorRT-LLM do this. 10–20× throughput vs static batching.

PagedAttention

Treat the KV cache like virtual memory pages instead of one contiguous block. Eliminates fragmentation; vLLM's core trick.

Speculative decoding

A small draft model proposes K tokens; the big model verifies in one forward pass. 2–3× faster on the same hardware, identical output.

Prompt / prefix caching

If many requests share the same system prompt, cache its KV state. Anthropic and OpenAI both expose this; vLLM does it automatically.

FlashAttention 2/3

Fused attention kernel that streams tiles through SRAM. 2–4× faster, less memory. Now the default in PyTorch / vLLM.

Tensor / pipeline parallelism

Shard weights across multiple GPUs. Needed once the model doesn't fit on one card.

4 · GPU vs CPU — when to leave the GPU

Workload Pick Why
Single-user 7B chat at > 30 tok/s GPU (or Apple Silicon MLX, Groq LPU) Bandwidth wins.
Single-user 7B chat at 8–15 tok/s CPU + llama.cpp (GGUF Q4) Acceptable for chat, $0 GPU bill.
Many concurrent users GPU with vLLM / TGI Batching only pays on GPU.
Embeddings / reranking GPU (small batch) or CPU (low QPS) Tiny models batch well on CPU too.
Mobile / browser WebGPU, CoreML, ONNX Runtime Mobile, MLC LLM No server at all.

5 · Caching — the cheapest 10× you'll ever get

  • Response cache — hash the full prompt; return prior answer for identical inputs.
  • Semantic cache — embed the prompt; return a prior answer if cosine sim > 0.95. (GPTCache, Redis Vector.)
  • Prompt-prefix cache — server-side KV reuse for shared system prompts. Free 50–90% latency on the prefix.
  • Tool-call cache — memoise deterministic tools (currency conversion, lookups) for a TTL.
  • Embedding cache — embeddings are deterministic per (text, model); cache by hash.

6 · A practical playbook in order

  1. Measure first. Profile with nvtop, vLLM metrics, OpenTelemetry. Find the bottleneck.
  2. Add prompt caching. Anthropic / OpenAI APIs: one flag. Self-hosted vLLM: automatic.
  3. Quantise to INT8 or INT4 (AWQ). 2–3× free.
  4. Switch to vLLM / TGI / TensorRT-LLM. Continuous batching + PagedAttention.
  5. Turn on speculative decoding if your model + draft pair are supported.
  6. Right-size the model. A fine-tuned 3B will beat an unmodified 70B on a narrow task at 1/30 the cost.
  7. Move embeddings + reranking off the LLM GPU onto cheap CPUs or Inferentia.

7 · Quick example — quantise + serve with vLLM

# Quantise a model to AWQ INT4 (one-time)
pip install autoawq
python -c "
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer
m = AutoAWQForCausalLM.from_pretrained('meta-llama/Llama-3.1-8B-Instruct')
t = AutoTokenizer.from_pretrained('meta-llama/Llama-3.1-8B-Instruct')
m.quantize(t, quant_config={'w_bit': 4, 'q_group_size': 128, 'zero_point': True})
m.save_quantized('Llama-3.1-8B-Instruct-AWQ')
t.save_pretrained('Llama-3.1-8B-Instruct-AWQ')
"

# Serve with vLLM (continuous batching, paged attention, prefix cache — all on)
pip install vllm
vllm serve ./Llama-3.1-8B-Instruct-AWQ \
  --quantization awq \
  --enable-prefix-caching \
  --max-num-seqs 256 \
  --gpu-memory-utilization 0.9
