LitServe — the batteries-included model server from Lightning AI

LitServe is an open-source serving framework built on FastAPI by Lightning AI, designed specifically for ML / AI workloads. It gives you dynamic batching, GPU scheduling, multi-model routing, streaming, and multi-worker scaling out of the box — so you write two methods (setup and predict) instead of an entire async server. Think FastAPI for models, with the model-server plumbing already wired.

3 · When to pick LitServe vs FastAPI

Pick LitServe

  • You're serving any ML model (vision, audio, embeddings, classical ML, or LLM).
  • You need batching + GPU pooling without writing the queue yourself.
  • You're juggling multiple models on one server.
  • You want an OpenAI-compatible LLM endpoint without writing the spec.

Pick plain FastAPI

  • Your endpoint isn't model inference (CRUD, auth, business logic).
  • You want full control over the HTTP layer.
  • You're not GPU-bound; concurrency is I/O.
  • You already have a battle-tested deployment.

Pick vLLM (only)

  • Pure LLM serving at scale; you want the absolute highest throughput.
  • You don't need a custom Python frontend.

Combine LitServe + vLLM

LitServe in front for routing, auth, and multi-model; vLLM as the LLM engine. Lightning ships official integration.

4 · Hello-LitServe in 15 lines

# pip install litserve
import litserve as ls
from transformers import pipeline

class SentimentAPI(ls.LitAPI):
    def setup(self, device):
        self.pipe = pipeline("sentiment-analysis", device=device)

    def decode_request(self, request):
        return request["text"]

    def predict(self, x):
        return self.pipe(x)[0]

    def encode_response(self, output):
        return {"label": output["label"], "score": output["score"]}

if __name__ == "__main__":
    server = ls.LitServer(SentimentAPI(), accelerator="auto",
                          max_batch_size=8, batch_timeout=0.05)
    server.run(port=8000)

That tiny class gives you: a /predict endpoint, automatic GPU placement, request batching up to 8 within 50 ms, OpenAPI docs, and worker pooling.

5 · LLM streaming with LitServe

import litserve as ls
from transformers import AutoTokenizer, AutoModelForCausalLM, TextIteratorStreamer
import torch
from threading import Thread

class LLM(ls.LitAPI):
    def setup(self, device):
        name = "microsoft/Phi-3.5-mini-instruct"
        self.tok = AutoTokenizer.from_pretrained(name)
        self.mdl = AutoModelForCausalLM.from_pretrained(
            name, torch_dtype=torch.bfloat16, device_map=device
        )

    def decode_request(self, request):
        return request["prompt"]

    def predict(self, prompt):
        streamer = TextIteratorStreamer(self.tok, skip_prompt=True)
        inputs = self.tok(prompt, return_tensors="pt").to(self.mdl.device)
        Thread(target=self.mdl.generate,
               kwargs=dict(**inputs, streamer=streamer, max_new_tokens=256)).start()
        for chunk in streamer:
            yield chunk        # LitServe turns this into an SSE stream

    def encode_response(self, output):
        for chunk in output:
            yield {"delta": chunk}

if __name__ == "__main__":
    ls.LitServer(LLM(), accelerator="auto", stream=True).run(port=8000)

6 · Multi-model routing

import litserve as ls

class MultiModel(ls.LitAPI):
    def setup(self, device):
        self.classifier = load_classifier(device)
        self.summariser = load_summariser(device)

    def decode_request(self, request):
        return request["task"], request["text"]

    def predict(self, payload):
        task, text = payload
        if task == "classify":
            return self.classifier(text)
        elif task == "summarise":
            return self.summariser(text)
        raise ValueError(f"unknown task {task}")

One server, one GPU, two models, automatic batching per task.

7 · Production checklist

  1. Set max_batch_size and batch_timeout based on your p95 latency budget.
  2. Use workers_per_device>1 for I/O-bound preprocessing.
  3. Front it with Caddy / nginx for TLS & rate limiting.
  4. Expose /health and /metrics (Prometheus middleware on the underlying FastAPI app).
  5. Deploy with Lightning Studios, Docker, or any Kubernetes (it's stateless).
