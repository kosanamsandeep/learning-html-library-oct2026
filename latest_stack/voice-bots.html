Voice bots — sub-800 ms architecture

A voice agent feels human only if the round-trip from "user stops talking" to "user hears the first word of reply" stays under ~800 ms. That budget is allocated across STT, LLM, TTS, and the network — and every component has to stream. This page gives you the architecture, the latency budget, and the production patterns (interruptions, jitter buffers, endpointing).

1 · End-to-end architecture (pipelined)

flowchart LR
  mic[Mic
browser / phone] -->|WebRTC| vad[VAD + Endpointer]
  vad -->|audio chunks| stt[Streaming STT
Deepgram / Whisper]
  stt -->|partials| logic{Turn manager}
  logic -->|stable| llm[Streaming LLM
SLM 7B or GPT-4o-mini]
  llm -->|tokens| ttssplit[Sentence chunker]
  ttssplit --> tts[Streaming TTS
ElevenLabs / Cartesia]
  tts -->|audio frames| jitter[Jitter buffer]
  jitter -->|WebRTC| spk[Speaker]
  interrupt[User starts speaking] -.barge-in.-> tts
  interrupt -.cancel.-> llm

2 · Latency budget (800 ms target)

Stage Budget How to hit it
Endpoint detection (silence → "user done") ~200 ms Tunable VAD (Silero, WebRTC VAD) at 180–250 ms
STT final transcript after silence ~100 ms Streaming STT (Deepgram Nova, Whisper streaming)
LLM first token ~250 ms SLM 7B on dedicated GPU, or GPT-4o-mini, or Groq
First TTS audio chunk ~150 ms Streaming TTS (Cartesia Sonic ~75 ms, ElevenLabs flash)
Network + jitter buffer ~100 ms WebRTC over UDP, 60–80 ms jitter buffer
Total ~800 ms Below this, it feels alive.
The single biggest win: pipe LLM tokens into TTS sentence-by-sentence. The user hears sentence one while the model is still writing sentence two. Don't wait for the full response.

3 · The non-obvious problems

Barge-in / interruption

If the user starts speaking, you must cut off the TTS audio and cancel the LLM generation within ~100 ms. Most beginner bots talk over the user.

Endpointing

Fixed silence thresholds are wrong. Use semantic endpointing (an SLM judges "did the user finish a thought?") for tricky users.

False barge-in

The bot hears its own speaker via the mic. Use AEC (acoustic echo cancellation — built into WebRTC) and ignore VAD while TTS is playing if AEC is off.

Filler words

"Mm-hmm", "let me check" played early masks the LLM latency without lying.

Function calls mid-utterance

If the LLM needs to call a tool, you've already burned 300 ms. Speak a filler, then continue.

Number / unit pronunciation

"$1,234.56" must be normalised to "twelve hundred thirty-four dollars and fifty-six cents" or the TTS gets it wrong.

4 · Frameworks that hide most of this

Framework What it gives you
Pipecat (Daily) Open-source Python pipeline: VAD → STT → LLM → TTS with barge-in built in.
LiveKit Agents Hosted WebRTC + Python/Node agent SDK; ships with VAD, multilingual STT, TTS, telephony.
OpenAI Realtime API Single WebSocket, speech-to-speech via GPT-4o; no STT/TTS plumbing.
Vapi / Retell / Bland Managed voice-agent platforms; ship in a day, less control.
Twilio Voice + ConversationRelay Telephony front-end + bring-your-own LLM backend.

5 · Minimal Pipecat-style pipeline (pseudocode)

# pip install pipecat-ai
from pipecat.pipeline.pipeline import Pipeline
from pipecat.pipeline.runner import PipelineRunner
from pipecat.pipeline.task import PipelineTask
from pipecat.services.deepgram import DeepgramSTTService
from pipecat.services.elevenlabs import ElevenLabsTTSService
from pipecat.services.openai import OpenAILLMService
from pipecat.transports.services.daily import DailyTransport, DailyParams
from pipecat.vad.silero import SileroVADAnalyzer

transport = DailyTransport(
    room_url, token, "Bot",
    DailyParams(audio_in_enabled=True, audio_out_enabled=True,
                vad_analyzer=SileroVADAnalyzer()),
)
stt = DeepgramSTTService(api_key=DG_KEY)
llm = OpenAILLMService(api_key=OAI_KEY, model="gpt-4o-mini")
tts = ElevenLabsTTSService(api_key=EL_KEY, voice_id="Rachel")

pipeline = Pipeline([
    transport.input(),
    stt,
    llm,                      # streams tokens
    tts,                      # streams audio chunks back
    transport.output(),
])

task = PipelineTask(pipeline)
PipelineRunner().run(task)

The framework handles barge-in (TTS interruption), sentence chunking, and jitter buffer for you.

6 · Telephony note

If the bot needs to answer a real phone number, you pick up either (a) Twilio / Telnyx SIP → WebSocket bridge into your pipeline, or (b) LiveKit Telephony which wraps SIP for you. The audio will be 8 kHz μ-law — your STT must support narrow-band, and TTS output must be downsampled.
