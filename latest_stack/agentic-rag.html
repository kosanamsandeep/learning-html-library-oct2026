Agentic RAG — RAG that can decide, retry, and route

Classic RAG is a straight line: embed query → search vector DB → stuff top-k → generate. Agentic RAG wraps that pipeline in an LLM-driven loop that can rewrite the query, pick the right source, decide whether more retrieval is needed, and critique its own answer before returning. It solves the failure modes everyone hits with naive RAG: ambiguous queries, multi-hop questions, wrong index, stale context.

2 · The problems agentic RAG actually solves

Failure of naive RAG Agentic fix
"What changed between v2 and v3?" — top-k brings back v3 docs only. Query decomposition: agent splits into two retrievals and diffs.
Vague question ("any issues?") returns irrelevant chunks. Query rewriting: agent asks the LLM to expand into 3 specific queries.
Multi-source: docs + Jira + Slack — one index can't answer. Source routing: agent picks the right tool / index per sub-query.
Top-k missed the answer; the model hallucinates anyway. Self-critique loop: LLM judges its own draft against retrieved evidence; retries with a new query.
Time-sensitive question ("latest pricing") returns stale doc. Freshness check: agent escalates to a live web / API tool.
Complex 3-hop questions ("CEO of the company that acquired X?") Multi-hop chaining: agent retrieves, partial-answers, retrieves again.

3 · The four canonical agentic-RAG patterns

1. Query rewriter (HyDE)

LLM expands the query into a hypothetical answer, then embeds and searches. Beats keyword overlap on vague questions.

2. Router agent

LLM classifies query → picks one of N indexes / tools. Classic LlamaIndex pattern.

3. Self-RAG / CRAG

Model emits "retrieve?" tokens, judges retrieved chunks for relevance, and decides to keep, retry, or fall back to web search.

4. Multi-agent research

Coordinator spawns parallel sub-agents (each with its own index), then synthesises. Used in Anthropic's research-mode agents and LangGraph's create_react_agent.

4 · Minimal agentic-RAG loop (LangGraph style)

# pip install langgraph langchain-openai langchain-community chromadb
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from typing import TypedDict, List

llm = ChatOpenAI(model="gpt-4o-mini")
vs = Chroma(persist_directory="./db", embedding_function=OpenAIEmbeddings())

class S(TypedDict):
    question: str
    queries: List[str]
    docs: List[str]
    draft: str
    attempts: int

def rewrite(s):
    prompt = f"Decompose into 1-3 retrieval queries (JSON list):\n{s['question']}"
    s["queries"] = eval(llm.invoke(prompt).content)
    return s

def retrieve(s):
    s["docs"] = [d.page_content for q in s["queries"] for d in vs.similarity_search(q, k=4)]
    return s

def generate(s):
    ctx = "\n\n".join(s["docs"])
    s["draft"] = llm.invoke(f"Answer using ONLY this context.\nQ: {s['question']}\n\n{ctx}").content
    return s

def critique(s):
    verdict = llm.invoke(
        f"Is this answer fully supported by the context?\nA: {s['draft']}\nReply YES or NO."
    ).content.strip().upper()
    s["attempts"] = s.get("attempts", 0) + 1
    return "ok" if verdict.startswith("YES") or s["attempts"] >= 2 else "retry"

g = StateGraph(S)
g.add_node("rewrite", rewrite); g.add_node("retrieve", retrieve); g.add_node("generate", generate)
g.set_entry_point("rewrite")
g.add_edge("rewrite", "retrieve"); g.add_edge("retrieve", "generate")
g.add_conditional_edges("generate", critique, {"ok": END, "retry": "rewrite"})
app = g.compile()

print(app.invoke({"question": "What changed in v3 vs v2 of the API?"})["draft"])

5 · When NOT to use agentic RAG

  • Latency-critical paths (< 500 ms total): the extra LLM hops cost 1–3 seconds. Use classic RAG with a strong reranker instead.
  • Cost-sensitive high-volume traffic: 3–5× LLM calls per query. Cache aggressively or fall back to classic.
  • Single homogeneous corpus + simple questions: a hybrid BM25 + dense + Cohere reranker beats most agentic loops on quality and is 5× cheaper.
Rule of thumb: add an agentic step only when an eval shows naive RAG failing on a specific failure class — and remove it if the same eval shows the cost not paying off.

6 · Production checklist

  1. Caching: hash (query + index version) → cached chunks; reuse across retries.
  2. Tool budget: cap retrieval calls per question (e.g. 3). Stop the loop hard.
  3. Citations: the critic check must verify citation IDs, not just plausibility.
  4. Eval set: golden Q&A pairs scored by RAGAS / DeepEval (faithfulness + context-recall + answer-relevance). Re-run on every prompt change.
  5. Observability: log query, queries-after-rewrite, chunk IDs, draft, critic verdict, attempts. Use LangSmith / Phoenix / Arize.
