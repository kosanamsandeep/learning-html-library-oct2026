Hospital Management — composition, with the borrow checker watching

Hospital → Department → Doctor → Appointment. The fun bit in Rust: when you want to mutate a Doctor that lives inside a Department that lives inside a Hospital, you have to walk down through mutable borrows. That's get_mut, iter_mut, and the ? operator working together.

The mutable-walk pattern

fn book(&mut self, dept: &str, doctor_id: u64, ...) -> Result<(), String> {
    let d = self.departments.get_mut(dept)
        .ok_or_else(|| format!("no such department: {dept}"))?;
    let doc = d.find_doctor_mut(doctor_id)
        .ok_or("no such doctor")?;
    doc.book(patient, when);
    Ok(())
}

Each get_mut hands you a fresh mutable borrow that lives as long as the surrounding scope needs it. ? propagates the None/Err case to the caller. You cannot accidentally hold two mutable borrows of the same data at once — the compiler refuses.

Tradeoff

Yes, this is more code than Python's hospital["Cardiology"][1].book(...). The payoff is that races, dangling references, and accidental aliasing are compile errors. In a 50k-line codebase, that pays back many times over.
