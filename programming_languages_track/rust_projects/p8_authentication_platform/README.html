Authentication — strategies behind a trait

Two providers, one trait, one service. The new wrinkle in Rust is the lifetime annotation on AuthService<'a> — it says "this service borrows an authenticator that lives at least as long as 'a".

Lifetimes in 30 seconds

struct AuthService<'a> { a: &'a dyn Authenticator }
  • &'a dyn Authenticator = a borrowed trait object that lives for the lifetime 'a.
  • The compiler infers 'a from the call site. You rarely have to spell it out, but you do have to name it on the struct.
  • If you want owned data instead, swap to Box<dyn Authenticator> — same idea, no lifetime in the struct.

What's missing for production

  • Replace the demo hash with the argon2 crate. Do not ship the demo hash.
  • Add a session/JWT issuer at the service layer, not in the strategies.
  • Add rate-limiting on failed logins (see Rate Limiter).
Security note: the FNV fold here is not a real hash. It is here only so the demo runs without dependencies.

Run it

cd rust_projects/p8_authentication_platform
cargo run
