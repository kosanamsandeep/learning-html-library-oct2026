Student Management — Rust edition

Same domain as the Python and Go versions. The interesting bits in Rust: &mut self on the methods that mutate state, Result<T, String> instead of exceptions, Option<&Student> from get instead of None.

What's new vs Python

  1. Mutability is explicit. fn add(&mut self, ...) — only the methods that need to change self say so. The compiler refuses calls that try to mutate through a shared borrow.
  2. Errors as values. Result<Student, String>. The caller writes a match or uses the ? operator.
  3. Ownership shows up immediately. insert(s.id, s.clone()) — without the .clone(), the value moves into the map and is unusable afterward.
  4. derive(Debug, Clone) auto-implements Debug (so you can println!("{:?}", ...)) and Clone (so s.clone() compiles).

The shape

Python

@dataclass
class Student:
    id: int
    name: str
    grade: int

class StudentService:
    def __init__(self):
        self.students = {}
        self.next_id = 1

    def add(self, name, grade):
        if not name:
            raise ValueError("...")
        s = Student(self.next_id, name, grade)
        self.students[s.id] = s
        self.next_id += 1
        return s

Rust

#[derive(Debug, Clone)]
struct Student {
    id: u64,
    name: String,
    grade: u32,
}

impl StudentService {
    fn add(&mut self, name: &str, grade: u32)
        -> Result<Student, String>
    {
        if name.trim().is_empty() {
            return Err("name required".into());
        }
        let s = Student { ... };
        self.students.insert(s.id, s.clone());
        self.next_id += 1;
        Ok(s)
    }
}

Win for Rust

Three categories of bugs are now compile errors: forgetting to mutate-through-mut, accidentally consuming a value before you're done with it, ignoring the error case from add.
