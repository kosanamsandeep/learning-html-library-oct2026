RAG end-to-end — the shape Rust crates use in production

All ten projects' patterns wired into a tiny RAG pipeline. The Embedder is a trait; the store is Arc<Mutex<VectorStore>>; ingest runs across N worker threads each pulling from a shared work queue. This is the exact shape tokenizers, candle, and the major Rust vector DBs use — just larger.

The Rust-specific bits worth lingering on

  1. Trait object across threads. Arc<dyn Embedder> requires Embedder: Send + Sync. The compiler refuses to give you a thread-shared embedder that isn't thread-safe.
  2. Shared work queue. A single Arc<Mutex<Vec<Chunk>>> from which every worker pop()s. Simple, predictable, no lost work.
  3. Cosine ranking is monomorphised. cosine(a: &[f64], b: &[f64]) compiles to a tight loop with no virtual dispatch — exactly what makes Rust the right home for vector math.

How a real Rust RAG service would extend this

  • Replace HashEmbedder with the candle-transformers crate, or call OpenAI via reqwest.
  • Replace the in-memory store with an HNSW index (e.g. hnsw_rs) for sub-ms search over millions of vectors.
  • Wrap the whole thing in axum; expose POST /ingest + POST /query.
  • Switch std::thread to tokio::spawn for cheap async I/O when calling out to remote embedders.
