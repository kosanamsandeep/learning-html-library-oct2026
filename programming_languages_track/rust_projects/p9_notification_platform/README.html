Rust · P9

Notifications — trait registry + thread fan-out with Arc<dyn Channel>

Same shape as the Go version. The interesting bits in Rust: every channel is wrapped in Arc so multiple threads can hold a reference, and the trait must be marked Send + Sync so the compiler trusts it across thread boundaries.

The two-marker trait

trait Channel: Send + Sync {
    fn name(&self) -> &'static str;
    fn send(&self, to: &str, body: &str);
}
  • Send = "values of this type can be moved to another thread."
  • Sync = "references to this type can be shared across threads."
  • The compiler checks both at compile time. If a channel held something thread-unsafe (like an Rc), this declaration would force you to fix it.

How it compares to Go's goroutines

Aspect Go Rust (std)
Spawn go func() { ... }() thread::spawn(move || { ... })
Cost per spawn ~2 KB (lightweight) ~1 MB (real OS thread)
Capture rules Closure captures by reference (Go 1.22+ safer) move closure transfers ownership; compiler enforces Send/Sync
Joining sync.WaitGroup handle.join()

For thousands of concurrent sends use Tokio — its tokio::spawn is the lightweight equivalent of a goroutine.
