Banking System — traits + trait objects

Python's inheritance becomes a trait Account with two implementations. To keep a heterogeneous collection (savings + checking in one slice), we wrap each in Box<dyn Account> — the same idea as a Java interface reference, only built on a vtable the compiler set up.

Two flavours of polymorphism in Rust

Form Cost When
Static (generics): fn f<A: Account>(a: &A) Zero — monomorphised. You know the concrete type at the call site.
Dynamic (trait object): Box<dyn Account> One vtable lookup per call. You need a heterogeneous collection.

This project uses the dynamic form because Vec<Box<dyn Account>> can hold both Savings and Checking in the same slice.

What you gain over Go and Python

  • The compiler enforces the contract. Forget to implement one of the trait methods and the build fails.
  • No accidental float money. i64 for cents — typed, not by convention.
  • Errors must be handled. .unwrap() in the demo is the loud version; the ? operator is the quiet version. Either way, you can't ignore them.

cd rust_projects/p2_banking_system
