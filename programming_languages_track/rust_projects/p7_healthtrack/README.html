HealthTrack — layered service + Arc<Mutex<Repo>>

The Go version uses net/http. To stay dependency-free in Rust this version simulates the HTTP boundary with two functions — simulate_post and simulate_get — but everything else (service, repo, locking) is exactly what a real axum app would have.

The new piece — Arc<Mutex<T>>

struct HealthService { repo: Arc<Mutex<RecordRepo>> }
  • Arc = atomic reference-counted pointer. Lets multiple threads (or async tasks) share ownership of the same value.
  • Mutex = exclusive lock around the inner value. Only one thread at a time can mutate.
  • Together: the canonical "shared mutable state" pattern in Rust. repo.lock().unwrap().save(rec) takes the lock, mutates, releases when the guard drops at the end of the line.

Upgrade path to a real server

  1. Add axum + tokio in Cargo.toml.
  2. Write async fn create_record(State(svc): State<HealthService>, Json(req): Json<RecordRequest>).
  3. Wire routes; everything else stays.

Run it

cd rust_projects/p7_healthtrack
cargo run
