Contact Management — multi-error validator + an enum for phone kind

Rust's enum turns "kind is mobile/work/home" into a closed set of values the compiler knows about. Unknown strings produce None — which the validator reports as a friendly error rather than crashing.

The enum trick

enum PhoneKind { Mobile, Work, Home }

impl PhoneKind {
    fn parse(s: &str) -> Option<Self> {
        match s {
            "mobile" => Some(Self::Mobile),
            "work"   => Some(Self::Work),
            "home"   => Some(Self::Home),
            _        => None,
        }
    }
}

Anywhere downstream that takes a PhoneKind can match on it exhaustively. Add a fourth kind tomorrow and every match in the codebase will refuse to compile until you handle the new arm. That is how Rust prevents drift in large codebases.

Result<(), Vec<String>> — collecting errors

Returning a vector of errors instead of stopping at the first is a friendly API choice and equally valid in any language. Rust just gives you a clean way to express it in the type signature.
