Why this matters for GenAI / agentic systems

Most production GenAI services live behind a small, fast, network-heavy backend. Python is great at the orchestration layer (prompts, agents, evaluations) but it is rarely the layer that actually serves traffic at p99. Three patterns you will see in the wild:

  1. Go for the gateway / proxy / orchestrator. Tools like Ollama, vLLM's router, MCP host implementations, GitHub's own Copilot stack, and most modern AI-infra control planes are written in Go. The reason is operational: one static binary, low memory, predictable GC pauses, first-class concurrency.
  2. Rust for the inference / data path. Hugging Face's tokenizers, candle, text-generation-inference, Pinecone's core engine, Qdrant, LanceDB and many vector indexes are Rust. Tokenisation, vector math, and bytes-on-the-wire are exactly where Python's overhead stops being acceptable.
  3. Python for the brain. The agent itself, prompt templating, evaluation loops, notebook research — these stay in Python because the ecosystem is unbeatable. The trick is knowing which 10% of your stack belongs in Go or Rust to make the other 90% comfortable.

The full story is in Bootcamp · 1.

How to actually use this track

  1. Read all 5 bootcamp pages. ~90 minutes total.
  2. For each numbered project (1 → 10): re-read the Python README, then read the Go README, then the Rust README. Do not try to memorise — just notice the differences.
  3. Pick one of Go or Rust to actually run. Install the toolchain (cheatsheet in Bootcamp · 5), go run main.go or cargo run, observe.
  4. By project 5 you'll naturally start preferring one of the two. Lean into that, finish that side first, then come back for the other.
