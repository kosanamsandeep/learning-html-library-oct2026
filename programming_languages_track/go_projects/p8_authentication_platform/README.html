Authentication — strategies behind a one-method interface

Two providers (password, API key), one entry point. The service depends on the Authenticator interface; both providers satisfy it implicitly. This is the dependency-injection pattern Python achieves with Protocols, only enforced at compile time.

The shape

type Authenticator interface {
    Authenticate(creds map[string]string) (Identity, error)
}

func main() {
    pwSvc  := &AuthService{a: NewPasswordAuth()}
    apiSvc := &AuthService{a: NewAPIKeyAuth()}
    // same AuthService.Login works for both
}

Real-world extensions

  • Add an OIDC strategy — same interface.
  • Add a session token issuer (JWT, opaque) at the service layer, not inside the strategies.
  • Use bcrypt (golang.org/x/crypto/bcrypt) instead of plain SHA-256 for password hashing in production. SHA-256 here is only for demo.
Security note: never use SHA-256 for passwords in real code. Use bcrypt, scrypt, or argon2id.
