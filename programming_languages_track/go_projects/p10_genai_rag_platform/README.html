Go · P10 · Capstone

RAG end-to-end — chunker, embedder interface, vector store, generator

All the patterns from p1-p9 wired into a tiny RAG pipeline. The embedder is an interface so you can swap a deterministic hash embedder for a real OpenAI client. Ingest runs in parallel across a goroutine pool.

Why this is a great Go fit (and a real production pattern)

  1. The embedder is the seam. One interface — Embed(text) []float64 + Dim(). Swap fake, OpenAI, Ollama, BedRock without touching the rest of the code.
  2. Worker pool ingest. N workers pulling chunks from a buffered channel. Easy backpressure. This is exactly the shape used by real ingest pipelines that fan out to remote embedding APIs.
  3. Concurrency-safe store. A single mutex around an append-only slice. Predictable, cache-friendly, and good enough for hundreds of thousands of chunks.
  4. No GC pressure surprises. Vectors are []float64 slices — flat, contiguous memory. The same shape NumPy gives Python, but native here.

Where Rust would beat Go

If your store grows past a few million vectors, the cosine loop becomes the bottleneck. That's where teams swap the store for a Rust crate (HNSW, FAISS-rs, LanceDB) or a dedicated vector DB (Qdrant, also Rust). The Go service stays — it just calls into the Rust index over a network or FFI boundary. See Bootcamp 1 for the layered pattern.
