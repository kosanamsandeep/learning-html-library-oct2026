Go · P5

Contact Management — nested structs + hand-rolled validation

Python reaches for pydantic. Go's static type system already enforces "shape" at compile time, so you only need a small Validate() method for cross-field rules — exactly one primary email, phone numbers long enough, kind in a known set.

Why this is a good fit for Go

  • The struct is the schema. No "is this field a string?" check at runtime — the compiler already proved it.
  • Validation collects all errors. Don't fail-fast on the first issue; show every problem at once. Friendlier API.
  • Regex is in the standard library. regexp.MustCompile at package level for a prebuilt, thread-safe matcher.

Patterns to lift back into Python

Even if you stay in Python, two patterns from this version travel well:

  1. Always return all validation errors, not just the first.
  2. Pre-compile your regexes at module load — not on every call.
