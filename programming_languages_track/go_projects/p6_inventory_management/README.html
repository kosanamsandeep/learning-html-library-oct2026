Inventory — Repository pattern via tiny Go interfaces

The Python version uses an abstract base class. In Go, an interface with three methods is enough. InventoryService depends on the interface, not on the concrete store, so swapping memory ↔ file is a one-line change in main.

The interface trick

type Repository interface {
    Save(it Item) error
    Get(sku string) (Item, bool)
    All() []Item
}

func NewInventoryService(r Repository) *InventoryService { ... }

Both *MemoryRepo and *FileRepo have those three methods, so both satisfy Repository automatically. Go's interfaces are structural — no implements keyword.

What you'd write differently in production

  • Use a real DB (SQLite, Postgres) and depend on the same interface.
  • Add a context.Context parameter to every repo method — that's the Go convention for cancellation/timeouts.
  • Wrap the file repo in a mutex if you need concurrent access.
