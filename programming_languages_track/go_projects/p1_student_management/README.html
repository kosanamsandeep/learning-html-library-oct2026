Student Management — Go edition

Same domain, same operations as the Python version: a service that owns an in-memory store of students and exposes add / get / list / average. The interesting bit is what changes when you remove classes, exceptions, and dynamic types.

What the Python version did

  • Student dataclass with id, name, grade.
  • StudentService class holding a dict store and an __init__.
  • Raises ValueError if validation fails.

What changes in Go

  1. No classes. A struct holds the data; methods are functions with a receiver: func (svc *StudentService) Add(...).
  2. No exceptions. Add returns (Student, error). The caller writes if err != nil { ... }.
  3. No __repr__. Implementing String() string makes fmt.Println print nicely — Go's "stringer" interface.
  4. Pointer receiver vs value receiver. (svc *StudentService) means the method can mutate svc. A method on (s Student) can not mutate the original.
  5. Capitalisation = visibility. Student, Add, List are exported. Lowercase names like students are package-private.

The shape

Python

@dataclass
class Student:
    id: int
    name: str
    grade: int

class StudentService:
    def __init__(self):
        self.students = {}
        self.next_id = 1

    def add(self, name, grade):
        if not name:
            raise ValueError("name required")
        s = Student(self.next_id, name, grade)
        self.students[s.id] = s
        self.next_id += 1
        return s

Go

type Student struct {
    ID    int
    Name  string
    Grade int
}

type StudentService struct {
    students map[int]Student
    nextID   int
}

func (svc *StudentService) Add(name string, grade int) (Student, error) {
    if name == "" {
        return Student{}, errors.New("name required")
    }
    s := Student{ID: svc.nextID, Name: name, Grade: grade}
    svc.students[s.ID] = s
    svc.nextID++
    return s, nil
}

Win for Go

Errors are visible at every call site — no hidden control flow. The struct + method receiver is more verbose than a Python class, but easier to reason about: there's no inheritance ladder to walk.
