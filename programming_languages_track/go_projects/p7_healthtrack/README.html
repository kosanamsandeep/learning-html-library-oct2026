HealthTrack — the classic Go HTTP service shape

A real (tiny) HTTP service: handler → service → repository → domain. No framework, no external deps — just net/http and encoding/json. This is what 80% of Go services look like in production.

Record struct

Each layer only knows the one below. Tests can mock the layer below.

What's special vs Python/FastAPI

  • Routing is just http.ServeMux. No decorators, no app object. Add a path with mux.HandleFunc("/records", api.records).
  • Method dispatch in the handler. One handler per resource; switch on r.Method. Tiny and explicit.
  • sync.Mutex in the repo. Multiple goroutines hit the handler concurrently — Go expects you to handle that. Python/FastAPI typically gives you one event loop and async I/O.
  • No global app state. Build the chain in main, pass dependencies down. Easy to test.

cd go_projects/p7_healthtrack
go run .
