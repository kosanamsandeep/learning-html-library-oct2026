Go · P9

Notifications — Factory + Strategy + a goroutine fan-out

Three notification channels behind one interface. A registry maps name → implementation (the factory). And the broadcast runs all channels in parallel using goroutines + a sync.WaitGroup.

The fan-out — Go's headline feature in two lines

for _, name := range channels {
    name, c := name, c            // capture the loop vars
    go func() {                   // 2KB stack, scheduled by the runtime
        defer wg.Done()
        c.Send(to, body)
    }()
}
wg.Wait()

Three channels, three goroutines, total time = slowest channel, not the sum. In Python you'd reach for asyncio.gather(...); here it's the language's primary concurrency primitive.

Why the loop-var copy?

name, c := name, c creates a fresh copy per iteration. Without it, every goroutine would close over the same shared variable and you'd see only the last value. (Go 1.22+ makes this safer by default but the explicit copy still reads better.)

cd go_projects/p9_notification_platform
