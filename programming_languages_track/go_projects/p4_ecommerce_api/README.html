E-commerce API — DTO pattern, JSON tags, and the wire/domain seam

Go's encoding/json uses struct tags to control the wire format. That makes DTOs feel native: keep one set of structs for the API contract, another for the domain, and a small mapper between them.

The seam in two screens

// internal — never reaches the wire
type Product struct {
    ID          int
    Name        string
    PriceCent   int
    StockCount  int
    internalSKU string   // private (lowercase) — also skipped by json
}

// the wire shape
type ProductDTO struct {
    ID    int     `json:"id"`
    Name  string  `json:"name"`
    Price float64 `json:"price"`
    Stock int     `json:"stock"`
}
  • Tags drive serialisation. json:"price" renames the field on the wire; omitting a tag uses the field name; lowercase fields are skipped by encoding/json.
  • Money stays in cents internally, mapped to a float for the wire. Same lesson as the Python original.
  • The mapper is one function. toProductDTO(p Product) ProductDTO. No magic, no auto-binding library required.
