System Design learning track · LLD + HLD

From "I know OOP" to "I can design Twitter on a whiteboard"

This track teaches both halves of system design that product companies ask about: Low-Level Design (LLD) — modeling a single system with classes, responsibilities, and patterns (parking lot, elevator, ATM), and High-Level Design (HLD) — designing distributed systems that scale to millions of users (URL shortener, Twitter, WhatsApp, Uber).

Every page tells a story, shows the industry-standard approach, and gives you "what if you use it vs what if you don't" comparisons so the tradeoffs stick.

👉 New to this? Read What is System Design? HLD vs LLD first, then follow the 30-day roadmap.

Track 1 — Low-Level Design (LLD) Beginner → Intermediate

LLD is "given a problem statement, design the classes". This is the bread and butter of rounds 1–2 in product company interviews. You'll learn OOP done right, SOLID, design patterns, UML, and apply all of it to real interview cases.

LLD · 01

OOP & SOLID Principles

Encapsulation, inheritance, polymorphism, abstraction — then the 5 SOLID principles with before/after refactors.

 LLD · 02

Design Patterns Survey

Creational, Structural, Behavioral — the 12 patterns that come up most often, with code and "use vs don't" tradeoffs.

 LLD · 03

UML for the Whiteboard

Class diagrams, sequence diagrams, state diagrams — only the parts that matter in interviews and PRs.

 LLD · 04

Case Studies

Parking Lot, Elevator, Library, ATM — walked end-to-end the way an interviewer expects.

Track 2 — High-Level Design (HLD) Intermediate → Advanced

HLD is "design a system that handles 100M users". This is where you learn the actual moving parts of the internet: load balancers, caches, databases, queues, CDNs. You'll first learn the primitives, then combine them in famous case studies.

HLD · 01

Fundamentals & Scalability

Latency, throughput, vertical vs horizontal scaling, stateless services, back-of-envelope math.

 HLD · 02

Databases & Caching

SQL vs NoSQL, indexes, sharding, replication, cache-aside, write-through, CDN.

 HLD · 03

Distributed Systems Building Blocks

Load balancers, message queues, microservices, API gateways, CAP theorem, consistency.

 HLD · 04

Famous System Designs

URL shortener, Twitter feed, WhatsApp chat, Uber dispatch, YouTube — the canonical interview problems.

 HLD · 05

Choosing the Right Database

SQL · Mongo · Redis · Cassandra · Neo4j · Elasticsearch · Vector · S3 — when to use what, with Mermaid diagrams and 10 horror stories.

How to use this track

  1. Spend Week 1 on LLD pages 01–04. Practice drawing the case studies on paper.
  2. Spend Week 2 on HLD pages 01–03 (the primitives).
  3. Spend Weeks 3–4 attacking HLD case studies, one per day. Time-box yourself to 45 minutes per case as if it were a real interview.
  4. Follow the 30-day roadmap for the exact daily plan.
